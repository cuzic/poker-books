# 第15章　リバーでの相手タイプ別エクスプロイト — 攻守両面

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: 相手の4タイプ（Fish / Station / Nit / LAG）に応じてリバーのIP側ベット戦略とOOP側ディフェンス戦略を調整し、相手の弱点を数値で突けるようにする。

---

## 15-1 リバーはエクスプロイト効果が最大になるストリート

ポーカーにはフロップ・ターン・リバーという3つのポストフロップストリートがあります。エクスプロイト（相手の傾向を逆手に取る調整）の効果は、ストリートが進むほど大きくなります。

フロップでの判断ミスは「まだターンとリバーで修正できる」余地があります。しかしリバーはその余地がゼロです。リバーでの1回の判断ミスが「ポット全体の損得」に直結します。逆に言えば、リバーで相手タイプを正確に読んで適切な調整を加えれば、その効果も最大になります。

### なぜリバーで効果が最大なのか

リバーではブラフが「最後の砦」になります。フロップやターンでのブラフには「次のストリートで降ろせる」という継続的な圧力がありました。リバーでのブラフは「今フォールドさせなければ終わり」という1回切りです。この構造から、相手タイプによってブラフの価値が極端に変わります。

```
Fish（フォールドしない）の場合:
  ブラフの期待値 ≈ 0（Fish は通常フォールドしない）
  → リバーブラフに使うチップは損失確定

Nit（フォールドしやすい）の場合:
  ブラフの期待値 > 0（Nit は弱いベットにも反応してフォールド）
  → ブラフが利益を生む
```

バリューベットについても同じです。Fish はバリューベットに対してほぼコールするため、サイズを大きくするほどリターンが増えます。Nit は大サイズに反応してフォールドするため、小サイズでコールを誘う必要があります。

### 4タイプの基本特性（リバー版）

本章では次の4タイプを扱います。それぞれのリバーでの行動傾向を把握することが、調整の出発点です。

| タイプ | コール傾向 | ブラフ頻度 | IP攻撃の方向 | OOP守備の方向 |
|---|---|---|---|---|
| Fish | 広く（何でも）コール | ほぼゼロ | バリューのみ・大サイズ | 相手ベット≒バリュー、降りる準備 |
| Station | 超広くコール | 少しある | 薄いバリューまで全てベット | やや広くコール |
| Nit | フォールドが多い | ほぼゼロ | ブラフ増加・小サイズで誘う | 相手ベット≒ナッツ、降りる準備 |
| LAG | 広くコール | 多い | バリューを絞る | ブラフキャッチ積極化 |

この4タイプは「コール傾向」と「ブラフ頻度」の2軸で整理できます。FishとNitは「ブラフが少ない」点で共通しますが、コール傾向が真逆です。StationとLAGは「コールが多い」点で共通しますが、ブラフ頻度が異なります。

### HandScoreバケットの確認

本章では巻④ 第11章で確立したHandScoreを使って判断します。リバーでのバケット区分は次の通りです。

```
V バケット  (HS ≥ 70): セット・ストレート・フラッシュ以上のバリューゾーン
M+ バケット (HS 55-69): TPTK・強い2ペア。ショーダウン価値が高い
M- バケット (HS 35-54): 弱いペア・ショーダウン価値は中程度
B バケット  (HS < 35): 役なし・Aハイなど。ブラフ候補またはフォールド
```

通常（GTO基準）のリバーIP攻撃では、M+ バケット（HS ≥ 55）以上でベット、Bバケットはブラフ候補か チェックです。OOP側は後手スコア（巻④ 第11章）で守備基準を計算し、フォールド閾値 HS < 42（vs 50%ベット基準）を使います。相手タイプの調整はこの基準値をシフトさせます。

## 15-2 vs Fish：IP は 75% でバリュー最大化、OOP は降りる準備

### Fishの弱点と攻略方向

Fishの最大の特徴は「コールレンジが広すぎる」ことです。GTOが「コール」とする範囲より大幅に広いハンドでコールしてきます。同時に、Fishがリバーをベットするときはほぼバリューハンドです。ブラフに必要な「相手が降りてくれる」という前提が成立しないため、Fishに対してブラフを打つのは損失確定の行為になります。

Fish相手のリバー戦略は「バリューを最大化し、ブラフはゼロにする」のシンプルな方針です。

### IP（ベット側）の調整

```
vs Fish のIP リバー攻撃（blank river想定）:

V バケット  (HS ≥ 70): ベット 75% pot（バリュー最大化）
M+ バケット (HS 55-69): ベット 75% pot（Fish はコールしてくれる）
M- バケット (HS 35-54): チェック（SDVで逆転勝ちを狙う）
B バケット  (HS < 35): チェック（ブラフ禁止：Fish はフォールドしない）

サイズ方針: GTO標準 50% → Fish相手は 75% に引き上げ
ブラフ頻度: 0%（Fish へのブラフは期待値マイナス）
```

GTO基準では50%ベットが標準的なリバーサイズです。Fish相手ではこれを75%に引き上げます。Fishがコールしてくれる確率が高いため、サイズを大きくするほどEVが上がります。ポットベット（100%）も場合によっては正当化されます。

ただしM-バケット（HS 35〜54）のSDV（ショーダウンバリュー）ハンドは慎重に扱います。Fishはコールしてくることが多いため、ベットしてもショーダウンバリューを活かしにくい場面があります。チェックしてショーダウンを目指し、Fishの弱いハンドに逆転勝ちを狙うほうが高EVになります。

**実例1**: AhKh（TPTK）、ボード Kc-7d-2s-9h-3d、IP、vs Fish

```
ハンド + ボード確認:
  手: Ah,Kh  ボード: Kc,7d,2s,9h,3d（リバー5枚）
  ランク別カウント: A=1枚, K=2枚（Kh+Kc）, 9=1枚, 7=1枚, 3=1枚, 2=1枚
  役: Kのペア（トップペア）、Aキッカー → TPTK
  ストレート確認: A,K,9,7,3,2 → 5連続なし → なし
  フラッシュ確認: ハート Ah,Kh = 2枚のみ → なし
  HandScore = 65（TPTK、リバーでの評価）→ M+ バケット

vs Fish の調整:
  M+ バケット × Fish → BET 75% pot
  理由: Fish はM+コールしてくる。サイズ最大化で期待値を引き出す。
  ブラフ: 不要（チェックバックでSDVを活かす選択肢もある）
```

### OOP（守備側）の調整

Fish がリバーをベットしてきたとき、そのベットに含まれるブラフの割合はほぼゼロです。Fishのリバーベットはほぼバリューハンドです。

```
vs Fish のOOP フォールド閾値調整（vs 50%ベット基準）:

通常: HS < 42 でフォールド
vs Fish: HS < 57（+15 引き上げ）
        → M+ バケット（HS 55-69）の下限付近でもフォールド候補

river_tag 補正を追加で適用:
  SC/FC ボード: −5（ドロー完成でコールしやすい）
  PB ボード:    +10（ペアボードでバリューが強化）
  例: Fish × SC ボード → 57 − 5 = 52

OOP ブラフキャッチ方針:
  B バケット（HS < 35）: フォールド確定（Fish にブラフキャッチ不要）
  M- バケット（HS 35-54）: フォールド候補（Fish のベットはほぼバリュー）
  M+ バケット（HS 55-69）: フォールド域に入ることが多い（閾値57と比較）
```

**実例2**: AhQd（Aハイ）、ボード Kc-7d-2s-9h-3d、OOP、vs Fish

```
ハンド + ボード確認:
  手: Ah,Qd  ボード: Kc,7d,2s,9h,3d
  ランク別カウント: A=1枚, Q=1枚, K=1枚, 9=1枚, 7=1枚, 3=1枚, 2=1枚
  役: ペアなし。best 5 = A-K-Q-9-7 → Aハイ
  ストレート確認: A,K,Q,9,7,3,2 → A-K-Q-J-T? J,T なし。なし。
  HandScore = 25（Aハイ、役なし）→ B バケット

vs Fish の OOP 守備判断:
  フォールド閾値 = 42 + 15 = 57（blank board, +15 Fish 補正）
  HandScore 25 < 57 → FOLD
  （通常 GTO 基準 42 でもフォールドだが、Fish補正でさらに明確にフォールド）
```

### OOP リードの方針（Fish に先手ベット）

Fish がリバーをチェックしてきた場面でのOOPリード（先手ベット）は限定的です。FishはVバケットに対してコールしてくる可能性が高いため、Vバケット × SC/FC ボードでのリードは有効です。M-バケット以下でのリードは、Fishのコールで負け越す展開になるため避けます。

## 15-3 vs Station：薄いバリューまで全てベット、OOP はやや広くコール

### Stationの特徴と攻略方向

Stationは「呼び名の通り何でも呼ぶ」プレイヤーです。コールレンジがFish同様に広い一方で、Fishと異なり少量のブラフも打ってきます。Stationのブラフは頻度は低いですが、皆無ではありません。

この性質から次の2つの方向性が生まれます。

1. **IPから見ると**: Stationがコールしてくれるため、薄いバリュー（M-バケット）でもベットできる
2. **OOPから見ると**: Stationのベットには少量のブラフが含まれるため、GTO基準より少しコールを広げられる

### IP（ベット側）の調整

```
vs Station の IP リバー攻撃（blank river想定）:

V バケット  (HS ≥ 70): ベット 50% pot（通常通り）
M+ バケット (HS 55-69): ベット 50% pot（Station はコールしてくれる）
M- バケット (HS 35-54): ベット 50% 検討（SDVがStationのブラフに勝てる）
B バケット  (HS < 35): ブラフ削減（Stationはコールするためブラフ −EV）

ベット閾値 (blank river, 50%ベット想定):
  通常: HS ≥ 55（M+ 以上でベット）
  vs Station: HS ≥ 50（−5 引き下げ）→ M- 下限付近もベット候補

サイズ方針: 50%（Stationはサイズに関わらずコールするため、EV最大は50%前後）
ブラフ方針: 削減（Stationのコール頻度が高いため、ブラフは期待値マイナス傾向）
```

M-バケットのベット判断には補足が必要です。M-バケット（HS 35〜54）のハンドはSDVを持ちつつ、Station のリバーブラフ（低頻度）に対しても勝てる可能性があります。通常であれば「チェックしてSDVを守る」選択肢を取りますが、Station相手では「ベットして薄いバリューを取り、Station の弱いコールを引き出す」ほうが期待値が高い場合があります。

**実例3**: KhJh（TPMK）、ボード Kc-7d-2s-9h-3d、IP、vs Station

```
ハンド + ボード確認:
  手: Kh,Jh  ボード: Kc,7d,2s,9h,3d
  ランク別カウント: K=2枚（Kh+Kc）, J=1枚, 9=1枚, 7=1枚, 3=1枚, 2=1枚
  役: Kのペア（トップペア）、Jキッカー → TPMK（トップペア・ミドルキッカー）
  ストレート確認: K,J,9,7,3,2 → 5連続なし（K-J間にQ,Tが必要）
  フラッシュ確認: ハート Kh,Jh,9h = 3枚のみ → なし
  HandScore = 60（TPMK）→ M+ バケット

vs Station の調整:
  M+ バケット × Station → BET 50% pot
  理由: Station はM+コールしてくる。確実なバリューを取る。
  比較: vs GTO では HS≥55 でベットと同じ結論だが、Stationは確実にコールするため安心してベットできる。
```

### OOP（守備側）の調整

Station のリバーベットにはバリューが多く含まれますが、少量のブラフも存在します。GTO基準よりわずかにコールを広げることが正当化されます。

```
vs Station の OOP フォールド閾値調整（vs 50%ベット基準）:

通常: HS < 42 でフォールド
vs Station: HS < 37（−5 引き下げ）→ M- バケット下限でもコール候補

M- バケット（HS 35-54）の追加指針:
  ポットオッズ次第でコール可（SDVが Station のブラフに勝てる）
  Station のコール傾向から、Station がリードしたとき → やや弱いハンドもコール検討

OOP リードの方針:
  Station 相手にはやや積極的にリードしてもよい
  M+ バケット + SC/FC ボード → リード候補（Station は広くコールしてくれる）
```

## 15-4 vs Nit：ブラフを増やし、相手のベットには降りる

### Nit の弱点と攻略方向

Nit の最大の弱点は「フォールドしすぎること」です。GTOが要求するディフェンス頻度（後手下限確率）を大幅に下回るフォールド率を持ちます。この「フォールドしすぎ」をブラフで突くのがNit攻略の核心です。

一方、Nit がリバーをベットしてきたときは、そのレンジがほぼナッツ付近に絞られています。Nit はブラフをほとんどしないため、Nit のリバーベット = 強いバリューハンドと解釈できます。

### IP（ベット側）の調整

```
vs Nit の IP リバー攻撃（blank river想定）:

V バケット  (HS ≥ 70): ベット 33% pot（小サイズでコールを誘う）
M+ バケット (HS 55-69): ベット 33%（Nit のフォールドを防ぐ。大サイズは逃げられる）
M- / B バケット: ブラフ増加
  通常ブラフ頻度 約30% → vs Nit 約40-45% に増加
  ブラフサイズ: 33-50% pot（Nit がフォールドしやすいサイズ）

ベット閾値 (blank river):
  通常: HS ≥ 55
  vs Nit: HS ≥ 50（ブラフを含む全体的な頻度を増加）
```

バリューのサイズを33%に落とす理由は「Nit は大きいベットにフォールドしやすい」からです。75%ベットしても Nit にフォールドされるなら、33%ベットでコールを引き出すほうが期待値は高くなります。

ブラフサイズも同じ論理です。Nit に対しては「小サイズで恐怖を与える」ことでフォールドを取れます。ポットを大きくする必要はありません。

**実例4**: QhJh（役なし）、ボード Kc-7d-2s-9h-3d、IP、vs Nit

```
ハンド + ボード確認:
  手: Qh,Jh  ボード: Kc,7d,2s,9h,3d
  ランク別カウント: Q=1枚, J=1枚, K=1枚, 9=1枚, 7=1枚, 3=1枚, 2=1枚
  役: Q,J ともにボードに当たらず → ハイカード（Q-J、Kは共有）
  ストレート確認: K,Q,J,9,7,3,2 → K-Q-J-T-9? T なし。Q-J-T-9-8? T,8 なし。なし。
  フラッシュ確認: ハート Qh,Jh,9h = 3枚のみ → なし
  HandScore ≈ 28（役なし、Q-J ハイ）→ B バケット

vs Nit の調整:
  B バケット × Nit → BLUFF 33% pot（ブラフ推奨）
  理由: Nit はフォールドしやすい。33%サイズで確実にフォールドを取る。
  通常なら: B バケットはブラフ条件付き（ブロッカー保有推奨）
  vs Nit なら: ブロッカー要件が緩くなる（Nit のフォールド頻度が高いため）
```

### OOP（守備側）の調整

Nit がリバーをベットしてきたとき、そのベットに含まれるハンドはほぼナッツ付近です。通常の後手スコアで「コール」と計算されたとしても、Nit 相手では慎重になるべきです。

```
vs Nit の OOP フォールド閾値調整（vs 50%ベット基準）:

通常: HS < 42 でフォールド
vs Nit: HS < 57（+15 引き上げ）→ M+ バケット（HS 55-69）でもフォールド候補

指針:
  V バケット（HS ≥ 70）のみ、Nit のベットに対してコール（または CR）
  M+ バケット以下: フォールドが正解になることが多い

OOP リードの方針:
  Nit 相手にはリード有効（Nit はレイズしにくい）
  SC/FC ボード + M+ バケット → リード候補（Nit はコールまたはフォールド、CR は少ない）
  Nit のリードへの対応: V → CR または コール、M+ → フォールド推奨
```

**実例5**: QhJh（役なし）、ボード Kc-7d-2s-9h-3d、OOP、vs Nit（Nit がリバーベット）

```
ハンド + ボード確認:
  （実例4と同じハンド・ボード、ポジションのみ異なる）
  HandScore ≈ 28（役なし）→ B バケット

vs Nit の OOP 守備判断:
  フォールド閾値 = 42 + 15 = 57（blank board、+15 Nit 補正）
  HandScore 28 < 57 → FOLD（明確なフォールド）
  （通常 GTO 基準 42 でもフォールドだが、Nit 補正でさらに確実）
```

**実例6**: Th9c（T-high ストレート）、ボード 9s-8d-7c-6h-3d、OOP、vs Nit（Nit がリバーベット）

```
ハンド + ボード確認:
  手: Th,9c  ボード: 9s,8d,7c,6h,3d（リバー5枚）
  ランク別カウント: T=1枚, 9=2枚（9c+9s）, 8=1枚, 7=1枚, 6=1枚, 3=1枚
  ストレート確認: T(10),9,8,7,6 = 5連続 → T-high ストレート完成
  フラッシュ確認: ハート Th,6h = 2枚のみ → なし
  HandScore = 82（ストレート）→ V バケット

vs Nit の OOP 守備判断:
  フォールド閾値調整: blank base = 42、SC ボード補正 −5 = 37、Nit 補正 +15 → 37 + 15 = 52
  HandScore 82 ≥ 52 → CALL（Vバケット、フォールド閾値を大幅に超える）
  さらに: V バケット × Nit → CR も検討（Nit のブラフが少ないため、バリューを最大化するCR）
```

## 15-5 vs LAG：バリューを絞り、OOP でブラフキャッチ

### LAG の特徴と攻略方向

LAG（Loose Aggressive）は最も複雑なタイプです。バリューレンジもブラフレンジも広く、ベット頻度が高い。LAG の弱点は「ブラフが多すぎること」です。

LAG がリバーをベットしてきたとき、そのベットには大量のブラフが含まれています。M-バケットのハンドでも「LAG のブラフに対するブラフキャッチャー」として機能することがあります。逆に IP から LAG に対してブラフを打つのは難しくなります。LAG のコールレンジが広いためブラフが通りにくく、LAG のチェックレイズにも注意が必要です。

### IP（ベット側）の調整

```
vs LAG の IP リバー攻撃（blank river想定）:

V バケット  (HS ≥ 70): ベット 50% pot（通常通り）
M+ バケット (HS 55-69): ベット慎重（LAG の CR/レイズに注意）
M- バケット (HS 35-54): チェック（LAG の CR が怖い。SDVを守る）
B バケット  (HS < 35): ブラフ削減（LAG のコール範囲が広いためブラフ −EV）

ベット閾値 (blank river):
  通常: HS ≥ 55
  vs LAG: HS ≥ 60（+5 引き上げ）→ バリューを絞る

サイズ方針: 50%（LAGに過大サイズは CR で返ってくるリスク）
```

vs LAG でベット閾値を+5引き上げる理由は「LAGのレイズレンジが広く、薄いバリューでベットすると CR に合ってしまう」からです。M-バケットはチェックして、LAG が打ってきたときに後手スコアで守備判断します。

### OOP（守備側）の調整

LAG のリバーベットに含まれるブラフ頻度は高く、GTO基準よりコールを広げることが正当化されます。

```
vs LAG の OOP フォールド閾値調整（vs 50%ベット基準）:

通常: HS < 42 でフォールド
vs LAG: HS < 32（−10 引き下げ）→ M- バケット（HS 35-54）でもコール候補

ブラフキャッチャーの活用:
  M- バケット（HS 35-54）: LAG のブラフに対して有効なブラフキャッチャー
  B バケット下限（HS 32-34）: ポットオッズ次第でコール候補（閾値32との比較）

OOP チェックレイズ:
  通常より積極的: HS ≥ 70 で LAG のベットに CR
  理由: LAG はブラフが多い → CR でブラフを排除しつつバリューを最大化

OOP リードの方針:
  LAG には控えめ（LAG が逆 CR してくる可能性）
  V バケット + SC/FC ボードのみリード。M+ はチェックが安全
```

**実例7**: AhKh（TPTK）、ボード Kc-7d-2s-9h-3d、OOP、vs LAG（LAG がリバーベット）

```
ハンド + ボード確認:
  （実例1と同じハンド・ボード、ポジション・対戦相手が異なる）
  HandScore = 65（TPTK）→ M+ バケット

vs LAG の OOP 守備判断:
  フォールド閾値 = 42 − 10 = 32（−10 LAG 補正）
  HandScore 65 ≥ 32 → CALL（M+バケット、LAGのブラフも相当数含まれる）
  比較: 通常 GTO 基準（閾値 42）でも 65 ≥ 42 → CALL だが、
        LAG 補正によって「確信を持ってコール」に変わる
```

**実例8**: 8h7h（2ペア）、ボード 9s-8d-7c-6h-3d、OOP、vs Station（先手リード）

```
ハンド + ボード確認:
  手: 8h,7h  ボード: 9s,8d,7c,6h,3d（リバー5枚）
  ランク別カウント: 8=2枚（8h+8d）, 7=2枚（7h+7c）, 9=1枚, 6=1枚, 3=1枚
  ストレート確認: 8,7,9,8,7,6,3 → 9-8-7-6-5? 5なし。T-9-8-7-6? Tなし。なし。
  best 5: 9s-8h-8d-7h-7c = 2ペア（8s & 7s、9キッカー）
  HandScore ≈ 68（2ペア、セカンド+サード）→ M+ バケット

vs Station の OOP リード判断:
  M+ バケット × SC ボード × vs Station → リード候補（+50% pot）
  理由: Station は M+ ハンドに広くコールしてくる。
        SC（スーテッド・コネクテッド）ボードでのM+リードが有効。
  期待効果: Station からリバーコールを引き出してバリューを確定させる。
```

## 15-6 タイプ × ポジション調整表（リバー早見表）

### 調整の全体像

4タイプ × IP/OOP の調整を1枚の表に整理します。

| タイプ | IP ベット閾値 | IP サイズ | IP ブラフ | OOP フォールド閾値 | OOP リード |
|---|---|---|---|---|---|
| Fish | M+（HS ≥ 55） | 75% pot | 0% | +15（HS < 57） | V + SC/FC のみ |
| Station | M-（HS ≥ 50、−5） | 50% pot | 削減 | −5（HS < 37） | M+ + SC/FC |
| Nit | HS ≥ 50 + ブラフ増 | 33% pot | 45% | +15（HS < 57） | M+ + SC/FC（積極） |
| LAG | HS ≥ 60（+5） | 50% pot | 削減 | −10（HS < 32） | V + SC/FC のみ |

基準値は「vs 50% ベット、blank ボード、GTO通常」です。river_tag 補正（SC/FC −5、PB +10 等）はタイプ補正に加算して適用します。

### 複合補正の計算例

| 状況 | 計算式 | 結果 |
|---|---|---|
| Fish × SC ボード | 42 + 15 − 5 = 52 | HS < 52 でフォールド |
| Nit × SC ボード | 42 + 15 − 5 = 52 | HS < 52 でフォールド |
| LAG × SC ボード | 42 − 10 − 5 = 27 | HS < 27 でフォールド |
| Station × PB ボード | 42 − 5 + 10 = 47 | HS < 47 でフォールド |
| Fish × PB ボード | 42 + 15 + 10 = 67 | HS < 67 でフォールド（V バケット下限でフォールド候補） |

### 調整を適用するタイミングの注意点

相手タイプへの調整は「傾向が確認できた後」に適用します。50ハンド以上のサンプルで一貫した傾向が見えてから調整を始めるのが安全です。不確実な場合はGTO基準（調整なし）を維持します。

また、調整は「相手が変化しない」という前提を置いています。Nit に対してブラフを繰り返すうちに、相手がブラフに気づいてアジャストしてくる可能性があります。相手が調整してきたら、こちらも再調整が必要です。

## 15-7 攻守の統合判断フロー

本章の内容を統合した実戦判断フローを示します。

### IPのリバー判断フロー（相手タイプ別）

```
Step 1: 相手タイプを確認
  Fish / Station / Nit / LAG のどれか？

Step 2: HandScore を確認（巻④ 第11章）
  ボード+ハンドで役を計算し、バケット（V/M+/M-/B）を確定

Step 3: タイプ別調整を適用
  Fish:    V/M+ → 75% ベット。M-/B → チェック。ブラフ0%
  Station: V/M+/M- → 50% ベット。B → ブラフ削減
  Nit:     V/M+ → 33% ベット。M-/B → ブラフ増加（45%）
  LAG:     V → 50% ベット。M+ → 慎重ベット。M-/B → チェックまたはブラフ削減

Step 4: river_tag 補正を追加
  SC/FC: Nit への M+ ベットに加えて OOP リードも検討
  PB:    全タイプでバリューを強化（大きい役が多い）
```

### OOPの守備判断フロー（相手タイプ別）

```
Step 1: 相手タイプを確認
Step 2: HandScore を確認し、フォールド閾値を計算
  基準閾値 42 にタイプ補正とriver_tag 補正を加算

Step 3: 比較して判断
  HS ≥ 調整後閾値 → コール（または CR の検討）
  HS < 調整後閾値 → フォールド

Step 4: CR の検討（HS ≥ 70 のみ）
  LAG 相手: 積極的に CR
  Nit 相手: CR よりコールが安全（Nit のベット=バリュー）
  Fish/Station: 通常の CR 基準（巻④ 第11章の後手スコアに従う）
```

## ミニクイズ

### 問1

BTN（IP）がリバーでAhKc（TPTK）を持っています。ボードはKd-7s-2h-9c-4d（blank）で、相手が Fish です。HandScore = 65。どのアクションが最適ですか。

1. チェックバック（Fishのリバーベットを誘う）
2. ベット 33% pot（小サイズでコールを誘う）
3. ベット 75% pot（Fishはコールしてくれる、サイズを最大化）

### 問2

BB（OOP）がリバーでQcJc（役なし、Qハイ）を持っています。ボードはKs-8h-3d-6c-2s（blank）です。HandScore = 28。相手のタイプが Nit の場合、Nit がリバーで 50% ベットしてきました。どうしますか。

1. 通常のGTO判断（後手スコアでコール/フォールドを計算）
2. Nit のベット = ほぼバリューなので、通常より strict なフォールド基準を適用してフォールド
3. Nit はブラフしないのでコール（ブラフキャッチ）

### 問3

CO（OOP）がリバーでKhQh（TPTK に近い、HS = 68）を持っています。ボードはKd-9s-5c-3h-2d（blank）です。相手が LAG で、LAG がリバーで50%ベットしてきました。通常のフォールド閾値は 42 です。どうしますか。

1. HS 68 > フォールド閾値 42 → コール（通常通り）
2. vs LAG は −10 補正 → フォールド閾値 32。HS 68 ≥ 32 → 確信を持ってコール
3. LAG は強いハンドが多いのでフォールド

---

### 解答

- **問1**: 3（Fish はコールレンジが広く、M+バケット（HS=65）でも Fish はコールしてくれます。Fish 相手のIP攻撃は「バリューのみ、大サイズ」が基本方針です。75% ベットを打つことで期待値を最大化できます。チェックバックは Fish のリバーベットを誘いますが、Fish のベットサイズが小さいと損になるため積極的にベットするほうが有利です）
- **問2**: 2（HandScore 28 < Nit 補正後フォールド閾値 57（= 42 + 15）→ FOLD。Nit のリバーベットはほぼバリューハンドです。通常の GTO 判断では HS 28 < 42 でも当然フォールドですが、Nit 補正を加えると「M+バケット下限（HS55付近）でもフォールド候補」になります。選択肢3はブラフキャッチの説明が逆です。Nit はブラフしないため、Nit のベットにブラフキャッチは機能しません）
- **問3**: 2（vs LAG のフォールド閾値 = 42 − 10 = 32。HS 68 ≥ 32 → CALL。LAG はブラフが多いため、GTO 基準（閾値 42）でもコールですが、vs LAG 補正（−10）によって「確信を持ってコール」できます。選択肢3は LAG に対して正反対の対応です。LAG にはフォールドを増やすのではなく、コールを広げてブラフをキャッチすることが正解です）

---

> **本章まとめ**
>
> - Fish 相手 IP は「バリューのみ 75%、ブラフゼロ」。OOP のフォールド閾値を +15（HS < 57）に引き上げ
> - Station 相手 IP は「M- まで全てベット 50%、ブラフ削減」。OOP のフォールド閾値を −5（HS < 37）に引き下げ
> - Nit 相手 IP は「バリュー 33% で誘い、ブラフを 45% まで増加」。OOP のフォールド閾値を +15（HS < 57）に引き上げ
> - LAG 相手 IP は「ベット閾値 +5（HS ≥ 60）でバリューを絞る」。OOP のフォールド閾値を −10（HS < 32）に引き下げてブラフキャッチ
> - OOP リードは Fish と LAG には V + SC/FC のみ。Station と Nit には M+ + SC/FC でも積極的に
> - タイプ補正と river_tag 補正は加算して計算する。50+ ハンドの傾向確認後に適用し、不確実な場合は GTO 基準を維持

**【GTOとのズレ】**

本章で示した「タイプ別調整」はGTOから外れた戦略です。GTO は相手の傾向に関係なく均衡した頻度でプレイしますが、エクスプロイト戦略は相手が均衡を破っていることを前提に一方的な利益を狙います。

最も起きやすいズレは「Nit に対するブラフの過剰適用」です。ブラフ頻度を 45% まで引き上げるのは、Nit のフォールド傾向が「50ハンド以上の実測で確認できた」場合の話です。数ハンドの観察でNit認定してブラフを増やすと、Nit が実はアジャストしていた場合や、そもそもの分類が誤っていた場合に大きな損失を生みます。GTO 基準（約 30% ブラフ頻度）から大きく外れるエクスプロイトほど、分類ミスのコストが高くなります。

次に起きやすいズレは「Fish に対する OOP での過剰フォールド」です。フォールド閾値を +15 して HS < 57 でフォールドするのは「Fish のリバーベット = ほぼバリュー」という前提に依存します。Fish の中でも「一応ブラフも打つ初心者」と「本当に何も考えずにベットする人」は区別が必要で、後者にのみこの補正が有効です。Fish を同質なタイプとして扱いすぎると、適度なブラフを持つ相手に対してフォールドしすぎる「Nit 化」が起きます。

「LAG のブラフキャッチを積極化」も注意が必要なエクスプロイトです。M-バケット（HS 35〜54）でのコールは「ショーダウン時に LAG のブラフに勝てる」ことが前提です。LAG の実際のブラフ頻度が思ったより低い場合、M-バケットでのコール拡大は逆に EV を悪化させます。フォールド閾値の引き下げは「LAG のブラフ率が高いという強い根拠がある」ときに限定するのが安全です。

エクスプロイト量に関する目安として、適切に実行された場合の EV 向上は Fish 相手で約 8〜12%、Station 相手で約 5〜8%、LAG 相手で約 6〜10%、Nit 相手で約 4〜7% とされています。ただしこれは「相手が変化しない」場合の数値です。相手がアジャストしてきた後も同じ調整を続けると、この EV アドバンテージはゼロまたはマイナスに逆転することがあります。エクスプロイトは「生きた戦略」として常に更新が必要です。
