## A　3軸統合（本書の中心概念）

### 3軸統合

ターン判断における3つの情報軸を同時に評価するフレームワーク。本書の中心テーゼ。

| 軸 | 内容 | 参照 |
|---|---|---|
| **forward 軸** | プリフロップ・フロップの過去レンジから引き継いだレンジ情報 | 第1章・第3章 |
| **current 軸** | ターンカードがレンジに与える影響（ターンカード5分類） | 第1章・巻4 第7章 |
| **backward 軸** | リバーで何が起きるかを先読みし、ターン判断を設計する視点 | 第1章・第2章 |

3軸の積として判断するのがポイントです。いずれかの軸が欠けると精度が落ちます。リバーには将来カードがないため backward 軸が消え、forward + current の2軸で判断します。第1章参照。

### forward 軸（フォワード軸）

過去レンジを現在の判断に活かす視点。プリフロップの役割（オープン / コール / 3-bet側）とフロップのアクションシーケンスによって形成される Capped / Uncapped 状態が forward 軸の核。

forward 軸が示す最重要の知見は「双方のレンジは同じ条件で始まっていない」という非対称性です。アグレッサーは Uncapped 寄り、コーラーは Capped 寄り、というデフォルト状態を前提に判断を組み立てます。第1章・第3章参照。

### current 軸（カレント軸）

ターンカードが双方のレンジに与える影響の評価。巻4で学んだターンカードの5分類（ペア / OC / ブランク / フラッシュ / コネクター）がこの軸の評価基準です。同じ forward 軸の状態であっても、current 軸のターンカードが変わるだけで「攻めるべき局面」と「慎重になるべき局面」が入れ替わります。第1章参照。

### backward 軸（バックワード軸）

リバーで起きうることを先読みしてターン判断を設計する視点。「リバーのEVが最大になるターン判断はどれか」という問いがこの軸の核心です。backward induction（逆算設計）を実行するために必要な軸で、ターン特有の視点です。第1章・第2章参照。

## B　backward induction（逆算設計）

### backward induction（バックワードインダクション）

リバーから逆算してターン判断を設計する思考法。ゲーム理論の概念を実戦判断に応用したもの。

```
最終状態（リバー）のEVを先に推定し、
そのEVを最大化するターンのアクションを選ぶ
```

5ステップのフロー（詳細 → 第2章・付録A の A-2）:

1. リバー到達時の想定シナリオを列挙する
2. 各シナリオでのリバー EV を概算する
3. ターンアクションと最終 EV を対応させる
4. ターン判断を決定する
5. サイズがリバー SPR に与える影響を確認する

backward induction が最も有効な局面は「ターンで弱いバリューをベットすべきか、チェックでトラップすべきか」という判断です。単独のストリートでの判断よりも最終 EV が大きい方を選べます。第2章参照。

### リバーSPR（リバー時点のスタック対ポット比）

ターンのアクション後にリバーに入る時点でのスタック対ポット比。backward induction において、リバーでのベットサイズと戦略の自由度を規定します。

```
リバー SPR = ターン後の残りスタック ÷ ターン後のポット
```

| リバー後のSPR | 状況 | 方針 |
|---|---|---|
| < 1 | ポットコミット | 強いハンドならオールイン前提 |
| 1〜2 | 準コミット | バリューはほぼ全額ベット |
| 2〜4 | 通常 | 75%〜100%ポットのオプションあり |
| > 4 | 余裕あり | 小〜中サイズから選択可能 |

ターンで大きいサイズを使うほど、リバーのSPRが下がりポットコミット化が進みます。第2章・第9章参照。

## C　forward thinking（前向き思考）

### forward thinking（フォワードシンキング）

3軸統合における「forward 軸を起点とした判断フロー」の名称。巻1〜3 で確立されたレンジ情報を現在のストリートで最大限に活用する思考習慣。

forward thinking の対象情報:
- プリフロップでのポジション・オープン役割・3-betの有無
- フロップでの CBet / コール / CR のシーケンスによるレンジ状態の変化
- フロップボードタイプ（ドライ / セミ / ウェット）とナッツアドバンテージの方向

forward thinking と backward induction の組み合わせが本書の統合判断の核心です。forward で「今誰がどの状態か」を確認し、backward で「最終EVを最大化するターン判断」を設計します。第3章参照。

## D　ハンドエボリューション

### ハンドエボリューション（hand evolution）

ターンカードやリバーカードが落ちることで、ハンドの役が変化すること。本書で特に重視する概念で、ペアターン（フロップと同ランクのターンカード）での役変化が最も頻繁に見落とされます。

**典型的な誤認と正しい更新例**

| ボード | ハンド | 誤った判断 | 正しい更新 |
|---|---|---|---|
| K72 + 7ターン | AK | 「TPTKのまま」 | 2ペア（K's & 7's, A kicker）に昇格 |
| K72 + 7ターン | KK | 「セットのまま」 | フルハウス（K's full of 7's）に昇格 |
| K72 + 7ターン | 77 | 「セットのまま」 | クワッズ（4 7's）に昇格 |
| K72 + Kターン | AK | 「TPTKのまま」 | トリップス（K's, A kicker）に昇格 |

「フロップ時点の役がそのまま続く」という思い込みを排除し、ストリートごとに役を更新して評価することが基本です。第1章・第4章・第14章・第15章参照。

## E　ブロッカー実戦概念

### バリューブロッカー（value blocker）

相手のバリューコールレンジの中心ハンドを「ブロック」するカード。自分がそのカードを持つことで、相手がそのカードを持てなくなり、相手のバリュー保有確率が下がります。

主な使用場面:
- ブラフ選択: バリューブロッカーが強いコンボをブラフとして優先する
- ブラフ期待値の計算: 相手のコール確率が相対的に下がるため、フォールドエクイティが高まる

```
例: フラッシュ完成ボードで A♥ を持つ場合
  → 相手のナッツフラッシュ（A♥ + もう1ハート）の可能性をゼロにする
  → ブラフとして A♥ 保持コンボを優先
```

第5章参照。

### ブラフブロッカー（bluff blocker）

相手のブラフ候補コンボを「ブロック」するカード。自分がそのカードを持つことで、相手がそのカードを持てなくなり、相手のブラフ保有確率が下がります。

主な使用場面:
- コール判断: ブラフブロッカーを保持している場合、相手のベットはよりバリューに偏っているためコール価値が下がります

```
例: セミブラフ候補として J♥T♥ があるボードで自分が J♦ を持つ場合
  → 相手の J♥T♥ 等のセミブラフ候補が減少
  → 相手のベット = よりバリュー寄り
  → 自分のコール価値が低下
```

第5章参照。

### ダブルブロッカー（double blocker）

バリューブロッカーとブラフブロッカーを同時に保持している状態。相手のバリューコール候補とブラフ候補の両方が減るため、効果がキャンセルしあい、標準的な後手スコアで判断することが多くなります。第5章参照。

### ブロッカー選択フロー

```
同強度のコンボ群から最終コンボを選ぶとき:

1. 相手のバリューコール候補を3つ特定する
2. 各コンボのバリューブロッカー強度を比較する
3. バリューブロッカーが強いコンボを優先する
4. ブロッカー強度が同等なら、ショーダウン価値が低い方を選ぶ

注: ブロッカーは「方針を変えない」
    α式で「ブラフが打てない」と判断した局面でのブラフ実行は誤り
```

## F　オーバーベット関連（応用）

### ナッツアドバンテージ活用型オーバーベット

Uncapped レンジを持つ側が、ナッツアドバンテージを利用して通常サイズを超えるオーバーベットを実行する戦略。ポラライズ型とコンティニュエーション型に分類されます。

**発動条件（ターン）**:
1. 自分が Uncapped かつ相手が Capped
2. ターンカードが自分のレンジをより強化している（ペア・OC）
3. バレルスコアが高い（9以上が目安）

**発動条件（リバー）**:
1. レンジがポラライズしている（ナッツ + ブラフ、中強度が少ない）
2. フロップ〜ターンを通じたストーリーが一貫している
3. リバーカードが自分のレンジをより強化している

詳細 → 第6章（ターンOB）・第7章（リバーOB）。

### ポラライズ型レンジ（polarized range）

「ナッツ〜準ナッツ」と「弱い手（ブラフ）」の両端のみで構成され、中強度のハンドが少ないレンジ状態。ポラライズ型レンジを持つ側はオーバーベットが有効です。

対義語は「コンデンス型レンジ（condensed range）」——中強度が集まったレンジで、大サイズへの対応が難しい状態。Capped 状態に近いレンジです。第7章参照。

## G　ポットコミットメント

### ポットコミット（pot-committed）

既に投じたチップとポットの比率から、スタックを全額ベット / コールしてもEV上好ましい状態。SPRが1を下回ると一般にポットコミット状態とみなします。

```
ポットコミット目安: SPR < 1
  → コールしてEV期待値がマイナスでも「たたむ」ことのコストが高い
  → 強いハンドであればオールインが前提になる
```

ポットコミット閾値の精密計算（第9章参照）:

| SPR | 最低必要勝率（簡易） |
|---|---|
| 0.5 | 約 33% |
| 1.0 | 約 50% |
| 1.5 | 約 60% |
| 2.0 | 約 67% |

backward induction の5ステップ（Step 5）でリバーSPRを確認し、ポットコミット化する前に対処します。第9章参照。

### ポットコミット閾値（pot-commit threshold）

コール EV がゼロになるスタックとポットの境界値。この閾値を超えてスタックを失ってもコールすべき根拠がある状態。backward induction の設計でターンのサイズを決めるときに考慮します。第9章参照。

## H　マルチストリート統合

### マルチストリート統合判断

フロップ・ターン・リバーの3ストリートを個別に判断するのではなく、「3ストリート全体の EV が最大になるライン」として選択する判断フレームワーク。本書第4章の中心テーマ。

```
個別最適化（誤り）:
  「このターンだけ見れば CBet の方がEVが高そう」
  → 実はリバーの展開も含めたトータルEVが下がっている場合がある

マルチストリート最適化（正しい）:
  「ターン CBet を打てば、リバーSPRがXになり、
   バリュー / ブラフの設計の自由度が変わる。
   それを含めてターン CBet のトータルEVが最大か？」
```

第4章参照。

### ライン一貫性（line consistency）

フロップ → ターン → リバーのアクションが「ひとつの物語として整合している」こと。ライン一貫性が高いほど相手にとって読みにくく、ブラフのフォールドエクイティと、バリューのコールを引くエクイティの両方が高まります。

ライン不一貫の典型例:
- フロップでチェックバックしながら、ターンでオーバーベット（Capped なのに大きいサイズ）
- フロップでCBetしながら、ターンでチェック → リバーで大きいブラフ（CBetレンジへの疑問を与えず）

第3章・第4章参照。
