# 第4章　マルチストリート統合判断

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: 第1章で定義した3軸（forward・current・backward）を、フロップ→ターン→リバーの3ストリートを貫く「ライン設計」として統合する。バリューライン・ブラフライン・ディフェンスラインの3つの実例を通じて、3軸が連動する実戦的な判断フローを身につける。

---

## 4-1 第I部の集大成として

第1章では、ターンが「forward 軸 × current 軸 × backward 軸」という3軸の交差点であることを学びました。第2章ではそのうち backward 軸を体系化し、リバーのシナリオを先読みしてターンのアクションを逆算する「backward induction」の5ステップを習得しました。第3章では forward 軸を体系化し、プリフロップからフロップまでの全アクション履歴が「現在の双方のレンジ」をどう確定するかという「forward thinking」を学びました。

本章は第I部の集大成です。

3軸の各概念を個別に理解することと、実際に3ストリートを一気通貫で判断することのあいだには、一段の壁があります。「フロップで何かを決めたことがターンに引き継がれ、ターンで何かを決めたことがリバーに引き継がれる」という連鎖の中で、3軸がどう連動するかを実例で確認することが本章の目的です。

本章で扱う実例は3つです。

```
実例1: バリューラインの構築
  BTN の強いハンドが3ストリートでどう価値を積み上げるか

実例2: ブラフラインの設計
  リバーで「ブラフできる手」を起点に backward induction でターンを設計する

実例3: ディフェンスラインの選別
  OOP から見た「コールの累積判断」と「どこで降りるか」の見極め
```

各実例では、ストリートごとに3軸を更新しながら判断を積み上げます。「フロップで決まった状態がターンで更新され、リバーで終結する」という流れを体感することが、本章の実践的な到達点です。

---

## 4-2 マルチストリート判断のフレーム

### 各ストリートで何を更新するか

3ストリートを通じた統合判断では、各ストリートで3つのものを更新します。

**更新1: 双方のレンジ（forward 軸の更新）**

各ストリートのアクションが、双方のレンジをフィルタリングします。フロップの CBet コールでBBがCappedになります。ターンのダブルバレルコールでBBのレンジが「強い中強度」に収束します。リバーのコールでBBのレンジがさらに絞られます。この連鎖がforward 軸の更新です。

**更新2: HandScore（ハンドエボリューション）**

ターンカードとリバーカードが落ちるたびに、各コンボの役が変化します。フロップでTPTKだったハンドがペアターンで2ペアに昇格する場合があります。フラッシュドローがリバーで完成または外れに確定する場合もあります。この役の変化の追跡がハンドエボリューションです。HandScoreが変化すれば、バリューかブラフかの判断も変わります。

**更新3: リバー予測（backward 軸の更新）**

ターンが落ちるたびに、リバーで何が起きるかの予測を精緻化します。フロップ段階では「リバーでフラッシュが完成する」という大まかな予測でした。ターン段階では「ターンで同スートが落ちたから、リバーのフラッシュシナリオの確率が上がった」という更新が入ります。backward 軸はストリートが進むたびに精度が上がります。

### 3軸が同じ方向を示すとき

3軸の評価が一致するとき、その一致は強い確信の根拠になります。

- forward 軸: 自分がUncapped、相手がCapped
- current 軸: ペアターンでIPのナッツが強化
- backward 軸: リバーのどのシナリオでもバリューが残る

この3軸が揃っていれば、積極的なバレルは強く正当化されます。バレルスコアで定量的に確認する前から、方向性の確信度が高い状態です。

### 3軸が異なる方向を示すとき

3軸がそれぞれ異なる方向を示す場合こそ、統合判断が試されます。

- forward 軸: 自分がUncapped（有利）
- current 軸: フラッシュターンでOOPのドローが完成（不利方向）
- backward 軸: リバーのブランクシナリオではバリューが残る

この状況では「forward 軸の優位」と「current 軸の不利」を天秤にかける必要があります。一般に、current 軸の影響（ターンカードによるレンジ更新）は即時かつ具体的であるため、forward 軸の「過去の優位」を一部打ち消します。判断はバレルスコアでの定量確認（巻④ 第8章）に委ね、スコアが閾値を下回る場合はハンド依存での慎重な対応が適切です。

## 4-3 実例1: バリューラインの構築

### 状況設定

6-max、100BB、BTN vs BB、シングルレイズポット（SRP）。

BTN が 2.5BB オープン、BB がコール。ポット = 5BB、残りスタック ≈ 97.5BB。

- **BTN のハンド**: A♣K♥（スーテッド）
- **BB のハンド**: 不明

### フロップ: K♠7♦2♣（ドライボード）

**ボード確認**:
ランク = K・7・2。3スート（スペード・ダイヤ・クラブ）= レインボー。ストレート要素確認: A-K-Q-J-T（Qが欠け）→ 不成立。K-Q-J-T-9（Q以下欠け）→ 不成立。7-6-5-4-3（連続なし）→ 不成立。フラッシュドロー: 各スート1枚のみ → フラッシュドローなし。ドライボード確定。

**BTN のハンド評価**:
A♣K♥ + ボード K♠7♦2♣。カード列挙: A♣・K♥・K♠・7♦・2♣。
ランク別: A = 1枚、K = 2枚（ハンド1枚 + ボード1枚）、7 = 1枚、2 = 1枚。
K が2枚 → **トップペア・トップキッカー（TPTK）**。HandScore = 70。

**forward 軸の確認**:
BTN オープン → BB コール の SRP。フロップアクション前の状態: 双方ともに広いレンジ。ここでCBetを打てば BTN が Uncapped（ナッツを含む可能性あり）、コールのBBがCapped気味という標準状態が確立します。

**current 軸の評価**:
Board Score B が高（ドライ板、B≥62）→ FlopType = ドライ（FlopType係数 = 8）。ドライボードはIPがレンジ優位を持ちやすい。

**backward 軸の事前設計**:
リバーの主要シナリオを2個想定します。

- シナリオA（ブランクリバー）: TPTKが維持され、バリューとして機能する。
- シナリオB（フラッシュ or ペアリバー）: ボードへの影響は少ない（レインボーボードのため）。

多くのリバーシナリオでTPTKとしてバリューを打てる → ターンでポットを積み上げる意図が正当化される。

**フロップのアクション**:
先手スコア確認: 先手スコア = HandScore + A − M（HU前提のためM=0）= 70 + 12（ドライ=12）− 0 = **82** → ≥ 60 で 75%pot 級ベット可能。ただし K-high ドライボードは BBのコール率が高く、この backward induction 実例では小ベット（33%）を採用してターン・リバーで段階的にポットを積み上げる設計を採る。
→ **BTN CBet 33%（1.65BB）、BB コール**。
コール後: ポット ≈ 8.3BB、残りスタック ≈ 95.8BB。

---

### ターン: 9♦（ブランク）

**ボード確認**:
ターンボード: K♠7♦2♣9♦。9 はフロップ最高位の K より低く、7・2より高い → ブランク分類。スペードのフラッシュ: 1枚のみ。ダイヤ: 7♦・9♦ = 2枚 → フラッシュドロー（リバーにダイヤが落ちれば可能性あるが2枚のみで確率は低い）。ストレート確認: K・9・7・2 + A・K（ハンド）= A・K・K・9・7・2 → 連続なし。不成立。

**ハンドエボリューション**:
A♣・K♥ + K♠・7♦・2♣・9♦。ランク別: A = 1枚、K = 2枚（K♥手 + K♠ボード）、9 = 1枚、7 = 1枚、2 = 1枚。K が2枚 → **TPTK のまま（変化なし）**。HandScore = 70。

**3軸の統合評価**:

forward 軸: フロップCBet → BBコールでBTN Uncapped / BB Capped が確立。ブランクターンでこの状態が維持される。

current 軸: バレルスコア = ドライ(8) + ブランク(2) = **10** → 積極バレル確定。ブランクターンはフロップ時のレンジ優位が継続することを意味する。

backward 軸: リバーの主要シナリオを更新。

- シナリオA（ブランクリバー）: TPTKのまま、バリューとして機能 → 75%ベット想定。
- シナリオB（ダイヤリバー）: ダイヤ2枚のため相手のフラッシュドローが完成する可能性あり。ただしA♣でクラブフラッシュのバリューブロッカーを持つ。

主要シナリオのほとんどでTPTKとしてバリューを打てる → ターンでのダブルバレル推奨。

**ターンのアクション**:
バレルスコア10 = 積極バレル。TPTKはバリューとして十分。
→ **BTN ダブルバレル 50%（4.15BB）、BB コール**。
コール後: ポット ≈ 16.6BB、残りスタック ≈ 91.65BB、SPR ≈ 5.5。

---

### リバー: 3♠

**ボード確認**:
リバーボード: K♠7♦2♣9♦3♠。ランク = K・9・7・3・2。ストレート確認: A・K・K・9・7・3・2（全カード列挙）→ 9-8-7（8欠け）、7-6-5-4-3（6・5・4欠け）→ 不成立。スペード: K♠・3♠ = 2枚 → フラッシュ不成立。フラッシュリスクなし。ダイヤ: 7♦・9♦ = 2枚 → 同様に不成立。完全なブランクリバー。

**ハンドエボリューション**:
A♣・K♥ + K♠・7♦・2♣・9♦・3♠。ランク別: A = 1枚、K = 2枚、9・7・3・2 = 各1枚。K の2ペア継続 → **TPTK のまま（変化なし）**。HandScore = 70。

**α 式でリバーサイズを設計**:
75%ベットを想定。ベット額 = 16.6 × 75% ≈ 12.5BB。
α = 12.5 ÷ (16.6 + 12.5) = 12.5 ÷ 29.1 ≈ **0.43**。
MDF = 1 − α ≈ 0.57。バリュー比率 = 0.57、ブラフ比率 = 0.43。

TPTKのA♣K♥はバリューゾーンにあります。BB のコールレンジには K（弱キッカー）・99・77・中ペアが残っており、リバーでのバリューが成立します。

**後手スコアの確認（BB の視点）**:
BB のミドルポケット（例: TT）を想定。HandScore = 40（アンダーペア中）。ドライA = 12、75%ベット C = 22、HU前提M = 0。
後手スコア = 40 + 12 − 22 − 0 = **30** → コールゾーン（20〜39）。TTはコールしてくる。自分のTPTKが勝つ。

**リバーのアクション**:
→ **BTN バリューベット 75%（12.5BB）**。

**ラインのまとめ**:

```
フロップ: CBet 33% → BB コール（BTN Uncapped / BB Capped 確立）
ターン:   バレルスコア10、TPTK確認、50% バレル → BB コール
リバー:   α 式でバリューゾーン確認、75% バリューベット

SPR推移: ≈19.5 → ≈5.5 → リバーで戦術余地あり（スタック残存）
ストーリー: 段階的圧力（33% → 50% → 75%）の自然な連鎖
```

3軸がすべて同方向（Uncapped優位 × ブランクターン × バリュー維持）で一致したため、積極的なバレルが一貫して正当化されたラインです。HandScoreの更新（フロップTPTK → ターンTPTK → リバーTPTK）が変化なしであることを毎ストリートで確認したことが、バリューラインを崩さなかった理由です。

## 4-4 実例2: ブラフラインの設計

### 状況設定

6-max、100BB、BTN vs BB、SRP。BTN 2.5BB オープン、BB コール。ポット = 5BB。

- **BTN のハンド**: Q♣J♣（スーテッドコネクター）

### フロップ: T♠9♥4♣（セミウェット）

**ボード確認**:
ランク = T・9・4。スペード・ハート・クラブの3スート = レインボー。ストレート要素: T-9 が連続。8・J が落ちればOESDに進展する候補。コネクター要素あり → セミウェット分類。

**BTN のハンド評価**:
Q♣・J♣ + T♠・9♥・4♣。カード列挙: Q・J・T・9・4。
ランク別: Q・J・T・9 = 各1枚、4 = 1枚。4枚連続（Q-J-T-9）→ K または 8 が落ちれば5連続ストレート完成。

- K が落ちれば: A-K-Q-J-T = broadway 完成（... A は不要。K-Q-J-T-9 = K-high straight）
- 8 が落ちれば: 9-8（ターン8）か Q-J-T-9-8 = Q-high straight

**OESD（両端どちらでも完成 = 8アウツ）確認**: Q-J-T-9 の4連続で、8（低端）またはK（高端）で5連続。8アウツ = OESD確定。ストレートは未完成。フラッシュ: クラブ = Q♣・J♣・4♣ = 3枚 → バックドアフラッシュドロー（ターン + リバーで2枚追加が必要）。

役なし（OESD + バックドアFD）。役スコア = 15（Qハイ）。ドロー加点 = OESD（8アウツ × 4 = +32）+ BDFD（+5）= 37。HandScore = 15 + 37 = 52。

**forward 軸の確認**:
SRP、フロップアクション前の標準状態。セミウェット板のためCBet頻度は高頻度ではないが、OESD + バックドアFDのセミブラフは CBet の有効な候補。

**backward 軸の事前設計（リバー逆算）**:
リバーで何になるかを先に考えます。

- **シナリオA: ストレート完成リバー（8 または K が落ちる）**: Q♣J♣でOESDが完成。ストレートとしてバリューベット可能。フロップからの2バレルを経てリバーで強ハンドが完成する理想のライン。
- **シナリオB: クラブリバー（バックドアFD完成）**: Q♣・J♣ + クラブがターンにも落ちれば、リバーにクラブが来てナッツフラッシュに近い完成の可能性。ただし2枚追加が必要であり確率は低い。
- **シナリオC: ブランクリバー（OESD・FD両外れ）**: 役なし（ハイカード）。バリューなし。ブラフ候補となりますが、Q♣J♣はQ・Jを持つことで「K-Q-J-T-9 のストレート」を相手が保有するケースを削る効果（ブロッカー効果）がある。

**逆算のルール適用**:

- シナリオA: リバーでバリュー → ターンでセミブラフとして打つ（逆算ルール1・2の複合）
- シナリオC: ブロッカーを持つブラフ候補 → ターンでのブラフベットの文脈を維持

backward 軸の結論: リバーで「ストレート完成または有効ブロッカーを持つブラフ」の2系統が期待できるため、ターンでのセミブラフバレルは正当化される。

**フロップのアクション**:
→ **BTN CBet 50%（2.5BB）、BB コール**。セミウェット板でOESDのセミブラフ = 50% サイズで積極的に打てる。コール後: ポット ≈ 10BB、残りスタック ≈ 95BB。

---

### ターン: K♦（OC）

**ボード確認**:
ターンボード: T♠9♥4♣K♦。K はフロップ最高位 T より高い → **OC（オーバーカード）分類**。ダイヤ: K♦ = 1枚 → フラッシュ要素なし。

**ハンドエボリューション**:
Q♣・J♣ + T♠・9♥・4♣・K♦。カード列挙: Q・J・T・9・4・K。
ランク別: K・Q・J・T・9 = 各1枚、4 = 1枚。
ストレート再チェック: K-Q-J-T-9 = **5枚連続** → **K-high ストレート完成**。

```
ハンドエボリューション（フロップ → ターン）:
  フロップ: OESD（役なし、8 アウツ）
  ターン:   K♦ 落下 → K-Q-J-T-9 = ストレート完成（K-high）
```

フロップで「ブラフ・セミブラフ」として打っていたラインが、ターンでナッツに近い**ストレート完成**に昇格しました。

**3軸の統合評価**:

forward 軸: フロップCBet → BBコールでBTN Uncapped / BB Capped。OC ターンで BBのコールレンジ内のAx・Kxが昇格する可能性あり。ただしKxがセカンドペアになっても、BTNのナッツストレートには及ばない。

current 軸: バレルスコア = セミウェット（FlopType係数 = 6）+ OC（TurnCard係数 = 3）= **9** → 積極バレル（≥7）。

backward 軸: ストレート完成により、リバーシナリオを全面更新。

- ブランクリバー: ストレートのバリューが継続 → 高確率でバリューベット可能。
- Aが落ちるリバー: A-K-Q-J-T（broadway）がより明確なナッツストレートとして上乗せ。
- ペアリバー（ボードペア化）: T・9・4 のいずれかがペアになった場合、相手がフルハウスを持つ可能性が生まれる。最大の懸念シナリオ。

リバーのほとんどのシナリオでストレートとしてバリューを打てる。backward 軸の結論: ターンでダブルバレルを打ち、ポットを積み上げる。

**ターンのアクション**:
バレルスコア9 = 積極バレル。ストレート完成による HandScore 急上昇（K-high straight = 82）。
→ **BTN ダブルバレル 75%（7.5BB）、BB コール**。
コール後: ポット ≈ 25BB、残りスタック ≈ 87.5BB、SPR ≈ 3.5。

---

### リバー: 2♥（ブランク）

**ボード確認**:
リバーボード: T♠9♥4♣K♦2♥。ランク = K・T・9・4・2。ハート: 9♥・2♥ = 2枚 → フラッシュ不成立。ストレート: K・Q・J・T・9 = ナッツストレート継続（BTNのハンドで確認）。2♥ はボードに新たなドロー要素をもたらさない = ブランクリバー。

**ハンドエボリューション**:
Q♣・J♣ + T♠・9♥・4♣・K♦・2♥。ランク別: K・Q・J・T・9・4・2 = 各1枚。5連続最長: K-Q-J-T-9 = **K-high ストレート継続**。HandScore = 82（ストレート high）。

**α 式でリバーサイズを設計**:
ポット ≈ 25BB。75%ベット想定。ベット額 = 25 × 75% ≈ 18.75BB。
α = 18.75 ÷ (25 + 18.75) = 18.75 ÷ 43.75 ≈ **0.43**。

BTNのナッツストレートはバリューゾーンの中核です。BBのコールレンジ（K ペア・T ペア・ストレートドロー残り）に対してストレートはほぼ勝ちます。バリューとして最大化するサイズを打ちます。

**リバーのアクション**:
→ **BTN バリューベット 75%（18.75BB）**。

**ラインのまとめ**:

```
フロップ: OESD + バックドアFDでセミブラフ CBet 50%
ターン:   K♦ 落下でストレート完成 → セミブラフがバリューに昇格
          バレルスコア9、ダブルバレル 75%
リバー:   ブランク、ストレート継続 → α 式でバリュー確認、75% バリューベット

backward 軸の機能:
  フロップ段階で「K または 8 が落ちればストレート完成」と設計
  → ターンのK落ちを確認した瞬間に即座に「バリーラインに切り替え」
  → リバーのシナリオ設計がすでに完了していたため、ターンで迷わなかった
```

このラインの重要なポイントは、フロップ段階で**backward induction を使って「ストレート完成シナリオ」を主要シナリオとして事前に想定していた**ことです。ターンでK♦が落ちた瞬間に「予定通り」とすぐに判断できます。逆算なしで「今のハンドで打つかどうか」だけを考えていれば、「フロップでブラフとして打ったハンドでターンにも打つ」という判断が遅れたり、サイズ選択が迷走したりします。

## 4-5 実例3: ディフェンスラインの選別

### 状況設定

6-max、100BB、BTN vs BB、SRP。BTN が 2.5BB オープン、BB がコール。ポット = 5BB。今回は **BB の視点**（OOP）で見ます。

- **BB のハンド**: T♥9♥（スーテッドコネクター）
- **BTN の行動**: 積極的にベット

### フロップ: K♦8♣3♠（セミドライボード）

**ボード確認**:
ランク = K・8・3。3スート = レインボー。ストレート要素: K-8-3 は不連続（5連続なし）。フラッシュドロー: 各スート1枚のみ → なし。セミドライ分類（ストレート要素が薄い）。

**BB のハンド評価**:
T♥・9♥ + K♦・8♣・3♠。カード列挙: T・9・K・8・3。
ランク別: K・T・9・8・3 = 各1枚。ストレート: T-9-8（3枚連続）。7またはJで4連続可能。フラッシュ: ハート = T♥・9♥ = 2枚 → バックドアハートFD。
役なし（T9ハイカード）。セカンドペア（9 = フロップの2番目8より上、Tも上）は不成立。ハイカードのまま。

役スコア = 10（T9ハイカード）。BDFD = +5、BDSD = +2。HandScore = 10 + 5 + 2 = 17。

**forward 軸の確認**（BBとして）:
BBとして、BTNがCBetを打てば「BTN Uncapped / BB Capped」という状態になります。BBのT♥9♥はコールレンジに含まれる標準的なハンドです（セミドライ板での薄めのコール候補）。

**backward 軸（BBとして）の事前設計**:
リバーで何になるかを確認します。

- シナリオA（Jまたは7が落ちる）: ターンでOESDが進展し、リバーでストレートが完成する可能性。ドロー系のラインを維持できる。
- シナリオB（TまたはJが落ちてペア化）: T ペアが完成すればセカンドペア。9 ペアが完成すればサードペア。コールレンジ内で中程度の強さ。
- シナリオC（ブランクリバー）: ハイカードのままショーダウン価値がほぼゼロ。コールし続けることの期待値が薄い。

逆算の結論: 主要シナリオでドローが完成しない場合、ハイカードのT9はリバーでコールする根拠を持てない。ドロー継続のためにはターン・リバーでの連続コールのコストが正当化される必要がある。

**後手スコア（フロップ）**:
HandScore = 17（T9ハイ + BDFD + BDSD、上記再計算）。A 係数（セミウェット=6）、Cは BTN のサイズ依存（33%なら C = 12）、M = 0（HU）。
後手スコア = 17 + 6 − 12 − 0 = **11** → フォールド境界（< 20）。

しかしT9♥のドロー性能（バックドアFD + 将来OESDの可能性）を考慮すると、コールの余地も存在します（ターンでのドロー昇格が見込める場合は実質エクイティが上振れする）。

→ **BB が BTN の CBet 33% にコール**（ドロー継続の判断）。コール後: ポット ≈ 10BB、残りスタック ≈ 95BB。

### ターン: 7♣（コネクター）

**ボード確認**:
ターンボード: K♦8♣3♠7♣。7 はフロップのランク（K・8・3）の中間に入る → コネクター分類（8と7が連続）。クラブ: 8♣・7♣ = 2枚 → フラッシュドロー進展なし（ハートFDに影響なし）。

**ハンドエボリューション**:
T♥・9♥ + K♦・8♣・3♠・7♣。カード列挙: T・9・8・7・K・3。
ランク別: K・T・9・8・7・3 = 各1枚。
ストレート確認: T-9-8-7 = **4連続** → 両端のどちらかで5連続完成。

- J が落ちれば: J-T-9-8-7 = J-high straight 完成。
- 6 が落ちれば: T-9-8-7-6 = T-high straight 完成。

T-9-8-7 の4連続で、**OESD に昇格（8アウツ）**。フラッシュ: ハート = T♥・9♥ = 2枚のまま（バックドアFD継続）。

```
ハンドエボリューション（フロップ → ターン）:
  フロップ: T9 ハイカード、バックドアドロー
  ターン:   7♣ 落下で T-9-8-7 の 4連続 → OESD（8アウツ）に昇格
```

**3軸の統合評価**（BB の視点）:

forward 軸: BTN Uncapped / BB Capped の状態継続。BTNがダブルバレルを打つことは「BTNのレンジにバリューが多い」ことを意味する。BB は Capped 状態。

current 軸: コネクターターン（7♣）で T-9-8-7 が OESD に昇格。BB のコールレンジには 6♣5♣ や J♣T♣ 等のコネクターも含まれる可能性があり、コネクターターンは BB のレンジをある程度強化する。ただし BTN のUncapped優位は継続。

backward 軸（BB として）: リバーで何になるかを更新。

- J または 6 が落ちる: ストレート完成（バリューベット可能）
- ブランクリバー: OESD 外れ、ハイカードのまま → コールの根拠が薄い
- ハートリバー: バックドアFD完成 → ただし2枚追加が必要で確率は低い

**後手スコア（ターン）**:
HandScore: OESDに昇格（8アウツ × 2 = +16）。役スコア = 10（T9ハイ） + OESD +16 = 26。A 係数（セミウェット=6）。BTN が 50% バレルの場合 C = 17。M = 0（HU）。
後手スコア = 26 + 6 − 17 − 0 = **15** → フォールド境界（< 20）。

ターンでのコールは「OESD（8アウツ）のドロー価値」で正当化できます。Rule of 2（巻② 第6章）でエクイティを確認: 8アウツ × 2 ≈ 16% のリバー勝率。ポットオッズ確認: 4.15BB コールで 10BB + 8.3BB = 18.3BB を獲得可能（ポットオッズ ≈ 18%）。ポットオッズとエクイティがほぼ拮抗 → コールが成立する境界。

→ **BB が BTN のバレル 50% にコール**。コール後: ポット ≈ 16.6BB、残りスタック ≈ 91BB、SPR ≈ 5.5。

### リバー: 4♠（ドロー外れ）

**ボード確認**:
リバーボード: K♦8♣3♠7♣4♠。ランク = K・8・7・4・3。スペード: 3♠・4♠ = 2枚 → フラッシュ不成立。ストレート確認: T・9・8・7 + K・3・4（ボード）= T・9・K・8・7・3・4 → T-9-8-7-6（6なし）、J-T-9-8-7（Jなし）→ ストレート不成立。

**ハンドエボリューション**:
T♥・9♥ + K♦・8♣・3♠・7♣・4♠。カード列挙: T・9・K・8・7・4・3。
ランク別: すべて1枚。T-9-8-7 の4連続 → 6またはJで5連続だが、4♠はいずれでもない → **OESD外れ、役なし（ハイカード）**。ハート: T♥・9♥ = 2枚のみ → フラッシュ未完成。

HandScore = 20（K ハイ）。

**後手スコア（リバー）**:
BTNが75%ベットを打った場合、C = 22。A 係数（セミウェット=6）。リバーはドロー加点 = 0。
後手スコア = 20 + 6 − 22 − 0 = **4** → 明確なフォールドゾーン（< 20）。

ただし **OOP の視点でベストハンドの確認**: K♦8♣3♠7♣4♠ + T♥9♥の best 5。ランク: K・T・9・8・7（5枚選択）= Kハイ（ワンペアなし）。BBのショーダウン価値はほぼゼロです。

**リバーの判断**:
BTNがバリューベットを打ってきた場合、後手スコア = -8 は明確なフォールドを示します。ポットオッズの計算でも確認します。例えばBTNが75%（12.5BB）ベットしてきた場合、コール額12.5BB に対してポット = 16.6 + 12.5 = 29.1BB → ポットオッズ = 12.5 ÷ 29.1 ≈ 43%。ハイカードの勝率は相手のバリューレンジに対して非常に低い。コールは明確に期待値マイナス。

→ **BB フォールド**。

**ラインのまとめ**（累積コールの評価）:

```
フロップ: T9♥ ハイカード → 後手スコア 11 → ギリギリコール（ドロー継続）
ターン:   OESD昇格 → 後手スコア 15 → ドロー継続でコール（境界）
リバー:   OESD外れ、Kハイ → 後手スコア 4 → フォールド確定

コールした理由:
  フロップ: バックドアドローでギリギリコール
  ターン:   OESD に昇格し、エクイティがポットオッズに拮抗
  リバー:   ドロー外れで即フォールド（ショーダウン価値なし）
```

このラインの核心は「各ストリートで後手スコアを再計算し、コールできる根拠が変化するたびに判断を更新した」点です。フロップのコールはギリギリの判断でしたが、ターンで OESD に昇格したことでコールが正当化されました。リバーで外れたことで、コールを継続する根拠がゼロになり、迷わずフォールドします。

「どこで降りるか」の判断は、事前に「ドローが外れたリバーではフォールドする」と backward 軸で決めていたからこそ速くできます。リバーで初めて「どうしよう」と考え始めるのでは遅いのです。

## 4-6 マルチストリート統合の留意点

### 留意点1: HandScore の更新は毎ストリートで必須

ターンカードとリバーカードが落ちるたびに、HandScoreが変化することがあります。実例1のTPTKは変化しませんでしたが、実例2のOESDはターンでストレートに完成しました。実例3のOESDはリバーで外れてハイカードに戻りました。

「フロップで決めた評価をそのままターン・リバーに使う」ことは誤りです。特に注意が必要なのは以下のパターンです。

| ターンカード | 典型的な role 変化 |
|---|---|
| ペアターン | TPTK → 2ペア、セット → フルハウス、クワッズ |
| OCターン | 弱ペア → セカンドペア格下げ、ドロー → ペア昇格 |
| フラッシュターン | FD → フラッシュ完成 |
| コネクターターン | バックドアドロー → OESD昇格 |
| ブランクターン | ほぼ変化なし（稀に影響あり） |

HandScore の更新を怠ると、バリューとして打つべき局面でチェックしたり、コールできない局面でコールしたりします。

### 留意点2: 相手のレンジも各ストリートで更新される

3ストリートを通じて、相手のレンジも変化します。最も重要な更新は以下の3点です。

**コールが続くほどレンジが強くなる**。フロップでCBetにコールした相手は幅広いレンジを持っています。ターンでのダブルバレルにもコールすると、そのレンジは「強い中強度」に収束します。2ストリートコールした相手に対してリバーでブラフを打つのは、相手のレンジが想定より強いことを無視した判断になりやすいです（第3章 forward thinking 参照）。

**ターンカードで相手のレンジも変化する**。OCターンはBBのコールレンジ内のAx・Kxを昇格させます。フラッシュターンはフラッシュドロー保有コンボを完成させます。相手のレンジの変化を確認せずに「ターンの前と同じ強さの相手に打つ」判断は不正確になります。

**3-betポットではレンジが最初から絞られている**。SRPでの判断を3-betポットにそのまま適用すると誤ります。SPRが異なり（SRP≈19 vs 3-betポット≈4〜5）、双方のレンジが高強度帯に偏っています。ターンのバレルスコア閾値や後手スコアの基準が変わることを意識してください。

### 留意点3: SPRの変化がコミット閾値を引き寄せる

ストリートが進むたびにSPRが低下します。この低下が「コミット閾値」を引き寄せます。

```
コミット閾値の目安:
  SPR ≥ 6: まだフォールドできる余地が十分ある
  SPR 3〜6: コミット圏が近づいている
  SPR < 3: 実質的なコミット圏（エクイティ優位なら自動コール）
```

実例1では、ターンバレル後のSPR ≈ 5.5 はまだ「フォールドできる余地」が残る状態でした。フロップで75%、ターンで75%と連続して大きく打った場合は、ターン終了後のSPRが2前後まで低下し、リバーは実質コミットになります。「フロップのサイズ設計がリバーの戦術余地を決める」ことを3ストリート視点で常に確認してください。

### 留意点4: ターンのベットがリバーで何を生み出すかを意識する

ターンのベットは「現時点の期待値」だけで測ってはいけません。ターンのベットがリバーに与える影響を合わせて考えることが3軸統合の本質です。

- ターンでバレルすると、リバーのポットが大きくなる（バリューベット額が増える）
- ターンでチェックバックすると、リバーに相手がベットしてくる可能性が生まれる（チェックバックレンジへの対応が変わる）
- ターンでオーバーベットすると、リバーのSPRが下がりコミット近くなる

ターンアクションを「今この一手」として独立させず、「リバーで何が起きるかを含めた一連の設計」として捉えることが、マルチストリート統合判断の実践です。

## 4-7 レンジ形態とサイズ選択の対応

（出典: GTO Wizard [Range Morphology]）

レンジの形態が最適なベットサイズを規定します。

| レンジ形態 | 構成 | 最適サイズ | 理由 |
|---|---|---|---|
| ポーラード | ナッツ＋ブラフのみ | 大（ジオメトリック） | 中間ハンドがないため相手は降りるかコールするかの2択になる |
| マージド | 中間ハンドが多い | 小（線形） | 相手を不利なエクイティポジションに追い込む |
| リニア | 広いレンジ全体 | 避ける | 「シンプルなオーバーフォールド」で対応される |

ポーラードレンジで大サイズ（オーバーベット含む）が最適なのは、相手のコールレンジがナッツを含まない場合にのみ成立します。「なぜオーバーベットの裏にはナッツが必要か」—ナッツを持たずにオーバーベットすると、相手のナッツコールに対してEVがマイナスになるためです。

**ジオメトリックサイジング**: ポーラードレンジの理想形では、各ストリートを等比のポット割合でベットします（例: フロップ50%、ターン50%、リバー50%）。これにより毎ストリートで相手への圧力が均等に分配されます。

> **本章まとめ**
>
> - マルチストリート統合判断の本質は「3ストリートを一気通貫で設計すること」であり、各ストリートを独立した問題として解くのではない
> - 各ストリートで更新すべき3つのもの: 双方のレンジ（forward 軸）・HandScore（ハンドエボリューション）・リバー予測（backward 軸）
> - 3軸が同方向を示すとき（Uncapped優位 × 有利なターンカード × リバーでバリュー維持）は積極的なアクションが強く正当化される
> - 3軸が異なる方向を示すとき（例: forward 優位 × 不利なターンカード × リバー不安定）はバレルスコアで定量確認し、ハンド依存で判断する
> - backward induction の真価は「ターンでアクションを決める前にリバーシナリオを先読みしておく」ことにあり、ターン・リバー両方の判断速度が上がる
> - OOP のディフェンスでは「どこで降りるか」を backward 軸で事前設計しておくことで、リバーでの即座のフォールドが迷いなくできるようになる
> - SPRの変化がコミット閾値を引き寄せる。フロップのサイズ設計がリバーの戦術余地を決める

**【GTOとのズレ】**

本章の3実例で示した「フロップ → ターン → リバー」の統合判断フローはGTOを近似したものですが、いくつかの点でGTOとズレが生じやすい箇所があります。

第一のズレは「HandScore の更新精度」に関するものです。本章の実例では HandScore の変化を「TPTK のまま」「ストレート完成」「OESD外れ」のように大まかに評価しました。GTOはコンボ単位でより精密に評価しており、例えば「AK のどのスートの組み合わせか」「ブロッカー効果の有無」によってコンボ間で異なる頻度を割り当てます。本章の近似は「大まかな役の変化を正しく追う」水準であり、コンボレベルの精密さは持っていません。実戦での影響は「バリューベットのサイズが数%ズレる」程度に留まることが多いですが、ナッツ近傍のハンドではコンボ間の差異が大きくなることがあります。

第二のズレは「ブラフラインの設計」です。実例2でOESD + バックドアFDでフロップCBetを打ちましたが、GTOではこのハンドの CBet 頻度はボードやスタック状況によって30〜60%程度の混合戦略になることが多いです。「OESDは常にCBetする」という単純なルールとは乖離があります。本章のバレルスコアを使った判断（FlopType係数 + TurnCard係数で閾値判定）は方向性として正しいですが、「全頻度か0か」という二択の近似であり、GTOの混合頻度には対応していません。

第三のズレは「ディフェンスラインの累積コスト計算」です。実例3でT9♥のフロップコールをギリギリ正当化しましたが、GTOでは相手のレンジ全体のエクイティ配分を考慮した精密なコール/フォールド境界を計算します。後手スコアの式（HandScore + A − C − M）は「コールできるかどうかの目安」を提供しますが、境界付近のハンドではGTOの実際の最善手と数%のズレが生じやすいです。本章のフロップ後手スコア = 11 という計算での「ギリギリコール」判断は、ドロー加点の評価精度に依存しており、ここが実戦での最大の誤差源になりえます。

これらのズレを縮めるためには、ハンドレビューの習慣（第13章）とソルバーでの実測確認を組み合わせることが有効です。本章の3軸統合の枠組みで「大まかな判断の方向性」を掴み、境界付近のハンドについてこと後にソルバーで確認する習慣が、実戦での精度向上への実践的な道筋です。
