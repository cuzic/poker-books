# 第13章　ソルバーによるハンドレビュー

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: gto_query.py を使ったハンドレビューの実行手順を習得し、EV差の読み方と4種の典型的ミスパターンを通じて、実戦後の改善サイクルを自分で回せるようになる。

---

## 13-1 ソルバーレビューの目的 ─ ミスを発見し、感覚を校正する

プレイ中に「これで正しかったのか」という疑問が頭をよぎることがあります。バレルスコアを計算し、α式でバリュー比率を確認し、後手スコアで判断したにもかかわらず、なぜか手応えが薄い。そういう瞬間こそ、ソルバーレビューの出発点です。

ソルバーレビューには2つの目的があります。

**目的1: ミスを発見する**

人間は「直感で正しいと思う判断」を繰り返します。しかし直感は訓練されていない状態では体系的に歪んでいます。「ブラフには弱い気がする」「ナッツはいつも大きく打てばいい」などのバイアスが、毎ハンドわずかなEV損失を生み出します。ソルバーはこれを数値で可視化します。

**目的2: 感覚を校正する**

実戦で使う本書の暗算式は「GTO を 80〜90% 程度再現する近似式」です。どこが近く、どこが離れているかを知ることで、式の限界を把握できます。バレルスコアが「積極バレル」を示してもGTO推奨が「混合戦略」になる場面、後手スコアが「コール」を示してもGTO推奨が「フォールド」になる場面——これらを蓄積することで、式の使い方が精密になります。

ソルバーはあなたの「判断の鏡」です。反射した像と実際の選択を比べることで、差分を学習します。

---

## 13-2 レビューの基本フロー ─ 4ステップ

ハンドレビューは4ステップで完結します。

```
ステップ1: ハンドを記録する
  実戦中または直後に、以下の情報をメモする
    - ポジション（IP / OOP）と対戦相手の数
    - フロップ・ターン・リバーのカード（スート込み）
    - 各ストリートのアクション（ベットサイズ・ポットサイズ）
    - 自分のホールカード
    - 「迷った」ストリートと実際のアクション

ステップ2: 局面を再現する
  以下の情報を整理する
    - ボード（フロップ3枚 or ターン4枚 or リバー5枚）
    - そのストリートのポットサイズとスタック残り
    - IPか OOPか、誰がFirst-to-Actか

ステップ3: ソルバーを実行して推奨アクションを確認する
  gto_query.py に入力し、自分のコンボの推奨アクションと各頻度を確認する
  EV差（推奨アクションのEV − 自分が取ったアクションのEV）を記録する

ステップ4: 差分を「式」で解釈する
  なぜ差が生まれたかを本書の暗算式で言語化する
    - バレルスコアとの一致・差異
    - α式から見たバリュー/ブラフ配分との整合
    - 後手スコアとの一致・差異
```

## 13-3 gto_query.py の使い方 ─ 実用ガイド

本書では `gto_query.py`（v7b 蒸留モデル）をソルバーレビューの補助ツールとして使用します。

### 基本的な呼び出し方

```bash
cd ~/poker-distill/training && python gto_query.py \
  --board "Kh,7d,2c,Ah" \
  --ip-range "AKs,KQs,KJs,KTs,QQ,JJ,TT,99,88,77,AQs,AJs,ATs,KQo,AQo" \
  --oop-range "QQ,JJ,TT,99,88,77,66,AQs,AJs,ATs,KQs,KJs,QJs,JTs,AQo,AJo,KQo" \
  --pot 12 --stack 88 --player 1 \
  --street 1 \
  --combo "KdQs"
```

### 主要オプションの使い分け

| オプション | 意味 | 例 |
|---|---|---|
| `--board` | ボード（カンマ区切り） | "Kh,7d,2c" (フロップ) / "Kh,7d,2c,Ah" (ターン) |
| `--street` | ストリート番号 | 0=フロップ / 1=ターン / 2=リバー |
| `--player` | アクティブプレイヤー | 0=OOP / 1=IP |
| `--combo` | 特定コンボを指定 | "AhKs", "KdQs" |
| `--facing-bet` | 直前のベットサイズ | 4=4BB ベット（first-to-actなら省略） |
| `--top` | 上位N件のみ表示 | --top 15 |
| `--sort` | 出力のソートキー | check_call / fold / bet_large |

### 出力の読み方

```
combo        FOLD  CHECK_CALL  BET_SMALL  BET_LARGE  ALLIN  best_action
KdQs         0.00      0.35       0.40      0.25      0.00  BET_SMALL
```

この例では、KdQsの推奨は「35%チェックバック/コール、40%小ベット（33%ポット相当）、25%大ベット（75%ポット相当）」です。`best_action` は最頻度のアクションを示します。

### v7b 蒸留モデルの限界

v7b 蒸留モデルは TexasSolver の近似モデルであり、以下の点に注意が必要です。

- **誤差**: TexasSolver 実測値に対して数%程度の誤差があります
- **混合戦略の圧縮**: TexasSolver が「35%チェック・65%ベット」を推奨する局面で、蒸留モデルは「100%ベット」と出力することがあります
- **レンジ依存**: 入力レンジが実際のプレイと乖離していると、結果も乖離します

この限界を踏まえ、出力は「絶対値」ではなく「方向性」として読みます。「ベットが推奨か、チェックが推奨か」を確認するツールとして活用してください。

## 13-4 EV差の読み方 ─ 重大度別の判断基準

ソルバー出力を得た後、自分の実際のアクションとの差分をEV差で評価します。

```
EV差の重大度分類:

0 BB          : GTO と完全一致（または誤差以内）
0〜−0.5 BB   : 許容範囲（混合戦略の選択違い程度）
−0.5〜−2 BB  : 軽微なミス（学習対象。パターン化して記憶する）
−2〜−5 BB    : 中程度のミス（要改善。プレイスタイルを見直す）
−5 BB 以下    : 重大なミス（即修正。このパターンを繰り返さない）
```

この分類で優先する学習対象は「中程度以上のミス」です。

EV差が0〜−0.5 BBの判断は、GTO が混合戦略を採用している局面での「どちらを選ぶか」の違いです。GTOの均衡点では、複数のアクションが同等のEVを持ちます。この差は意識するに値しますが、改善を急ぐ必要はありません。

EV差が−0.5〜−2 BBの判断は、体系的なバイアスが生み出すミスパターンです。同じ状況が100回あれば50〜200BB の損失につながります。記録して、条件反射で回避できる水準まで訓練します。

EV差が−2 BBを超えるミスは、根本的な概念の誤解から生まれることが多いです。これらは週次レビューの最優先対象です。

## 13-5 典型的なミスパターン ─ 4類型

実戦で繰り返されるミスには共通のパターンがあります。本書の暗算式を使っていても発生しやすい4つを解説します。

### パターン1: サイズ選択ミス

α式は「ベットサイズが決まれば、最適なバリュー/ブラフ比率が一意に決まる」ことを示します。ここで起きやすいミスは、サイズを「慣れ」で選ぶことです。

リバーで「いつも75%」「いつも33%」という固定サイズは、ボードの構造に関係なく同じ比率でバリューとブラフを混ぜることになります。ナッツを持つ場面でコールレンジが厚い相手にはオーバーベット、薄バリューが多いハンドで相手のディフェンスレンジが広い場合は小ベット——サイズはボードとレンジに応じて選ぶ必要があります。

ソルバーレビューでこのミスを発見したとき、α式で逆算してみてください。「なぜこのサイズを選んだのか」を数値で確認することで、修正が定着します。

### パターン2: ハンドクラス別判断ミス

後手スコアを計算するとき、HandScore の入力値が適切かどうかを確認します。よくある混同は TPTK（HandScore 18）と TPWK（HandScore 10）の間を「同じトップペア」として扱うことです。

キッカーの違いは HandScore に直接反映されます。A♣K♦ on A♥7♦2♣ はTPTK（キッカーK）でHandScore 18。A♣J♦ on A♥7♦2♣ はTPGK（キッカーJ）でHandScore 15。A♣4♦ on A♥7♦2♣ はTPWK（キッカー4）でHandScore 10。それぞれで後手スコアは大きく変わります。

特にリバーでベットに直面した場合、HandScore の8点差は後手スコアの判断を逆転させることがあります。TPTK はコール、TPWK はフォールドという結果になる場面は実戦で頻繁に発生します。

### パターン3: ボード読みミス

ターンやリバーでカードが落ちるたびに、ハンドの役は更新されます。フロップのKQのTPTKは、Aターンでセカンドペアに降格します。フロップの77は、K♥7♦2♣ボードではセットですが、ターンで7♦が落ちてボード上のカードが77と揃うとクワッズになります。

特に注意が必要なのはペアターンでの hand evolution です。ターンカードがフロップのカードと同ランクになると、既存の役が全員一段昇格します。TPTK → 2ペア、セット → フルハウス、2ペア → フルハウス、という変化を即座に計算する習慣が必要です。

ソルバーレビューで「なぜこのハンドが高頻度ベットを推奨されているのか」と感じた場合、まずハンドの役を再計算してください。役が変化していることに気づいていなかったというケースが多くあります。

### パターン4: ストーリー不整合

フロップでチェックバックしたIPが、ターンでオーバーベット（OB）を打つことを相手に許容させるには、チェックバックしたレンジにナッツに近いハンドが含まれていることが前提です。フロップをすべてCBetしてきたIPが突然ターンOBを打つと、ストーリーが成立しません。

ソルバーは「相手がGTO的なベット・チェックを行っている」前提でレンジを計算します。自分の過去アクションとコンシステントなレンジを維持していないと、実際のEV とソルバー推奨のEVが大きくずれます。

レビュー時は「フロップ→ターン→リバーを通じて自分のレンジが相手にどう見えているか」を俯瞰してください。

## 13-6 ハンドレビュー例1: ターンCBet判断の検証

### 実戦ハンド

- BTN vs BB、SRP（シングルレイズドポット）、100BB
- フロップ: K♥7♦2♣（ドライ）。BTN が 33%CBet（2BB）。BB コール
- ポット: 10BB。ターン: A♥
- BTN のハンド: K♦Q♠（フロップでは TPTK、ターンでAが落ちてセカンドペア）
- BTN の実際のアクション: 75%ポット CBet（7.5BB）

### ボード検証

K♦Q♠ on K♥7♦2♣A♥（ターン4枚）:
- カード: K♦,Q♠ + K♥,7♦,2♣,A♥ → Aランク1枚、Kランク2枚、Q・7・2各1枚
- Kペア（セカンドペア）、Aがオーバーカード。役 = ワンペア（K's）
- フロップのTPTKがターンでセカンドペアに降格

### バレルスコアでの事前判断

```
FlopType: ドライ（K♥7♦2♣ = レインボー・不連続）→ 係数 8
TurnCard: A♥ = オーバーカード（フロップ最高カードKよりAが高い）→ 係数 3
バレルスコア = 8 + 3 = 11 → 積極バレル域（閾値 7 以上）
```

バレルスコア 11 はレンジ全体での積極バレルを示します。しかし K♦Q♠ はレンジ内で「薄バリュー」に位置します。

### ソルバーとの比較（参考：v7b 蒸留モデル実測の傾向）

ドライボード + OCターンの組み合わせでは、GTO ソルバーは**ナッツクラス（AK、A7スーテッドのトリップス等）に大ベット、KQ 等の薄バリューに小ベットまたはチェックバック**を割り当てる傾向があります。具体的な頻度はレンジ設定によって変わりますが、KQ のようなハンドが高頻度の大ベットを推奨されることは少ない局面です。

75%ポット CBet は EV 差として軽微〜中程度のミスになることがある選択です。

### 学習ポイント

バレルスコアは「レンジ全体の傾向」を示します。スコア 11 は「このボード+ターン組み合わせでは、ナッツ寄りのコンボがレンジ全体を押し上げて積極的にバレル」という意味です。KQ は薄バリューであるため、レンジ内での役割は「控えめなベット（33%）かチェックバック」に傾きます。

**修正ポイント**: バレルスコアが積極バレル域でも、自分の具体的なコンボの強さを確認してください。OCターンでセカンドペアになったハンドは、大ベットよりも小ベットまたはチェックバックが適切な局面があります。

## 13-7 ハンドレビュー例2: リバーブラフ判断の検証

### 実戦ハンド

- BTN vs BB、100BB
- ボード: K♥7♦2♣A♥9♦（リバー5枚）
- ポット: 30BB。BTN のハンド: A♣J♣
- BB がチェック。BTN は 75%ポット（22.5BB）でブラフを試みた

### ボード検証

A♣J♣ on K♥7♦2♣A♥9♦（リバー5枚）:
- カード: A♣,J♣ + K♥,7♦,2♣,A♥,9♦ → Aランク2枚、K・J・9・7・2各1枚
- Aペア（A♣+A♥）。Best5 = A♣,A♥,K♥,J♣,9♦ = ワンペア（A's）
- A♣J♣ はブラフではなくAハイのトップペア（ブラフキャッチャー的な役）
- ストレートチェック: A-K-J-9-7 → 5連続なし（成立しない）

### α式での事前計算

```
α = ベット額 ÷ (ポット + ベット額) = 22.5 ÷ (30 + 22.5) = 22.5 ÷ 52.5 ≒ 0.43
後手下限確率 = 1 − 0.43 = 0.57（57%がBBの最低防御率）
```

BBは57%以上の頻度で防御（コール）する必要があります。この状況でBTNが打てるブラフは、ナッツ（フラッシュやツーペア以上）に対するブロッカーを持ち、かつバリューレンジのように見えるコンボに限られます。

### ソルバーとの比較

A♣J♣ はリバーで1ペア（Aペア）を持ちます。GTO ソルバーはこのハンドをブラフよりも**バリューベット候補**として扱うことが多い局面です。A♣J♣はナッツ（フルハウスやツーペア）に対してブラフを打つよりも、薄バリュー（Kペアや9ペア）からコールを引き出すハンドです。

典型的なGTO推奨としては、チェックバックかブロッキングベット（33%ポット程度）が多くなります。75%ポットは、バリューの観点ではやや過大であり、ブラフの観点ではブロッカー（A♣がAペアをブロックする）を持つものの、相手のフォールド率がαを超えるかどうかが焦点です。

### 学習ポイント

A♣J♣ のような「Aハイのトップペア」は、リバーでブラフではなく薄バリューとして扱います。小ベット（33%ポット）でKペアやポケットをコールさせる方向が、GTOに近い判断です。

α式でブラフを計算する前に、「自分のハンドはバリューかブラフか」を確認してください。Aペアはシャットダウン（チェックバック）か薄バリューという位置づけが多く、「ブラフを打つ」判断はブロッカー加点が高いハンド（Aをブロックするが自分ではAを完成させられないコンボ）で検討します。

**修正ポイント**: A♣J♣ でブラフを打つより、33%ポットの薄バリューで相手の弱いコールを引き出すことを優先します。

## 13-8 ハンドレビュー例3: 後手スコアの境界判断

### 実戦ハンド

- BB vs BTN（OOP でフロップCBetに対応）
- ボード: K♥9♦4♣（ドライ）。BTN が 33%CBet（2BB）
- BB のハンド: 8♣7♣（役なし、ガットショットドロー）
- BB の実際のアクション: フォールド
- ターンは考慮せず、フロップのコール判断をレビュー

### ボード検証

8♣7♣ on K♥9♦4♣（フロップ3枚）:
- カード: 8♣,7♣ + K♥,9♦,4♣ → 役なし（K,9,8,7,4）
- ストレートチェック: 9-8-7-6-5(6がない) / 8-7-6-5-4(6がない) → ガットショット（6待ち、4アウツ）
- 8♣7♣は2枚クラブ。ボードに4♣1枚のみ。バックドアフラッシュドロー

### 後手スコアの計算

```
HandScore:
  役スコア = 0（役なし）
  ドロー加点 = 2（ガットショット）
  ブロッカー加点 = 0
  HandScore = 2

後手スコア = HandScore + A − 3 − C − M
  A（ドライ = 3）
  C（33%ベット → C = 3）
  M（HU前提のためM = 0）

後手スコア = 2 + 3 − 3 − 3 − 0 = −1 → フォールド推奨
```

後手スコアは -1 でフォールド域に入ります。実戦のフォールドは式と一致しています。

### しかしGTOは何と言うか

後手下限確率の計算を確認します。

```
33%ポットへの後手下限確率:
  α = 2 ÷ (6 + 2) = 0.25
  後手下限確率 = 1 − 0.25 = 0.75（75%が最低防御率）
```

BBは BBのディフェンスレンジ全体で75%の頻度でコールまたはCRする必要があります。この75%という後手下限は非常に高く、BB は「ほぼすべてのハンド」をコールしなければなりません。

GTO ソルバーでは、このような小サイズに対してBBは広いレンジでコールします。8♣7♣ のようなガットショット+バックドアフラッシュドローは、コールレンジに含まれる可能性が高い局面です。

EV差として、実戦のフォールドは約+0.3〜0.5 BB を逃した可能性があります。

### 学習ポイント

後手スコアがわずかにマイナスでも、相手のベットサイズが小さい（33%以下）場合は、後手下限確率が75%と高く、GTOはほぼ全レンジでコールします。後手スコアの閾値（0）はあくまで目安であり、**小ベットに対しては境界値付近のマイナスでもコールを検討**してください。

**修正ポイント**: 後手スコア −1〜0 の境界域で、相手のベットが33%以下の場合は「コールの誤差範囲」として扱います。後手スコアを使うときは、C係数（ベット負担）の値も確認し、小サイズほどコールバイアスをかけることが有効です。

## 13-9 ハンドレビュー例4: ナッツのサイズ選択

### 実戦ハンド

- BTN vs BB、100BB
- ボード: K♥T♠5♦9♣J♦（リバー5枚）
- ポット: 28BB。BTN のハンド: Q♦K♦
- BB がチェック。BTN は 75%ポット（21BB）でバリューベットした

### ボード検証

Q♦K♦ on K♥T♠5♦9♣J♦（リバー5枚）:
- カード: Q♦,K♦ + K♥,T♠,5♦,9♣,J♦ → K=2枚、Q,J,T,9,5各1枚
- ストレートチェック: K-Q-J-T-9 = 5連続 → **ストレート完成（K-highストレート）**
- Aがボードにないため、K-high ストレートがナッツ
- BTN Q♦K♦ = ナッツストレート

### α式でのサイズ設計

```
75%ポットを選んだ場合:
  α = 21 ÷ (28 + 21) = 21 ÷ 49 ≒ 0.43（後手下限確率 57%）

150%ポット（オーバーベット）を選んだ場合:
  α = 42 ÷ (28 + 42) = 42 ÷ 70 ≒ 0.60（後手下限確率 40%）
```

オーバーベットはαが高い（60%）分、BBの防御レンジが狭くなります。しかし、ナッツを持つ場合は「BBがコールしてくれる回数 × 得られるEV」の積を最大化することが重要です。

### ソルバーとの比較

K♥T♠5♦9♣J♦ のようなストレート完成リバーでは、GTO ソルバーは**ナッツストレートを持つIPにオーバーベットを高頻度で割り当てる**傾向があります（v1の参考値：オーバーベット150%が約55%、75%ベットが約35%、EV差 −3.2 BB 程度）。

理由は2つです。

第一に、このボードではBBもストレート（Q8、QK等）や強い2ペア（KJ、J9等）を持てます。BB のコールレンジが厚いため、大きなベットにも応じてくれる局面です。

第二に、BTNがダブルバレルしてきたレンジには「バリューベット」と「ブラフ」が混在しています。BBはそのどちらかを判断できません。ナッツを持つ側がオーバーベットすることで、ブラフも同サイズで打てる構造（ストーリーの一貫性）が成立します。

### 学習ポイント

ナッツを持つとき、「どれだけ大きく打てるか」ではなく「相手がコールしてくれるサイズは何か」を考えます。α式でオーバーベットの後手下限を計算し、BBのコールレンジにその頻度で防御できるハンドが十分あるならオーバーベットが有効です。

**修正ポイント**: 「ナッツ = 75%で打つ」という固定ルールは大きなEVを逃します。相手のコールレンジが厚い局面（ストレート完成ボード等）ではオーバーベット（150%以上）を検討してください。

## 13-10 改善サイクル ─ 実戦からソルバーへ、ソルバーから実戦へ

ソルバーレビューは1回行えば終わりではありません。以下の4段階サイクルを継続することで、実力が段階的に向上します。

```
改善サイクル:

STEP 1: レビュー（週1回）
  「重要ハンド」を3〜5件選ぶ
  選択基準:
    - 大きなポットが動いたハンド
    - 「本当にこれで良かったか」と疑問を持ったハンド
    - 負けたハンドのうち判断ミスがあったかもしれないもの
    - 相手の予想外のアクションに対応したハンド

STEP 2: 仮説を立てる（レビュー前）
  ソルバーを実行する前に「自分の判断は合っていたか、ずれていたとすれば何が原因か」を書く
  この作業が「感覚を言語化する」訓練になる

STEP 3: 実測して差分を確認する
  gto_query.py を実行し、EV差と推奨アクションを確認する
  仮説と一致した部分、外れた部分を記録する

STEP 4: 実戦でパターンを試す
  「AターンでセカンドペアになったTPTKは、レンジ全体でバレルスコアが高くても個別に小ベットを選ぶ」など
  具体的な修正ルールを1つだけ持ち帰り、次のセッションで実行する
```

### 週次レビューで優先すべき判断

毎週全ハンドをレビューするのは非現実的です。EV差の重大度に応じて優先順位を付けます。

| 優先度 | EV差 | 学習内容 |
|---|---|---|
| 最優先 | −5 BB 以下 | 概念的な誤解が原因。即修正 |
| 高 | −2〜−5 BB | サイズ選択やハンドクラスの誤解。月1で集中修正 |
| 中 | −0.5〜−2 BB | 体系的バイアス。パターン化して記憶 |
| 低 | 0〜−0.5 BB | 混合戦略の誤差。記録するが急がない |

### ソルバーレビューの注意点

**GTO は均衡解であり、実戦の最善とは異なります。**相手が GTO から大きく外れている場合（常にバリューのみ、常にブラフ多数等）、GTO から逸脱したエクスプロイト戦略が高 EV になります。ソルバーのアウトプットは「ベースライン」として使い、相手の傾向に応じて調整します。

また、レンジ設定の影響が非常に大きいです。入力するIPレンジ・OOPレンジが実際のプレイと乖離していると、推奨アクションも乖離します。「標準的なBTNオープン・BB守備レンジ」を基本とし、相手が特定のパターンを持つ場合は入力レンジを調整してください。

## 13-11 本書 第16章への橋渡し

本章でソルバーレビューの手順と4つのミスパターンを学びました。

実力向上の最速ルートは「実戦 → レビュー → パターン化 → 実戦」のサイクルを回すことです。しかし実戦経験だけでは、遭遇する状況が偏ります。経験していない場面ではパターンが適用できません。

このギャップを埋めるのが**ドリル**です。

本書 本書 第16章（総合ドリル50問）では、本書全体を通じて学んだ3つの暗算式（バレルスコア・α式・後手スコア）を統合して使う問題を50問提供します。ターンとリバーの攻防双方を網羅し、4つのミスパターン（サイズ選択・ハンドクラス判断・ボード読み・ストーリー整合）を実際に問います。

ドリルを解いた後にソルバーレビューを行うという順序も有効です。「自分の答えがGTOから何BBずれているか」を50問通じて計測することで、弱点のパターンが見えてきます。

## ミニクイズ

### 問1

バレルスコアが 11（ドライ + OCターン）を示しているとき、KQ（セカンドペア相当）の大ベット（75%ポット）は適切ですか。

1. 適切。バレルスコアが高いので全コンボで大ベットを打つべきだ
2. 不適切。バレルスコアはレンジ全体の傾向であり、KQのような薄バリューは小ベットかチェックバックが適切な局面がある
3. バレルスコアが閾値（7）を超えているので、コンボの強さに関係なく全てベットすべきだ

### 問2

後手スコアが -1 の場合、33%ポットのベットに対して何をすべきですか。

1. 後手スコアがマイナスなので迷わずフォールドする
2. 後手スコアはあくまで目安。33%ベットの後手下限確率（75%）が高いため、境界値付近のマイナスはコールを検討する余地がある
3. チェックレイズを検討する

### 問3

EV差が −0.3 BB だったとします。この判断に対してどう対処するのが正しいですか。

1. 即座に修正対象として週次レビューの最優先に置く
2. 「混合戦略の誤差範囲」として記録にとどめ、−2 BB 以上のミスを先に改善する
3. EV 差がゼロでないなら毎回 GTO 推奨と完全に一致させなければならない

---

### 解答

- **問1**: 2（バレルスコアはフロップタイプ + ターンカードの組み合わせでレンジ全体の傾向を示します。スコア 11 は「このボード+ターンでは積極的なバレルが有利」という意味ですが、KQ（セカンドペア）のような薄バリューはレンジ内で小ベットかチェックバックの役割を担います。ナッツ寄りのコンボが大ベットを担い、薄バリューは引いて相手に守備の機会を与えます）
- **問2**: 2（33%ポットへの後手下限確率は 75%（α=0.25, 1-α=0.75）です。これはBBがほぼ全レンジで守る必要があることを意味します。後手スコア -1 はわずかなマイナスで、33%のような小サイズでは境界値として「コールの誤差範囲」に入ることがあります）
- **問3**: 2（EV差 0〜-0.5 BBは「許容範囲（混合戦略の選択違い程度）」です。GTOが均衡点で複数アクションに同等のEVを割り当てている局面での誤差であり、改善優先度は低い。-2 BB 以上のミスを先に修正することが実戦でのスコア向上に直結します）

> **本章まとめ**
>
> - ソルバーレビューの目的は「ミスの発見」と「感覚の校正」の2つ。ただし GTO は均衡解であり実戦の最善とは異なる
> - 4ステップ：記録 → 再現 → ソルバー実行 → 差分の言語化（式での解釈）
> - EV差は重大度別に分類する。−2 BB 以上を優先改善し、−0.5 BB 未満は急がない
> - 典型ミス4類型：サイズ選択ミス（α式から逆算）、ハンドクラス混同（TPTK/TPWK区別）、ボード読みミス（ペアターンでの役更新）、ストーリー不整合
> - 後手スコアの境界値（-1〜0）では、相手のベットサイズが小さいほどコールバイアスをかける
> - 改善サイクルは「レビュー → 仮説 → 実測 → 実戦での実践」の繰り返し

**【GTO とのズレ】**

本章で扱ったミスパターンは、すべて「暗算式をそのまま機械的に適用した結果」として発生するものではありません。むしろ、式を使わずに「なんとなく」判断したときに発生しやすいものです。

バレルスコアが「積極バレル」を示しても、個別コンボの強さ（薄バリューか否か）を確認しないまま大ベットを打つ。後手スコアがわずかにマイナスでも、ベットサイズ（C係数）を確認せずにフォールドする。これらは「式を形だけ使って中身を理解していない」状態で起きます。

GTOと暗算式がずれる根本的な理由は、式が「レンジ全体の平均挙動」を近似しているのに対し、GTOは「個別コンボの役割分担」を最適化するからです。式で方向を決め、ソルバーで個別コンボの役割を確認するという二段構えが、本書の推奨アプローチです。

また、実戦では相手がGTOから外れています。相手が常にバリューのみベットする場合、後手スコアのコール判断を絞ることが有効です。ソルバーは「GTO同士の均衡」を前提とするため、実戦では必ず相手の傾向を観察し、ソルバー推奨をベースラインとして調整してください。この調整能力こそ、暗算式では代替できない「読みの層」です。
