## A-1 3軸統合チェックリスト

ターン判断は「forward × current × backward」の3軸を同時に評価します。以下のリストを使って、どの軸が弱いかを確認してください。

```
【forward 軸】過去レンジを正確に引き継いでいるか

  □ プリフロップの役割（オープン / コール / 3-bet 側）を把握しているか
  □ フロップのアクションで Capped / Uncapped の状態が確定しているか
  □ 自分と相手のナッツアドバンテージはどちらに有利か

【current 軸】ターンカードを正確に分類しているか

  □ ターンカードを5分類（ペア / OC / ブランク / フラッシュ / コネクター）で即答できるか
  □ バレルスコア（FlopType係数 + TurnCard係数）を計算したか
  □ ターンカードで自分のハンドの役がどう変化したか確認したか

【backward 軸】リバーシナリオを先読みしているか

  □ リバーで打つなら何を打つか（バリュー / ブラフ / チェック）を決めているか
  □ ブラフなら α 式で枠を確認しているか
  □ ターンのサイズがリバーのSPRに与える影響を考えているか
```

## A-2 backward induction の5ステップ

リバーから逆算してターン判断を設計するフロー（詳細 → 第2章）。

```
Step 1: リバー到達時の想定シナリオを列挙する
  → 「ターンでベットしてコールされた場合」「ターンでチェックバックした場合」など
     主要な2〜3パターンを想定する

Step 2: 各シナリオでのリバーEVを概算する
  → バリューベットで取れる期待値 vs チェックバックの期待値
  → α式を使ってブラフの枠を確認する

Step 3: ターンアクションと最終EVを対応させる
  → 「ターンベット → バリューベット多い」vs「ターンチェック → ブラフ誘い多い」
  → どちらのラインが最終EV最大か

Step 4: ターン判断を決定する
  → 最大EVのラインに合わせてターンのアクション（ベット / チェック）とサイズを決める

Step 5: サイズがリバーSPRに与える影響を確認する
  → ターンに多く使うとリバーでオールインになりやすい
  → ポットコミット閾値（第9章）を超えないか確認する
```

**ポットコミット閾値早見表**（SPRによる判断）

| ターン後のSPR | コミット状況 | リバー判断 |
|---|---|---|
| SPR < 1 | ポットコミット | ベット = オールイン圧力。折れない |
| SPR 1〜2 | 準コミット | 強バリューはリバーでオールイン前提 |
| SPR 2〜4 | 検討余地あり | backward induction で計算 |
| SPR > 4 | 自由度高 | サイズ選択肢が広い |

通常のSRPフロップ（ポット=6BB、スタック=94BB）でターン後のSPRは概ねSPR 2〜4の範囲に収まります。3-betポットではフロップ時点でSPR 4〜5のため、ターンでのベットでSPR 1〜2になりやすく、コミット判断が早く訪れます。

## A-3 forward thinking の処理フロー

過去レンジを現在の判断に活かすフロー（詳細 → 第3章）。

```
Step 1: プリフロップ役割を確認する
  オープン側  → Uncapped ベース（ナッツを含む可能性あり）
  コール側    → セミ Uncapped（広いがナッツ可能）
  3-bet 側    → 強く絞られた Uncapped
  3-bet コール → 投機的コンボ多め

Step 2: フロップアクションでレンジ状態を更新する
  CBet → コール  : CBet側=Uncapped / コール側=Capped
  CBet → CR     : CR側=Uncapped強化 / CBet側=Capped化
  チェック → 両チェック: 両者ともナッツが薄いCapped同士
  チェック → ドンク : ドンク側=特定ナッツ保持 or ブラフ

Step 3: ターンでのナッツアドバンテージを評価する
  自分が Uncapped かつ ターンカードがIPを強化 → 積極的なライン
  自分が Capped かつ ターンカードが相手強化  → ディフェンス優先
  Capped 同士                               → バリューライン中心

Step 4: ターンカード（current 軸）と掛け合わせる
  ← バレルスコア・ターンカード5分類（巻④ 付録A 参照）
```

**レンジ状態別の基本方針**

| 自分の状態 | 相手の状態 | ターンの基本方針 |
|---|---|---|
| Uncapped | Capped | 積極バレル / オーバーベット検討 |
| Uncapped | Uncapped | バレルスコアで通常判断 |
| Capped | Uncapped | ディフェンス寄り / ドンク検討 |
| Capped | Capped | バリューライン中心、ブラフ少なめ |

## A-4 ブロッカー実戦選択表

同強度のコンボ群からブロッカーで最終選択をするときの基準（詳細 → 第5章）。

### ブラフ候補の優先順位（相手のバリューコールをブロックするコンボを選ぶ）

| ボード状況 | 最優先ブロッカー | 次点 | 最下位 |
|---|---|---|---|
| フラッシュ完成ボード | ナッツフラッシュのA（そのスート） | トップペア系バリューのA | ブロッカーなし |
| ペアボード（ポケットペア強化） | セット相当のブロッカーカード | TPTK系バリューのブロッカー | ランダムコンボ |
| ストレート完成ボード | ナッツストレートのコネクターカード | 準ナッツストレートのカード | ブロッカーなし |
| ドライボード | トップペア系バリューのAorK | 2ペア系のブロッカー | 無関係カード |

**判断手順**

```
1. 相手がコールしてくるバリューコール候補を3つ特定する
   例: フラッシュボード → Aハイフラッシュ、Kハイフラッシュ、フルハウス等

2. 自分の手がそのバリューをいくつブロックしているか確認する
   例: A♥保有 → Aハイフラッシュを含む全Aスタートコンボをブロック

3. 複数のブラフ候補を同じ基準で比較してブロッカー強度が高い方を選ぶ

4. ブロッカーがほぼ同等ならハンドのショーダウン価値が低い方を選ぶ
   （ショーダウン価値のあるハンドをブラフに使うのは二重のコスト）
```

### コール候補のブロッカー評価（コール価値の増減）

| 自分のブロッカー種類 | コール価値への影響 | 理由 |
|---|---|---|
| バリューブロッカー保持（相手のナッツを減らす） | コール価値 UP | 相手のベットにバリューが少なく、ブラフ比率が上がる |
| ブラフブロッカー保持（相手のブラフ候補を減らす） | コール価値 DOWN | 相手のベットがよりバリューに偏っている |
| 無関係カード | 変化なし | 標準的な後手スコアで判断 |

**ダブルブロッカーの特殊ケース**

```
バリューブロッカー + ブラフブロッカーを同時に持つ場合:
  → 相手のバリュー範囲も減り、ブラフ範囲も減る
  → ネット効果はキャンセルに近い
  → 標準的な後手スコアで判断することが多い
```

## A-5 リバー bluff catcher 早見表

後手スコアのキャリブレーション（ハンドの強度とコール判断）。

| HandScore | 代表ハンド例 | 75%ベット後手スコア (A=2, M=0) | 判断 |
|---|---|---|---|
| 30 | セット | 30 + 2 − 3 − 7 − 0 = **22** | コール |
| 25 | ストレート | 25 + 2 − 3 − 7 − 0 = **17** | コール |
| 20 | オーバーペア | 20 + 2 − 3 − 7 − 0 = **12** | コール |
| 18 | TPTK | 18 + 2 − 3 − 7 − 0 = **10** | コール |
| 15 | TPGK | 15 + 2 − 3 − 7 − 0 = **7** | コール（下限付近） |
| 10 | TPWK / セカンドペア良 | 10 + 2 − 3 − 7 − 0 = **2** | コール（警戒要） |
| 6 | セカンドペア弱 | 6 + 2 − 3 − 7 − 0 = **−2** | フォールド |
| 0 | 役なしハイカード | 0 + 2 − 3 − 7 − 0 = **−8** | フォールド |

計算条件: リバー（ドロー加点=0）、セミウェット(A=2)、75%ベット(C=7)、HU(M=0)。

100%ポットベット（C=9）の場合は各スコアが 2 ずつ低くなります。TPGK（HandScore=15）で後手スコアは 5 になり、ギリギリのコール判断です。150%ポットベット（C=11）ではTPGK後手スコアは 3 となり、よりタイトなコールが要求されます。

## A-6 リバーCR ブラフ候補表

リバーCRをブラフとして実行できる条件と候補ハンドの特徴。

```
リバーCRブラフの3条件

  条件1: 相手がブラフで打ってくる可能性が高い
    → ターンを弱いレンジでチェックしてきたIPが、リバーでブラフを打ちやすい状況
    → バレルスコアが低かった（< 7）なのにターンでベットしてきた場合

  条件2: 自分の手がショーダウン価値ゼロかそれに近い
    → HandScore 0〜3 程度（コールしても負ける確率が高い）
    → チェックコールが不利なとき、CR で相手のブラフをフォールドさせる

  条件3: CR額が後手スコアで正当化できる額を超えない
    → CRのサイズ（3〜4倍ベット）に対して相手の後手スコアが低いことを予想できる
```

**リバーCRブラフ候補の特徴**

| 候補ハンドの特徴 | 理由 |
|---|---|
| 外れたセミブラフ（フラッシュドロー失敗等） | ショーダウン価値ゼロ + 相手バリューブロッカー効果あり |
| 外れたストレートドロー | ショーダウン価値ゼロ + コネクターブロッカー |
| 弱いペア（ボードに負けるペア） | ショーダウン価値が低いとき限定 |
| 無役のAハイ（Aブロッカー） | ブラフキャッチレンジをブロック |

純粋ブラフのCRはリバーに限定されます（ターンCRは必ずセミブラフ性が必要です）。

## A-7 マルチストリート計画フローチャート

ハンドのライン設計を3ストリートにわたって決める大枠フロー（詳細 → 第4章）。

```
【フロップで決める】
  ├─ CBet打つ（Uncapped側）
  │    └─ ターン: バレルスコアで継続判断 → リバー: backward induction で設計
  ├─ チェックバック（SDV保護 / トラップ / バランス）
  │    └─ ターン: 遅延CBet or チェック継続 → リバー: 手の強度で判断
  └─ チェックレイズ（OOPのCR）
       └─ ターン: Uncappedとして攻め継続 → リバー: ナッツ持ち込みorブラフ

【ターンで確認する】
  ├─ 3軸統合チェック（A-1 参照）を実行
  ├─ backward induction で残りEVを確認（A-2 参照）
  └─ リバーSPRを計算してコミット有無を確認（A-2 参照）

【リバーで実行する】
  ├─ バリューベット: HandScore と勝率で 3層分類
  │    強バリュー（70%+）→ 75%〜100% bet
  │    標準バリュー（55〜70%）→ 33%〜50% bet
  │    弱役 / 役なし → チェック or ブラフ検討
  ├─ ブラフ: α式で枠を確認 → ブロッカー（A-4 参照）でコンボ選択
  └─ チェックバック: 中程度のバリュー / 混合戦略指示の局面
```

## A-8 ターン・リバー総合チェックリスト

**ターン前（3軸統合確認）**

- [ ] forward 軸: Capped / Uncapped の状態を確認したか
- [ ] current 軸: バレルスコアを計算したか（FlopType係数 + TurnCard係数）
- [ ] backward 軸: リバーシナリオを少なくとも1パターン考えたか
- [ ] ターンカードによるハンドの役変化を確認したか（ペアターン時は必ず再計算）
- [ ] ターンサイズがリバーSPRに与える影響を確認したか

**リバー前**

- [ ] ターンのアクション履歴から双方のレンジ状態を更新したか
- [ ] 自分のハンドを「強バリュー / 標準バリュー / チェックゾーン / ブラフ候補」に分類したか
- [ ] ベットするなら α 式で V:B 比率を確認したか
- [ ] ブロッカー評価を実施し、最終コンボを選んだか（A-4 参照）

**相手ベットへの応戦前**

- [ ] 後手スコアを計算したか（HandScore + A − 3 − C − M）
- [ ] リバーではドロー加点をゼロにしたか
- [ ] バリューブロッカー / ブラフブロッカーの有無を確認し、コール価値を調整したか
- [ ] CRは後手スコア ≥ 8 かつナッツ近辺のみを条件にしているか

**マルチウェイ（3名以上）**

- [ ] M 値を加算したか（3-way: M=3、4-way以上: M=6）
- [ ] マルチウェイではブラフ頻度を大幅に下げているか
- [ ] バリューラインのしきい値を上げているか（3-way: 2ペア以上が下限、4-way+: セット以上が大ベットの下限）

---

> **本書の中心テーゼ**
>
> - **ターンは3軸の交差点**: forward（過去レンジ）× current（ターンカード）× backward（リバー予測）
> - **backward induction**: リバーから逆算してターンを設計することで、3ストリートを一貫したラインとして扱える
> - **ブロッカーは方針を変えない**: α式と後手スコアが示した方針の中で、コンボ単位の最終選択のみをブロッカーが担う
>
> 巻4の4式（バレルスコア・α式・後手スコアターン版・後手スコアリバー版）に3軸統合の視点を加えることで、マルチストリートの意思決定が1枚のチェックリストで回せるようになります。
