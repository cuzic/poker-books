# 第14章　リバー vs チェックレイズの全体像

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: リバーでのチェックレイズ (IP/OOP 両面) のバランス構造を理解し、搾取されない対応を習得する。

---

## 14-1 リバー チェックレイズの特徴

ターンのチェックレイズと比べ、リバーのチェックレイズは特殊です。

```
ターンのチェックレイズ:
  セミブラフ (ドロー + ブラフ) が核となる
  → 「続けるとドローが完成するかも」の期待値を含む

リバーのチェックレイズ:
  純粋バリューか純粋ブラフのみ
  → セミブラフが存在しない
  → 相手のコールレンジに対してバリューかブラフかの二択
```

この特性から、リバーのチェックレイズは「高度なバランス技術」が要求されます。

---

## 14-2 OOP のチェックレイズ構造

BB が IP のベットにチェックレイズする状況です。

### バランスの原則

OOP がチェックレイズするとき、GTO では以下のバランスが求められます。

```
バリューチェックレイズ (VCR): IP のコールに対して勝率 50%+
ブラフチェックレイズ (BCR): IP をフォールドさせることが目的

バランス比率:
  レイズサイズで決まる。例: 3BB ベットに 10BB レイズ (3.3x)
  コールコスト (IP 側) = 7BB (追加) / (3+7+3+7)BB = 35%
  → BCR は VCR の 35/65 ≒ 54% の割合 (VCR:BCR = 65:35)
```

### BB の VCR レンジ (典型)

| ハンド強度 | VCR 候補 |
|---|---|
| ナッツ (FH, Straight, Flush) | ほぼ VCR (相手に価値を与えない) |
| 2ペア (ナッツ寄り) | 一部 VCR、一部チェックコール |
| トップペア | チェックコールか VCR (サイズ小) |

### BB の BCR レンジ (典型)

| 状況 | BCR 候補 |
|---|---|
| バストドロー | 最もよくある BCR ブラフ |
| ブロッカーを持つ弱ハンド | 相手の VCR をブロック |

---

## 14-3 IP のバリューベット → VCR への対応

IP がバリューベットして BB にチェックレイズされた場合。

### 対応の基準

```
コールの条件: IP のハンドが BB のチェックレイズレンジの
              バリュー/ブラフ比に対してコール EV+

具体的:
  ポット 20, IP ベット 10, BB レイズ 35
  → IP の追加コスト: 25BB
  → コールするポット: 20+10+35 = 65BB
  → コールオッズ: 25/65 = 38%
  → BB のレイズの 38% 以上がブラフなら、IP のコール有利
```

### BB のチェックレイズのブラフ率の推定

実戦では BB のブラフ率を正確に計算できませんが、以下の目安を使います。

```
BB のブラフ率が「高い」状況:
  ドロー完成リバー (FD や OESD が完成するリバー)
  → BB の VCR レンジが「ドロー完成ハンド」に絞られる
  → その分、BCR スペースが増える

BB のブラフ率が「低い」状況:
  ドロー完成しないリバー (完全なブランク)
  → BB はチェックレイズする理由が少ない (チェックコールが多い)
  → レイズしてきたら VCR 中心
```

### IP のコール・フォールドフローチャート

```
1. BB がチェックレイズしてきた
2. このリバーカードは何か?
   → ドロー完成系? → BB のブラフが多い可能性 → コールしやすい
   → ブランク?     → BB のバリュー中心 → コール基準を上げる
3. 自分のハンドは BB のバリューに勝てるか?
   → 勝てる → コール or レイズ
   → 負ける → フォールド (ブラフキャッチ目的でもコールが難しい)
```

## 14-4 CR サイズ別の対応方針

BB のチェックレイズサイズによって IP の対応基準が変わります。

### サイズ別コールオッズ早見表

ポット 20BB、IP ベット 10BB を前提に BB のレイズサイズ別でまとめます。

| BB のレイズ先 | IP の追加コスト | コールするポット | コールオッズ | 必要ブラフ率 |
|---|---|---|---|---|
| 20BB (2x) | 10BB | 50BB | 20% | 20%以上なら OK |
| 30BB (3x) | 20BB | 60BB | 33% | 33%以上なら OK |
| 40BB (4x) | 30BB | 70BB | 43% | 43%以上なら OK |
| 60BB (オールイン) | 50BB | 90BB | 56% | 56%以上なら OK |

**実戦的解釈**: レイズが大きいほど IP のコールに必要なブラフ率も上がります。小サイズの CR には 1ペアでのコールも検討できますが、オールインの CR には 2ペア以上が基本です。

### 小サイズ CR (2x 以下) への対応

```
小サイズ CR: BB が小さいレイズをしてくる
  → 弱いバリューやブラフの可能性が高い
  → IP の 1ペアでのコールも EV+ になりやすい
  → ただし BB のバリューに負ける場合はフォールド

例: IP が K♠Q♦でトップペア、BB が 2x CR
  → コールオッズ 20%
  → BB の CR のうち 20% 以上がブラフ = 多くの局面でコール有利
```

### 大サイズ CR (4x+) またはオールインへの対応

```
大サイズ CR / オールイン: BB が強い意思表示
  → VCR 中心の可能性が高い
  → IP の弱い 2ペアでさえコールが難しい場面がある

例: IP が T♣T♦でセット (ボード: K♣T♠5♦ A♦ 2♣)
  → BB がオールイン CR
  → IP の TT はスーパーナッツに近い → コール or レイズ
  
例: IP が A♠K♦で 2ペア (ボード: A♣K♠5♦ T♦ 9♣)
  → BB がオールイン CR
  → J♣Q♦でストレート完成の BB が多い → AK は追い詰められる
  → コールオッズ 56% = 非常にタイト
```

## 14-5 IP のバランス: ベット vs チェックビハインドの混合

IP がリバーでバリューベットとチェックビハインドを混合することが重要です。

### なぜ混合が必要か

IP が全バリューでベット → BB の戦略が単純化 (「ベット来た = バリューが多い → VCR に絞る」)

IP がバリューも一部チェックビハインド → BB はチェックレイズするとき IP の強いハンドも考慮する必要がある

```
IP のバランスの例:
  セット (3枚のK): 70% ベット + 30% チェックビハインド
  2ペア:           80% ベット + 20% チェックビハインド
  強いトップペア:  50% ベット + 50% チェックビハインド
```

実戦では「全部ベット」でも一定の EV は取れますが、GTO の観点では混合が最適です。

## 14-6 IP の 4bet リレイズ条件

BB の CR に対して IP がさらにレイズ (4bet) することがあります。

### 4bet が有効な条件

```
4bet の前提:
  IP のハンドが BB の VCR レンジほぼ全てに勝つ (絶対ナッツ)
  ポットにさらに多くの金額を押し込むと EV が出る

例 1: IP が T♥T♠ (セット), ボード T♣5♦2♠ A♣ 8♣
  フラッシュ完成リバー
  BB がフラッシュ完成でチェックレイズ → IP の TTT はフルハウス
  → 4bet オールインが最大 EV

例 2: IP が A♠K♠ (2ペア+トップキッカー), ボード A♣K♦5♠ 9♥ 3♦
  完全ブランクリバー
  BB の CR はナッツの可能性が高い (55 or AK or KK or AA のフルハウス等)
  → IP の 2ペアはナッツでない → 4bet は NG → コールが限界
```

### 4bet を避けるべき状況

```
4bet NG パターン:
  1. 自分がナッツでない状況でレイズ → バリューを引き出せず損
  2. BB のバリューレンジに自分が負けるとき → フォールドが正解
  3. ブラフ 4bet を打っても BB のコール確率が高い場面
     (特に IP がバレルし続けてきた場合、BB は強い確信を持ってコールする)
```

## 14-7 「チェックレイズトラップ」への対処

一部のプレイヤーは「強いハンドでチェックして IP のベットを待ち、大きくレイズする」チェックレイズトラップを多用します。

### トラップが多いプレイヤーへの対応

```
チェックレイズが多いプレイヤー:
  → IP のリバーチェックビハインドを増やす
  → 中程度のバリューはチェックビハインドでショーダウン

チェックレイズが少ないプレイヤー (チェックコールが多い):
  → 薄いバリューでもベット可
  → ブラフ頻度を標準より上げる
```

### トラップへの実戦対策

```
CR トラップを多用する相手への具体的な対策:

1. 薄いバリュー (1ペア、弱い 2ペア) でのベット頻度を下げる
   → CR を受けるとほぼフォールドになるため、最初からチェックビハインドが安全

2. 強いバリュー (セット, フルハウス) は、むしろ自分からベット
   → CR に対してリレイズできるため、チェックより多くを取れる

3. ブラフは CR を受けたらフォールドできるサイズで打つ
   → 大ベットブラフを CR されると費用が高くなる
   → 33〜50% ポットの小さいブラフは CR されてもフォールドコストが小さい
```

## 14-8 実戦例: チェックレイズの判断

### 例 1: BB のバリュー チェックレイズ

**ボード**: K♣7♦2♠ A♣ 6♣ (リバー: 4枚目のクラブ)
**BB のハンド**: A♠K♠ (2ペア)
**IP のベット**: 15BB (75% pot)

```
BB の選択:
  チェックコール: 安全だが、フラッシュ完成 IP からの最大価値が取れない
  チェックレイズ: フラッシュを持つ IP はコールできない (IP のバリューが限られる)

A♠K♠ の 2ペアは非常に強い。フラッシュ完成リバーで IP のレンジは:
  フラッシュ: クラブ持ち → BB の 2ペアに負ける場合も多いが、コールして大きいポット
  ノンフラッシュ: ストレートや 2ペアで慎重コール or フォールドへ

→ BB の VCR = AK 2ペア でチェックレイズが最大 EV
```

### 例 2: BB のブラフ チェックレイズ

**ボード**: J♠T♠9♣ 2♦ K♠ (リバー)
**BB のハンド**: Q♦8♦ (ストレートドロー外れ)
**IP がベット**

```
BB の考え方:
  Q♦8♦ はショーダウン価値なし (ターンで OESD を持ってたが外れ)
  しかし: Q♦ で IP の QT/QJ (2ペア) の一部をブロック
  → IP のバリュー範囲を削れる → BCR のタイミング

  さらに: K♠ でスペードフラッシュが完成。IP がスペードフラッシュを持っていない確率:
  Q♦8♦ はスペードを持っていない → BB のブロッカーはスペード側に「アンブロッカー」として機能

リスク: IP がナッツ (TT, 99, JJ, AQ でストレート) を持つ場合に負ける
計算: IP のベットレンジのブラフ率 > コール継続コスト率 なら BCR OK

実戦判断:
  K♠ 落ちでスペードフラッシュ完成 → IP のバリューが「フラッシュ持ち」に集中
  BB の Q♦8♦ はスペードなし → スペードフラッシュの IP にぶつかるリスクが低い
  → BCR 候補として有力
```

### 例 3: IP のコール判断

**ボード**: Q♥J♦8♣ 5♠ T♦ (リバー)
**IP のハンド**: Q♠Q♣ (トップセット)
**IP ベット**: 12BB, **BB がレイズ**: 35BB

```
IP の思考:
  T♦ でストレートが完成 (K9, 97, 69 等)
  BB の CR レンジ = ストレート完成 + 2ペア系バリュー + ブラフ

  Q♠Q♣ のセット: ストレート (K9, 97, 69) には負ける
  しかし QQQ はフルハウスの可能性は実はない (ボードに Q が 1 枚でセットのみ)
  
  コールコスト = 35 - 12 = 23BB
  コールポット = 12 + 12 + 35 = 59BB
  コールオッズ = 23/59 = 39%

  BB の CR の 39% 以上がブラフなら → コール有利
  T♦ はストレート完成リバー → BB の BCR ブラフも増える傾向
  → QQQ セット: コール (ブラフキャッチャーとしても機能)
```

## 14-9 BCR (ブラフ CR) の組み立て: 実践ガイド

BB が BCR を打つときの具体的な組み立て方です。

### BCR の 3 要件

```
要件 1: ショーダウン価値がない (コールできない)
  バストドロー、完全空振りハンドが対象
  「弱いペア」は BCR より チェックフォールドが多い

要件 2: ブロッカー効果がある
  IP のバリューレンジ (ナッツ) をブロックしているか
  例: Ax でボードにエースがある → IP の AA ブロック

要件 3: アンブロッカー効果がある
  IP の「フォールドするレンジ」をアンブロックしているか
  例: 非スペードハンドでスペードフラッシュ完成リバー → IP の薄バリューがフォールドしやすい
```

### BCR の有効例

| ハンド | ボード状況 | BCR の根拠 |
|---|---|---|
| 外れた OESD (78 外れ) | ストレート完成リバー | ストレートコンボをブロック |
| ナッツ FD 外れ (A♣K♣) | フラッシュ完成リバー | Ax でナッツブロッカー |
| 弱ハイカード+ブロッカー | ブランクリバー | ブロッカー優位でフォールド誘導 |

### BCR を避けるべきハンド

```
BCR 非推奨:
  - 弱いペア (ミドルペア、ボトムペア)
    理由: コールされたとき負けるが、BCR せずチェックフォールドが安全
  
  - ブロッカーがない空振り
    理由: IP のバリューに対してブロック効果ゼロ → BCR は単なるギャンブル
  
  - IP がチェックバックするシナリオで
    理由: IP がベットしてこなければ BCR チャンス自体がない
```

## ミニクイズ

### 問1

ポット 20BB、IP が 10BB ベット、BB が 30BB にチェックレイズしました。IP の追加コストとコールオッズはいくつですか。

1. 追加 20BB、コールオッズ 33%
2. 追加 30BB、コールオッズ 50%
3. 追加 10BB、コールオッズ 20%

### 問2

BB がフラッシュ完成リバーでチェックレイズしてきました。IP の対応として正しい考え方はどれですか。

1. フラッシュ完成リバー = BB のバリューが多い → タイトにフォールド
2. フラッシュ完成リバー = BB のブラフも増える傾向 → コール基準がやや緩む
3. フラッシュ完成リバーは無関係 → ハンドの絶対強度だけで判断

### 問3

IP がリバーバリューベットして BB にオールインCRされました。IP のハンドは A♠K♠ (ボード A♣K♣5♦ T♠ 9♣での 2ペア)。最も適切な対応はどれですか。

1. AK 2ペアは強いので必ずコール
2. ストレートや J♣Q♣フラッシュに負けうる → コールオッズ確認が必要
3. オールイン CR = 常にフォールド

---

### 解答

- **問1**: 1（IP の追加コスト = 30-10 = **20BB**。コールポット = 20+10+30 = 60BB。コールオッズ = 20/60 = **33%**）
- **問2**: 2（フラッシュ完成リバーは BB がフラッシュを持つか持たないかに分かれる → バストドロー側はブラフCR候補になる → ブラフ率が上がる傾向）
- **問3**: 2（AK 2ペアはナッツでない。ボードに J♣Q♣ストレート完成 or フラッシュ完成のハンドに負ける。コールオッズがブラフ率を上回るかを確認してから判断する）

---

> **本章まとめ**
>
> - リバーのチェックレイズはセミブラフなし: バリューかブラフの二択
> - OOP の VCR:BCR バランスはレイズサイズで決まる (例: 3xレイズで 65:35)
> - IP のコール基準: BB のチェックレイズのブラフ率 > コールコスト率
> - CR サイズが大きいほど必要ブラフ率が上がり、コール基準が厳しくなる
> - ドロー完成リバーは BB のブラフが多い → IP はコールしやすい
> - 4bet リレイズは絶対ナッツ (フルハウス等) のみ。2ペアでの 4bet は非推奨
> - BCR は「バストドロー + ブロッカー持ち」が最適候補
> - IP も一部チェックビハインドでバランスを取ることが重要

---

**【GTO とのズレ】**

本章のバランス比率 (VCR:BCR = 65:35 等) は「ゲームツリー全体でのバランス」を単純化したものです。

実際の GTO では各コンボが異なる頻度でチェックレイズ/チェックコール/フォールドを混合します。特に「バストドロー + ブロッカー持ち」は GTO でのブラフ頻度が高く、「弱いが構造的にブラフに向いていない手」は純フォールドです。

また、IP のコール基準も「平均的な BB レンジ」ではなく「この特定のボードで BB が持てるコンボ数」を正確に計算した上での判断です。ブロッカーを考慮すると VCR と BCR の比率は変わります。

実戦で最も重要なのは「チェックレイズの頻度が高い相手に対して標準的な薄いバリューで自動ベットしない」ことです。GTO との最大のズレは「相手固有のチェックレイズ頻度への不適切な対応」から来ます。
