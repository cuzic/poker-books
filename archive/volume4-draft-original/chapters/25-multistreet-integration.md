## 25-1 マルチストリート判断の本質

ポーカーで最も多い失敗のひとつは、各ストリートを独立した問題として解こうとすることです。「フロップで何をするか」「ターンで何をするか」「リバーで何をするか」と、3回の決断を別々に処理すると、ストリートをまたいだ一貫性が失われます。

本書のここまでの各章は、それぞれのストリートと局面に特化した技術を積み上げてきました。第7章のバレルスコアはターン攻撃を数値化し、第8章のα式はリバーの配分設計を定式化し、第9章の後手スコアはディフェンス判断を体系化しました。これらは別々の道具ではありません。3ストリートの統合判断を支える、ひとつのフレームワークの異なる入口です。

本章のテーマは統合です。各ストリートで正しい判断を繰り返すだけでなく、**3ストリート全体を見通したライン設計**を行うことが、長期的なEVを最大化する唯一の方法です。

### 3ストリート統合の3要素

マルチストリート判断には、以下の3つの要素が常に絡み合います。

```
要素1: スタック動態（ポットジオメトリ）
  ベットサイズ × ストリート数 でスタックがどう変化するか
  → フロップ時点でリバーのオールイン圏を設計する

要素2: ストーリーの一貫性
  各ストリートのアクションが作る「語られる物語」
  → ストーリー崩壊はブラフとして搾取される

要素3: ハンドの進化（Hand Evolution）
  ターンカード・リバーカードによる役の変化
  → ペアターンでTPTKが2ペアに昇格するような変化を常に追う
```

この3要素を同時に管理することが、マルチストリート統合判断の本質です。

## 25-2 ポットジオメトリ ─ スタックの動態を設計する

第4章でSPR（Stack-to-Pot Ratio）の概念を学びました。本章ではその動態を「設計」の視点から見ます。

### 標準SRPのSPR推移

6-max、100BB、BTN vs BB のシングルレイズドポット（SRP）を例に取ります。

```
プリフロップ: BTN 2.5BB オープン → BB コール
  ポット = 5BB、スタック = 97.5BB、SPR ≈ 19.5

フロップ後（33% CBet + コール）:
  ポット = 5BB + 1.65BB × 2 = 8.3BB、スタック ≈ 95.8BB、SPR ≈ 11.5

ターン後（50% バレル + コール）:
  ポット = 8.3BB + 4.15BB × 2 = 16.6BB、スタック ≈ 91.65BB、SPR ≈ 5.5

リバー前:
  ポット = 16.6BB、スタック ≈ 91.65BB、SPR ≈ 5.5
```

リバーでのSPR約5.5は「ポット額の5.5倍のスタックが残っている」状態です。リバーでオールインするには500%超のオーバーベットが必要になる計算で、標準的なSRPではリバーでのフル残金オールインは起きにくいことがわかります。

### 3ストリート全額コミット計画

スタック全額を3ストリートで自然に押し込むには、各ストリートのベットサイズを揃えて設計する必要があります。

```
例: 100BB スタート、SRP（ポット 5BB）で全額コミット設計

ベットサイズを各ストリート 75% ポットで揃えた場合:

フロップ: 75% of 5BB = 3.75BB → コールで ポット 12.5BB、スタック ≈ 96.25BB
ターン:  75% of 12.5BB = 9.4BB → コールで ポット 31.3BB、スタック ≈ 86.85BB
リバー:  75% of 31.3BB = 23.5BB → コールで ポット 78.3BB、スタック ≈ 63.35BB

→ リバーベット後もスタックが63BB残る。
  フルコミットには「リバーでの全残金」が必要で、自然にはなりにくい。
```

完全な3ストリート全額コミットが自然に起きるのは、フロップで大きく打つ場合（75%以上）や、3betポット（第22章）のように初期ポットが大きい場合です。SRPでは基本的にリバーまでスタックが残ります。

### ベットサイズとSPRの対応

| フロップCBet | ターンバレル | リバーSPR目安 | リバーでの戦術余地 |
|---|---|---|---|
| 33% | 33% | ≈ 7 | 大きな余地あり |
| 33% | 50% | ≈ 5〜6 | 標準的なリバーベットが可能 |
| 75% | 75% | ≈ 2 | オールインほぼ確定圏 |
| 100% | 100% | ≈ 1 | 実質オールイン |

フロップで大きく打てば打つほど、リバーはオールインに近づきます。「フロップで75%以上打つ」ライン設計は、リバーで必然的にコミット判断（第20章）が伴います。

## 25-3 4つの典型ライン ─ ストーリーの設計

マルチストリート戦略は、4つの典型ラインに整理できます。どのラインを選ぶかは、ハンドの強さ・ブロッカー・ボードの変化・SPRの4軸から決まります。

### ライン1: 3バレル設計（強バリューの最大化）

```
フロップ: CBet（通常33%〜50%）
ターン: ダブルバレル（50%〜75%）
リバー: 三回目のベット（75%〜100%）

対象ハンド: セット、ナッツ2ペア、ストレート、フラッシュ
バレルスコア: ≥ 7 が前提
α式: リバーのバリュー/ブラフ比率を設計
```

このラインの核心は「強いハンドを持っているから強く打ち続ける」という一貫性です。ターンカードがバレルスコアを押し上げる状況（ペア・OCなど）では、このラインが最大EVを生みます。

代表的なシナリオ: K72r（ドライ板）+ ブランクターン + ブランクリバー。バレルスコアは「ドライ8 + ブランク2 = 10」で積極バレル確定。3ストリートすべてでバリューを積み上げる設計です。

### ライン2: 小ベット保守（ショーダウンバリュー保護）

```
フロップ: CBet 33%
ターン: 33%〜50%（SDV保護）
リバー: チェックバック または 33% 薄いバリュー

対象ハンド: TPTK、中程度の2ペア、強ドロー（SDV兼用）
バレルスコア: ≥ 7 でも、ハンドがバリューと言い切れない場合
```

このラインはポットを肥大化させず、相手の強いハンドに搾り取られるリスクを抑えます。ターンのバレルスコアが高くても、自分のハンド（TPTK等）がリバーで弱くなりうる場合に選択します。

### ライン3: チェック挟み（トラップ設計）

```
フロップ: CBet
ターン: チェックバック（意図的なスロープレイ）
リバー: ベット（バリュー最大化）

対象ハンド: セット、ナッツ2ペア（特に相手がブラフしやすい状況）
前提条件: ターンのチェックバックが「ストーリーとして一貫」していること
```

このラインは相手に「IPが弱い」と思わせ、リバーのブラフを誘い込みます。注意点は「ターンでチェックバックした後のリバー大ベット」が搾取の標的になる点です（エラーパターンで後述）。セットのスロープレイが典型的な用途です。

### ライン4: 諦めライン（フォールドエクイティの管理）

```
フロップ: CBet（ブラフ or 薄いバリュー）
ターン: チェックバック（バレルスコア < 7、またはハンドが弱い）
リバー: 諦め（チェックビハインドまたはフォールド）

対象ハンド: バックドアドロー、弱いペア
バレルスコア: < 7 が指示
```

ブラフが機能しない局面でスタックを守るラインです。フロップCBetを打ったからといって、ターンでも必ずバレルする必要はありません。バレルスコア < 7 が示す「ハンド依存」の判断は、しばしばこの諦めラインへの移行を意味します。

## 25-4 ストリート別判断の連動表

3ストリートを貫く判断フローを整理します。

### 統合判断フロー

```
Step 1 プリフロップ
  └─ ポジション確認（IP/OOP）
  └─ レンジ確認（Uncapped / Capped）← 第2章
  └─ SPR計算（SRP ≈ 19 / 3-betポット ≈ 4〜5）

Step 2 フロップ
  └─ ボード特性を確認 → 簡易レンジスコア（巻2参照）
  └─ A係数（ドライ=3 / セミ=2 / ウェット=1）を確認 ← 第3章・第4章
  └─ CBet判断（先手スコア / 後手スコア）← 巻2 CBet統合式
  └─ フロップ板タイプを記録（ドライ / セミ / スーテッド / コネクテッド）

Step 3 ターン
  └─ ターンカード5分類 ← 第6章
     ペア / OC / ブランク / フラッシュ / コネクター
  └─ バレルスコア = FlopType係数 + TurnCard係数 ← 第7章
     ≥ 7 → 積極バレル
     < 7 → ハンド依存（強バリューのみ）
  └─ ハンドの役がターンで変化していないか確認 ← Hand Evolution
  └─ ベットサイズ設計 ← 第13章・第14章

Step 4 リバー
  └─ α = ベット ÷ (ポット + ベット) ← 第8章
  └─ バリュー枠 = 1−α、ブラフ枠 = α で配分設計
  └─ 後手スコア = HandScore + A − 3 − C − M ← 第9章
     ≥ 8 → CR / 0〜7 → コール / < 0 → フォールド
  └─ ブロッカー選別（ブラフ候補を絞る）← 第10章
  └─ コミット確認（SPR ≈ 1 なら勝率 > ポットオッズで自動コール）← 第20章
```

### バレルスコア × α式 × 後手スコアの三角形

3つの式は互いに補完します。

| 局面 | 使う式 | 出力 |
|---|---|---|
| ターン・先手 | バレルスコア | バレルするか否か |
| リバー・先手 | α式 | バリューとブラフの比率 |
| リバー・後手 | 後手スコア | コール/CR/フォールド |

先手がα式でバリュー8コンボ・ブラフ5コンボを設計した場合、後手は後手スコアで個別ハンドを評価します。先手の設計と後手の判断が噛み合うとき、ポットは均衡に近づきます。

## 25-5 エラーパターン4選 ─ 統合判断の典型的な失敗

各ストリートを単体で学ぶと見えにくいエラーが、統合の視点から浮かび上がります。

### エラー1: SPRを無視したベットサイズ → 意図せずオールイン圏

最も頻繁に起きるエラーです。

```
状況: SRP、100BB、フロップでセットを保有

エラーライン:
  フロップ: 75% CBet（欲張った大ベット）
  ターン: 75% バレル
  → ターン終了後 SPR ≈ 1.5 → リバーで実質オールイン圏

問題: リバーで相手がドローを完成させた場合でも、
  SPRが低くてフォールドできない状況を作ってしまう
  「セットだからと大ベットを続けた結果、降りられなくなった」

正しいアプローチ:
  フロップ 33% → ターン 50% → リバー 75% で3ストリートを設計
  → リバーSPR ≈ 5.5 → 十分な判断余地が残る
```

フロップで大きく打つことは必ずしも悪ではありませんが、「3ストリートでどこに着地するか」を意識せずに打つことが問題です。

### エラー2: ストーリー不整合（フロップCBなし → ターンOB）

「フロップでチェックバックしたIPがターンでオーバーベットする」パターンです。

```
エラーライン:
  フロップ: チェックバック（「弱い」シグナルを発信）
  ターン: OOPがチェック → IP がポット150%オーバーベット
  
問題: 「フロップで弱かったIPがターンで突然超強気」というストーリー矛盾
  → 相手は「ブラフか、スロープレイか」を考える
  → バリューならトラップ成功だが、ブラフならコールされやすい

GTOの対応:
  IPのフロップチェックバックレンジはCapped（ナッツが薄い）
  ターンでOBするUncappedな条件が揃わない
  → ストーリーとして成立しない
```

第11章で学んだ「遅延CBet」は存在しますが、オーバーベットは別の話です。遅延CBetは通常サイズ（33%〜50%）で機能します。

### エラー3: α式の計算を超えるブラフ

「バリューとブラフのバランス」を設計した後で、ブラフを追加してしまうエラーです。

```
状況: リバー、ポット 20BB、75% ベット（15BB）を打つ予定

α = 15 ÷ (20 + 15) = 15 ÷ 35 ≈ 0.43
後手下限確率 = 1 − α ≈ 0.57

バリューコンボ 8個に対して:
  最適ブラフ上限 = 8 × α ÷ (1−α) = 8 × 0.43 ÷ 0.57 ≈ 6コンボ

エラー: バリュー8 + ブラフ10 でベットする
  → ブラフ過多（相手はコールが有利になる）
  → 相手がコール頻度を上げて搾取してくる

正しいアプローチ:
  ブラフ候補が多い場合、第10章のブロッカー選別で6コンボに絞る
  バリューブロッカーを持つコンボ（A♥など）を優先して残す
```

α式の計算は「設計できる最大ブラフ枠」を示します。その枠を超えることは、相手に搾取の機会を与えます。

### エラー4: ハンド evolutionの見落とし（ペアターン後の役の更新）

ターンカードが落ちてハンドの役が変化しているのに、フロップ時の評価で判断を続けるエラーです。

```
状況:
  フロップ K♦7♣2♥: BTN の A♥K♠ = TPTK（HandScore 18相当）
  ターン K♣ 落下（ペアターン）

ハンド評価の更新:
  ボード K♦7♣2♥K♣ + ハンド A♥K♠
  カード列挙: A♥, K♠, K♦, 7♣, 2♥, K♣
  ランク別: A×1, K×3（ボード2枚+ハンド1枚）, 7×1, 2×1
  → K×3 → A♥ K♠ K♦ K♣ 7♣ = K のトリップス（A キッカー）
  Best 5: K♠-K♦-K♣-A♥-7♣

エラー: 「AKのままTTPK」として判断し、控えめに33%ベットする
正しい判断: トリップス（ナッツに近い）として積極的に75%〜100%バリューベット

逆パターン（弱化の見落とし）:
  フロップ K♦7♣2♥: BTN の A♠K♥ = TPTK
  ターン 7♦ 落下（ペアターン）
  ボード K♦7♣2♥7♦ + ハンド A♠K♥
  カード列挙: A♠, K♥, K♦, 7♣, 2♥, 7♦
  ランク別: A×1, K×2（ハンド+ボード）, 7×2（ボード2枚）, 2×1
  Best 5: A♠-K♥-K♦-7♣-7♦ = 2ペア（K's と 7's、A キッカー）
  → 「2ペア」に昇格しているが、ボードが7-7とペア化していて相手も7を絡めやすい
  → 相手の77（クワッズ）や K7（フルハウス）に負ける可能性が増加
  → バリューベットは継続できるが、ベットサイズは抑えめに設計する
```

ターンカードが落ちるたびに「自分のハンドが今何になったか」を確認することが、ハンド evolutionの管理です。

## 25-6 実戦例1 ─ 標準3バレル完全展開

ここから実戦例を通じて統合判断フローの全体を確認します。

**設定**: 6-max、100BB、BTN vs BB、SRP

**プリフロップ**:
BTN が 2.5BB オープン、BB コール。ポット 5BB、スタック 97.5BB。SPR ≈ 19.5。

**ハンド**: BTN A♦K♣ / BB 不明

---

**フロップ: K♠7♥2♣ （ドライボード）**

ボード読み確認: K,7,2 = レインボー、不連続。ストレートドロー確認: A-K-Q-J-T（KまではAKで拾えるが中間が欠け）→ ガットショット以下。フラッシュドロー: 全3スート別々 → フラッシュドローなし。

- 簡易レンジスコア: 高スコア（ドライ板）→ FlopType = ドライ
- A♦K♣: K♠がボードに1枚 + K♣がハンドに1枚 → **トップペア・トップキッカー（TPTK）**
- HandScore = 18 相当（TPTK基準）
- CBet判断: ドライ板でTPTK → 33%ベット（5BB × 33% ≈ 1.65BB → コール後: ポット8.3BB、スタック95.8BB）
- **BTN CBet 33%、BB コール**

---

**ターン: 9♦**

ターンカード分類: 9 はフロップ最高位 K より低い → ブランク
- ハンド evolution: A♦,K♣,K♠,7♥,2♣,9♦ → A×1,K×2,9×1,7×1,2×1 → Kペア継続 → **TPTKのまま（変化なし）**
- バレルスコア: ドライ(8) + ブランク(2) = **10** → 積極バレル
- ダブルバレル判断: バレルスコア 10 = 積極バレル確定、TPTKは十分なバリュー
- ベットサイズ: 50%（8.3BB × 50% ≈ 4.15BB → コール後: ポット16.6BB、スタック91.7BB）、SPR ≈ 5.5

**BTN バレル 50%、BB コール**

---

**リバー: 3♠**

リバーカード確認: 3♠。スペード枚数: K♠はフロップに1枚、3♠はリバーに1枚 → スペード計2枚。フラッシュ不成立。ストレート確認: A,K,9,7,3,2 → 5連続なし（9-7間に8が欠け）。

- ハンド evolution: A♦,K♣,K♠,7♥,2♣,9♦,3♠ → Kペア継続 → **TPTK（変化なし）**
- BTN のハンド評価: TPTK はリバーで「標準バリュー」。BBのコールレンジには K(弱キッカー)・77・22・99・中ペアが含まれる
- α式設計: 75%ベット想定 → 16.6 × 75% ≈ 12.45BB。α = 12.45 ÷ (16.6 + 12.45) = 12.45 ÷ 29.05 ≈ 0.43
- バリュー比率: 1−α ≈ 0.57 → AK等のTPTKはバリューゾーン内
- 後手（BB）の後手スコア: HandScore + A − 3 − C − M（HU前提、M=0）
  - BBの中ペア（例: TT）: HandScore ≈ 12、ドライA=3、C=7（75%ベット）
  - 後手スコア = 12 + 3 − 3 − 7 − 0 = **5** → コールゾーン

**BTN バリューベット 75%（≈12.45BB）**

ラインのまとめ: フロップ33% → ターン50%バレル（バレルスコア10=確定バレル） → リバー75%バリューベット。SPRは19.5→5.5と自然に収縮し、リバーでもまだスタックが残る標準設計。3ストリートのストーリー「段階的な圧力」が一貫しています。

## 25-7 実戦例2 ─ ストーリー不整合のアンチパターン

**設定**: 6-max、100BB、BTN vs BB、SRP

**フロップ: K♠T♥5♦ （セミウェット板）**

ボード読み確認: K,T,5 = 2スート（K♠,T♥は別スート、5♦で3スート目） → レインボー。ストレート連続性: K-T-5 は連続でない（J,Q,9 が欠ける）→ セミウェット判定。FlopType = セミ。

- BTN のハンド: Q♣J♦（ガットショット + 中コネクター）
  - Q♣,J♦,K♠,T♥,5♦ → Q,J,K,T,5 → K-Q-J-T-5の4連続（9があればストレート完成）またはQ-J-T-9-8の中間パーツ
  - 実際: K-Q-J-T で4連続 → OESD（Qが高端、7が低端... 確認: 高端=ACE方向: K-Q-J-T → A方向は不要、低端=A方向ではなくQ方向: A-K-Q-J → Aでも） → 正確に確認:
    - K,Q,J,T が揃っている → Q-J-T-9 で9ワンアウト + A-K-Q-J でAワンアウト → ガットショット×2 = 8アウツ相当 = OESD
  - BTN Q♣J♦ = OESDセミブラフ
- CBet判断: セミウェット板 + ガットショット/OESD → セミブラフ50%CBet（OESDは攻撃的に打てる）
- **BTN CBet 50%、BB コール**

---

**ターン: Q♦**

ターンカード分類確認: Q はフロップ最高位 K より低く（K>Q） → OC (Overcard) ではなく... 厳密には: OCとは「フロップ最高位より高いカード」。K が最高位なので、Q はフロップの2番目相当 → OC ではない。Q はKより低く、フロップに既出のT,5よりは高い → ブランク（フロップ連続性を強化しない中ランク）。

ハンド evolution: Q♣,J♦ + K♠,T♥,5♦,Q♦
- カード列挙: Q♣,J♦,K♠,T♥,5♦,Q♦
- ランク別: K×1, Q×2（ハンド1枚+ボード1枚）, J×1, T×1, 5×1
- Q×2 かつ K♠,T♥も絡む → Best 5: K♠-Q♣-Q♦-J♦-T♥ = **Qペア（TPSK相当）**
- ストレート確認: K-Q-J-T = 4連続 → 9または A で完成 → ストレートドロー（OESDまたはガットショット）
  - 9落ちで K-Q-J-T-9 = K-high straight
  - A落ちで A-K-Q-J-T = broadway
  - 両端どちらでも完成 → **OESD継続（8アウツ）**

バレルスコア: セミ(6) + ブランク(2) = **8** → 積極バレル
- BTN Q♣J♦: ダブルバレル推奨（Qペア + OESD = バリュー兼セミブラフの複合）
- ベットサイズ: 75%（強気に打つ）

エラー版（アンチパターン）として:
もしBTNがフロップをチェックバックしていた場合（「フロップで弱かった」シグナル）

```
エラーライン:
  フロップ: BTN チェックバック（「弱いから打てなかった」と解釈される）
  ターン: OOP チェック → BTN OB（ポット150%）

問題点:
  ① BTNのフロップCBなしレンジはCapped
    → ナッツ（AA, KK, AK等）はほぼフロップでCBetする
    → チェックバックレンジに超強ハンドが少ない
  ② ターンOBはUncappedレンジの権利（第2章）
    → Cappedレンジから打つOBは「ストーリー矛盾」
  ③ BBはコールしやすくなる（「ブラフのOBか」と判断）

BTNのOBが機能しない → BB にコールされてショーダウン負け
```

正しいラインはフロップでCBetを打ち、ストーリーを最初から積み上げることです。

## 25-8 実戦例3 ─ α式逆算でブラフ枠を確定

**設定**: 6-max、100BB、BTN vs BB、リバーに到達

**ボード（リバー5枚）: A♦K♥8♣ 5♦ 2♦**

ボード読み確認:
- スペード: なし、ハート: K♥、クラブ: 8♣、ダイヤ: A♦, 5♦, 2♦
- ダイヤモンド3枚 → フラッシュドローあり（リバー前のターン時点）
- リバー2♦で4枚目ダイヤ... 5枚確認: A♦, K♥, 8♣, 5♦, 2♦ → ダイヤ: A♦,5♦,2♦ = **3枚** → フラッシュ不成立（5枚必要）

実際のフラッシュ確認: ダイヤ3枚のみ → フラッシュは「ハンドに♦が2枚あれば合計5枚」の場合のみ成立。

ストレート確認: A,K,8,5,2 → A-K-(無)-8-... 連続性なし。5-4-3-2-A で確認: 2,A = 2枚、5 = 1枚、3,4欠け → なし。

**BTNのハンド候補（バリューコンボ設計）**:
- AK（2ペアA's and K's、例: A♠K♦）: ボードA♦K♥と合わせてベスト5 = A♠-A♦-K♦-K♥-8♣ = **2ペア**
- AA（セット、例: A♥A♣）: A♥,A♣,A♦,K♥,8♣ = **セット（ポケットペアとボードのAで3枚）**
- A8（2ペアA's and 8's）: A♠,8♦,A♦,K♥,8♣ = **2ペア**

仮定: BTNのバリューコンボ = 8個（AA/AK/A8系統）

**α式でブラフ枠を確定**:

```
設定: ポット 30BB、75%ベット（22.5BB）

α = 22.5 ÷ (30 + 22.5) = 22.5 ÷ 52.5 ≈ 0.43
後手下限確率 = 1 − α ≈ 0.57

バリューコンボ 8個に対して:
  最適ブラフ上限 = バリュー × (α ÷ (1−α))
                 = 8 × (0.43 ÷ 0.57)
                 ≈ 8 × 0.75
                 ≈ 6コンボ
```

ブラフ候補が多い（例: 10コンボ）場合、6コンボに絞る必要があります。ここでブロッカー論（第10章）が機能します。

**ブロッカーによるブラフ選別**:

ブラフ候補の条件:
- バリューブロッカーを持つ（相手のコールレンジの強いハンドを削る）
- キャップドブロッカーがない（自分のブラフが相手のフォールドを誘いやすい）

ボードがAKハイのため、相手のコールレンジには Aを含むハンドが多い想定。

```
ブラフ候補 → ブロッカー評価:
  Q♦J♦（A を持たない、フラッシュドロー）: バリューブロッカーなし → 低優先
  A♥9♥（A を保有 → 相手の AK/AA を削る）: バリューブロッカーあり → 高優先
  K♠Q♠（K を保有 → 相手の AK を削る）: バリューブロッカー → 中優先

→ A♥9♥系のコンボを優先してブラフ6コンボに含める
```

ブラフ枠6コンボ + バリュー8コンボ = 合計14コンボ のベットレンジが完成します。

## 25-9 実戦例4 ─ ハンド evolution を活かしたサイズ調整

**設定**: 6-max、100BB、BTN vs BB、SRP

**フロップ: K♥7♠2♦ （ドライボード）**

ボード読み確認: K,7,2 = 3スート → レインボー、不連続。ドライ板確定。

- BTN のハンド: A♣K♦（TPTK）
- CBet 33%（通常設計）、BB コール

---

**ターン: 7♥**

ターンカード分類: フロップに 7♠ あり → 7♥ はフロップと**同ランク** → **ペアターン**

ハンド evolution 計算:
```
ハンドカード: A♣, K♦
ボードカード: K♥, 7♠, 2♦, 7♥（ターン）

全カード: A♣, K♦, K♥, 7♠, 2♦, 7♥（6枚）
ランク別カウント:
  A: A♣ = 1枚
  K: K♦, K♥ = 2枚（ハンド1枚 + ボード1枚）
  7: 7♠, 7♥ = 2枚（ボード2枚）
  2: 2♦ = 1枚

ペアが2組: K×2 と 7×2
Best 5（高い順に取得）: A♣-K♦-K♥-7♠-7♥ = 2ペア（K's と 7's、A キッカー）
```

フロップでTPTKだったハンドが、ペアターンで**2ペアに昇格**しました。

- バレルスコア: ドライ(8) + ペア(4) = **12** → 積極バレル（最高ゾーン）
- 2ペア（K's and 7's）: 強バリュー。ボードで7が2枚あるため、相手の77（クワッズ）やK7（フルハウス）には負けるが、大半の相手ハンドに勝つ

**正しい判断**: フロップ33%から、ターン昇格ハンドに対してベットサイズを引き上げる。

```
フロップ: 33%（TPTKとして控えめ設計）
  5BB × 33% ≈ 1.65BB CBet → コール後: ポット8.3BB、スタック95.8BB

ターン 7♥（ペア）: 2ペア昇格
  → ベットサイズ引き上げ: 75%（8.3BB × 75% ≈ 6.2BB）
  → コール後: ポット20.7BB、スタック ≈ 89.6BB

設計意図:
  ・ターンでの役の昇格（TPTK → 2ペア）に応じてサイズを上げる
  ・バレルスコア12（ペアターン + ドライ板）= 最大バレルゾーン
  ・ポットを適切に育て、リバーでのバリューを確保する
```

**注意点**: ペアターン（7♥）で「2ペア昇格」が起きるのは、ハンドがKまたは7を含む場合です。例えば BTN の A♠9♣（フロップで役なし）をターン後に確認すると、全カード A♠,9♣,K♥,7♠,2♦,7♥ → ランク別: A×1, K×1, 9×1, 7×2, 2×1。Best 5 = K♥-A♠-9♣-7♠-7♥ = ボードペアの7-7が入った「1ペア（7's）」になります。「役なし」にはならず、ボードペアが自動的に最良の5枚に含まれます。ただし強さとしては「ボードペアのみ」で非常に弱い。ペアターンの影響は**ハンドと照合して毎回確認**することが鉄則です。

## 25-10 第26章への橋渡し ─ ソルバーレビューへの接続

本章で統合した判断フローは「3ストリートの全体像を見渡す思考枠」を提供します。しかし、実戦では想定外のライン・相手の変則プレイ・特殊なボード配列が常に起きます。

暗算式（バレルスコア・α式・後手スコア）は「平均的なGTO方針」を数値化したものです。個別の手をより深く検討するには、実際のソルバーデータとの照合が必要です。

第26章では、ソルバーを使った具体的なハンドレビューの手法を扱います。本章の統合フローを起点にして、「暗算式の判断がGTOとどこでズレているか」を追跡する方法を学びます。

本章で学んだ「3ストリートを通じたライン設計」の思考枠を持った上でソルバーを見ると、数値の意味が格段に見えやすくなります。

> **本章まとめ**
>
> - マルチストリート判断の本質は「3ストリートを連結したライン設計」であり、各ストリートを独立して考えることではない
> - ポットジオメトリを把握することで、リバーのSPRと戦術余地をフロップ時点で予測できる
> - 4つの典型ライン（3バレル・小ベット保守・チェック挟み・諦めライン）はハンド・ボード・SPRの組み合わせで選択する
> - バレルスコア（ターン）・α式（リバー配分）・後手スコア（ディフェンス）の3式は3ストリートを通じて連動する
> - ハンドevolutionの管理（ペアターンで役が変化）はマルチストリート判断の最重要チェック項目
> - α式を超えるブラフはGTOから外れた搾取対象になる。ブロッカー選別でブラフ枠内に収める

**【GTOとのズレ】**

本章で示した統合フローは「平均的なGTO方針を暗算で近似する」設計です。実際のGTOとのズレが生じやすい箇所を率直に挙げます。

第一のズレは、ストーリーの一貫性に関するものです。GTOは「前ストリートのアクションと後ストリートのアクションが一貫している必要はない」という原則を持ちます。各アクションは独立したEV計算で決まるため、「フロップで小ベット → ターンでオーバーベット」というストーリー上の矛盾がGTOの計算上は正当化される場合があります。本章で述べたストーリー一貫性のルールは「人間が実行可能な近似」であり、GTOの精密な計算を置き換えるものではありません。

第二のズレは、ポットジオメトリの固定的な扱いに関するものです。GTOは各コンボの強さ・ブロッカー・相手レンジの形状に応じて、ストリートごとにベットサイズを動的に変化させます。本章の「33%→50%→75%」のような固定ラインは、実戦での意思決定を簡素化するための目安です。特に、GTOではターンでのポラライズ（小ベットと大ベットの混在）が頻繁に発生し、単純な「サイズを段階的に上げる」モデルとは異なります。

第三のズレは、ブラフ枠の管理に関するものです。α式で計算したブラフ上限は「コンボ単位の均衡」を示しますが、GTOはさらに「どのコンボをバリューにし、どのコンボをブラフにするか」という組み合わせ最適化を行います。本章の「ブロッカーでブラフ候補を選ぶ」アプローチは正しい方向性ですが、GTOの精密な計算とは差があります。実戦ではα式の枠内でブロッカーを優先する方針を守ることが最優先です。
