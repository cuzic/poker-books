# 第17章　OOPの応戦 ─ 後手下限とブラフキャッチ

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: 第16章でIPが設計したリバーベットに対して、OOPがコール/CR/フォールドをどう選択するかを体系化する。第9章の後手スコアをリバーに適用し、後手下限ラインを満たすコールレンジを設計する。

---

## 17-1 第16章との対称性

第16章では、リバーでIPが取る3つの選択肢を整理しました。バリューベット・ブラフ・チェックバックのどれを選ぶか。α式でV:B比率を設計し、ブロッカー論で具体的なコンボを選ぶというフローでした。

本章ではそのIPのベットに対して、OOP（BBポジション）が応戦する側の論理を整理します。

対称性を確認しておきます。

```
IPの設計（第16章）:
  α = ベット額 ÷ (ポット + ベット額)
  → ブラフの損益分岐点フォールド率
  → 「相手がαより高い頻度でフォールドすればブラフが得」

OOPの応戦（本章）:
  後手下限確率 = 1 − α
  → 「αより低い頻度でフォールドすれば相手のブラフが得にならない」
  後手スコア = HandScore + A − 3 − C − M
  → 個別ハンドをコール/CR/フォールドに振り分ける
```

先手がα式で設計し、後手が後手下限確率を目標に守る。この対称性がリバーの均衡点を形成します。

本章では後手スコアを実際のリバー局面に適用し、「どのハンドでコールするか」「どのハンドでCRするか」「どのハンドでフォールドするか」を具体的に判断できるようにします。

## 17-2 リバー版後手スコアの確認

第9章で確認した後手スコアの形をリバー版として整理します。

```
後手スコア = HandScore + A − 3 − C − M

≥ 8 → チェックレイズ（CR）検討
0〜7 → コール
< 0 → フォールド
```

リバーでは、フロップ・ターンとの違いが2点あります。第9章で詳しく導出していますが、本章の実戦適用に向けて再確認します。

### ドロー加点の消滅

フロップ・ターンのHandScoreにはドロー加点（アウツ × 1.5）が含まれます。フラッシュドローで約13点、OESDで約12点が役スコアに上乗せされていました。

リバーではドローが完成したか外れたかが確定しています。ドロー加点は消えます。

```
フロップ/ターン: HandScore = 役スコア + ドロー加点 + ブロッカー加点
リバー:         HandScore = 役スコア + ブロッカー加点
                            （ドロー加点 = 0）

外れたフラッシュドロー（例: A♥9♥ on Kドライボード + ブランクリバー）:
  ターンまで: HandScore ≈ 13（FDの加点）
  リバー:     HandScore ≈ 0（Aハイ、役なし）→ 後手スコアが大幅に低下
```

### C値の拡張

リバーではIPがオーバーベット（100%以上）を使う場面が増えます。第9章で追加されたリバー専用のC値を使います。

| ベットサイズ | C値 | 後手下限確率（1−α） |
|---|---|---|
| 33%ポット | C = 3 | 75% |
| 50%ポット | C = 5 | 67% |
| 75%ポット | C = 7 | 57% |
| 100%ポット | C = 9 | 50% |
| 150%ポット | C = 11 | 40% |

C値は「ベット比率（%ポット）から決まる変換係数」です。ポットの絶対額が変わっても、ベット比率が同じならCは同じ値を使います。リバーでポットが30BBに膨らんでも、75%ベット（22.5BB）ならC=7のままです。

## 17-3 ハンドの3層分類 ─ リバーでの整理

リバーに到達した時点で、OOPのハンドを3層に整理します。

```
層1（強バリュー）: 後手スコア ≥ 8
  → チェックレイズ（CR）検討
  → コールされても相手のバリューに勝てる強さが必要

層2（ブラフキャッチャー）: 後手スコア 0〜7
  → コール
  → 相手のブラフには勝てるが、バリューには負けうる強さ

層3（フォールド対象）: 後手スコア < 0
  → フォールド
  → 相手のバリューにもブラフにも対抗困難なハンド
```

フロップ・ターンとの根本的な違いは、「ドロー成分」がなくなることでハンドの役割が明確に二分されることです。ターンでは「ショーダウン価値を持ちながら、次のカードでバリューになれる」という中間的なハンドが存在しました。リバーでその余地はありません。

ブラフキャッチャーとは、「相手がブラフなら勝てるが、バリューベットなら負けるという位置に立つハンド」です。ブラフキャッチャーでコールを選ぶことは、「相手のベットレンジのブラフ率がαを上回っている」という判断を前提にします。

## 17-4 後手下限ラインとコールレンジの設計

後手スコアは個別ハンドの判断ツールです。これとは別に、OOPがレンジ全体として守るべき「後手下限確率（= 1 − α）」があります。

第8章で確認した関係式を後手の視点で再確認します。

```
α = ベット額 ÷ (ポット + ベット額)   ← 先手のブラフ損益分岐フォールド率
後手下限確率 = 1 − α                 ← OOPがコールすべき最低頻度
後手下限ライン                        ← その水準を割るとブラフを許す境界
```

具体例で確認します。

**75%ポットベット:**

```
α = 0.75P ÷ (P + 0.75P) ≈ 0.43
後手下限確率 = 1 − 0.43 = 0.57（57%以上コールが必要）
```

後手下限確率57%は「OOPが全ハンドの中で少なくとも57%の頻度でコール以上を選ぶ必要がある」ことを意味します。これを下回ると、IPのブラフが自動的に利益になります。

### 後手スコアと後手下限確率の整合

後手スコアで個別ハンドを「コール/フォールド」に振り分けた結果が、後手下限確率を自然に満たしていれば問題ありません。ただし、特に**33%の小サイズベット**では注意が必要です。

```
33%ベット → 後手下限確率 = 75%（C=3）
  → OOPのハンドの75%以上でコールが必要

後手スコアが0以上のハンドだけコールした場合、75%に届かない場合がある
→ スコアが −3 程度までのハンドを一部コールに混ぜる調整が必要
（第9章で確認した「後手下限調整」）
```

大きなベット（75%以上）では後手下限確率が57%以下に下がるため、スコア0以上のハンドをコールすれば自然に水準を満たせる場合が多いです。小サイズほど「守りが薄くなりやすい」という逆説的な構造があります。これはIPが小サイズを使う場面でOOPが「安心してフォールドしがちになる」という実戦上の罠に対応しています。

## 17-5 ブラフキャッチの判断基準

ブラフキャッチャーとしてコールする際、「コールが利益になる条件」を正確に理解しておく必要があります。

### コールが利益になる条件

```
コールEV > フォールドEV

コールEV = （相手がブラフの確率）× P − （相手がバリューの確率）× コール額
フォールドEV = 0

コールが有利 ⟺ 相手のブラフ率 > α
```

αは「先手がブラフで損益分岐するフォールド率」でしたが、後手の視点では「相手のブラフ率がαを超えていればコールが有利」という基準になります。

| ベットサイズ | α（コール損益分岐ブラフ率） | 意味 |
|---|---|---|
| 33%ポット | 0.25（25%） | 相手のベット25%以上がブラフならコール有利 |
| 50%ポット | 0.33（33%） | 相手のベット33%以上がブラフならコール有利 |
| 75%ポット | 0.43（43%） | 相手のベット43%以上がブラフならコール有利 |
| 100%ポット | 0.50（50%） | 相手のベット50%以上がブラフならコール有利 |
| 150%ポット | 0.60（60%） | 相手のベット60%以上がブラフならコール有利 |

この数値はIPが均衡的なV:B比率を組んでいる場合と一致します。IPがGTOに近いベットレンジを組んでいれば、OOPはほぼインディファレンスの状態になり、コールとフォールドのどちらを選んでもEVの差は小さくなります。

### ウィッシュコールの罠

後手スコアが0〜7の「コール域」にあるからといって、ハンドがブラフキャッチャーとして機能するかは別問題です。

**ウィッシュコールとは**: 「相手がブラフであってほしい」という希望でコールすること。コールEVの計算なしに感情で選択するパターンです。

ウィッシュコールを防ぐチェックリスト:

```
□ このボードで相手はどんなブラフを持てるか？
  → バストドロー・外れたセミブラフ等が候補。フラッシュ完成リバーか？
□ 相手のブラフ率はαを超えているか？
  → 超えていれば合理的なコール
□ 自分のハンドは相手のブラフに実際に勝てるか？
  → ブラフキャッチャーの前提：「相手のバリューには負けても、ブラフには勝てる」
```

ハイカードのみで「一応コール」するのは典型的なウィッシュコールです。相手のブラフ候補に対しても自分が負ける立場なら、コールに意味はありません。

## 17-6 リバーCRの特殊性

後手スコアが8以上に達したとき、CR（チェックレイズ）の検討に入ります。しかしリバーのCRはターンのCRと根本的に異なる制約があります。

### セミブラフが消えた影響

ターンでのCRには「セミブラフ」という選択肢がありました。ドロー中のハンドでCRすることで、フォールドエクイティ（相手をフォールドさせる価値）とエクイティの両方を活用できました。

リバーではドローが完成か外れかで確定しています。リバーCRは純粋なバリューCR（VCR）か純粋なブラフCR（BCR）の二択です。セミブラフCRという中間は存在しません。

```
ターンCR: バリューCR / セミブラフCR / ブラフCR（3種類）
リバーCR: バリューCR / ブラフCR（2種類のみ）
```

### リバーCRに必要な条件

リバーCRを選ぶためには、後手スコアがCR域（≥8）に達するだけでは不十分です。追加の確認が必要です。

**バリューCR（VCR）の必要条件:**

```
(1) 後手スコア ≥ 8（CR域に入っている）
(2) IPがCRにコールした場合、相手のコールレンジの大部分に勝てる
(3) IPのリレイズ（4ベット）に対して耐えられる
```

条件（2）が重要です。後手スコアが高くても、「IPのリレイズに対してフォールドせざるを得ないハンド」でCRするのはGTOから外れます。CRしてコールされたとき、相手のレンジに勝率50%以上を確保できることが前提です。

**ブラフCR（BCR）の必要条件:**

```
(1) ショーダウン価値がほぼゼロ（コールされると負ける）
(2) ナッツブロッカーを持つ（相手のバリューコールを削る）
(3) IPがコールしてくる頻度がαを下回る（BCRがEV+）
```

BCRは基本的に「バストドロー＋ブロッカー持ち」の構成です。ミドルペアやボトムペアでBCRを打つことは推奨されません。これらはコールされると負けるが、チェックフォールドよりCRの方が良い場面はほとんどなく、チェック後にIPがベットしてこなければそのままショーダウンを目指す方が合理的です。

### 具体的な判断基準

```
後手スコア ≥ 8 → CR候補
  追加チェック:
    コールされて勝てるか？ YES → VCR実行
                          NO  → コールに下げる
  
  ショーダウン価値がゼロ？ YES → BCR候補（ブロッカー確認）
                          NO  → コールかチェックフォールド
```

後手スコアはCR検討の「入り口」です。CRを実行するかどうかの最終判断は「コールされたとき勝てるか」という追加確認で決まります。

## 17-7 ブロッカーによる調整（第10章の適用）

第10章で学んだブロッカー論を後手スコアの調整に使います。

後手スコアは「平均的なレンジを前提にした計算」です。ブロッカーはそこから1〜2点分の微調整を行う最終層です。

### コール方向への調整（バリューブロッカー）

自分のハンドが相手の主要なバリューベット候補を削っている場合、コールの根拠が強まります。

```
例: ドライボード K♠7♦2♣A♥Q♦で相手が75%ベット
    自分のハンドに A♣ が含まれる
    → 相手のナッツ候補（AK 2ペア, A7 2ペア等のAxコンボ）が減る
    → 後手スコアを +0.5〜+1 程度上方修正
```

### フォールド方向への調整（ブラフブロッカー）

自分のハンドが相手のブラフ候補を削っている場合、コールの根拠が弱まります。

```
例: フラッシュ完成リバー（ハート4枚のボード）で相手がベット
    自分のハンドに 9♥ が含まれる（弱いハートでブラフを削る）
    → 相手のブラフ候補（ハートを持たないバストドロー）は残るが、
      相手がハートのブラフを打てる余地が微減
    → 後手スコアを −0.5 程度下方修正
```

### ブロッカー調整の使い方

ブロッカーは「後手スコアが0〜2程度のコール境界にあるハンド」に特に効いてきます。スコアが5以上なら調整なしでコール。スコアが−5以下なら調整があってもフォールド。境界付近でブロッカー効果が判断の分かれ目になります。

```
後手スコア = 2、バリューブロッカーあり → スコア実質3 → コール
後手スコア = 1、ブラフブロッカーあり  → スコア実質0.5 → コール（薄い）
後手スコア = 0、バリューブロッカーなし → コール（後手下限確率の調整で含める場合あり）
```

## 17-8 実戦例5件

### 例1: TPGK でのブラフキャッチ（50%ポットベット）

**状況**: BTN（IP）vs BB（OOP）。6-max、100BB、キャッシュゲーム。

ボード（5枚）: K♠7♦2♣5♥3♦

ボード読みの確認:
- フラッシュチェック: ♠=K♠=1枚、♦=7♦,3♦=2枚、♣=2♣=1枚、♥=5♥=1枚 → 全スート2枚以下 → フラッシュなし
- ストレートチェック: K-7-5-3-2。5連続を探す → A-2-3-4-5（A不在）、2-3-4-5-6（4,6不在）→ ストレートなし
- ペアボード: 全ランク1枚ずつ → ペアボードなし

**BBのハンド**: K♣Q♣（TPGK）

全カード確認: K♣, Q♣, K♠, 7♦, 2♣, 5♥, 3♦

デッキ整合チェック: K♣（ハンド）と K♠（ボード）は別カード（OK）。2♣（ボード）と Q♣（ハンド）は別カード（OK）。重複なし。

役の計算:
- ランク: K=2（K♣+K♠）、Q=1、7=1、5=1、3=1、2=1
- best5: K-K-Q-7-5 → **ワンペアK、Qキッカー（TPGK）**

HandScore = 15（TPGK: Qキッカー ≥ Q基準）

**後手スコアの計算:**

```
A: K-7-2-5-3（ドライ、散開レインボー） → A = 3
C: 50%ポットベット → C = 5
M: BTN vs BB（HU） → M = 0

後手スコア = 15 + 3 − 3 − 5 − 0 = 10 → コール
```

**判断の根拠:**

IPがリバーで50%ポットベットを打った場合、α = 0.50P / (P + 0.50P) ≈ 0.33。相手のベットレンジのうち33%以上がブラフであれば、K♣Q♣でのコールはEV+です。

K♠7♦2♣5♥3♦のドライボードでは、IPのブラフ候補は「フロップでの浮遊ハンドが外れたもの」「Qx等の薄いハンドのブラフ」などが考えられます。K♣のバリューブロッカーは相手の強いKx（例: KJ, KT）の一部のコンボを削る効果もあります。

後手スコア10はコール域の中央付近。ブラフキャッチャーとして機能します。

**選択**: コール（ブラフキャッチ）

### 例2: TPTK でのコール vs CR 判断（75%ポットベット）

**状況**: BTN（IP）vs BB（OOP）。同上。フロップCBet → ターンバレルをコール継続。リバーでIPが75%ポットベット。

ボード（5枚）: A♣K♦7♠9♥2♣

ボード読みの確認:
- フラッシュチェック: ♣=A♣,2♣=2枚、♦=K♦=1枚、♠=7♠=1枚、♥=9♥=1枚 → フラッシュなし
- ストレートチェック: A-K-9-7-2。A-K（gap）、K-9（gap）、9-7（gap）→ 5連続なし、ストレートなし
- ペアボード: 全ランク1枚ずつ → ペアボードなし

**BBのハンド**: A♠Q♥

全カード確認: A♠, Q♥, A♣, K♦, 7♠, 9♥, 2♣

デッキ整合チェック: A♠（ハンド）と A♣（ボード）は別カード（OK）。7♠（ボード）と A♠（ハンド）は別スロット（OK）。重複なし。

役の計算:
- ランク: A=2（A♠+A♣）、K=1、Q=1、9=1、7=1、2=1
- best5: A-A-K-Q-9 → **ワンペアA（Aのトップペア、Qキッカー）**

HandScore = 18（TPTK: AはボードトップのA。Qキッカーはボード上Q以上 → TPTK扱い）

**後手スコアの計算:**

```
A: A-K-9-7-2（ドライ、散開レインボー） → A = 3
C: 75%ポットベット → C = 7
M: HU → M = 0

後手スコア = 18 + 3 − 3 − 7 − 0 = 11 → コール
（後手スコア ≥ 8 なので CR 候補にも入る）
```

**コールかCRかの追加判断:**

後手スコア11はCR域（≥8）に入ります。ここで「リバーCRの特殊性」が機能します。

A♠Q♥でCRを打ちIPにコールされた場合、IPのコールレンジには:
- AK（2ペア） → A♠Q♥に勝つ
- A9, A7（2ペア） → A♠Q♥に勝つ
- AQ、AJ（同じAペア・キッカー負けの可能性） → 引き分けかキッカー次第

IPが75%ポットベットを選ぶレンジには、Axの2ペア以上が多く含まれています（AK, A9, A7等）。これらに対してA♠Q♥のCRはコールされて負けます。「コールされて勝てる」条件を満たしていないためVCRは推奨されません。

一方でA♠のバリューブロッカー効果：相手のAKのコンボを4→3通りに削る効果があります。これはコールを正当化する方向に働きます。

**選択**: コール（CRは過剰、コールで十分）

後手スコアがCR域でも「コールされて勝てない」ならコールに留めます。これがリバーCR判断の核心です。

### 例3: TPWK でのブラフキャッチャー判断（75%ポットベット）

**状況**: BTN（IP）vs BB（OOP）。フラッシュドローが残存するリバー。

ボード（5枚）: K♥7♦2♣Q♥9♥

ボード読みの確認:
- フラッシュチェック: ♥=K♥,Q♥,9♥=3枚 → ハート3枚（フラッシュなし）。相手がハート2枚持てばフラッシュ完成する状態
- ストレートチェック: K-Q-9-7-2。K-Q（gap: J不在）、Q-J-T-9（Jなし）、9-8-7（8なし）→ 5連続なし、ストレートなし
- ペアボード: 全ランク1枚ずつ → ペアボードなし

**BBのハンド**: K♣J♣

全カード確認: K♣, J♣, K♥, 7♦, 2♣, Q♥, 9♥

デッキ整合チェック: K♣（ハンド）と K♥（ボード）は別カード（OK）。2♣（ボード）と J♣（ハンド）は別カード（OK）。重複なし。

ストレート確認（KJ手に対して）: K-Q-J-9-7。Q-J（連続）だが K-Q-J（3連続）で5連続には10, 8が必要 → ストレートなし。

役の計算:
- ランク: K=2（K♥+K♣）、Q=1、J=1、9=1、7=1、2=1
- best5: K-K-Q-J-9 → **ワンペアK（Jキッカー: TPWK）**

HandScore = 10（TPWK: Jキッカーは Q未満 → 弱キッカー）

**後手スコアの計算:**

```
A: K-7-2-Q-9（3ハートでウェット方向、ハートFDが3枚残存）
   ウェット/セミの評価が必要。ハート3枚はFD完成ゾーン → A = 2（セミウェット）
C: 75%ポットベット → C = 7
M: HU → M = 0

後手スコア = 10 + 2 − 3 − 7 − 0 = 2 → コール（薄い）
```

**ブロッカー考慮:**

K♣を保有することで、相手の KQ、KJ（Kペア+Qキッカー等）のコンボが減ります。相手がKを持つバリューを一部削ることができ、コール方向へわずかに修正できます。ただし調整幅は小さく（+0.5程度）、コール判断に影響するほどではありません。

**ブラフキャッチャーとしての機能:**

このボードでIPのブラフ候補として考えられるものは「ハートのフラッシュドローが外れたハンド（例: A♥T♥等のバストFD）」です。A♥T♥のバストFDはショーダウン価値がほぼゼロであり、IPがブラフとして選びやすいコンボです。

K♣J♣は相手のA♥T♥系のブラフに勝てます（K-J-K-Q-9 = Kペア vs Aハイ → Kペア勝ち）。ブラフキャッチャーとして機能します。

**選択**: コール（薄いブラフキャッチ）

後手スコア2は薄いコールですが、ハートのバストドローが相手のブラフ候補として豊富なボードでは、Kペアのブラフキャッチには根拠があります。

### 例4: broadway 完成ボードでの罠（チョップ警戒）

**状況**: BTN（IP）vs BB（OOP）。broadway完成ボードのリバー。IPがポットサイズベット。

ボード（5枚）: A♥K♦Q♣J♠T♦

ボード読みの確認:
- ストレートチェック: A-K-Q-J-T → **5連続（broadway）が成立**。ボード単体でbroadway完成。
- フラッシュチェック: ♥=A♥=1枚、♦=K♦,T♦=2枚、♣=Q♣=1枚、♠=J♠=1枚 → フラッシュなし
- ペアボード: 全ランク1枚ずつ → ペアボードなし

**「board itself plays」状況:**

A-K-Q-J-T の broadway がボードに成立しています。7枚の中からbest5枚を選ぶルールでは、ハンドの2枚に関係なく **A-K-Q-J-T が全プレイヤーの best5 になる可能性** があります。

**BBのハンド**: 8♣6♣

全カード確認: 8♣, 6♣, A♥, K♦, Q♣, J♠, T♦

デッキ整合チェック: Q♣（ボード）と 8♣（ハンド）は別カード（OK）。重複なし。

役の計算:
- ランク: 8, 6, A, K, Q, J, T → A-K-Q-J-T の5連続 + 8, 6 は使われない
- best5: A-K-Q-J-T（broadway） ← ハンドの8♣, 6♣は使わない
- ハンドカード（8, 6）を使う場合: K-Q-J-T-8（gap）、J-T-8-6（gap）→ 5連続にならない

**全プレイヤーが broadway を持つ = チョップ**

```
OOPのハンド 8♣6♣: best5 = A-K-Q-J-T（broadway）
IPのハンド（例えば 9♠5♠）: best5 = A-K-Q-J-T（broadway）→ 同じ
→ チョップ確定（フラッシュ・フルハウス等がない場合）
```

IPが100%ポットベットを打ってきた場合、その根拠は何か？

IPが持ちうる例外ハンド（チョップを破れるケース）:
- **フラッシュ**: ボードに♦が2枚（K♦, T♦）しかない。IPが♦3枚を持つと5枚になるが、通常のハンドには♦2枚+ボード2枚=4枚どまり → フラッシュ完成は現実的に困難
- **IPがストレートをさらに上回るナッツはない**: broadway = 最高ストレートのため、フラッシュまたはフルハウスでのみ超えられる

このボードでIPがベットを選ぶ根拠は薄く、通常はチョップを確認してショーダウンに向かうべきです。

**OOPの判断:**

```
後手スコアを計算する前に「チョップボードか」を確認する

broadway完成ボード → OOPの best5 も broadway → チョップ確率が高い
IPのベットに対して:
  フォールド = チョップポットを相手に渡す（損）
  コール = チョップポットを回収（正常）
  CR = IPがフラッシュ・フルハウスを持つ場合に反転されるリスク
```

このような状況では、IPの大きなベットは「フラッシュかフルハウスを持つ本物のバリュー」か「チョップと知っていてブラフを打っている」のどちらかです。OOPはコールしてチョップを確認することが合理的であり、フォールドはポットを失います。

**選択**: コール（チョップ確認）

**警告**: broadwayボードでフォールドすることは、チョップポットの自分の取り分を捨てる行為です。「ハンドが弱いからフォールド」という直感は、ボード単体でbroadwayが成立している事実を見落とした誤りです。

### 例5: 過剰フォールドの罠（33%小サイズ対策）

**状況**: BTN（IP）vs BB（OOP）。IPが33%の小サイズベットを連打する相手。

ボード（5枚）: K♠7♦2♣5♥3♦

ボード読みの確認（例1と同じボード）:
- ドライボード、フラッシュなし、ストレートなし、ペアボードなし

**BBのハンド**: J♣T♣

全カード確認: J♣, T♣, K♠, 7♦, 2♣, 5♥, 3♦

デッキ整合チェック: 2♣（ボード）と J♣、T♣（ハンド）は別カード（OK）。重複なし。

ストレート確認: J-T-K-7-5-3-2。K-J（gap）、J-T（連続）、T-9-8（9,8なし）→ ストレートなし。

役の計算:
- ランク: J, T, K, 7, 5, 3, 2 → 全て異なる、ペアなし
- best5: K-J-T-7-5 → **ハイカード（役なし）**

HandScore = 0（役なし、ドロー加点なし）

**後手スコアの計算（33%ベット）:**

```
A: K-7-2-5-3（ドライ） → A = 3
C: 33%ポットベット → C = 3
M: HU → M = 0

後手スコア = 0 + 3 − 3 − 3 − 0 = −3 → フォールド（スコア<0）
```

**しかし、機械的にフォールドするのは誤りです。**

33%ベットの後手下限確率 = 75%。BBのハンドレンジ全体の75%でコール以上が必要です。J♣T♣のような役なしハンドが多数含まれるBBのレンジにおいて、後手スコアが0以上のハンドだけコールすると、75%の後手下限確率を下回る可能性があります。

**後手下限調整の考え方:**

```
後手スコア = −3 〜 −1 のハンドを一部コールに混ぜる
  → 後手下限確率75%を達成するためのバッファ

J♣T♣（スコア −3）:
  75%ポットなら明確にフォールド
  33%ポットでは「後手下限確率を守るための一部コール」として混ぜる余地あり
  → 純粋なブラフキャッチではなく、「後手下限ラインを守るコール」

ただし、J♣T♣は役なしでIPのバリューレンジのほぼ全てに負ける
→ ブラフキャッチとしても機能が弱い
→ このハンドをコールに混ぜるよりも、
  スコアが −1〜0 の「弱いペア」（例: 3♥4♥で最低ペア等）を混ぜる方が合理的
```

**過剰フォールドを避ける実戦ルール:**

```
33%ベットへの対応:
  スコア 0〜7 → コール
  スコア −3〜−1 → ハンドクラスに応じて一部コール（後手下限調整）
  スコア −4 以下 → フォールド

75%以上ベットへの対応:
  スコア 0〜7 → コール
  スコア < 0 → フォールド（後手下限調整不要）
```

小サイズベットに対して「役なしだからフォールド」を連発すると、後手下限確率75%を大きく下回ります。IPはこの傾向を読んで33%ベットを多用して利益を得ます。「小サイズへの過剰フォールド」はIPのブラフレンジを無制限に価値化させる最も搾取されやすいパターンです。

**選択**: フォールドだが、全局面で機械的にフォールドしないこと。レンジ全体の後手下限確率を意識してコールを混ぜる。

## 17-9 過剰防御と過剰フォールドの罠

実戦で最も起きやすい2つの誤りを整理します。

### 過剰防御（コールしすぎ）

「後手下限ラインを守らなければ」という意識が行き過ぎると、ショーダウン価値のないハンドでコールを連発するウィッシュコールに陥ります。

```
典型的な過剰防御パターン:
  「ペアがあれば一応コール」→ 相手バリューに負けるミドルペアでコール
  「ポットが大きいからコール」→ 感情的コール
  「後手下限確率75%だから75%コールしなきゃ」→ 個別ハンドの強さを無視
```

後手下限確率は「レンジ全体の下限」であり、「個別ハンドの強さを無視してコール頻度を達成する」ものではありません。強いハンドが100%コールし、弱いハンドが0%コール（フォールド）という組み合わせの平均が後手下限確率を満たせば十分です。

### 過剰フォールド（フォールドしすぎ）

逆に「このハンドでは勝てない」という直感でフォールドを連発すると、後手下限確率を下回ります。

```
典型的な過剰フォールドパターン:
  「相手が大きなベットをした → バリューに違いない → フォールド」
    → 相手のブラフを見逃す
  「ハイカードしかない → フォールド」
    → 33%ベットでハイカードを全フォールド → 後手下限確率75%を大幅に下回る
  「broadway ボードで役なし → フォールド」
    → チョップポットを放棄（例4参照）
```

後手スコアと後手下限確率を両方意識することで、この2つの罠を避けられます。

### 適切なバランスのために

```
判断の優先順位:
  1. 後手スコアで個別ハンドを分類（コール/CR/フォールド）
  2. ベットサイズから後手下限確率（1−α）を確認
  3. コール域のハンドが後手下限確率を満たしているか概算
  4. 33%以下の小サイズなら、スコア −3〜−1 のハンドを後手下限調整で一部コールに混ぜる
```

### 後手下限確率を「頭数」で確認する方法

ソルバーを持たない実戦では、後手下限確率をコンボ数で概算します。

ドライボード K♠7♦2♣5♥3♦に対してIPが33%ベット（後手下限確率75%が必要）という状況を例にします。

BBのハンドレンジを大まかに分類します。

```
BBのリバー到達ハンドの典型例:
  強バリュー（後手スコア ≥ 8）:
    KQ〜KJ （Kのペア、Q or Jキッカー）: 約6コンボ
    77、22（セット）: 約3〜4コンボ
    ...合計 約15コンボ前後

  ブラフキャッチャー（後手スコア 0〜7）:
    K9〜K8（Kのペア、弱キッカー）: 約4コンボ
    77→セカンドペア（ターンで確定したセット以外）: 約6コンボ
    ...合計 約20コンボ前後

  フォールド対象（後手スコア < 0）:
    役なしハンド（JT、J9等）: 約15コンボ前後

全体: 約50コンボ
うちコール（強バリュー + ブラフキャッチャー） = 35コンボ
コール率 = 35/50 = 70% → 後手下限確率75%を下回る！
→ スコア −1〜−3 のハンドを5コンボほどコールに混ぜる
→ 40/50 = 80% → 75%をクリア
```

この概算は「頭の中で大まかに数える」レベルで十分です。重要なのは「フォールドしすぎかどうか」を数字で確認する習慣です。

## ミニクイズ

### 問1

BTN（IP）vs BB（OOP）。ボード A♠K♦7♣Q♥2♦（5枚、ドライ、ランク全異）。IPが75%ポットベット。BBのハンドは K♣J♦（セカンドペア、Jキッカー）。A値=3、M=0 とします。

HandScore はいくつか。後手スコアはいくつか。正しい判断はどれですか。

1. HandScore = 15（TPGK）、後手スコア = 8、CR検討
2. HandScore = 10（TPWK: セカンドペア）、後手スコア = 3、コール
3. HandScore = 8（セカンドペア）、後手スコア = 1、コール（薄い）

### 問2

75%ポットベットに対して、OOPのコールレンジを設計するとします。このベットのα（フォールド率）と後手下限確率（= 1 − α）の正しい値はどれですか。

1. α = 0.43、後手下限確率 = 0.57（57%）
2. α = 0.57、後手下限確率 = 0.43（43%）
3. α = 0.33、後手下限確率 = 0.67（67%）

### 問3

リバーで後手スコアが10に達したハンドでCRを実行しようとしています。次のうち「リバーCRの実行を断念してコールに変更すべき」なのはどれですか。

1. CRにコールされた場合、相手のバリューコールレンジ（AA、KK等）にほぼ全て負ける
2. CRにコールされた場合、相手のコールレンジの60%に勝てる
3. 後手スコアが10なので、コールされても十分なEVがある

---

### 解答

- **問1**: 3（K♣J♦ on A♠K♦7♣Q♥2♦。KはボードのセカンドカードではなくA-K-7-Q-2でのセカンドランクだが、AがトップのためKはセカンドペア扱い。HandScore = 8（セカンドペア）。後手スコア = 8+3−3−7−0 = 1。コール域の薄い判断。選択肢1はHandScore評価が誤り（TPGKは自分のハンドがトップペアの場合。ここはKがAのボードでセカンドペア）。選択肢2はHandScore評価が近いが15はTPGKの値）
- **問2**: 1（α = 0.75P ÷ (P + 0.75P) = 0.75/1.75 ≈ 0.43。後手下限確率 = 1 − 0.43 = 0.57。75%ベットでは57%のコール頻度が後手下限ライン）
- **問3**: 1（リバーCRの必要条件は「コールされて勝てること」。コールされた場合に相手のバリューコールレンジにほぼ全て負けるなら、VCRは損。後手スコアがCR域に入っていても「コールされて勝てる」という追加確認が必要。選択肢2（60%勝てる）はCR実行を正当化できる。選択肢3は誤り—後手スコアはCR検討の入り口であり、コール成立を自動的に保証しない）

> **本章まとめ**
>
> - リバーOOPの応戦は後手スコア（HandScore + A − 3 − C − M）で判断する。≥8はCR検討、0〜7はコール、<0はフォールド
> - リバー版HandScoreはドロー加点ゼロ。ショーダウン価値のみで評価する。リバー専用C値：100%=9、150%=11
> - 後手下限確率（= 1 − α）はレンジ全体の防御下限。33%ベットでは75%、75%ベットでは57%のコール頻度が必要
> - 33%の小サイズには後手下限確率75%を維持するため、スコア −3 程度のハンドを一部コールに混ぜる後手下限調整が必要
> - リバーCRはセミブラフが使えない。VCRは「コールされて勝てる」が必須条件。後手スコアCR域でも追加確認が必要
> - broadway完成ボードはチョップを確認してコール。「役なしだからフォールド」はチョップポットを捨てる誤り

**【GTOとのズレ】**

本章で示した「後手スコア0以上をコール、未満をフォールド」という基準はGTOの近似です。実際のGTOソルバーは各コンボを複数の頻度に分割した混合戦略で動かします。たとえば「後手スコア3のハンド」が60%コール・40%フォールドというように、純粋な境界ではなく混合が入ります。

人間が実戦で最も外れやすいのは、**リバーCRの過剰使用**です。後手スコアが8以上に達したとき、GTO的には「コールが最大EVになる場面がCRより多い」ことがあります。特に「相手のバリューに負けるハンドでのCR」は、コールされた時点で期待値が大幅にマイナスになります。GTO研究者がリバーCRを実行するのは、コールされた際の勝率がかなり高いナッツ級のハンドに偏っています。

もう一つのズレは、**相手のレンジ読みの精度**です。後手スコアは「相手のレンジが均衡的である」という前提の上に成立します。実際には相手のリバーベットレンジがバリューに偏っている場合（ブラフが少ない相手）、後手スコアが0以上でもフォールドが正解になります。逆に相手のブラフが多い場合は、後手スコアがマイナスのハンドでもコールが有利になります。相手の傾向を読んでコール頻度を調整することが、GTO的な均衡からの意図的な逸脱（エクスプロイト）であり、実戦ではこれが大きな利益源になります。

また、**broadway完成ボード等の特殊局面**では、後手スコアの計算よりもボード構造の把握が優先されます。「チョップボードをチョップと認識する」というボード読みの精度がGTOとの乖離を最小化します。後手スコアを計算する前に「このボードで私のbest5は何か」という基本確認が全ての判断の土台です。
