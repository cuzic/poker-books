# 提案: ナッツブロッカー補正の追加（spec 拡張案）

**起草日**: 2026-05-04
**起草者**: Claude (Opus 4.7)
**根拠**: tc_006 (J♥8♥5♣→4♥) の TexasSolver 検証で発見した境界例

---

## 1. 現状の課題

巻4 の暗算式は次のレイヤー構造になっています:

```
バレルスコア (FlopType + TurnCard)
  ≥ 7 → 全レンジCBet
  < 7 → 「H3ハンドのみ CBet」（依存ゾーン）

HandScore（巻② 第9章で導入）
  H3 (≥14) / H2 (8-13) / H1 (≤7)
  + ブロッカー加点 (+2〜+3)
```

**問題**: 「依存ゾーン × H2ハンド」の組み合わせで、本来は CBet すべきハンドが「Check」と判定される境界ケースがある。

### 具体例: tc_006 (J♥8♥5♣ → 4♥)

- バレルスコア = スーテッド(4) + フラッシュ(1) = 5（依存ゾーン）
- A♥K♦ の HandScore = 13（H2、A-high + フラッシュブロッカー）
- formula 判断: 「H2 → Check」
- 実 GTO: AK は **76-86% CBet**（A♥/K♥ がフラッシュブロッカーとして機能）

→ 簡易式では捕捉できない。

---

## 2. 提案: ナッツブロッカー補正

### 2.1 補正値

| 状況 | 現 HandScore | 補正後 |
|------|-----|-----|
| ナッツフラッシュブロッカー保有 (4枚以上ボードの A♠/♥/♦/♣) | +3（既存ブロッカー加点） | **+6** (+3 追加) |
| ナッツストレートブロッカー保有 (3-straight ボードの上端カード) | +3 | **+5** (+2 追加) |
| 上位セットブロッカー保有 (ペア板でのトップペア+トップキッカー) | +2 | +2（変更なし） |
| ナッツ以外のフラッシュブロッカー（A以外の高位♠等） | 0 | +1 |

### 2.2 バケツ判定への影響

```
現状:
  H3: HandScore ≥ 14
  H2: HandScore 8-13
  H1: HandScore ≤ 7

提案後（ナッツブロッカー保有時の実効スコア）:
  AK on 4-flush board (Ah blocker):
    base HandScore = 10（A-high）
    +3（ブロッカー加点 既存）
    +3（ナッツフラッシュブロッカー追加）
    = 16 → H3
  → CBet 候補に格上げ
```

これで「依存ゾーン × H2」の境界ケースが「依存ゾーン × H3」に格上げされ、formula は「CBet」と判定する。

### 2.3 適用条件

ナッツブロッカー補正は **リバー想定での攻撃判断** で適用する:

- ターンでフラッシュ完成（4枚同スートになる瞬間）
- リバーでフラッシュ完成済みボード
- リバーでブロードウェイ完成済みボード

3-card flop には適用しない（コンボ密度が高すぎてブロッカー効果が薄い、巻4 第7章 line 27 の議論と整合）。

## 3. 既存式との整合性

### 3.1 巻② 第9章 の HandScore（変更なし）

base score（役スコア）+ ドロー加点 + ブロッカー加点(+2〜+3) はそのまま維持。「ナッツブロッカー追加補正」は **別レイヤー** として上に乗せる。

### 3.2 巻④ 第7章 ブロッカー基礎 への加筆

7-5 節「ナッツブロッカー・セットブロッカー・ストレートブロッカー」を以下のように拡張:

```diff
+ 7-5-a ナッツブロッカーの実効スコア補正
+
+ ターン以降のフラッシュ完成ボード／ストレート完成ボードでナッツブロッカー
+ を保有している場合、HandScore に +2〜+3 の追加補正を加えます。これは巻②
+ で学んだ既存のブロッカー加点に上乗せされます。
+
+ - ナッツフラッシュブロッカー: +3 （既存 +3 と合算で +6）
+ - ナッツストレートブロッカー: +2 （既存 +3 と合算で +5）
+
+ 例: A♥K♦ on J♥8♥5♣4♥（4ハートターン）
+   役スコア（A-high）: 0
+   既存ブロッカー（A♥）: +3
+   ナッツブロッカー追加: +3
+   合計 HandScore: 6 → ブロッカー込みで H2 / 実効 H3 扱い
+   → 形式上 H2 だが、ナッツブロッカー込みなら H3 として CBet 候補
```

### 3.3 巻⑤ 第5章 ブロッカー実戦選択 との連結

巻⑤ 第5章では「コンボ単位の最終選択」として、複数のブロッカー候補から優先順位を決める手法を扱う。本補正値は巻⑤ の選択ロジックの数値的な裏付けとなる。

---

## 4. 検証計画

実装前に TexasSolver で以下を確認する:

| シナリオ | 期待動作 | 検証する CBet 頻度 |
|---|---|---|
| J♥8♥5♣→4♥（4-flush ターン）AK with A♥ | H3 扱い → 70%+ CBet | 確認済み: 76-86% ✓ |
| K♠Q♣7♣→J♣（4-club ターン）AKo with K♣ | H3 扱い → 60%+ CBet | **要確認** |
| A♥K♥7♥3♣→9♥（4-heart ターン）QJ with Q♥ | H2 扱い → 30%+ CBet | **要確認**（クォーターブロッカー） |
| K♠Q♥9♣J♦→Td（オープンエンド完成）AT with A | H3 扱い → 70%+ CBet | **要確認**（ナッツストレート blocker） |

3 ボード × 2 サイズ × 2 バケツ ≈ 12 シナリオで補正値の妥当性を確認。

---

## 5. 実装の優先度

**優先度: 中**

- 影響範囲: 巻④ 第7章への加筆 + 巻② 既存式は変更なし
- 影響カード（poker-drill）: tc_006 のような境界ケース（5〜10 件程度）
- 教育的価値: 高（「H2 でもブロッカーで格上げ」という直感的概念）

**実装する場合の手順:**
1. 検証計画の 12 シナリオを TexasSolver で実行（30〜60 分）
2. 補正値（+2/+3）を実測 GTO に合わせて微調整
3. 巻④ 第7章 7-5-a 節を加筆（70 word 程度）
4. poker-drill の `calc_hand_score` に nut blocker boost ロジックを追加
5. 関連カード（tc_006 等）の `formula.steps` を再生成して動作確認

**実装しない選択肢:**
- 現状の card は教育的に妥当（「H2 はチェック」のシンプル化は学習効果が高い）
- 境界ケースは knowledges/ にメモ程度の記録で十分
- v2 spec として将来検討に回す
