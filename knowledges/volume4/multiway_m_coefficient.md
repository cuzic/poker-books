# マルチウェイ M 係数: 理論根拠と検証計画

## 定義

ActionScore (AS) = H + A − **M**  
DefenseScore (DS) = H − C − **M**

| 参加者数 | M 値 | 備考 |
|---|---|---|
| 2-way (HU) | 0 | 基準 |
| 3-way | 3 | 理論値 |
| 4-way+ | 6 | 理論値 (上限) |

**これらの係数は TexasSolver で検証不可能な理論値** であり、書籍内にその旨を明記する。

---

## 理論的根拠

### 1. ブラフのフォールドエクイティが縮小する

CBet ブラフの期待値 = フォールドエクイティ × ポット − (1 − フォールドエクイティ) × ベット

| 人数 | フォールドエクイティ (相手フォールド率 f=50% 想定) |
|---|---|
| HU (1 相手) | f = 50% |
| 3-way (2 相手) | f² = 25% (半減) |
| 4-way (3 相手) | f³ = 12.5% (4分の1) |

M=3 の解釈: ドライ板 (A=3) の 3-way は、AS から 3 引くことでセミ板 (A=2) 相当の
ブラフ価値に調整される。

### 2. コール要件が上昇する

3-way でのベットは「ナッツを持つプレイヤーがいる確率が高い」ため、
コールに必要な DS 閾値も実質的に上昇する。M を DS にも適用することでこれを表現している。

### 3. チェックレイズが強レンジに絞れる

HU では OOP のチェックレイズにセミブラフが含まれる。
3-way ではチェックレイズに対する IP のレンジが両者いるため、
OOP がブラフ CR を混ぜるインセンティブが下がる。
→ IP は 3-way の CR をより強く受け止める必要がある。

## 将来的な検証手段

### GTO Wizard Elite プラン (3-way Single Size solutions)

検証手順:
1. 同一ボード (K72r, KJ7r, T98r) を HU と 3-way で比較
2. 各ハンドクラスの CBet 頻度差・OOP フォールド率差を測定
3. 実測差が M=3 の仮定と整合するか確認

### 判断基準

- HU CBet% − 3-way CBet% ≈ 10〜15pp ならば M=3 は適切
- ズレが大きい場合は M=2 または M=4 に調整

### 検証優先度: 低

書籍の主テーマは HU (BTN vs BB)。3-way は補足説明として扱う。
将来の改訂版または巻5 (マルチウェイ編) で検証する。

## 書籍内での扱い方

> M 係数 (M=3: 3-way, M=6: 4-way+) はフォールドエクイティの縮小則 (f² ≈ f×50%) に
> 基づく近似値です。GTO ソルバーによる 3-way 実測検証は将来の課題であり、
> 実戦では「3-way では 1 ランク上のハンド要件」と覚えるのが実用的です。
