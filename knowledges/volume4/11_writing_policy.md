## 1. 検証環境の確定

### TexasSolver の採用

Rust 自作ソルバー (`poker-gto`) に IP/OOP ゲームツリー順序バグが発見され、
フロップ CBet 精度が平均誤差 21.6% と不十分だった。
代替として **TexasSolver** (OSS C++ CFR ソルバー) を採用。

```
バイナリ: /home/cuzic/TexasSolver/build/console_solver
パイプライン: scripts/texassolver_volume4_102.py
```

### 精度実績

| ターンシナリオ | CBet | Exploitability | 所要時間 |
|---|---|---|---|
| K72r + As (overcard) | 86.0% | 0.33% | 69秒 |
| K72r + Qs (blank/Q) | 78.3% | 測定中 | ~70秒 |

- Exploitability < 0.5% → 十分な収束と判断
- 270 シナリオ × 70 秒 ≈ 5.2 時間 (1 プロセス)

### フロップ精度テスト (参考)

TexasSolver フロップ完結ツリーは系統的バイアスあり:
- ドライ rainbow 板: −12〜−24% 低め推定
- ペア板: +33% 高め推定

→ フロップ完結ツリーは相対順序は維持するが絶対値の信頼性が低い。
ターンシナリオ (4 枚ボード + ターン/リバーツリー) は完全ゲームツリーで正確。

## 4. 巻4 の中核公式 (仮定義)

### ターン CBet 判断フロー (BDM_turn)

```
Turn_CBet_Score =
  + FloppAdvantage (フロップ CBet 頻度: 高→+30, 中→0, 低→-30)
  + TurnCard (overcard→+20, blank→0, pair→-30, flush→+5, connector→-10)
  + EquityBoost (Aオーバー→+15, Kオーバー→+10, その他→0)
```

- Score ≥ 40: ダブルバレル推奨
- 20 ≤ Score < 40: ミックス (頻度 50%)
- Score < 20: チェックバック推奨

**注**: 係数は #102 データ取得後に R² 最大化で調整。

### リバー価値/ブラフ配分 (Alpha Formula)

Alpha = 1/(1+PotOdds) を使用した既存フレームワークを拡張。

## 5. TexasSolver データ活用方針

### 書籍での表記

- 「GTO ソルバー実測」と表記 (ソルバー実装名は言及しない)
- 絶対値は参考値として提示、読者が体感できる幅 (±10%) を許容
- 傾向・方向性を強調 (「overcard は blank より 20-25% 高い」)

### レンジの前提

- TexasSolver 実行時レンジ: BTN open 100BB / BB defend vs BTN
- フロップ絞り込みなし (事前プリフロップ範囲を使用)
- → 実戦では絞り込みにより若干異なるが、方向性は正確

### 巻2 との整合性

- 巻2 の BoardScore が高いフロップ (≥ 5) は flop CBet 頻度も高い
- ターン CBet は「フロップ CBet 頻度 × ターンカード調整」の構造
- 巻2 の読者が自然にステップアップできるフレームワークにする
