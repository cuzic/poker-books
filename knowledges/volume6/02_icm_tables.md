# ICM equity 早見表（実測テーブル）

`scripts/icm_calc.py` で計算した、典型的なトーナメント状況の ICM equity（ICM%）。
本書 付録B「ICM equity早見表」の元データ。

---

## ヘッズアップ（HU、50/30 payout）

賞金合計 $80。チップが 50/50 のとき各プレイヤーの $EV は等しく、賞金の中央値（$40）になる。

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 5000 | 50.00% | 40.00 | 50.00% |
| P2 | 5000 | 50.00% | 40.00 | 50.00% |

スタック非対称な HU は以下。

```bash
python scripts/icm_calc.py --stacks "7000,3000" --payouts "50,30"
```

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 7000 | 70.00% | 44.00 | 55.00% |
| P2 | 3000 | 30.00% | 36.00 | 45.00% |

**観察**: 70% chip リードでも $EV は 55% しか取れない。HU では ICM 圧縮が一番弱い（賞金構造が単純だから）が、それでも 15 ポイントぶん圧縮される。

## 3-handed FT（50/30/20 payout）

### A. 等スタック

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 3333 | 33.33% | 33.33 | 33.33% |
| P2 | 3333 | 33.33% | 33.33 | 33.33% |
| P3 | 3334 | 33.34% | 33.34 | 33.34% |

### B. リーダー vs 2 ショート（50% / 25% / 25%）

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 5000 | 50.00% | 38.33 | 38.33% |
| P2 | 2500 | 25.00% | 30.83 | 30.83% |
| P3 | 2500 | 25.00% | 30.83 | 30.83% |

**観察**: 50% chip リードでも $EV は 38% しか得られない。**ショート 2 人が合計で 61.7% の $EV を持つ**。リーダーがショートに対してもらえる価値が小さいのに対し、失う価値は大きい。これが「リーダーが守備的になる」根拠。

### C. リーダー vs 中スタック vs ショート（60% / 25% / 15%）

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 6000 | 60.00% | 41.06 | 41.06% |
| P2 | 2500 | 25.00% | 31.69 | 31.69% |
| P3 | 1500 | 15.00% | 27.25 | 27.25% |

**観察**: 15% chip しか持たないショート (P3) でも、賞金の 27% を確保している。ICM はショートを保護する。

## 9-max STT（Top 3 払い、4-handed バブル）

賞金 50/30/20、4 人残りで 1 人脱落するとバブルブレイク。

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 4500 | 45.00% | 35.64 | 35.64% |
| P2 | 3000 | 30.00% | 30.02 | 30.02% |
| P3 | 1500 | 15.00% | 20.13 | 20.13% |
| P4 | 1000 | 10.00% | 14.21 | 14.21% |

**観察**:

- リーダー (P1) は 45% chip でも 35.6% ICM equity（ICM ペナルティ約 9.4 ポイント）
- ショート (P4) は 10% chip でも 14.2% ICM equity（ICM ボーナス約 4.2 ポイント）
- バブル直前は **チップを失う $EV ペナルティが、チップを得る $EV ボーナスより大きい**
- 結論: バブルでは **コール頻度を下げる** のが最適

## MTT バブル（Top 15% 払い、10-handed 例）

賞金分布 40/25/15/10/6/4 + 0×4、典型的な大型 MTT のバブル直前。

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 3000 | 24.79% | 20.34 | 20.34% |
| P2 | 2500 | 20.66% | 18.33 | 18.33% |
| P3 | 2000 | 16.53% | 15.99 | 15.99% |
| P4 | 1500 | 12.40% | 13.20 | 13.20% |
| P5 | 1000 | 8.26% | 9.77 | 9.77% |
| P6 | 800 | 6.61% | 8.15 | 8.15% |
| P7 | 600 | 4.96% | 6.37 | 6.37% |
| P8 | 400 | 3.31% | 4.41 | 4.41% |
| P9 | 200 | 1.65% | 2.28 | 2.28% |
| P10 | 100 | 0.83% | 1.16 | 1.16% |

**観察**:

- ショート (P10) は 0.83% chip → 1.16% ICM equity（チップ価値の 1.4 倍）
- リーダー (P1) は 24.79% chip → 20.34% ICM equity（チップ価値の 0.82 倍）
- バブル直前のショートスタックは「ICM ボーナス係数 = 1.4倍」を獲得 = チップを温存することの $価値が大きい

## 9-max FT 等スタック（標準 9-place 払い）

賞金分布 30/20/13/10/8/6/5/4/4 = 100% を 9 人で分割。

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1〜P9 | 10000 | 11.11% | 11.11 | 11.11% |

等スタックなので全員同じ。これがバブルではなく FT 開始時点の「公平な配分」。

## ファイナルテーブル進行（典型的 9-max FT）

FT が 9 → 6 → 3 → 1 と進むにつれて、賞金構造を残された人数で割り直して計算する。

例: スタートが 100k chip 等分（9 人）、賞金プールが $1000 と仮定。標準 PokerStars 9-max FT 賞金:
- 1位: $300, 2位: $200, 3位: $130, 4位: $100, 5位: $80, 6位: $60, 7位: $50, 8位: $40, 9位: $40

```bash
python scripts/icm_calc.py \
  --stacks "100000,100000,100000,100000,100000,100000,100000,100000,100000" \
  --payouts "300,200,130,100,80,60,50,40,40"
```

各プレイヤーの $EV = $111.11（公平に分割される）。

### FT 5 人残り（リーダー独走、1 大スタック + 4 中スタック）

スタック: 400k / 200k / 150k / 150k / 100k = 1M chip total

```bash
python scripts/icm_calc.py \
  --stacks "400000,200000,150000,150000,100000" \
  --payouts "300,200,130,100,80"
```

| Player | Stack | Chip% | $EV |
| ---: | ---: | ---: | ---: |
| P1 | 400000 | 40.0% | $237.04 |
| P2 | 200000 | 20.0% | $172.96 |
| P3 | 150000 | 15.0% | $147.78 |
| P4 | 150000 | 15.0% | $147.78 |
| P5 | 100000 | 10.0% | $104.45 |

合計 = $810（$610 賞金合計 + 残った $0 = 賞金プール）。チップシェア比 40% が $EV シェア 29% に圧縮される。

## ICM 早見表（チップシェア → ICM% 換算、独立サンプル）

実用上、自分の chip% を見てICM% を即座に推定したい。代表値を以下に。

### バブル直前（n=4、Top 3 払い、50/30/20、他プレイヤー均等分配）

実測値（`scripts/icm_calc.py` 出力）。

| Chip% | ICM% | ボーナス/ペナルティ |
| ---: | ---: | ---: |
| 5% | 7.0% | +40% (ボーナス) |
| 10% | 12.7% | +27% (ボーナス) |
| 20% | 21.5% | +8% (ボーナス) |
| 30% | 28.0% | -7% (ペナルティ) |
| 50% | 37.0% | -26% (ペナルティ) |
| 60% | 40.3% | -33% (ペナルティ) |

### 中盤（n=6、Top 3 払い、50/30/20、他プレイヤー均等分配）

| Chip% | ICM% | ボーナス/ペナルティ |
| ---: | ---: | ---: |
| 5% | 5.7% | +14% |
| 10% | 10.8% | +8% |
| 20% | 19.3% | -3% |
| 33% | 27.9% | -15% |
| 50% | 36.1% | -28% |

### FT（n=9、Top 9 全員 in the money、9-place payout 30/20/13/10/8/6/5/4/4）

賞金構造が傾斜的なため、リーダーは大きな ICM 圧縮を受ける。

| Chip% | ICM% | ボーナス/ペナルティ |
| ---: | ---: | ---: |
| 5% | 7.7% | +53% |
| 10% | 10.5% | +5% |
| 20% | 14.9% | -25% |
| 33% | 19.1% | -42% |
| 50% | 23.0% | -54% |

**観察**: FT 9-place payout でも、リーダー (Chip 50%) はICM equity 23% しか取れない。賞金構造が下位にも配分されているため、トップを取る価値は思ったほど大きくない。これが「FT ではバブルほどでないが、リーダーは依然として守備的に振る舞うべき」という指針の根拠。

## 計算の再現方法

すべての値は `scripts/icm_calc.py` で再計算可能:

```bash
# 任意のシナリオ
python scripts/icm_calc.py --stacks "4500,3000,1500,1000" --payouts "50,30,20"

# 全プリセット
python scripts/icm_calc.py --all-presets

# JSON 出力
python scripts/icm_calc.py --preset bubble-9max-stt --json
```

本書では各章で「想定状況のスタック分布 → ICM 値」を都度提示します。読者は同じスクリプトで自分の状況を計算できます。
