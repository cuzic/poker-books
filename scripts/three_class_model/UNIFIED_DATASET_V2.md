## How to Generate

```bash
python3 research/v4-postflop/build_unified_rows.py
# Output: scripts/three_class_model/dataset_unified_v2.csv
```

The script reads all probe phase CSVs from `research/v4-postflop/`, deduplicates
identical rows that appear in both `priority` and `phase2`, and concatenates everything
into a single CSV. Missing input files are skipped gracefully.

## Schema (39 columns)

| Column | Description |
|--------|-------------|
| `source_phase` | Which phase produced this row (`priority`, `phase2`–`phase6`, `past_r1`) |
| `scenario_id` | Context identifier (e.g. `N_cash_3bp_flop`, `B_turn`, `P5_A_cash_3bp_turn`) |
| `board_label` | Board texture label (e.g. `dry_K72`, `dynamic_2tone_T97`) |
| `board_family` | Board family category (e.g. `dry_high`, `dynamic_2tone`) |
| `board_str` | Full board string with run-out cards (e.g. `Ks7d2c3c`) |
| `card_a`, `card_b` | Hero hand cards |
| `mv_cat` | Made-value category (`set`, `two_pair`, `overpair`, etc.) |
| `dv_cat` | Draw-value category (`flush_draw`, `oesd`, `no_draw`, etc.) |
| `equity_bucket` | GTO equity bucket label (`best_hands`, `good_hands`, `medium_hands`, `weak_hands`, `trash_hands`) |
| `eq_percentile` | Hero equity percentile vs. full range (0–1) |
| `hand_eq` | Hero raw equity vs. opponent range |
| `fold_freq`, `call_freq`, `raise_freq` | GTO action frequencies |
| `ev_fold`, `ev_call`, `ev_raise` | EV of each action |
| `best_action` | Optimal GTO action (`FOLD`, `CALL`, `RAISE`) |
| `best_ev` | EV of optimal action |
| `ev_gap` | EV gap between best action and second-best |
| `gto_modal` | Modal GTO action (weighted by frequency) |
| `per_combo_bimodal` | Bimodal frequency (fraction of combos that split between actions) |
| `ip_bet_size` | In-position bet size label (e.g. `small_33`, `med_75p`, `overbet_185`) |
| `opp_bucket` | Opponent range bucket (`best_hands`, …, `trash_hands`) |
| `opp_eq_percentile` | Opponent equity percentile |
| `opp_eq` | Opponent raw equity |
| `hand_eq_vs_opp_nut` | Hero equity vs. opponent's nut portion |
| `opp_total_combos` | Opponent total combos in range |
| `opp_strong_pct`, `opp_weak_pct` | Fraction of opponent range that is strong/weak |
| `opp_polarization` | Opponent range polarization metric |
| `opp_nut_class` | Opponent nut hand class |
| `opp_nut_pct` | Fraction of opponent range that is nuts |
| `opp_nut_eq_median` | Median equity of opponent nuts |
| `opp_draw_pct` | Fraction of opponent range with draws |
| `formula_action` | Formula-predicted action (empty if not yet evaluated) |
| `formula_loss` | EV loss from formula prediction vs. GTO |
| `formula_correct` | Whether formula prediction matches GTO modal (`True`/`False`/empty) |

Three scenario_ids appear in both `priority` and `phase2` with identical rows:
- `N_mtt_3bp_flop` (7,056 rows)
- `N_mtt200_turn` (6,768 rows)
- `N_mtt200_river` (6,486 rows)

The script keeps `priority` versions and drops the `phase2` duplicates (20,310 rows removed).
Raw total before dedup was 313,629 rows.

## Usage Examples

```python
import pandas as pd

df = pd.read_csv("scripts/three_class_model/dataset_unified_v2.csv")

# Filter by scenario context
cash_3bp = df[df["scenario_id"].str.startswith("N_cash_3bp")]

# Filter by source phase
priority_only = df[df["source_phase"] == "priority"]

# Only rows with formula evaluation
evaluated = df[df["formula_action"] != ""]

# Accuracy per scenario
acc = df[df["formula_correct"] != ""].groupby("scenario_id")["formula_correct"].apply(
    lambda x: (x == "True").mean()
)

# Filter by street (board_str length)
flop_rows = df[df["board_str"].str.len() == 8]   # 3 cards = 8 chars (e.g. Ks7d2c)
turn_rows = df[df["board_str"].str.len() == 11]  # 4 cards
river_rows = df[df["board_str"].str.len() == 14] # 5 cards
```
