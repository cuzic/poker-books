# 第15章　チェックビハインドとブラフキャッチ基礎

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: IPがベット機会をパスして「チェックビハインド」を選ぶ判断を体系化し、OOPが相手のベットを受けて「ブラフキャッチ」する際の基礎的な選択基準を身につける。

---

## 15-1 チェック後の判断とは

ターンとリバーで「チェック」が絡む場面には、2つの異なる構造があります。一方は IP（インポジション）がベットを選ばずに手番を終える「チェックビハインド」、もう一方は OOP（アウトオブポジション）がチェックした後に IP がベットしてきて、OOP が「コールするかフォールドするか」を問われる「ブラフキャッチ」です。

この2つは起点が違います。チェックビハインドは IP 側の意思決定であり、ブラフキャッチは OOP 側の意思決定です。どちらも「チェック」というアクションが絡むという共通点はありますが、判断の軸がまったく異なります。

```
チェックが絡む2つの状況:

IP がチェックする → チェックビハインド
  → OOP もチェック → ショーダウン
  → OOP がベット  → IP がコール/フォールド/レイズを選択

OOP がチェックする → IP がベット
  → OOP がコール → ブラフキャッチ（コール）
  → OOP がフォールド → ポットを失う
  → OOP がレイズ  → チェックレイズ（本書では基礎のみ）
```

本章では「IP のチェックビハインド」と「OOP のブラフキャッチ（コール）」を扱います。チェックレイズ（CR）を使った高度なディフェンスについては、応用部分として巻� で扱います。

## 15-2 IP のチェックビハインド ─ 基礎判断

IP がリバーでチェックビハインドを選ぶとき、そのハンドは3つのクラスに分類できます。「なんとなくチェック」はどのクラスにも属さず、期待値を失う選択です。チェックを選ぶ前に「今のチェックは何のためか」を明確にしてください。

### クラス1: SDV 保護（ショーダウンバリュー保護）

ハンドの強さが「バリューベットの直下」にある中間ハンドです。コールされた場合に相手のコールレンジに対して勝率が 50% 前後に留まるハンドがこのクラスに入ります。

第12章で確認した原則を思い出してください。バリューベットの成立条件は「コールレンジに対して 50% 以上の確率で勝てること」です。この条件を満たさないハンドにベットを打つと、コールしてくる相手が強いハンドに偏り、勝率がさらに下がります。チェックビハインドならショーダウンに持ち込め、相手の弱いハンドにも届く分だけ期待値が上がります。

```
SDV保護の典型例:
  - トップペア弱キッカー（J以下のキッカー）
  - セカンドペア（ボードの2番目に高いランクと一致するペア）
  - ボードが連続しておりストレートを懸念する2ペア
```

### クラス2: トラップ（スロープレイ）

ナッツまたは準ナッツのハンドで、相手のブラフを誘うためにあえてチェックを選びます。相手がブラフ頻度の高いプレイヤー、あるいは OOP がベットしやすいボードテクスチャのとき、トラップが有効です。

ただしトラップにはバランス管理が必要です。強いハンドで全てチェックすると「IP がチェックしたら弱いハンド」と読まれます。強いハンドでもベットとチェックを混在させることが重要です。

```
トラップの典型例:
  - セット（相手がドロー外れのブラフを期待できる）
  - フラッシュ・ストレート完成（相手がドロー外れと読んで攻めてくる局面）
```

### クラス3: 攻撃の放棄

バリューにも、ブラフにも機能しないハンドです。ベットすれば相手のコールレンジに負け、フォールドに追い込める確率も低い。チェックビハインドでショーダウンに持ち込み、わずかに残るショーダウンバリューを確保します。

```
攻撃の放棄の典型例:
  - バストドロー（役を形成せず、ショーダウンバリューもほぼない）
  - 弱いペアでブラフが通る見込みもない局面
```

### 3クラスの整理

| クラス | ハンドの強さ | チェックの目的 |
|---|---|---|
| SDV 保護 | 薄いバリュー（コールレンジに対して勝率 50% 前後） | ベットで逆選択されるのを避ける |
| トラップ | ナッツ〜準ナッツ | 相手のブラフを誘って利益を最大化する |
| 攻撃の放棄 | 役なし〜弱いペア | バリューにもブラフにもなれない |

実戦でよく迷うのは「SDV 保護か薄いバリューベットか」の境界です。「コールされたとき相手のコールレンジに対して 50% を下回ると判断したらチェックビハインド」という基準で決めてください。

## 15-3 リバーチェックビハインド後の挙動

IP がリバーでチェックビハインドをした後、OOP も追いかけてチェックすれば両者はショーダウンへ進みます。OOP がベットしてきた場合は、IP はコール/フォールドの判断をし直す必要があります。

### IP がチェックビハインドした後に OOP がベットしてきた場合

IP がチェックビハインドを選んだということは、多くの場合「バリューとして大きく打ちにくいハンド」か「ナッツ級のトラップ」のどちらかです。OOP がベットしてきたとき、IP はその文脈を考慮して判断します。

```
IP チェックビハインド後に OOP がベットしてきた場合の判断軸:

SDV系ハンド（セカンドペア・弱いトップペア等）:
  → OOPのベットに対してコールするか否かを後手スコアで判断
  → 弱いトップペアなら、OOPのバリューレンジに負ける頻度が高い
  → フォールドが増える

トラップ系ハンド（セット・フラッシュ等）:
  → OOPのベットを歓迎してコール（または選択的にレイズ）
  → トラップの目的が達成された局面
```

### ショーダウンで勝つ可能性の確認

IP がリバーでチェックビハインドをし、OOP もチェックして両者ショーダウンになった場合、IP のチェックビハインドしたハンドが実際にポットを取るかどうかが重要です。

SDV 保護のチェックビハインドが正しく機能している状況では、OOP のショーダウンハンドには次のものが含まれます。

```
OOPがリバーでチェックするハンドの一例:
  - バストドロー（役が完成せず、ショーダウンバリューが薄い）
  - 弱いミドルペア（ベットするには薄い）
  - セカンドペア（IPのチェックを受けてショーダウンを試みる）
```

トップペア弱キッカーやミドルペアでのチェックビハインドは、これらのハンドに対してショーダウンで勝てる可能性を確保します。「ベットせずにショーダウンを目指す」というアクションが、実際にポットを取る手段として機能するわけです。

## 15-4 ブラフキャッチの基本

OOP がリバーで IP のベットを受けるとき、「コールか、フォールドか」の二択になります（基礎レベルでは CR は除外します）。この判断に使う道具が、第11章で学んだ後手スコア（リバー版）と、第9章で学んだ α 式です。

### 後手スコア（リバー版）で判断する

第11章で導入した式を確認します（HU 前提のため M = 0）。

```
後手スコア = HandScore + A − 3 − C（HU前提: M=0）

A（ボード値）: ドライ=3 / セミウェット=2 / ウェット=1
C（ベット負担）: 33%ポット=3 / 50%ポット=5 / 75%ポット=7
              100%ポット=9 / 150%ポット=11

後手スコア 0〜7 → コール（ブラフキャッチ域）
後手スコア ≥ 8  → CR 検討（本書基礎レベルでは多くの場合コールを選ぶ）
後手スコア < 0  → フォールド
```

リバー版の最重要点はドロー加点がゼロになることです。ターンでドロー加点込みの HandScore でコールしていたハンドが、リバーでドローを外すと HandScore が大幅に下落します。ターンの判断とリバーの判断は切り離して計算し直してください。

### α 式でブラフ率を確認する

第9章の α 式は、先手（ベット側）の設計式として導入しました。OOP 側では、この α 値を「相手のベットレンジに含まれるブラフ率がα以上あれば、コールはプラス EV」という基準として使います。

```
α = ベット額 ÷ (ポット + ベット額)

ベットサイズ別 α 値:
  33%ポット → α ≈ 0.25（相手のベットの25%以上がブラフならコール有利）
  50%ポット → α ≈ 0.33（相手のベットの33%以上がブラフならコール有利）
  75%ポット → α ≈ 0.43（相手のベットの43%以上がブラフならコール有利）
  100%ポット → α = 0.50（相手のベットの50%以上がブラフならコール有利）
```

後手スコアが 0 以上になるハンドをコールに振り分けつつ、全体として「自分がコールしているレンジの割合」が相手のMDF（= 1 − α）を満たしているかを確認します。

### 後手スコアとα式の組み合わせ方

2 つの道具を実戦でどう組み合わせるかを整理します。

```
Step 1: リバーの HandScore を計算する
  → ドロー加点 = 0 を確認
  → 役スコア（完成役の点数）とブロッカー加点のみで評価

Step 2: 後手スコアを計算する
  → 後手スコア = HandScore + A − 3 − C（M=0 でHU前提）
  → 0 以上 → コール候補
  → マイナス → フォールド候補

Step 3: α 式でレンジ全体を確認する
  → 相手のブラフ率が α を超えているか？
  → コール候補のハンドがMDF（1 − α）を満たすか？
  → 満たすならコール、大幅に満たせない状況ではフォールドを増やす
```

後手スコアは個別ハンドの判断に使い、α 式はレンジ全体のバランス確認に使います。この使い分けが実戦での「2 つの式の役割分担」です。

## 15-5 ブラフキャッチハンドの選び方（基礎）

同じ後手スコア域に複数のハンドがある場合、どのハンドをコール（ブラフキャッチ）に選ぶかが問題になります。

### HandScore の中間域が中心

ブラフキャッチャーとして機能するハンドは、おおよそ HandScore が 10〜25 の中間域です。この域のハンドは「相手のブラフには勝てるが、相手のバリューベットには負ける」という性質を持ちます。

```
HandScore の大まかな目安:
  HandScore 0〜9  : ハイカード〜弱いペア（ブラフキャッチには薄い）
  HandScore 10〜19: トップペア系・強いセカンドペア（ブラフキャッチの中心域）
  HandScore 20〜30: 2ペア・セット（バリューコールかつブラフキャッチ兼用）
  HandScore 30+   : ストレート・フラッシュ以上（バリューコール中心）
```

HandScore が 10〜19 のトップペア系ハンドが、多くの局面でブラフキャッチの主力になります。これらは相手のバストドロー（役なし）や弱いペアのブラフには勝て、相手の強い役（2ペア・セット等）のバリューには負けるという構造を持ちます。

### ブラフキャッチャーとしての機能確認

コール候補のハンドが実際にブラフキャッチャーとして機能するかを確認する3点チェックです。

```
□ 相手のブラフ候補は何か？
  → バストフラッシュドロー、バストストレートドロー等を特定する

□ 自分のハンドはその候補に実際に勝てるか？
  → 役なしのハイカードだけで「とりあえずコール」するのは避ける

□ 相手のブラフ率は α 値を超えているか？
  → 超えていれば合理的なコール。超えていなければフォールドが優位
```

HandScore が低い（5 以下）ハンドでの「ウィッシュコール（願望コール）」は、特にリバーで損失を生みやすいパターンです。自分のハンドが相手のブラフ候補に実際に勝てるかを確認してからコールしてください。

### ブロッカーの基本的な活用

同程度の HandScore を持つ複数のハンドからコール・フォールドを選ぶとき、相手の強いバリューコンボをブロックするカードを持つハンドを優先してコールに回します。

例として「トップペア相当の2つのハンド」があるとします。一方は相手のナッツコンボを構成するカードを持ち（ブロッカー有り）、もう一方はそのカードを持ちません（ブロッカーなし）。ブロッカーがある方が「相手がナッツを持っている確率が相対的に低い」ため、コールの期待値が高くなります。

ブロッカーの詳細な活用法（どのコンボを選ぶか、ナッツブロッカー vs. ブラフブロッカーの優先順位等）については、巻� 第5章で扱います。本章では「相手の強いバリューコンボを持つカードを保有する側がコール有利になりやすい」という方向性を把握してください。

## 15-6 実戦例

### 実戦例1: SDV 保護によるチェックビハインド

**状況**: 6-max、100BB、BTN（IP）vs BB（OOP）。BTN オープン、BB コール。

**ボード（5枚）**: A♠9♣2♦K♥2♣

フロップ A♠9♣2♦ で BTN が 33% CBet → BB コール。ターン K♥ で BTN が 50% CBet → BB コール。リバー 2♣。

**ボード検証**（5枚: A♠, 9♣, 2♦, K♥, 2♣）:
- 2が2枚（2♦, 2♣）→ ペアボード
- ストレート: A-K-9-2-2。5連続なし
- フラッシュ: ♣=9♣, 2♣=2枚のみ → フラッシュ不成立

**BTN のハンド**: A♥J♠

カード確認: A♥, J♠, A♠, 9♣, 2♦, K♥, 2♣（7枚）
- ランク: A×2（A♥+A♠）、K×1、J×1、9×1、2×2（2♦+2♣）
- best 5: A-A-K-J-9 → **ワンペア A's（Kキッカー、Jも残る）**
- ペアボードなのでボードの 2-2 が最良 5 枚に入る可能性を確認: A-A-K-J-9 の方が A-A-2-2-K より強い → best 5 = A-A-K-J-9

HandScore = 15 前後（TPTK 相当の A ペア、キッカーは J）。ただし A ペアのキッカーとして J は K には劣る。

```
バリューベット検討:
  BTN（AJ）でリバーベットするとき、BB のコールレンジには
  AK（2ペア: A's & K's）、A9（2ペア: A's & 9's）、K2（2ペア: K's & 2's）等が含まれる
  ※ ボードの 2-2 があるため、K を1枚持つだけで2ペア（K's & board pair 2-2）が成立する

  AJ のバリューベット（50%ポット）でコールしてくるレンジには上記の強ハンドが多い
  コールレンジに対する AJ の勝率は 50% を下回る可能性が高い

→ チェックビハインド（SDV保護）が合理的
```

**判断**: チェックビハインド。A ペアは十分なショーダウンバリューを持つが、リバーベットはコールレンジに対して逆選択されやすい。相手の弱いハンド（バストドロー等）に対してもショーダウンで勝てる可能性を確保する。

### 実戦例2: ブラフキャッチ（コール）

**状況**: 6-max、100BB、BTN（IP）vs BB（OOP）。

**ボード（5枚）**: K♦7♣2♠5♥9♦

フロップ K♦7♣2♠（ドライ、A=3）でBTN 33% CBet → BB コール。ターン 5♥（ブランク）で BB チェック → BTN 50% CBet → BB コール。リバー 9♦。BTN が 50% ポットベット。

**ボード検証**（5枚: K♦, 7♣, 2♠, 5♥, 9♦）:
- ストレート: K-9-7-5-2。5連続なし（7-8-9-T-J は 8, T, J 不在）
- フラッシュ: ♦=K♦, 9♦=2枚 → フラッシュ不成立
- ペアボード: 全ランク1枚ずつ → ペアボードなし

A 値（5枚ドライ）: ドライ = 3

**BB のハンド**: K♣J♦

カード確認: K♣, J♦, K♦, 7♣, 2♠, 5♥, 9♦（7枚）
- ランク: K×2（K♣+K♦）、J×1、9×1、7×1、5×1、2×1
- best 5: K-K-J-9-7 → **ワンペア K's（Jキッカー）**
- ドロー: J-T-9 の3連続があるが 5 枚連続不成立 → ドローなし

HandScore = 15（TPGK 相当、リバーなのでドロー加点=0）

```
後手スコア = 15 + 3 − 3 − 5 − 0 = 10 → コール域（0〜7は基本コール）

ただし後手スコアが10というのはCR検討域（≥8）に入る計算値だが、
K♣J♦（トップペア）でCRしても、BTNの3betには対応しきれない
→ 基礎レベルではコールを選択する
```

α 確認（50% ポット、α ≈ 0.33）: BTN のリバーベットレンジに 33% 以上のブラフが含まれているか？

BTN が 3 ストリート打ち続けるレンジにはバストドロー（OESDやFDが外れたもの）が一定数含まれます。ドライボードでのバストドローはハイカード〜弱いペア程度のショーダウンバリューしかなく、BB の K ペアに負けます。50% ベットの α 基準を超えるブラフが含まれると判断できれば、コールはプラス EV です。

**判断**: コール（ブラフキャッチ）。K♣ のブロッカー効果（BTN の KK コンボや KQ を削減する）もコールを支持します。

## ミニクイズ

### 問1

BTN（IP）vs BB、6-max、100BB、SRP。ボード（5枚）: A♦9♣2♠K♦2♥。BTN のハンド: A♠J♣。BB がリバーでチェックした後、BTN が 75% ポットでバリューベットをするかチェックビハインドするかを選んでください。

1. バリューベット 75%。A♠J♣は A ペア + J キッカー。バリューは十分ある。
2. チェックビハインド。ペアボード（2-2）上の A ペアはコールレンジに対して勝率が 50% を大きく下回る可能性がある。
3. 33% で薄いバリューベット。サイズを下げれば安全。

### 問2

BB（OOP）vs BTN。ボード（5枚）: K♦7♣2♠5♥9♦（ドライ、A=3）。BB ハンド: 8♦8♣（アンダーペア）。BTN が 50% ポットベット（C=5）。HandScore = 8（8's ペア、中程度のペア）。HU 前提（M=0）。後手スコアを計算して正しいアクションを選んでください。

1. 後手スコア = 3、コール（ブラフキャッチ）。
2. 後手スコア = 1、コール（ブラフキャッチ）。
3. 後手スコア = −1、フォールド。

### 問3

BB（OOP）vs BTN。フロップ J♠8♣5♠ でフラッシュドローをコールしてターンもコール。リバーでドロー外れ（役なし、ハイカード）。BTN が 75% ポットベット（C=7）。A=2（セミウェット）。HandScore = 0。コール・フォールドの正しい判断と理由はどれですか。

1. コール。ドロー外れでも相手のブラフを捕まえられる可能性がある。
2. フォールド。後手スコア = 0 + 2 − 3 − 7 = −8 で、明確なフォールド域に入る。
3. フォールド。ドロー外れは常にフォールドするルールがある。

---

### 解答

- **問1**: 2（ボード A♦, 9♣, 2♠, K♦, 2♥ はペアボード（2-2）。BTN（A♠J♣）の役: A×2（A♠+A♦）、K、J、9、2×2 → best 5 = A-A-K-J-9 = A ペア。BB のコールレンジには KK 以下の2ペア（A2、K2、92 等）、AK の 2ペアが含まれる。ペアボードではコールハンドが強くなりやすい。A♠J♣の勝率は 50% を下回りやすいため、チェックビハインドによる SDV 保護が合理的。選択肢3の「33% なら安全」は、サイズを下げてもコールレンジが強い場合は変わらない）

- **問2**: 1（後手スコア = HandScore + A − 3 − C − M = 8 + 3 − 3 − 5 − 0 = **3** → コール域（0〜7）。8♦8♣はボード上アンダーペア（K, 7 より低い）だが、コール域に入る。BTN のブラフ（バストドロー等）に対してはペアが勝てるため、ブラフキャッチャーとして機能する。ただし BTN の K ペアや2ペアには負ける点を承知でコールする）

- **問3**: 2（後手スコア = 0 + 2 − 3 − 7 − 0 = −8 → 明確なフォールド域。選択肢3の「ドロー外れは常にフォールド」というルールは誤り。ドロー外れでも別の役（トップペア等）が残れば HandScore がプラスになり、コールが成立することがある。本問はドロー外れ かつ 役なし のためフォールドが正解だが、理由は「常にフォールドのルール」ではなく「後手スコアがマイナスになるから」が正確な説明）

> **本章まとめ**
>
> - IP のチェックビハインドには「SDV 保護」「トラップ」「攻撃の放棄」の3クラスがある。「なんとなくチェック」はどのクラスにも属さず期待値を失う。
> - SDV 保護の基準は「コールレンジに対して勝率 50% を下回るか」。下回るなら、ベットより チェックビハインドの方が期待値が高い。
> - ブラフキャッチの判断軸は後手スコア（リバー版）。スコア 0 以上がコール域、マイナスがフォールド域。ドロー加点がゼロになる点が最大の注意事項。
> - α 式はブラフキャッチのレンジ全体バランス確認に使う。相手のブラフ率が α を超えていればコールはプラス EV。
> - ブラフキャッチの主力は HandScore が 10〜25 の中間域ハンド（トップペア系・強いセカンドペア・2ペア等）。
> - ブロッカー（相手の強いバリューコンボを削るカード）を持つ方がブラフキャッチとしての期待値が上がる。詳細は巻� 第5章で扱う。

**【GTOとのズレ】**

チェックビハインドについてのよくあるズレは「強いハンドを全てベットする」ことです。GTO 的には、ナッツ〜準ナッツのハンドの一定割合をチェックビハインド（トラップ）に回してレンジのバランスを保ちます。強いハンドを全てベットしてしまうと、IP のチェックビハインドが一方的に「弱いハンド」として読まれます。そうなると OOP は「IP がチェックしたら積極的に攻める」という搾取戦略を取れます。実戦では完全な GTO 頻度管理は難しいですが、「時にはナッツ級ハンドでチェックビハインドする」という意識を持つだけで搾取されにくくなります。

逆方向のズレとして「薄いバリューをチェックビハインドしすぎる」問題もあります。セカンドペアや弱い2ペアを全てチェックバックすると、IP のベットレンジが強ハンドに偏ります。相手が「IP のベット = 強い」と判断して全フォールドを増やし、ブラフが機能しなくなります。SDV 保護とバリューベットの境界を「50% の勝率」を基準に明確に引くことが大切です。

ブラフキャッチについては、実戦プレイヤーのリバーブラフ率が均衡値（α 値前後）より低い傾向があります。GTO 的には 50% ポットベットに対して相手は 33% 程度のブラフを混ぜますが、実戦の一般プレイヤーはこれより低いことが多いです。「相手がどの程度ブラフしているか」というプロファイル情報を蓄積し、α 値との乖離を判断材料に加えることが実戦上の重要なアジャストになります。
