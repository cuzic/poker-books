# 第13章　OOPの応戦 ─ ターン・リバー基礎

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: OOP（アウトオブポジション）がターンとリバーでIPのベットを受けたとき、後手スコアを使って「コール・チェックレイズ・フォールド」を正確に選択できるようになる。さらに、先手でベットするドンクベットの基本的な使いどころを把握する。

---

## 13-1 OOP応戦の基本フレーム

OOP（アウトオブポジション）とは、相手の前にアクションしなければならないポジションです。BB（ビッグブラインド）がBTN（ボタン）と対戦するとき、BBはほぼ常にOOPに置かれます。

OOPの不利は「情報の非対称性」にあります。チェックした後にIPがベットしてくるか・チェックバックするかを見てからでないと、自分のアクションが決まりません。ターンとリバーでこの制約はさらに強まります。フロップよりポットが大きく、残りスタックが少ないため、誤った判断のコストが高くなります。

ターン・リバーを通じて、OOPの応戦は以下の4つの選択肢に整理できます。

```
OOP応戦の4選択肢:

1. コール（チェックコール）
   → IPのベットを受け入れ、次のストリートへ持ち込む
   → ブラフキャッチャーとして機能するか、ドローが残っている場面

2. チェックレイズ（CR）
   → IPのベットに対して大きく反撃する
   → バリューCR（強ハンドでポットを大きくする）と
     ブラフCR（フォールドエクイティを狙う）の2種類

3. フォールド
   → ハンドが弱く、コールのEVがマイナスになる場面

4. ドンクベット
   → IPのアクションを待たずに先手でベットする
   → 大半の場面では使わない例外戦略
```

これら4つの選択肢を使い分けるための道具が、すでに学習済みの後手スコアです。第10章（後手スコア・ターン版）と第11章（後手スコア・リバー版）で導入した式を、本章では実際の判断に適用します。

ターンとリバーで後手スコアの計算式は共通ですが、HandScore の評価方法に重要な違いがあります。ターンではドロー加点（FD +13、OESD +14、ガット +10 等の表）を含めて評価しますが、リバーではドロー加点がゼロになります。この違いは実戦判断で非常に大きく効いてきます。

## 13-2 ターン OOP応戦 ─ コール基準

IPのターンバレルを受けたOOPがまず判断するのは「コールか、それ以外か」です。その軸となるのが後手スコア（ターン版）です。

### 後手スコアの確認（ターン版）

第10章で導入した式を確認します。HU（BTN vs BB）前提のため M=0 です。

```
後手スコア = HandScore + A − 3 − C（HU前提、M=0）

A（ボード値・ターン4枚で評価）: ドライ=3 / セミウェット=2 / ウェット=1
C（ベット負担）: 33%ベット=3 / 50%ベット=4 / 75%ベット=6

判定:
  後手スコア ≥ 8 → CR検討
  後手スコア 0〜7 → コール
  後手スコア < 0 → フォールド
```

ターン版の後手スコアを適用するときの最重要注意点が2つあります。

**注意点1: A値はターン4枚で評価し直す**

フロップのA値をそのまま引き継いではいけません。たとえばフロップがドライ（A=3）でも、ターンカードにフラッシュ系やコネクター系が落ちればA値が2または1に更新されます。ターンのボード全体（4枚）を見てA値を決めてください。

**注意点2: HandScoreはターンカードで更新する**

ペアターンが落ちてハンドが2ペアに昇格した場合、HandScoreも昇格後の役で計算し直します。「フロップのHandScoreをそのまま使う」は典型的な誤りです。

### コールの実例

**状況**: BTN vs BB、6-max、100BB、SRP。フロップ K♦7♣2♠（ドライ）でBTNが33%CBet、BBがコール。ターン前ポット: 10BB。ターン: 5♥（ブランク）が落ち、BTNが50%ベット（5BB）。

BBのハンド: K♣J♣

- カード確認: K♣, J♣, K♦, 7♣, 2♠, 5♥（6枚）
- ランク: K×2, J×1, 7×1, 5×1, 2×1
- ストレート: J-7-5-2は離れており5連続不成立 → なし
- フラッシュ: ♣はK♣, J♣, 7♣の3枚 → フラッシュ不成立
- 役: トップペア（K's）、Jキッカー

HandScore = 15（TPGK相当、Jキッカーは十分なキッカー値）

```
後手スコア = 15 + 3 − 3 − 4 = 11 → コール
```

後手スコア10はCR閾値（≥8）を超えていますが、ここで注意が必要です。K♣J♣はトップペアGKですが、BTNのバリューレンジには KK・AK・77・22・55（ペアターンではないため55はセットではない）などの強ハンドが含まれます。これらにCRを打ち3betが返ってくると対応できません。

後手スコアが8〜10のTPGK相当ハンドは「CR域の計算上の数値」であっても、ハンド特性上コールが安全です。コールしてリバーへ持ち込み、ショーダウンバリューを活かします。

**判断**: コール。

### ドロー加点の効果

ターンでのコール判断では、ドロー加点が後手スコアを押し上げる効果が大きく出ます。

フロップでコールした局面で OESD やフラッシュドローを持つ場合、ドロー加点（**OESD なら +14**、FD なら +13）が HandScore に含まれます。これにより後手スコアが高くなり、コール判断が容易になります。

例として、ターン後手スコアが「役スコアだけなら −3」のハンドでも、OESD ドロー加点 +14 があれば「HandScore ≈ 14（役なし + ドロー）」となり、後手スコア = 14 + A − 3 − C が CR 検討域（≥8）に入る可能性もあります。

ドロー加点はリバーではゼロになります。ドロー加点込みでコールしたターンに対して、リバーで外れた場合は後手スコアが大幅に下落することを事前に認識してください。

### ベットサイズ別コール目安

| ベットサイズ | C値 | MDF | 実戦上の目安 |
|---|---|---|---|
| 33%ポット | 3 | 75% | スコア−2前後まで広くコール |
| 50%ポット | 4 | 67% | スコア0以上が基本コール域 |
| 75%ポット | 6 | 57% | スコア1以上でコール |
| 100%ポット | 9 | 50% | スコア3以上でないとコールが薄い |

33%ベットへのコールはMDF75%（C=3）を守る必要があるため、レンジ全体の75%でコール以上が必要です。後手スコアが0以上のハンドだけでは75%に届かない場合、スコアが−2程度のハンドも一部コールに含める「MDF調整」が必要になります。詳細は第11章で確認してください。

## 13-3 ターン OOP応戦 ─ チェックレイズの基本

後手スコアが8以上になった場合、CR（チェックレイズ）の検討に入ります。CRには「バリューCR」と「ブラフCR」の2種類があります。

### バリューCRの要件

バリューCRは自分のハンドが強く、ポットをさらに大きくすることで期待値を伸ばす場面のCRです。基礎レベルでは3つの条件を確認します。

**条件1: IPのベットレンジの大部分に勝てる強さがある**

セット・2ペア（ペアターン後のペアボードで成立した場合）・完成フラッシュ・完成ストレートが対象です。トップペアのみではCRの返しを受けたとき対応できません。

**条件2: IPが確実にベットしてくる局面である**

第12章で確認したバレルスコアが高い局面（スコア ≥ 7）では、IPがレンジ全体として攻撃してきます。このような場面でOOPはチェックしてからCRを待てます。逆に、バレルスコアが低い（IPがチェックバックしやすい）局面でのCR待ちは機会損失になります。

**条件3: IPが3betしてきたときに対応できる**

バリューCRを打ったあとIPが3bet（再レイズ）してくることがあります。セット・フラッシュ・ストレートなどのナッツ系はコールまたは4bet（オールイン）で対応できます。2ペアでのCRは、IPの3betに対してフォールドを準備しておきます。

### バリューCRの実例

**状況**: フロップ K♦7♣2♠（ドライ、A=3）、BTN 50%CBet → BBコール。ターン: 7♥（ペアターン）。ボードは K♦7♣2♠7♥。BTN 75%ベット（C=6）。

BBのハンド: K♣J♦

- カード確認: K♣, J♦, K♦, 7♣, 2♠, 7♥（6枚）
- ランク: K×2（K♣, K♦）、J×1、7×2（7♣, 7♥）、2×1
- best 5: K-K-7-7-J → **2ペア（K's & 7's、Jキッカー）**
- ターン前のTPTKが7♥ペアターンで2ペアに昇格

HandScore = 18（強い2ペア）

```
後手スコア = 18 + 3 − 3 − 6 = 12 → CR閾値（≥8）を大きく上回る
```

**判断**: バリューCR（2.5x標準）。IPの3betには2ペアのためフォールドを検討。

### ブラフCR（BCR）の要件

BCRはショーダウンバリューがほぼなく、IPをフォールドさせることを目的とするCRです。基礎レベルでは次の3点を確認します。

1. **フォールドエクイティがある**: IPのバレルレンジにブラフが多く含まれる局面
2. **ストーリー整合がある**: OOPがCRするストーリーがレンジとして成立するか
3. **ブロッカーがある（あると有利）**: IPのバリューレンジをブロックするカードを持つ

BCRは「何もないからレイズしてみる」という感覚では成立しません。3要件がどれか1つでも欠ける場合は、チェックフォールドの方が損失が少ないケースが多いです。

### CRサイズの目安

```
ターンCRのサイズ標準:

  2.5x: バリューCR / BCR の標準。IPにコールしてもらいやすいサイズ
  3x: セット・フラッシュ等のナッツ系。SPRを下げてリバーで圧力をかける
  4x以上: SPRが低く、一撃でコミットラインに持ち込める場面
```

標準ポット（SRP）のターン時点はSPR≈9前後と高く、CR後もリバーが残ります。この場合は2.5x〜3xが中心です。

## 13-4 ターン OOP応戦 ─ ドンクベット

通常のOOP応戦フローでは、OOPはチェックしてIPのアクションを見てから判断します。しかし例外として、OOPが先手でベットする「ドンクベット」が有効な局面が存在します。

### ドンクベットの位置づけ

GTO的に、OOPのターンリード（ドンクベット）頻度は全体の約17%にとどまります。約83%の局面ではOOPはチェックが正解です。「ドンクは常にミス」ではありませんが、「大半のターンではチェック」が基本です。

### ドンクベットが有効な条件

ターンドンクが有効なのは、「OOPのレンジが相対的に強化される（Uncapped化する）ターンカード」の場面です。

**条件1: コネクターターン（OOPのストレートが完成しやすい）**

BBがコールするレンジはコネクテッドなハンドを多く含みます。ターンカードがOOPのストレートを完成させやすいカードでは、OOPのレンジが強化されます。

**条件2: OOPに有利なペアターン**

フロップでBBが7xをコールしていた局面で7ターンが落ちた場合、OOPが相対的に7xを多く持つ状況が生まれます。このケースでは限定的にドンクが有効です。

**条件3: フラッシュコンプリーティングターン（OOPがFDをコールしていた）**

フロップでBBがフラッシュドローをコールしていた場合、フラッシュ完成ターンはOOPのレンジを爆発的に強化します。

### ドンクベットのサイズと注意点

ドンクベットのサイズは33〜50%ポットが標準です。IPがレイズしてきたときの対応リスクを管理するため、大きすぎるサイズは避けます。

重要なのは「このターンカードでドンクするレンジ全体」を意識することです。特定のハンド1コンボだけでドンクするのではなく、OOPのレンジとして成立する複数のコンボとバランスを取ります。

## 13-5 リバー OOP応戦 ─ ブラフキャッチ基準

リバーに到達したOOPが最初に行うべきことは「ハンドの役を確認すること」です。ドロー加点がゼロになるため、ターンとリバーでHandScoreが大きく変わります。

### 後手スコアの確認（リバー版）

第11章で確認したリバー版後手スコアを整理します。

```
後手スコア = HandScore + A − 3 − C − M（HU前提: M=0）

リバー版の特徴:
  HandScore = 役スコア + ブロッカー加点（ドロー加点=0）
  C値の拡張:
    33%ポット → C=3
    50%ポット → C=4
    75%ポット → C=6
    100%ポット → C=9
    150%ポット → C=11

後手スコア ≥ 8 → CR検討
後手スコア 0〜7 → コール
後手スコア < 0 → フォールド
```

### α 式で相手のブラフ比率を確認する

第9章で学んだα 式は、先手の設計式でした。OOPの視点からは、このα値を「相手のブラフ比率がα以上あるかどうか」の確認に使います。

```
α = ベット額 ÷ (ポット + ベット額)

α以上のブラフ比率が相手のレンジにあれば、コールはEV+になる

ベットサイズ別α値:
  33%ポット → α ≈ 0.25（相手のベット25%以上がブラフならコール有利）
  50%ポット → α ≈ 0.33（相手のベット33%以上がブラフならコール有利）
  75%ポット → α ≈ 0.43（相手のベット43%以上がブラフならコール有利）
  100%ポット → α = 0.50（相手のベット50%以上がブラフならコール有利）
```

IPがGTOに近い均衡的なベットレンジを組んでいれば、OOPはほぼインディファレンス（コールとフォールドのEVが拮抗）の状態になります。後手スコアで個別ハンドを振り分けつつ、α 式で全体感を確認するのが実戦での使い方です。

### ブラフキャッチャーとしての機能確認

後手スコアが0〜7のコール域にあっても、そのハンドが「ブラフキャッチャーとして機能するか」を確認します。

ブラフキャッチャーとは「IPのブラフには勝てるが、IPのバリューベットには負けるハンド」です。機能確認の3点を押さえてください。

```
ブラフキャッチャー機能確認:

□ このボードで相手のブラフ候補は何か？
  → バストFD（外れたフラッシュドロー）、バストストレートドロー等
□ 自分のハンドはその候補に勝てるか？
  → 役なしのハイカードだけで「一応コール」するのは避ける
□ 相手のブラフ率はα値を超えているか？
  → 超えていれば合理的なコール
```

ハイカードのみで「とりあえずコール」するウィッシュコールは、特にリバーで損失を生みやすいパターンです。自分のハンドが相手のブラフ候補に実際に勝てるかを確認してからコールします。

### リバーブラフキャッチの実例

**状況**: BTN vs BB、SRP。ボード（5枚）: K♠7♦2♣5♥3♦。BTNがリバー50%ポットベット（C=4）。

ボード読み確認:

- フラッシュ: ♦=7♦, 3♦=2枚、他スートも2枚以下 → フラッシュ不成立
- ストレート: K-7-5-3-2。5連続なし（A-2-3-4-5はAが不在）→ ストレートなし
- ペアボード: 全ランク1枚ずつ → ペアボードなし

BBのハンド: K♣Q♣

- カード確認: K♣, Q♣, K♠, 7♦, 2♣, 5♥, 3♦（7枚）
- デッキ整合: K♣（ハンド）とK♠（ボード）は別カード。2♣（ボード）とQ♣（ハンド）は別カード。重複なし
- ランク: K×2（K♣+K♠）、Q×1、7×1、5×1、3×1、2×1
- best 5: K-K-Q-7-5 → **ワンペアK's、Qキッカー（TPGK）**

HandScore = 15（ドロー加点なし、役スコアのみ）

```
後手スコア = 15 + 3 − 3 − 4 − 0 = 11 → コール
```

このドライボードではIPのブラフ候補として「フロップでの浮遊ハンドが外れたもの」「Qx等の薄いバリュー化したブラフ」などが考えられます。50%ポットのα≈0.33を上回るブラフ率があれば、K♣Q♣でのコールはEV+です。K♣のバリューブロッカー効果（相手のKxコンボを一部削る）もコールを支持します。

**判断**: コール（ブラフキャッチ）。

## 13-6 リバー OOP応戦 ─ ドンクベット

リバーでもOOPが先手でベットする「ドンクベット」の場面があります。ターンドンクと同様に例外戦略ですが、リバーでは独自の位置づけがあります。

### リバードンクの戦術的位置づけ

リバーでIPがチェックバックしそうな局面、つまり「IPがリバーでベットしてくる確率が低い」と読める局面では、OOPがドンクすることで価値を回収できます。

具体的には次のような場面です。

**強ナッツでIPがチェックバックしそうな局面**

リバーカードがOOPのレンジを大きく強化した場合（例: OOPが多く保有するスーツのフラッシュ完成リバー）、IPはベットリスクを感じてチェックバックを選ぶことがあります。この局面でOOPのナッツ系ハンドがドンクすることで、IPがコール（または3bet）してポットが大きくなります。

**ブロッカーを活かしたブラフドンク**

リバーで自分のハンドが完全に外れ（役なし）でも、IPのナッツ系をブロックするブロッカーを持つ場合、OOPからのドンクブラフが機能することがあります。ただしこれは基礎レベルの域を超えるため、本章では「強いハンドからのドンク」を中心に把握してください。

### リバードンクのサイズ

リバードンクのサイズは50〜75%ポットが一般的です。強いバリューハンドでドンクする場合は、IPにコールさせられる程度の大きさを選びます。「ベットを受けてもらえるサイズ」を意識することが基本です。

## 13-7 リバー OOP応戦 ─ フォールド基準

後手スコアがマイナスになったハンドはフォールドです。リバーではドロー加点がゼロになるため、ターンと比べてフォールドが増えるのは自然なことです。

### フォールドの基本基準

```
後手スコア < 0 → フォールド

後手スコア = HandScore + A − 3 − C − M

リバーでのHandScore（ドロー加点ゼロ）が低く、
C値が高い（大きなベットサイズ）と後手スコアはマイナスになりやすい
```

特に「フロップ・ターンでドロー加点込みのHandScoreでコールしていたハンドがドローを外した場合」は、リバーで後手スコアが大幅に低下します。

フラッシュドロー（加点約13点）が外れた場合: ターン版HandScore ≈ 15 → リバー版HandScore ≈ 2（役なし、キッカーのみ）

こうしたケースではリバーの後手スコアが明確にマイナスになりやすく、フォールドが合理的です。

### ベットサイズ別のフォールド目安

| ベットサイズ | C値 | フォールドになるHandScore（A=3、HU）の目安 |
|---|---|---|
| 33%（C=3） | 3 | HandScore ≤ 3 でフォールド候補（スコア<0） |
| 50%（C=4） | 4 | HandScore ≤ 4 でフォールド候補 |
| 75%（C=6） | 6 | HandScore ≤ 6 でフォールド候補 |
| 100%（C=9） | 9 | HandScore ≤ 9 でフォールド候補 |

A値がドライ（A=3）の場合、後手スコア = HandScore + 3 − 3 − C = HandScore − C になります。C値がHandScoreを上回った瞬間にフォールド域に入ります。

### フォールドの実例

**状況**: BTN vs BB、SRP。ボード（5枚）: K♠7♦2♣5♥3♦（ドライ、A=3）。BTNがリバー75%ポットベット（C=6）。

BBのハンド: J♣T♣（ドロー外れ、役なし）

- カード確認: J♣, T♣, K♠, 7♦, 2♣, 5♥, 3♦（7枚）
- 2♣（ボード）とJ♣, T♣（ハンド）は別カード。重複なし
- ランク: J, T, K, 7, 5, 3, 2 → 全て異なる、ペアなし
- best 5: K-J-T-7-5 → **ハイカード**

HandScore = 0（役なし、ドロー加点なし）

```
後手スコア = 0 + 3 − 3 − 6 − 0 = −6 → フォールド確定
```

J♣T♣が何らかのドローを持っていた場合も、ドライボードのリバーではほぼ改善の余地がありません。相手の75%ベットに対してハイカードでコールしても、相手のバリューレンジ全体に負けます。

**判断**: フォールド。

## ミニクイズ

### 問1

BTN vs BB、SRP（6-max、100BB）。フロップ A♣9♣2♠（セミウェット、A=2）、BTNが33%CBet → BBコール。ターン K♦（OC）が落ち、ボードはA♣9♣2♠K♦になった。A値を再評価すると、ランダウンは減りK落ちでセミウェット維持（A=2）とする。BTNが50%ポットベット（C=4）。

BBのハンド: K♠Q♠（ターン後: セカンドペア）。HandScore = 12（セカンドペア相当）。HU前提（M=0）。

後手スコアはいくつか。正しい判断はどれですか。

1. 後手スコア = 7、コール
2. 後手スコア = 5、コール
3. 後手スコア = −2、フォールド

### 問2

BTN vs BB、SRP。ターン後手スコアが−5のハンドに対し、BTNが50%ポットベット（C=4）。BBの正しい判断はどれですか。

1. 後手スコアが0〜7の「コール域」に近いのでコール
2. 後手スコア < 0 なので、フォールド
3. 後手スコアに関係なく、ポット中程度なのでコール

### 問3

BTN vs BB、リバー。BTNが50%ポットベット。このベットに対するα（コール損益分岐ブラフ率）とMDF（= 1 − α）を正しく示した選択肢はどれですか。

1. α ≈ 0.33、MDF = 0.67（67%）
2. α ≈ 0.43、MDF = 0.57（57%）
3. α = 0.50、MDF = 0.50（50%）

---

### 解答

- **問1**: 1（後手スコア = HandScore + A − 3 − C − M = 12 + 2 − 3 − 4 − 0 = **7** → コール域。A値はターン後の4枚（A♣9♣2♠K♦）を評価してA=2（セミウェット）とし、C=4（50%ベット）を代入する。HU前提のためM=0）

- **問2**: 2（後手スコア < 0 → フォールドが基本判断。後手スコアは「コールが損益分岐するかどうか」を数値化した式であり、マイナスはコールのEVがフォールドより低いことを意味する。スコアが−5は明確なフォールド域で、コールを検討する余地はない）

- **問3**: 1（α = ベット額 ÷ (ポット + ベット額) = 0.5P ÷ (P + 0.5P) = 0.5 ÷ 1.5 ≈ 0.33。MDF = 1 − 0.33 = 0.67（67%）。50%ポットベットに対して、OOPはレンジ全体の67%以上でコール以上が必要。相手のブラフ率がα（33%）以上あればコールはEV+）

> **本章まとめ**
>
> - OOP応戦の基本軸は後手スコア（≥8でCR検討、0〜7でコール、<0でフォールド）。ターン版とリバー版で共通の式だが、HandScoreの評価方法が異なる
> - ターン版HandScoreはドロー加点を含む。ドロー加点がコール判断を支える場面が多いため、アウツを正確に把握してから後手スコアを計算する
> - リバー版HandScoreはドロー加点ゼロ。外れたドローは役スコアのみに落下するため、ターンでコールしていたハンドがリバーでフォールド域に入ることが多い
> - α 式はOOPの視点では「相手のブラフ率がα以上あればコールはEV+」という基準として使う。ベットサイズが大きいほどαが高くなり、コールに必要なブラフ率が上がる
> - ドンクベットはターン・リバーとも約17%の例外戦略。OOPのレンジが強化される特定の局面（コネクターターン・フラッシュコンプリーティングターン等）でのみ有効
> - バリューCRの核心は「IPの3betに対応できる強さがあるか」。後手スコアがCR域でも、IPの3betにフォールドせざるを得ないTPTK程度のハンドはコールが安全

---

**【GTOとのズレ】**

実戦でOOPが最も犯しやすいミスは、「後手スコアがCR域に入ったトップペアで大きなCRを打つ」ことです。後手スコアが8〜11程度のTPGK相当ハンドは、式の上ではCR域に入ります。しかしIPが3betを返してくると、トップペアでは対応しきれません。GTO的にも「トップペアでのターンCRは非常にレア」であり、実戦で最も多く搾取されるパターンの一つです。後手スコアがCR域に入っても「IPの3betに耐えられるか」を確認する習慣をつけてください。

逆方向のズレも多く見られます。小サイズ（33%ポット）のベットに対して、「どうせ負けそうだから」とハイカードを全フォールドするパターンです。33%ポットのMDFは75%であり、レンジの75%を守らないとIPのブラフが自動的に利益になります。実戦では「小サイズだから守らなくていい」という感覚がありますが、実際は「小サイズほど広く守らなければならない」という逆説的な構造があります。スコアがマイナスのハンドを一部コールに混ぜるMDF調整を意識してください。

リバーのドロー外れについては、「外れたドローでもキッカーとして残ることがある」という認識が重要です。フラッシュドローが外れてもトップペアが残れば役スコアが10〜18程度あり、コールが成立することがあります。「ドロー外れ = 即フォールド」と機械的に判断せず、リバーのHandScoreを正確に再計算してから判断してください。
