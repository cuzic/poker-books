# 第10章　OOPの応戦 ─ コール / チェックレイズ / ドンクベット

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: ターンでIPがベットしてきたとき、BB（OOP）が取るべき3つの応戦選択肢（コール・チェックレイズ・ドンクベット）を後手スコアで体系化し、実戦で迷わず選べるようになる。

---

## 10-1 OOPが直面する3つの選択肢

フロップでコールしたBBは、ターンで「IPが再びベットしてきた」という局面に頻繁に直面します。このとき選べる応戦手段は3つです。

```
OOPターン応戦の3選択肢（IPベット後）:

1. チェックコール（コール）
   → ポットに参加して、リバーへ進む
   → ブラフキャッチ、ショーダウンバリューの消費

2. チェックレイズ（CR）
   → IPをフォールドさせるか、ポットをさらに大きくする
   → バリューCR と ブラフCR（BCR）の2種類

3. チェックフォールド（フォールド）
   → ハンドが弱すぎてコールの期待値がない場合
```

第9章で学んだIPの攻撃パターン（ダブルバレル・チェックバック・遅延CBet）に対し、BBはこの3選択肢で対応します。IPがどれだけ積極的にバレルしてきても、OOPがランダムに応戦していては搾取されます。

**本章の中心は「いつコールし、いつCRし、いつフォールドするか」を後手スコアで決める**ことです。第7章で導入した後手スコアがここで実戦道具として機能します。

なお、ドンクベット（IPのベット前にOOPが先手でベットする選択肢）は本章後半で「例外戦略」として独立して扱います。通常のOOP応戦フローとは発生条件が異なるからです。

## 10-2 後手スコアによる基本判断

第7章で学んだ後手スコアの式を確認します（HU前提のため M=0）。

```
後手スコア = HandScore + A − 3 − C（HU前提）

A（ボード値）: ドライ=3 / セミウェット=2 / ウェット=1
C（ベット負担）: 33%ベット=3 / 50%ベット=5 / 75%ベット=7

判定:
  後手スコア ≥ 8  → チェックレイズ（CR）検討
  後手スコア 0〜7 → コール
  後手スコア < 0  → フォールド
```

この式を使う前に2点を確認します。

**A値はターンの4枚で評価し直す**: フロップでドライ（A=3）だったボードも、ターンカードがコネクターやフラッシュカードなら A=2 または A=1 に下がります。フロップのA値をそのまま使わないよう注意してください（第7章参照）。

**HandScoreはターンカードで更新する**: ペアターンが落ちてハンドが2ペアに昇格した場合、HandScoreもその強さに合わせて計算し直します。「フロップ時点のHandScoreをそのまま使う」のは典型的な誤りです。

### ベットサイズ別の守りやすさ

C値の設計はベット比率から来ています（第7章で詳述）。ここで実戦上重要な点を再確認します。

33%ベット（C=3）の後手下限確率は75%です。これはコールレンジが非常に広いことを意味します。後手スコアが計算上「−1」や「−2」でも、レンジ全体の75%を守るために、スコアが微妙にマイナスのハンドをコールに含めることがあります。

75%ベット（C=7）の後手下限確率は57%です。守る義務がより小さく、フォールドの余裕が増えます。

この違いを踏まえると、実戦での運用指針はこうなります。

| ベットサイズ | C値 | 後手下限確率 | 運用上の目安 |
|---|---|---|---|
| 33% | 3 | 75% | スコア−2前後までコール検討 |
| 50% | 5 | 67% | スコア0以上が基本コール域 |
| 75% | 7 | 57% | スコア1以上をコール、0以下は慎重 |
| 100%（ポットベット） | 9 | 50% | スコア3以上でないとコールは薄い |

## 10-3 コールの判断基準 ─ ブラフキャッチャーとして機能するか

後手スコアが0〜7の範囲にあるハンドは「コール」です。しかし、単に「フォールドしない」というだけでは不十分で、「ブラフキャッチャーとして機能するかどうか」という観点が重要です。

### ブラフキャッチャーの定義

ブラフキャッチャーとは、IPのバリューベットには負けるが、IPのブラフには勝てるハンドです。コールの期待値はこの「ブラフに勝てる確率」から生まれます。

典型的なブラフキャッチャー:
- トップペア良キッカー（IPのブラフには勝てるが、IPのセット・2ペアには負ける）
- セカンドペア（IPの弱いバリューには負けるが、純ブラフには勝てる）
- 完成ドロー（フラッシュやストレートが完成したが、ナッツではない）

### ショーダウンバリューのコントロール

ターンでコールするときは「リバーで何をするか」を同時に考えます。リバーで追加のベットが来たとき、コールしてショーダウンできるだけのハンド強度があるかどうかです。

後手スコアが高い（5〜7）コールハンドは、リバーでも守れる可能性が高く、積極的にコールします。後手スコアが低い（0〜2）ハンドは「ターンのコールは通過するが、リバーはフォールド予定」という使い方になります。

## 10-4 チェックレイズの組み立て ─ バリューCRとブラフCR

後手スコアが8以上のハンドはCRを検討します。CRには「バリューCR」と「ブラフCR（BCR）」の2種類があり、それぞれ要件が異なります。

### バリューCRの3要件

バリューCRとは、自分のハンドが非常に強く、ポットをさらに大きくすることでEVを伸ばせる場面のCRです。

**要件1: ハンドがIPのベットレンジの大部分に勝てる**

セット・2ペア（ボードペアターン後）・完成フラッシュ・完成ストレートが典型です。トップペアのみではCRのリスクが高く、IPの3betに対応できません。

**要件2: IPがほぼ確実にベットしてくる場面**

バレルスコアが高い場面（第6章参照）では、IPが積極的にバレルしてきます。IPがベットしてくれることが確実なら、OOPはチェックしてからCRを待てます。逆に、IPがチェックバックしやすい場面でのCRは「空振り」になります。

**要件3: CRサイズでIPに続けてもらえる**

ナッツ近辺の強さがあっても、CRサイズが大きすぎるとIPがフォールドして利益が減ります。バリューCRは「IPにコールしてもらえるサイズ」を意識します。

### ブラフCR（BCR）の3要件

BCRとは、ショーダウンバリューがないハンドでIPをフォールドさせることを目的とするCRです。

**要件1: ブロッカーがある**

IPのバリューレンジをブロックしているカードを持っていることが理想です。たとえば、フラッシュドローが完成したターンで自分がそのスートを1枚持っていれば、IPのナッツフラッシュを部分的にブロックできます。

ただし、ブロッカーは必須条件ではなく「あると有利」という補強要素です。

**要件2: ストーリー整合性がある**

OOPがCRするストーリーがレンジとして成立するかどうかです。フロップでコールし、ターンのこのボード上でCRするハンド群がOOPのレンジに実際に含まれているかを考えます。「ストーリーとして成立するCR」はIPがフォールドしやすく、「ストーリーが成立しないCR」はIPに見透かされます。

**要件3: フォールドエクイティがある**

IPのバレルレンジにブラフが多い局面や、ターンカードがIPのレンジを弱化させた局面では、BCRのフォールドエクイティが高まります。逆に、IPが強いバリューで打ってきた可能性が高い局面では、BCRは成功しにくいです。

### バリューCRとBCRの使い分け

```
CR判断フロー:

Step 1: ハンドの強さ確認
  セット・完成ストレート・フラッシュ・2ペア（上位） → バリューCR候補
  ショーダウンバリューなし → BCR候補
  トップペア以下でショーダウンバリューあり → チェックコール基本

Step 2: IPの3betリスク確認
  ウェットボード + 自分がナッツでない → CR危険、コールが安全
  IPのバレルレンジが広い → CR後のフォールドエクイティあり

Step 3: サイズ選択（次節参照）
```

## 10-5 CRのサイズ選択 ─ 2x / 2.5x / 3xの使い分け

CRのサイズ選択はターンの残りスタックとIPに何をしてもらいたいかで決まります。

```
CRサイズの計算例:
  ターン前ポット: 20BB、IPベット: 10BB
  
  2.0x CR → BB からの追加: 20BB（トータルCR額: 20BB）
  2.5x CR → BB からの追加: 25BB（トータルCR額: 25BB）
  3.0x CR → BB からの追加: 30BB（トータルCR額: 30BB）
```

| サイズ | 特徴 | 使いどころ |
|---|---|---|
| 2x | コールされやすい小サイズ | トップペア相当でバリューを薄取り |
| 2.5x | バランス型 | バリューCR標準、BCR標準 |
| 3x | 圧力強め | セット・フラッシュ等の強ナッツでSPRを下げる |
| 4x以上 | オールイン狙い | SPRが低く一撃でコミットできる場面 |

### SPRとCRサイズの関係

ターン時点のSPR（スタック÷ポット比率）が低ければ、大きなCRで一気にコミットラインに持ち込めます。標準ポット（SRP）のターン前ポット約10BB、スタック約90BBならSPR≈9と高く、CR後もリバーが残ります。

この場合は2.5x〜3x CRが標準です。リバーでさらに一ベットを仕掛けられるサイズ設計にします。

3betポット（SPR≈4〜5）ではターンでCRするとオールイン射程に入りやすく、大きなCRまたはオールインが選択肢になります（巻5「3betポットのターン・リバー」参照）。

## 10-6 IPの3bet（CR後の再レイズ）への準備

BBがターンでCRを打った後、IPが3bet（再レイズ）してくることがあります。これへの備えを事前に整理しておくことが重要です。

### 3bet対応の基本方針

```
バリューCR後にIPが3betしてきた:
  ナッツ〜準ナッツ（セット、フラッシュ、ストレート）→ コールまたは4bet（オールイン）
  2ペア（ボードペアが含まれる）              → フォールド検討
  トップペアでのCR                           → フォールドが安全

BCR後にIPが3betしてきた:
  ほぼフォールド確定
  BCRはIPがフォールドすることを期待して打つ。IPの3betは強いバリューのシグナル
```

### なぜ2ペアは3betにフォールドするか

GTO的に、IPがターンCRに3betするハンドはほぼセット以上に絞られます。2ペアは大半のIPの3betレンジに負けます。「2ペアは強いから続けたい」という感情は、IP側の3bet頻度を正確に評価していないからです。

## 10-7 ドンクベット ─ OOPが先手を打てる例外条件

ここまでは「IPがベットしてきた後のOOP応戦」でした。しかし、OOPがIPのベットを待たずに先手でベットする「ドンクベット」も選択肢として存在します。

### ドンクベットの基本的な立ち位置

GTO的に、OOPのターンリード頻度は**全体の約17%**にとどまります（83%はチェックしてIPのアクションを待ちます）。ドンクベットは例外戦略であり、大半のターンではOOPはチェックが正解です。

「フロップでコールしたのだからターンでも受け身のままでいい」という発想ではなく、「特定の条件でのみドンクが有効」という考え方が正確です。

### ドンクベットが有効な条件 ─ OOPのUncapped化

第2章で学んだCapped/Uncapedの概念を思い出してください。フロップで3betしなかったOOP（BB）のレンジは一般的にCapped（上限がある）です。しかしターンカードによっては、OOPのレンジが相対的に強くなり、Uncapped化する局面があります。

**条件1: ペアターン（OOPがペアを多く持つ場合）**

フロップがドライなK72rで、ターンに7が落ちた場合（ボード: K-7-2-7）を考えます。BTN（IP）は高い頻度でプリフロップからKxを持つため、KがペアになるKターンはIPに有利です。しかし7ターンはBBのコールレンジに7xが含まれることで、OOPが相対的に強化される場合があります。

**条件2: ストレートコンプリーティングターン（OOPのストレートが多く完成する）**

フロップでBBがコールするレンジにはコネクテッドなハンドが多く含まれます。ターンカードが落ちてBBのストレートが完成しやすい局面では、OOPのUncapped化が起きます。

**条件3: OOPに有利なフラッシュコンプリーティングターン**

OOPがフロップでフラッシュドローをコールしていた場合、フラッシュ完成ターンはOOPのレンジを爆発的に強化します。

### ドンクベットのサイズ

ドンクベットのサイズは通常33〜50%ポットが標準です。理由は2つあります。

第一に、OOPがドンクする際は「広いレンジで打てる」局面ではなく、「特定の強いハンドで打つ」局面です。サイズを小さくしてブラフと合わせるより、中サイズでバランスを保つ方がシンプルです。

第二に、ドンクベットに対してIPが3betしてきた場合のリスク管理です。75%以上の大きなドンクは、IPの3betに対応しにくくなります。

### 多くのターンでドンクしない理由

大半のターンでOOPがドンクしないのは、レンジ優位がIPにあるからです。フロップをCBetしたIPはレンジが圧縮されており、ターンでもナッツアドバンテージを保持しています（第2章・第3章参照）。

OOPが何でもドンクしていると、IPにとって「ドンクに対してレイズするか、コールして後から攻めるか」という明確な搾取ラインが見えてしまいます。

## 10-8 実戦例 ─ 後手スコアで応戦を決める

以下の実戦例はすべて「BTN vs BB、SRP、100BB、6-maxキャッシュゲーム」を前提とします。

### 実戦例1: TPGK でのコール

**状況**: フロップ K♦7♣2♠ (ドライ、A=3)。BTN が 33%CBet → BB コール。
ターン: 5♥ (ブランク、TurnCard係数=2)。ターン後ボード K♦7♣2♠5♥ (ドライ維持、A=3)。
BTN が 50%ベット（C=5）。

**BBのハンド**: K♥Q♥
- 全カード: K♥, Q♥, K♦, 7♣, 2♠, 5♥
- ランク確認: K×2, Q×1, 7×1, 2×1, 5×1 → トップペア（Kペア）Qキッカー
- ストレート: 5-7 は離れていて連続なし → なし
- フラッシュ: ♥はK♥, Q♥, 5♥の3枚 → なし
- 役: トップペア良キッカー（TPGK）

HandScoreはTPGKとして約15と設定します。

```
後手スコア = 15 + 3 − 3 − 5 = 10 → コール域（0〜7）の上限近く
```

スコアは10で、数値上はCR閾値（≥8）を超えています。しかしここで重要な補正が必要です。

K♥Q♥はトップペアGKですが、BTNのバリューレンジにはKK・AK・77・22・55などが含まれます。これらに対してCRを打つと3betを受けてほぼフォールド確定です。後手スコアが8〜10の「CR閾値近辺」のTPGKはコールが安全です。

**判断**: コール。スコア10はCR閾値を超えているが、ハンドの特性上コールで進む。

---

### 実戦例2: 2ペアでのバリューCR（ペアターン）

**状況**: フロップ K♦7♣2♠ (ドライ、A=3)。BTN が 50%CBet → BB コール。
ターン: 7♥ (ペアターン)。ターン後ボード K♦7♣2♠7♥ (ペアボード、A=3維持)。
BTN が 75%ベット（C=7）。

**BBのハンド**: K♣J♦
- 全カード: K♣, J♦, K♦, 7♣, 2♠, 7♥
- ランク確認: K×2 (K♣, K♦), J×1, 7×2 (7♣, 7♥), 2×1
- best 5: K-K-7-7-J → 2ペア（K's & 7's、Jキッカー）
- K♣J♦ は K♦7♣2♠ フロップで TPTK（Jキッカー）、7♥ターンで **2ペア（K's & 7's）に昇格**
- 役: 2ペア

HandScoreを2ペアとして22程度と評価します（強めの2ペア）。

```
後手スコア = 22 + 3 − 3 − 7 = 15 → CR閾値（≥8）を大きく上回る
```

ただし、2ペアはCRの対象になり得ますが、IPの3betに対してはフォールド準備が必要です。バリューCRを打ち、IPがコールすればリバーで追加プレッシャーをかけます。

**判断**: バリューCR（2.5x標準）。IPの3betには2ペア相当のハンドなのでフォールド検討。

---

### 実戦例3: BCRの実行（ガットショット + 高フォールドエクイティ）

**状況**: フロップ K♦7♣2♠ (ドライ)。BTN が 33%CBet → BB コール。
ターン: J♥ (オーバーカード、TurnCard係数=3)。ターン後ボード K♦7♣2♠J♥。
BTN が 75%ベット（C=7）。

**BBのハンド**: T♥9♥
- 全カード: T♥, 9♥, K♦, 7♣, 2♠, J♥
- ストレート確認:
  - J-T-9-8-7: T, 9, J, 7を所持 → 8で K-Q-J-T-9 は成立せず、J-T-9-8-7は8が必要 → ガットショット（8で完成）
  - Q-J-T-9-8: Q必要 → ガットショット（Q含む先のドロー）
  - 2方向ガットショット（8またはQで完成）
- フラッシュ: ♥はT♥, 9♥, J♥の3枚 → バックドアフラッシュドロー（2枚必要）
- 役: ガットショット（ノーペア）

HandScoreは約7（ドロー加点込み）。

```
後手スコア = 7 + 3 − 3 − 7 = 0 → コール/フォールド境界
```

ショーダウンバリューがほぼなく、コールすると「IPのバリューに支払うだけ」になりやすいハンドです。

**BCRの判断**:
- ブロッカー: T♥9♥は特別なブロッカーなし（KKやAAをブロックしない）
- ストーリー整合: BBがJ♥ターンでCRするストーリーはKJやJ7などの2ペア系と重なる
- フォールドエクイティ: BTNの75%バレルにはブラフが相当数含まれる

フォールドエクイティは一定あります。しかしブロッカーがなく、ストーリー整合も「あるがIPには見抜かれやすい」状況です。

**判断**: 基本はチェックフォールド。BCRを試みる場合はIPのブラフ比率が高いと読んだ場合のみ、スモールサイズ（2x）で試みる。慣れないうちはフォールドを推奨。

### 実戦例4: ドンクベット（例外シナリオ）

**状況**: フロップ K♦7♣2♠ (ドライ)。BTN が 33%CBet → BB コール。
ターン: 6♥ (コネクター系のカード)。ターン後ボード K♦7♣2♠6♥。

**BBのハンド**: 6♦5♦
- 全カード: 6♦, 5♦, K♦, 7♣, 2♠, 6♥
- ランク確認: K×1, 7×1, 2×1, 6×2 (6♦, 6♥), 5×1
- 役: 6のペア（セカンドペア）
- ストレート: 5-6-7連続 → 4-5-6-7-8の5連続は4か8が必要 → OESD（8 outs）
- 役: セカンドペア（6's）+ OESD

このターンで、BBのレンジには6xや5xなどの連続ハンドが多く含まれます。BTNはKxやAKなどでプリフロップからレンジを組んでおり、6♥ターンはBTNのレンジより**BBのレンジを相対的に強化する**カードです。

ドンクベットの条件「OOPのUncapped化」が一定程度満たされています。

**判断**: 33〜50%のドンクベットが選択肢。セカンドペア＋OESDは十分な強さがあり、IPのレイズに対して再考余地もあります。ただし、多くの場面ではチェックしてIPのアクションを待つことも同程度に有効です。

**重要な注意**: 6♥ターンでドンクするのは「6xを持つ相当数のコンボ」とのバランスが必要です。6♦5♦単独でドンクするのではなく、「このターンでドンクするレンジ全体」を意識してください。

---

### 実戦例5: ナッツフラッシュでのバリューCR

**状況**: フロップ J♣T♣3♦ (スーテッド、フラッシュ可能性あり、A=2程度)。BTN が 50%CBet → BB コール。
ターン: 9♣ (フラッシュコンプリーティング、TurnCard係数=1)。ターン後ボード J♣T♣3♦9♣。
A値: フラッシュ完成ボードでウェット寄り（A=1）。
BTN が 50%ベット（C=5）。

**BBのハンド**: A♣K♣
- 全カード: A♣, K♣, J♣, T♣, 3♦, 9♣
- フラッシュ確認: ♣ = A♣, K♣, J♣, T♣, 9♣ → 5枚同スート → **ナッツフラッシュ完成**
- ストレート確認: A-K-J-T-9: Q抜けていて連続ではない（K-Q-J-T-9 ならQが必要）
- 役: ナッツフラッシュ（A♣K♣J♣T♣9♣）

HandScoreはナッツフラッシュとして32程度。

```
後手スコア = 32 + 1 − 3 − 5 = 25 → CR閾値（≥8）を大きく上回る
```

バリューCR確定です。IPの3betにもコール以上で対応できます（ナッツなので4betオールインも選択肢）。

**判断**: バリューCR（3x前後）。IPの3betにはコールまたは4betオールイン。

## 10-9 ボード別の応戦方針まとめ

第9章のIPのバレルパターンと対応させて、BBの応戦方針を整理します。

### ドライボード（K72r等）

バレルスコアが高く（ドライ係数=8）、IPは全ターンカードで積極的にバレルしてきます。

- **BBのバリューCR**: セット・2ペア（ペアターン後）・完成ストレート
- **BBのチェックコール**: TPTK・TPGK・強セカンドペア
- **BCR**: レア（ドライボードはIPのナッツが多く、BCRのフォールドエクイティが低い）
- **ドンク**: 基本なし。例外は7ターン（BBの7xが多い）や特殊コネクターターン

### セミウェットボード

IPのバレルスコアはドライより低く、OOPの応戦にも余地が生まれます。

- **BBのバリューCR**: セット・ストレート・フラッシュ完成
- **BBのチェックコール**: 2ペア・強ドロー（OESD + オーバーペア等）
- **BCR**: ブロッカーあり + フォールドエクイティが読める場面で有効
- **ドンク**: コネクターターン・フラッシュコンプリーティングターンで検討

### ウェットボード（T♣9♣8♦等）

バレルスコアが低く（コネクテッド係数=3〜4）、IPはハンド依存でバレルします。

- **BBのバリューCR**: ナッツストレート・フラッシュ（完成）
- **BBのチェックコール**: セット・2ペア・強ドロー
- **BCR**: バストドロー + ブロッカーあり → 比較的有効
- **ドンク**: ストレート完成ターンでOOPが多くのコンボを持つ場合に有効

## ミニクイズ

### 問1

BTN vs BB のSRP、フロップ K♦7♣2♠ (ドライ) でBTNが50%CBet → BBコール。ターン5♠（ブランク）が落ち、ターン後ボード K♦7♣2♠5♠、A=3（ドライ維持）。BTNが75%ベット（C=7）。BBのハンドは 7♥6♥ (HandScore=10)。後手スコアはいくつで、正しいアクションはどれですか。

1. 後手スコア=3、コール
2. 後手スコア=7、コール
3. 後手スコア=10、CR

### 問2

BTN vs BB、フロップ K♦7♣2♠でBTNが33%CBet → BBコール。ターン7♠（ペアターン）が落ちてボード K♦7♣2♠7♠となり、BTNが50%バレル（C=5）。BBのハンド 7♦6♦ でターン後の役はどれですか。

1. トリップス（7が3枚: 7♣, 7♠, 7♦）
2. セット（ポケットペア+ボード同ランク1枚）
3. 2ペア（7's & 6's）

### 問3

OOPのドンクベットについて、GTO的に最も正しい説明はどれですか。

1. OOPは常にIPのアクションを待つべきで、ドンクは常にミス
2. OOPのドンクは全ターンの約17%程度で有効であり、OOPのレンジが強化される特定のターンカードで使う例外戦略
3. OOPはIPよりポットを大きくしたい場合、どんなターンでもドンクしてよい

---

### 解答

- **問1**: 1（HandScore=10、A=3、C=7 → 10+3−3−7 = **3** → コール域。数値はコールの中でも低め。HU前提でM=0）
- **問2**: 1（7♦6♦のハンドの7♦と、ボードの7♣・7♠で同ランク3枚になる → **トリップス**。ポケットペアではないので「セット」ではなく「トリップス」が正確な用語。best5はK-7-7-7-6）
- **問3**: 2（GTO的にOOPのターンリードは約17%にとどまる。大半のターンではチェックが正解で、ドンクはOOPのレンジが強化される特定の局面での例外戦略）

> **本章まとめ**
>
> - OOPターン応戦の基本判断は**後手スコア**で決まる（≥8でCR、0〜7でコール、<0でフォールド）
> - **A値はターンの4枚で評価し直す**こと。フロップのA値を引き継がない
> - バリューCRの3要件: IPが確実にベット + 自分がナッツ近辺 + IPにコールしてもらえるサイズ
> - BCRの3要件: ブロッカー + ストーリー整合 + フォールドエクイティ
> - CRサイズの標準は2.5x〜3x。IPの3betにはバリューCRのみ対応し、BCRはフォールド
> - ドンクベットは例外戦略（全ターンの約17%）。OOPのレンジがUncapped化する特定のターンカードでのみ使う

**【GTOとのズレ】**

実戦で最も頻繁に見られるOOPのミスは「チェックレイズすべきでないハンドでCRしてしまう」ことです。特に「トップペアで大きくCR」は典型的なオーバープレイで、IPに3betされると壊滅的なEVロスになります。後手スコアが8〜10のTPTK相当は、式上はCR閾値を超えていても、ハンドの特性（IPの3betに耐えられない）を考慮してコールが安全です。

もう一つの典型的なズレは「BCRの乱用」です。「何もないからCRしてみる」というブラフCRは、ブロッカーもフォールドエクイティの読みもないまま打つと搾取されます。GTO的なBCR頻度は思ったより低く、特に「ドライボードではほぼ使わない」という認識が現実に近いです。

ドンクベットについては逆方向のズレが多いです。実戦では「チェックすべきターンでドンクしてしまう」ケースが頻発します。OOPがUncapedになるターンは限られており、「ターンで何かしたい」という衝動でドンクするのは控えてください。基本はチェックしてIPのアクションを見てから判断するのが正解です。
