# 第14章　マルチストリート統合判断 ─ リバーから逆算してターンを設計する

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: バレルスコア・後手スコア・ブロッカー論・α式・ポットコミットメントという5つの道具を「リバーから逆算するターン設計」として統合し、ターンのアクションに「理由のある根拠」を持てるようになる。

---

## 14-1 本章の目的 ─ ターン判断の頂点へ

本書は第I部で概念の基盤を固め、第II部でバレルスコア・後手スコア・ブロッカー論という3つの暗算式を確立し、第III部でダブルバレル・チェックバック・ターンオーバーベットといった戦術に展開してきました。本章はそのすべてを「リバーから逆算するターン設計」として一本に統合します。

第4章で確認した問いをもう一度思い出してください。

```
問1. リバーで自分は何を value bet するか？
問2. リバーで自分は何を bluff するか？
問3. リバーで相手のコールラインはどこか？
問4. リバーまでにコミットしてしまうか？
```

この4問いに対して、すでに学んだ各式が対応します。

| 問い | 対応する道具 |
|---|---|
| 問1・問2（バリュー/ブラフの配分） | 巻5 第6章で見た α 式 |
| 問3（相手のコール/フォールドライン） | 巻5 第7章で見た後手スコア（リバー版） |
| 問4（コミット閾値） | 巻5 第13章で見たポットコミットメント |

各道具が「リバーで何が起きるか」を予測するための材料です。そしてターンのアクション（バレルするか・サイズをいくつにするか・チェックバックするか）は、この予測の結論から逆算して決まります。

本章を読み終えたとき、ターンの判断は「いま打つかどうか」という問いではなく、「**リバーで何をするか決まっているから、いまこう打つ**」という未来起点の思考に変わります。これがポーカーにおける backward induction（後ろ向き帰納）を、暗算式の水準で実装する最終段階です。

---

## 14-2 backward induction の原理 ─ 未来から現在を決める

ゲーム理論における backward induction は、最終局面から逆算して現在の最適行動を確定させる手法です。ポーカーへの適用は明快です。

```
通常の（前向きの）思考:
  今の手が強い → ベットする → リバーを見る

backward induction（後ろ向きの思考）:
  リバーで何が起きるか概算する
  → その結果から「ターンで何をすべきか」を逆算する
  → ターンのアクションを選ぶ
```

通常の思考は「今」を起点にします。backward induction は「未来」を起点にします。この違いが、ターン判断の精度を根本から変えます。

なぜリバーを起点にする必要があるのか。リバーには将来カードが存在しないため、判断が「現在のハンド価値だけ」に収束します。リバーの判断はターンより単純です。単純な判断（リバー）を先に固めてから、複雑な判断（ターン）に移る。これが backward induction の直感です。

ソルバーが内部で行っているのもこれと同じ計算です。すべてのリバーカードに対してリバーのゲームツリーを解き、その期待値の平均を取ってターンのベット頻度を算出しています。本書の暗算式は、その計算を「主要シナリオ2〜3個への絞り込み」によって 5 秒で実行できる近似にしています。

精度はソルバーに劣りますが、「根拠のある判断」と「感覚の判断」の間には、暗算式でも十分に超えられない壁が存在します。重要なのは、リバーを起点にする習慣そのものです。

## 14-3 「リバープラン」を立てる手順

ターンでアクションを決める前に、リバープランを頭の中で設計します。以下の5ステップを、おおむね10〜15秒で通過する練習をしてください。慣れれば5秒以内に収まります。

### ステップ 1: リバーの主要シナリオを 2〜3 個想定する

リバーカードは無数に存在しますが、影響の大きいものは限られます。次の分類で「最もあり得るシナリオ」を選びます。

| シナリオ | 代表的なカード | 主な影響 |
|---|---|---|
| ブランクリバー | ドロー未完成の中位カード | ターンの構図がほぼそのまま持続 |
| フラッシュ完成 | フロップ・ターンのスートが揃う | フラッシュドロー保有側が急浮上 |
| ペアリング | 既存ボードカードと同ランク | フルハウス・クワッズが生まれる |
| オーバーカード | A・K などトップに出るカード | レンジ全体の強度分布が変わる |
| ストレート完成 | ボードの連続性を埋めるカード | ストレートドロー保有側が急浮上 |

すべてを考慮する必要はありません。自分のハンドに「最も重要な影響を与えるシナリオ」を 2〜3 個選びます。

### ステップ 2: 各シナリオで自分の手がバリューか・ブラフか・チェックかを確認する

ターンのハンドがリバー各シナリオでどう変化するか、第5章のターンカード5分類と同じ視点でリバーを読みます。

- **バリュー候補**: フルハウス・フラッシュ・セット・2ペア以上
- **ブラフ候補**: ドローが外れたが、相手の強ハンドをブロックしているコンボ
- **チェック候補**: バリューとしても弱く、ブラフとしても価値が薄いコンボ

### ステップ 3: 巻5 第6章で見た α 式でリバーのバリュー/ブラフ配分を概算する

リバーで打つ予定のサイズを仮定し、α 式を一度計算します。

```
α = ベット額 ÷ (ポット + ベット額)
後手下限確率 = 1 − α

ハーフポット（50%）ベット: α ≈ 0.33 → バリュー 2 : ブラフ 1
75%ポットベット:            α ≈ 0.43 → バリュー 57 : ブラフ 43 ≒ バリュー 4 : ブラフ 3
ポット（100%）ベット:       α = 0.50 → バリュー 1 : ブラフ 1
```

自分のリバーバリュー候補がブラフ候補よりはるかに多ければ、大きいサイズが選択肢に入ります。逆にバリューが薄くブラフが多ければ、小さいサイズか、あるいはベット自体を諦める判断になります。

### ステップ 4: 巻5 第7章で見た後手スコア（リバー版）で相手のコールラインを概算する

相手の典型的なコールハンドを想定し、後手スコアで確認します。

```
後手スコア（リバー版）= HandScore + A − 3 − C − M
（HU前提のためM=0）

判定: ≥ 8 → チェックレイズ検討 / 0〜7 → コール / < 0 → フォールド
```

相手が何をコールするかを知ることで、ターンのベットが「コールを引き出せるかどうか」を事前に検証できます。相手のコールラインを超えるバリューが自分にあれば、ターンでベットする根拠が固まります。

### ステップ 5: 巻5 第13章で見たポットコミットメントでコミット閾値を確認する

ターンでベットした場合、リバー前のポットとスタックを試算します。

```
コミット条件: 勝率 ≥ コール額 ÷ (ポット + コール額)

ターン後のSPR目安:
  3未満  → 事実上のコミット圏
  3〜6   → コミット圏が迫っている
  6以上  → まだ判断余地がある
```

強いバリューを持つなら、意図的にコミット軌道に乗せることが最大 EV になる場合があります。弱いハンドの場合は、意図せずコミット圏に入ることを避けるためにサイズを抑えるか、チェックバックを選びます。

### ステップ 5 完了後: ターンのアクションを逆算で確定する

ステップ 1〜5 の答えを総合して、ターンのアクションと適切なサイズを選びます。バレルスコア（第6章）はターンのアクション方向性の確認として最後に使います。「リバープランに整合するアクション」であるかを、バレルスコアで裏付けます。

```
リバープランの結論
  → バリューでバレルできる → ターンでベット（バレルスコアで方向性確認）
  → ブラフでバレルできる  → ターンでベット（ブロッカー論で候補を絞る）
  → バリューもブラフも薄い → ターンでチェックバック（SDV保護）
```

## 14-4 実例 1: バレルライン ─ ブロッカーを起点にした逆算

backward induction が最も明確に機能するのは、「ブロッカーを持ちリバーでブラフができる」と判断してターンでベットするラインです。

**シナリオ**: BTN vs BB、6-max 100BB、SRP。BTN がフロップで 1/3 ポット CBet、BB がコール。

- フロップ: K♠7♠4♥（セミ板、スペード2枚）
- ターン: T♠（フラッシュ完成カード）
- BTN ハンド: A♠Q♥

**ボード確認**:
- ボード K♠, 7♠, 4♥, T♠ の 4 枚
- BTN ハンド A♠, Q♥ との組み合わせ: A♠, Q♥, K♠, 7♠, 4♥, T♠

ランク別: A×1, K×1, Q×1, T×1, 7×1, 4×1 → 全てシングル → 役なし（ハイカードのみ）

スペード確認: A♠, K♠, 7♠, T♠ = 4枚 → BTN がスペードを 1 枚（A♠）持ち、ボードに 3 枚 → 合計 5 枚 → **ナッツフラッシュ（A♠ ハイ）完成**

したがって BTN A♠Q♥ on K♠7♠4♥T♠ = **ナッツフラッシュ**

**リバープラン（ステップ 1〜5 を通過）**:

**ステップ 1: シナリオ想定**

- ブランクリバー（例: 2♣）: フラッシュが追加されない。自分はナッツフラッシュを保有継続
- スペードリバー（例: 5♠）: 相手がスペード 2 枚持ちならフラッシュ完成するが、A♠ を持つ自分がナッツ
- ボードペアリバー（例: K♥）: K♠ とペア、相手の K ペアがフルハウスに昇格する場合があるが、自分はフラッシュ継続

どのシナリオでも自分のナッツフラッシュは A♠ ハイフラッシュとして機能します。

**ステップ 2: 各シナリオでのアクション**

- ブランクリバー: バリューベット（ナッツフラッシュ）
- スペードリバー: バリューベット継続（相手のフラッシュ = セカンドナッツ以下が多い）
- ボードペアリバー: バリューベット（自分はフラッシュ優先）

全シナリオでバリュー。ターン時点でナッツが確定していれば、リバーの不確実性はほぼ問題になりません。

**ステップ 3: α 式**

リバーでハーフポット（50%）を想定。α ≈ 0.33、バリュー 2 : ブラフ 1 の比率が必要です。自分のバリュー（ナッツフラッシュ）が確定しているため、ブラフを適切に混ぜる必要があります。

**ステップ 4: 相手のコールライン**

ターン前のポットを仮定 12BB、ターン 50% ベット（6BB）を想定とします。リバーポットは約 24BB。相手（BB）がリバーでコールできるのは後手スコアがゼロ以上のハンドです。ターン T♠ 落下後の BB のコールレンジ（K7 系のツーペア・ミドルセット・自分より下位のフラッシュ）は十分にあります。

**ステップ 5: コミット確認**

ターン 50% ベット後のリバー SPR を試算します。フロップ前ポット 5.5BB → フロップ 33% CBet + コールで ターン前ポット約 10BB → ターン 50%（5BB）ベット + コールでリバー前ポット約 20BB。残スタック約 87BB。SPR ≈ 4.4。コミット圏ではありませんが、リバーで打てる余地は十分です。

**ターン判断（逆算）**:

リバープランが「全シナリオでバリュー」として確立されました。ターンのアクションは明確です。

- バレルスコア確認: セミ板（FlopType = スーテッド）+ フラッシュ（TurnCard = 1）= スーテッド(4) + フラッシュ(1) = **5** → ハンド依存ゾーン

バレルスコアはハンド依存を示しますが、リバープランでは「どのシナリオでもバリュー」と確定しました。ハンド依存ゾーンでも HandScore が高いハンドはベットです。ナッツフラッシュの HandScore は 25 前後（役スコア 25 ≈ フラッシュ相当）で、バレルスコアのハンド依存 HandScore 基準（≥ 15 → バリューベット）を大きく超えています。

**ターンでハーフポット ベット**（50%、約 5BB）。

A♠ のブロッカーとしての役割も重要です。相手がスペードの A を持てない状況が確定しているため、リバーで BB のフラッシュドローが完成してもそれはナッツ未満です。ターンでベットすることで、リバーでのバリュー最大化に向けてポットを育てます。

## 14-5 実例 2: チェックバックライン ─ SDV 保護の逆算

backward induction がチェックバックを正当化するパターンを見ます。「ベットしてもリバーで困る」という逆算がチェックを選ばせます。

**シナリオ**: BTN vs BB、6-max 100BB、SRP。BTN がフロップで 1/3 ポット CBet、BB がコール。

- フロップ: A♠K♣7♥（ドライ板）
- ターン: 3♦（ブランク）
- BTN ハンド: A♥J♣（トップペア・中キッカー）

**ボード確認**:
- ボード A♠, K♣, 7♥, 3♦ の 4 枚
- BTN ハンド A♥, J♣ との組み合わせ: A♥, J♣, A♠, K♣, 7♥, 3♦
- ランク別: A×2（hand+board）, K×1, J×1, 7×1, 3×1
- A が 2 枚 → **トップペア（A's）、K・J キッカー** → HandScore ≈ 12（キッカーは J で中程度）

**リバープラン（ステップ 1〜5 を通過）**:

**ステップ 1: シナリオ想定**

- ブランクリバー（例: 2♣）: 自分はトップペアのまま。相手の KX（セカンドペア）・77 がコールしてくれる可能性
- K 系リバー（例: K♦）: ボード A♠K♣7♥3♦K♦。自分のハンド A♥J♣ + A♠,K♣,K♦ → A×2, K×2, J×1 → ツーペア（A's & K's）に昇格
- フラッシュ完成リバー: ダイヤが多ければ BB のフラッシュドローが完成する（フロップがドライなので可能性は低い）

**ステップ 2: 各シナリオでのアクション**

- ブランクリバー: トップペア中キッカー（AJ）でのバリューベットは薄い。相手の BB が KX や 77 でコールしてくれればよいが、AK・AQ・AA には負ける。バリュー / チェック の選択
- K リバー: ツーペア（A's & K's）に昇格、ただし相手の AK には負ける（AK は A-A-K-K-J でツーペア上位）
- スペアリング: A のペアリングは自分をトリップスに昇格させる → バリュー最強

AJ を持つ場合、ブランクリバーでの「バリューベットすべき相手レンジ」が薄い点が問題です。相手の BB は、フロップ A♠K♣7♥ で CBet にコールしているので、KX・77・弱い Ax が中心です。これらはリバーで自分のトップペアに負けているため、コールしてくれます。しかし AK・AQ・AA にコールされると負けます。

**ステップ 3: α 式**

リバーでハーフポット（50%）を想定。相手がコールするレンジと負けるレンジを考慮すると、バリュー枠に AJ を入れることはできますが、薄いバリューです。

**ステップ 4: 相手のコールライン**

相手の BB がリバーでコールするのは HandScore が十分なハンドです。BB の K♠T♦（KT、セカンドペア）の後手スコアを概算します（ブランクリバー、A 係数 = ドライ 3、50% ベット C = 5）。

```
HandScore（KT、セカンドペア）: 役スコア 6 + ドロー加点 0（リバー）= 約 6
後手スコア = 6 + 3 − 3 − 5 − 0 = 1 → コールゾーン
```

KT はコールしてきます。しかし自分の AJ（トップペア中キッカー）は KT に勝ちます。コールされる分の期待値はプラスです。

一方、BB の A♠Q♥（AQ）を想定します。

```
HandScore（AQ、トップペアトップキッカー）: 役スコア 18 程度
後手スコア = 18 + 3 − 3 − 5 − 0 = 13 → コールゾーン（強いコール）
```

AQ がコールしてきて、自分の AJ は A♠-A♥-Q♥-K♣-J♣（5 枚確認）= **AQ が A のペアかつキッカーが Q > J で上位** → 自分の AJ が負けます。

コールされるハンドの中に「自分が勝てるハンド」と「負けるハンド」が混在します。バリューは薄く、リスクがあります。

**ステップ 5: コミット確認**

ターン 50% ベット後のリバー SPR。フロップ 33% CBet でターン前ポット約 10BB。ターン 50%（5BB）後のリバー前ポット約 20BB。残スタック約 87BB。SPR ≈ 4.4。コミット圏ではなく、チェックバックを選ぶ余裕があります。

**ターン判断（逆算）**:

リバープランの結論として「バリューが薄く、コールされるとリスクがある」と判断されました。

- バレルスコア確認: ドライ板（FlopType = ドライ 8）+ ブランク（TurnCard = 2）= **10** → 積極バレルゾーン

バレルスコアは積極バレルを示していますが、リバープランでは「このハンド（AJ）は薄バリューでリスクが伴う」と判断されました。バレルスコアはレンジ全体の傾向です。AJ（トップペア中キッカー）という個別ハンドの視点では、**チェックバック（SDV保護）が現実的**です。

ただし、AJ のオフスート（A♥J♣）でブロッカーが使えない場合と、A♥J♥（スーテッド）でリバーでフラッシュドロー継続の場合では判断が微妙に異なります。本例のオフスート AJ は、SDV 保護のチェックバックが標準です。

**チェックバックを選択**し、リバーでのショーダウンバリューを最大限に保護します。

**comparison（スーテッド AJs との比較）**:

もし BTN が A♥J♥（スーテッド）を持っていたとします。ターン 3♦ で変化はありません。ただし、リバーにハート系のカードが落ちた場合のシナリオを追加できます。

- ハートリバー（フラッシュ完成）: A♥J♥ + ハートが 2 枚ボードにある場合、フラッシュ完成 → バリュー急上昇
- その他リバー: AJ トップペアのまま

ハートのフラッシュドロー可能性がある場合、ターンでのチェックバックでリバーのフラッシュ価値を守るラインも成立します。フロップがドライ（A♠K♣7♥）なので、ハートは 7♥ の 1 枚のみ。フラッシュドローとしては弱い。それでも、「リバーでブラフとして使えるバックアップがある」という点で、スーテッド AJ はオフスート AJ よりもわずかに攻撃的なラインを選べます。

## 14-6 3つのターン選択肢と逆算の対応

ターンで取りうる 3 つの選択肢（ベット・チェックバック・チェックレイズ）はそれぞれ、リバープランの内容が異なります。

### 選択肢 A: ターンでベット

リバーで「バリューまたはブラフとして打てる」と計画している場合に選びます。

バリューのターンベットは「リバーでも打ち続ける意思表示」です。ターン → リバーの 2 ストリートで相手から価値を最大化することが目的です。ターンのサイズはリバーの α 値を見越して設計します。ターン 50% + リバー 75% のように「ストリートをまたいだサイズ設計」を事前に決めておくことが重要です。

ブラフのターンベットは「リバーでもブラフを打てるハンドがある」場合に限ります。リバーでブラフを打てないハンド（バリューにもブラフにもならない空振り）をターンでブラフベットしても、2 ストリートにわたる損失になります。巻5 第8章で見たブロッカー論で「リバーで効くブロッカーを持つハンドをターンで残す」ことが、ブラフバレルの前提条件です。

巻5 第13章で見たポットコミットメントも確認します。ターンベット後のSPRがコミット圏に近ければ、リバーでオールインが見えています。強いバリューハンドなら意図的に選ぶ道ですが、弱いハンドなら避けるべき道です。

### 選択肢 B: ターンでチェックバック

リバーでのアクションが「チェックビハインドまたはブラフキャッチ」になる場合に選びます。

第9章で確認した SDV 保護がこのラインの典型です。「ターンでベットして得られるバリューよりも、リバーへ持ち込んでショーダウンする方が期待値が高い」判断です。

巻5 第7章で見た後手スコア（リバー版）を「自分が後手になった場合」で概算するのが有効です。「相手がリバーでベットしてきたとき、自分は何をコールできるか」を事前に確認することで、チェックバックが正しいかどうかを検証できます。

チェックバックには「トラップ（スロープレイ）」の用途もあります（第9章参照）。ナッツに近い強ハンドで相手のブラフを誘う目的のチェックバックは、「リバーで相手が動いてくれる」前提があります。

### 選択肢 C: ターンでチェックレイズ（OOP の場合）

OOP でチェックしてから相手のベットに対してレイズするラインです。チェックレイズは「相手のベット後の pot が大きくなる」効果があるため、ポットを膨らませたい強ハンドか、フォールドエクイティを使いたいドロー系セミブラフが典型的な用途です。

チェックレイズ後のリバープランには「レイズを受けた後の残スタックとポット」を再計算する必要があります。巻5 第13章のコミット計算がここでも機能します。チェックレイズ後のスタックが少なければ、リバーはオールイン一択になります。

## 14-7 サイズ設計 ─ ターンとリバーを連動させる

ターンのベットサイズは、リバーの残スタックと連動します。リバーでどのくらいのサイズを打てるかを先に決め、そこから逆算してターンのサイズを選びます。

### ポットジオメトリの標準パターン

6-max、100BB、BTN vs BB、SRP を想定します。

```
フロップ前ポット: 約 6BB（BTN 2.5BB オープン + BB コール）
フロップ 33% CBet + コール後: ターン前ポット 約 10BB、スタック約 94BB

ターン 50% ベット（5BB）+ コール後:
  リバー前ポット: 約 20BB、スタック約 89BB、SPR ≈ 4.5

ターン 75% ベット（7.5BB）+ コール後:
  リバー前ポット: 約 25BB、スタック約 86.5BB、SPR ≈ 3.5
```

SPR 3〜4.5 のリバーでは、ポットサイズの 2〜3 倍のスタックが残っています。ポット以下のリバーベットが可能です。

```
ターン 33% ベット（3.3BB）+ コール後:
  リバー前ポット: 約 16.6BB、スタック約 90.7BB、SPR ≈ 5.5
```

ターンで小さく打つと、リバーの余地が増えます。「弱いハンドでターンを打ちつつ、リバーでブラフを打てる可能性を残す」ラインです。

| ターンサイズ | リバー前 SPR | リバー戦術余地 |
|:---:|:---:|---|
| 33% | 約 5.5 | 幅広いサイズが選べる |
| 50% | 約 4.5 | 標準的なリバーベットが可能 |
| 75% | 約 3.5 | ポット近辺のサイズ中心 |
| 150%（OB） | 約 1.5 | リバーはほぼオールイン |

リバーで「大きく打ちたい」（セットや強フラッシュでのバリュー最大化）なら、ターンを大きく打ってポットを育てます。リバーで「小さく打ちたい」（薄バリューや SDV 保護後のブロッキングベット）なら、ターンを小さく抑えます。

### 3ベットポットでの注意点

3ベットポットでは初期ポットが大きく（約 18〜20BB）、SPR は最初から 4〜5 程度です。ターンで一度ベットすると、リバーはすでにコミット圏です。

3ベットポットでのターンベットは「リバーオールインを視野に入れた戦略的な打ち出し」です。弱いハンドでターンに参加することそのものがリスクになります。SPR が低い状況でのターン判断については、巻5 第15章（3ベットポット）を合わせて参照してください。

## 14-8 統合チェックリスト

実戦で backward induction を5秒以内に実行するための最終チェックリストです。

```
【ターンアクション前の backward induction チェックリスト】

Step 1: レンジ確認（第3章）
  □ 自分は Uncapped か Capped か
  □ 相手は Uncapped か Capped か

Step 2: ターンカード評価（第5章）
  □ ターンカードは 5 分類のどれか
  □ バレルスコアを計算する（第6章）

Step 3: リバープラン
  □ リバーの主要シナリオ 2〜3 個を想定する
  □ 各シナリオで自分はバリュー / ブラフ / チェック のどれか

Step 4: α 式（巻5 第6章）
  □ リバーで打つサイズを仮定し α を計算する
  □ バリュー : ブラフ の比率が成立するか

Step 5: 相手のコールライン（巻5 第7章）
  □ 相手の典型ハンドの後手スコアを概算する
  □ コールされると勝てるか・負けるかを確認する

Step 6: コミット確認（巻5 第13章）
  □ ターンベット後のリバー前 SPR を試算する
  □ コミット圏に入る場合、バリューがあるか確認する

Step 7: ターンアクションを逆算で決定
  □ リバープランに整合するアクション（ベット / チェック / CR）を選ぶ
  □ バレルスコアで全体的な方向性と照合する
```

全 7 ステップのうち、Step 3〜6 が backward induction の本体です。Step 1・2・7 は前後の文脈整理と確認です。慣れてくれば「Step 3〜5 を 5 秒で頭に通す」だけでも十分な精度が出ます。

## ミニクイズ

### 問1

ターンで「リバーで何をするか分からない」状態でベットすると、主に何が問題になりますか。

1. ベットサイズが恣意的になり、リバーで応用できないサイズを選びやすい。EV を取り逃すか、過剰リスクを取る
2. ルール違反になるので失格になる
3. ポットが大きくなりすぎて次の手に影響する

---

### 問2

BTN vs BB（100BB、SRP）、フロップ K♠7♠4♥-T♠ のターン 4 枚ボード。BTN のハンドは A♠Q♥。このハンドのターン時点での役は何ですか。また、リバーでナッツフラッシュブロッカーとして機能する根拠は何ですか。

1. ハイカード（A ハイ）。ナッツフラッシュ（A♠ ハイ）を自分が持つため、相手が A♠ を保有できない
2. ワンペア（A ペア）。相手の A を削るため
3. ストレート。ブロードウェイが完成しているため

---

### 問3

「リバーでブラフを打てないハンド」を持っているときに、ターンでブラフベットすることは適切ですか。

1. 適切。ターンでフォールドを取れれば、リバーは関係ない
2. 原則として不適切。リバーでも打てないブラフをターンで打つと、ターン単独でフォールドを取れない場合に 2 ストリート分の損失になる。例外は「ターン単独でフォールドさせる確率が極めて高い局面」のみ
3. ハーフポットベットなら問題ない

---

### 解答

- **問1**: 1（ターンのベットは「リバーで何をしたいか」から逆算して選ぶものです。リバープランがなければ、ターンのサイズがポットに対して大きすぎる・小さすぎるという問題が生じます。根拠がないベットはリバーで応用できず、EV を取り逃すか、相手に対して過剰なリスクを取る結果になります）

- **問2**: 1（A♠, Q♥ + ボード K♠, 7♠, 4♥, T♠。スペード確認: A♠（ハンド）+ K♠, 7♠, T♠（ボード）= 合計 4 スペード。通常のフラッシュは 5 枚必要ですが、「ハンドに A♠ を含む」ため、リバーにスペードが 1 枚来れば 5 スペードでナッツフラッシュが完成します。現時点でリバー前のターンでは「ナッツフラッシュドロー」です。A♠ を自分が持つことで相手は A♠ を保有できないため、相手がスペードフラッシュを作っても A ハイにはなれません。これがナッツフラッシュブロッカーとして機能する理由です。Q♥ はブロードウェイ（A-K-Q-J-T）を構成しますが、J が抜けているためストレートは不成立です）

- **問3**: 2（ターンのブラフは「ターン単独でフォールドを取る」か「リバーでも継続できる」の 2 パターンで機能します。リバーでブラフを打てないハンドでターンにブラフを打つと、コールされたときにリバーは「チェックしてショーダウン」になります。コールされ続けた 2 ストリート分の損失が残るため、リバーでの継続ができないブラフはターンでも打つべきではありません。例外は「このターンベットがほぼ確実にフォールドを取れる」と判断できる局面のみです）

---

> **本章まとめ**
>
> - ターン判断の本質は backward induction（後ろ向き帰納）。リバーで何が起きるかを先に概算してから、ターンのアクションを逆算で決める
> - リバープランの 5 ステップ: シナリオ想定 → バリュー/ブラフ確認 → α 式でサイズ設計（巻5 第6章）→ 相手のコールライン確認（巻5 第7章）→ コミット閾値確認（巻5 第13章）
> - ターンのベット・チェックバック・チェックレイズは「リバーで何をしたいか」から逆算して選ぶ
> - ターンのサイズはリバーの残 SPR と連動する。大きく打てばリバーはコミット寄り、小さく打てばリバーの選択肢が広がる
> - バレルスコアはターンの方向性確認に使うが、最終判断はリバープランの結論が優先する
> - 「リバープランなきターン bet」は 2 ストリート分の EV ロスを生むリスクがある

**【GTOとのズレ】**

GTOソルバーは backward induction を完全に実行します。すべての可能なリバーカード（約 40〜44 枚）に対するリバーのゲームツリーを計算し、その期待値の平均を取ってターンのベット頻度を出力します。本章の暗算式が行うのは「主要シナリオ 2〜3 個への絞り込み」であり、残り 40 枚分のシナリオは省略されています。

この省略が最も大きくズレを生む場面は「ブランクリバーカードが多数存在し、それぞれに微妙な差異がある」状況です。GTOは「2♠ が落ちた場合」「4♥ が落ちた場合」「6♣ が落ちた場合」をすべて別々に計算しています。人間が「ブランクリバー」とまとめて扱うと、相手のレンジへの細かい影響を見逃します。特に、ブランクカードがボードのセカンドペアを形成するケース（例: ボードに 7 があるときに 7 以外のブランクを「同等」と扱う）は精度が落ちます。

もう一つのズレは「α式のバリュー/ブラフ比率の概算精度」です。本章では「ハーフポット = バリュー 2 : ブラフ 1」と整数比で示しましたが、GTOはコンボ単位で個別に最適化しています。たとえばリバーバリューが 8 コンボある場合、最適ブラフは 75% ベットで約 6 コンボですが、どの 6 コンボを選ぶかはブロッカー論（巻5 第8章）と組み合わせた計算が必要です。α式の比率は「枠の上限」を示すものであり、「この枠の中で最も効果的なコンボ選択」はさらに精密な判断が要ります。

実戦では「暗算式で 90% の判断をカバーし、残りはハンドレビューで補完する」という方針が合理的です。第15章（付録A）のチートシートと、ソルバーでのハンドレビューを組み合わせることで、backward induction の精度を継続的に上げていけます。
