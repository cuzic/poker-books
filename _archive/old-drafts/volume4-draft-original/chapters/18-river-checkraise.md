# 第18章　チェック後の判断 ─ チェックビハインドとリバーCR

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: リバーで「チェック」を挟んだ後の判断を体系化する。IPのチェックビハインド・OOPのチェックレイズ（CR）・インダクトベットの3つを習得し、第16章・第17章の攻守を「チェック経由の複合戦略」として統合する。

---

## 18-1 「チェック」というアクションの3つの役割

第16章でIPのリバー攻撃を、第17章でOOPのディフェンスを整理しました。本章では両者を貫く「チェック」というアクションに焦点を当てます。

リバーのチェックは単なる「パス」ではありません。攻撃側（IP）にとっても防御側（OOP）にとっても、チェックには積極的な戦略的意図が存在します。

```
役割1: ショーダウンバリュー確保（SDV保護）
  ハンドの強さが「バリューベットにはわずかに足りない」水準のとき、
  チェックでリスクなくショーダウンに持ち込む
  対象: トップペア弱キッカー、ミドルペア、薄い2ペアなど

役割2: トラップ（スロープレイ）
  ナッツ〜準ナッツのハンドで、相手のベットを誘うためにあえてチェックする
  相手がブラフを打ってくれれば、CRまたはコールで利益を最大化できる
  対象: セット、ストレート、フラッシュなど

役割3: インダクト（罠張り）
  強いハンドで相手の攻撃性を利用する点でトラップと似るが、
  「相手が特定のアクションを取りやすいボードテクスチャ」を意識して仕掛ける
  詳細は18-6節で扱う
```

これら3つの役割はプレイヤーが意識的に選択するものです。「なんとなくチェック」は3つのどれにも属さず、EVを失う最悪の選択です。チェックを選ぶ前に「今のチェックは何のためか」を明確にすることが本章の核心です。

### チェック後のアクション分岐

チェックの後には次のアクションが続きます。

```
IPがチェックした後:
  → OOPがチェック → ショーダウン（チェックビハインド完了）
  → OOPがベット  → IPはコール/フォールド/レイズを選択

OOPがチェックした後:
  → IPがチェック → ショーダウン
  → IPがベット  → OOPはコール/CR/フォールドを選択
                   本章ではとくにCR（チェックレイズ）を詳しく扱う
```

## 18-2 IPのチェックビハインドレンジ ─ 3つのクラス

IPがリバーでチェックビハインドを選ぶとき、そのハンドは3つのクラスに分類できます。この分類を意識することで「チェックか、ベットか」の迷いが消えます。

### クラス1: SDV保護（薄バリューの安全着地）

ハンドの強さが「バリューラインの直下」にある中間ハンドです。第16章の50%の法則に照らすと、コールされた場合に相手のコールレンジに対して勝率が50%前後に留まるハンドがこのクラスに入ります。

ベットすると相手のコールレンジが強いハンドに絞り込まれ、勝率がさらに下がります。チェックビハインドなら相手のチェックを受けてショーダウンに持ち込め、弱いハンドにも届く分だけ期待値が上がります。

```
典型例:
  - トップペア弱キッカー（J以下のキッカー）
  - ミドルペア（セカンドペア以下）
  - 2ペアだが、ボードが連続していて相手のストレートが懸念される
```

### クラス2: トラップ（スロープレイ）

ナッツまたは準ナッツのハンドで、相手のブラフを誘うためにチェックを選びます。相手がブラフ頻度の高いプレイヤーであるとき、またはボードテクスチャ上でOOPがブラフしやすい状況のとき、トラップが有効です。

ただしトラップはバランスが必要です。強いハンドで全てチェックすると「IPがチェックしたら弱いハンド」と読まれて搾取されます。強いハンドでもベットとチェックを混在させるのがGTO的な設計です。

```
典型例:
  - セット（ナッツに近く、相手のドロー外れブラフを期待できる）
  - フラッシュ・ストレート（相手が「ドロー外れ」と読んで攻めてくる場面）
```

### クラス3: 諦めチェック

バリューにも、ブラフにも機能しないハンドです。ベットすれば相手のコールレンジに負け、フォールドに追い込める相手の割合も低い。チェックビハインドでショーダウンに持ち込むことが最善です。

```
典型例:
  - バストドロー（役を形成せず、ショーダウンバリューもない）
  - 弱いペア（ミドル〜ボトムペア）でブラフが通る見込みもない
```

### 3クラスの整理

| クラス | ハンドの強さ | チェックの目的 |
|---|---|---|
| SDV保護 | 薄いバリュー（勝率50〜55%前後） | ベットで逆選択されるのを避ける |
| トラップ | ナッツ〜準ナッツ | 相手のブラフを誘って利益を最大化する |
| 諦めチェック | 役なし〜弱いペア | バリューにもブラフにもなれない |

実戦でよく迷うのはSDV保護と薄いバリューベットの境界です。「ベットするかチェックするか」の判断は第16章の50%の法則で決めます。コールされたとき相手のコールレンジに対して50%を下回ると判断したらチェックビハインドを選んでください。

## 18-3 OOPのリバーCR ─ バリューCRとブラフCR

OOP（BBポジション）がリバーでチェックし、IPがベットしてきたとき、OOPには3つの選択肢があります。コール・フォールド・チェックレイズ（CR）です。第17章ではコールとフォールドを後手スコアで判断しました。本節ではCRに焦点を当てます。

### リバーCRの2種類

```
バリューCR: 強いハンドでIPのベットにレイズして利益を最大化する
  条件: コールされても勝てる強さ（セット以上、ナッツフラッシュ等）
  目的: IPのコールハンドから追加利益を得る

ブラフCR（BCR）: ブラフとしてレイズしてIPをフォールドさせる
  条件: フォールドエクイティ + ブロッカー + ストーリーの一貫性
  目的: 強くないハンドでポットを取る
```

フロップ・ターンのCRにはセミブラフ（ドロー+フォールドエクイティ）が存在しました。しかしリバーでは第5章で確認したとおりセミブラフは消滅しています。リバーのCRはバリューかブラフかの純粋な二択です。この点がフロップ・ターンのCRと根本的に異なります。

### バリューCRの条件

バリューCRが成立するためには次の条件が揃う必要があります。

```
条件1: IPのベットにコールされても勝てる強さがある
  セット以上、ナッツフラッシュ、ナッツストレートなど
  IPのコールレンジの70%以上に勝てることが目安

条件2: IPがCRに対してコールしてくれるハンドが存在する
  IPのベットレンジが広い（弱いバリューやブラフを含む）
  IPのレンジがCRに対してフォールドしてしまう確率が高すぎない

条件3: ポットを大きくするメリットがある
  自分のナッツ強度が高く、IPのコールで利益が確定する
```

バリューCRはIPが「広いレンジでベットしている」場面で特に有効です。IPが強いバリューのみでベットしている場面では、CRにコールするのはさらに強いハンドだけになるため、CRの利益が限定されます。

### BCR（ブラフCR）の構成要素

BCRはリバーで最もリスクの高い戦術です。失敗するとレイズ額を丸ごと失います。BCRが機能するためには3つの要素が揃う必要があります。

```
要素1: フォールドエクイティ
  IPのベットレンジに、CRに対してフォールドする中程度のハンドが十分含まれている
  IPが1ペア以下でベットしている場面でBCRが最も機能する

要素2: ブロッカー（第10章）
  IPの強いコールハンドをブロックするカードを持っている
  例: ナッツフラッシュの構成カード（Aスペードなど）を持ち、
      IPのナッツフラッシュコールを削減する

要素3: ストーリーの一貫性
  フロップ・ターンのアクション履歴がリバーCRと矛盾しない
  例: フロップでコールしたのがドロー候補であり、
      リバーでCRしてもアクション履歴として自然に説明できる
```

BCRの頻度はバリューCRのコンボ数を基準に制限します。ポット等倍サイズのCRならα = 0.5なので、バリュー:ブラフ = 1:1が均衡した比率です。バリューCRのコンボが6つなら、BCRは6コンボ以内に抑えます。

### OOPの後手スコアとCRの関係

第17章で確認した後手スコアの復習です。

```
後手スコア = HandScore + A − 3 − C − M
（HU前提のためM=0）

≥ 8 → CR検討
0〜7 → コール
< 0  → フォールド
```

後手スコアが8以上になるハンドがバリューCRの候補です。ただし後手スコアは「CR検討」を示すにとどまります。実際にバリューCRかBCRかは、ハンドの役の強さとブロッカー条件で最終判断します。

## 18-4 リバーCRのサイズ選択

チェックレイズのサイズは「IPのベットサイズの何倍か」で決まります。

### 標準サイズ: 2〜3倍

リバーCRの標準サイズはIPのベットの2〜3倍です。具体例で確認します。

```
状況: ポット20BB、IPが10BB（50%ポット）ベット

2倍CR: 20BBにレイズ
  IPのコールコスト = 10BB（差額）
  コール後のポット = 20 + 10 + 20 = 50BB
  IPのコールオッズ = 10 ÷ 50 = 20%

3倍CR: 30BBにレイズ
  IPのコールコスト = 20BB（差額）
  コール後のポット = 20 + 10 + 30 = 60BB
  IPのコールオッズ = 20 ÷ 60 ≒ 33%
```

コールオッズが高いほどIPのコールが安くなります。つまり大きなCRは相手のコールを促しやすく、バリューCRに向いています。

### α式でCRサイズを設計する

第8章のα式をCR設計に適用します。ここではIPがCRを「受ける側」として計算します。

```
IPの立場（CRの後手）:
  α = IPのコールコスト ÷ コール後のポット

例（3倍CR）:
  α = 20 ÷ 60 ≒ 0.33

  → IPの後手下限確率 = 1 − 0.33 = 0.67（67%）
  → OOPのCRレンジのうちブラフ率が33%を超えればIPはコール有利
```

OOP（CR側）から見ると、3倍CRのとき「BCRの割合はバリューCRの50%以内（1:2比率）」が均衡点です（IPがコールオッズ33%でコール/フォールドを判断するため）。

### サイズ別の用途まとめ

| CRサイズ | IPのコールオッズ | 主な用途 |
|---|---|---|
| 2倍CR | 20%（50%ポットベット時） | バリューCR（IPにコールさせる） |
| 3倍CR | 33%（50%ポットベット時） | バリューCR（より広いコールを引き出す） |
| ポット等倍CR | 50%前後 | バリューCRのトップクラス / 一部BCR |

BCRで大きなサイズを使うと「ブラフ比率をさらに多く必要とする」という逆説が生まれます。BCRには2〜3倍の標準サイズが使いやすいです。

## 18-5 IPがリバーCRを受けたときの判断

IPがリバーでベットし、OOPがCRしてきたとき、IPは「コール」「フォールド」「4bet（再レイズ）」の3択を迫られます。

### コール基準の計算

IPがCRを受けた側になったとき、後手スコアの裏返しで判断します。IPが後手として機能するためです。

```
IPのコール判断:
  コールオッズ = IPのコールコスト ÷ コール後のポット
  OOPのCRレンジのブラフ率 > コールオッズ → コール有利
  OOPのCRレンジのブラフ率 < コールオッズ → フォールド有利
```

具体例で確認します。

```
状況: ポット20BB、IPが10BBベット、OOPが30BB（3倍）にCR

IPのコールコスト: 20BB（差額）
コール後のポット: 20 + 10 + 30 = 60BB
コールオッズ: 20 ÷ 60 ≒ 33%

→ OOPのCRレンジのブラフ率が33%を上回るならコール有利
  OOPのCRレンジのブラフ率が33%を下回るならフォールド有利
```

### ハンド強度別の対応方針

| IPのハンド | 基本対応 | 理由 |
|---|---|---|
| ナッツ〜準ナッツ | コールまたは4bet | バリューCRにもBCRにも対応できる |
| セット・強いフラッシュ・ストレート | コール（多く）/ 4bet（一部） | 大半のCRバリューに対応できる |
| 強い2ペア | コール検討 | OOPのCRレンジの構成による |
| TPTK | フォールド基本 | OOPのCRレンジはTPTKを上回る強さが中心 |
| 1ペア以下 | フォールド | 例外的状況を除いて不採算 |

**重要な原則**: リバーのCRは強いシグナルです。GTO理論ではCRレンジのブラフが33%程度存在するため1ペアでのコールが成立する局面もありますが、実戦での一般プレイヤーのCRブラフ率は10〜15%程度に留まることが多いです。「リバーCRに1ペアでコール」は実戦上ほぼマイナスEVです。

### 4bet（再レイズ）の条件

IPがCRに対して4betする場面は限定的です。

```
4betが適切な状況:
  1. 自分がナッツまたはナッツに極めて近い
  2. OOPがBCRを多用すると判断できるプロファイル
  3. スタックが浅く（SPR < 2）、オールイン4betが自然な流れ

4betが不適切な状況:
  1. 自分が強い2ペア以下のハンド（OOPのCRバリューに挟まれる）
  2. 深いスタック（SPR > 4）でOOPのバリューCRが機能する状況
```

OOPからCRに対して4betしてくるプレイヤーはほぼ確実にナッツを持っています。IPが4betを受けた場合、準ナッツ以下でのコールはほぼ不採算です。

## 18-6 インダクトベット ─ 罠張りチェックの構造

インダクトベット（誘いベット）とは、強いハンドで意図的にチェックして相手のブラフを引き出し、利益を最大化する戦術です。単純なトラップと似ていますが、「相手が特定の状況でブラフしやすい」という文脈を積極的に活用する点で異なります。

### トラップとインダクトの違い

```
トラップ（スロープレイ）:
  強いハンドでチェックして相手のベットを受け身で待つ
  相手がどのアクションを取っても受け入れる構え

インダクトベット:
  相手が「ここはブラフしやすい」と感じるボードテクスチャや
  アクション履歴を意識して、あえてチェックする
  相手のブラフを積極的に「引き出す」意図がある
```

### インダクトが機能する4条件

```
条件1: 相手が攻撃的なプレイヤーである
  チェックを「弱さのシグナル」と読んで積極的にベットしてくる相手

条件2: ボードが相手のブラフを誘発しやすい
  例: ターンでドローを見せるボード → リバーがブランク
      （相手が「ドロー外れてブラフしてくる」と読める）

条件3: 自分がナッツまたは準ナッツ
  相手のブラフベットにコールまたはCRして確実に勝てる強さ

条件4: アクション履歴に一貫性がある
  フロップ・ターンを通して「弱い動き」をしており、
  「IPがリバーでチェックするのは弱い」と相手が自然に読める
```

### インダクトの利益構造

```
通常のバリューベット（75%ポット）:
  相手コール → ポットの1.75倍を獲得
  相手フォールド → ポット獲得

インダクト成功（相手が50%ポットのブラフ）:
  コールでCR → ポットの2倍以上を獲得
  コールのみ → ポットの1.5倍を獲得
  相手チェック → ショーダウン（インダクト失敗 = 機会コスト発生）
```

インダクトが有利になる条件は「相手のブラフ頻度 × ブラフサイズ」が、チェックの機会コスト（通常バリューベットで得られるEV）を上回るときです。相手が高頻度でブラフしてくるプロファイルが分かっている場合に最も強力な武器になります。

## 18-7 実戦例

### 実戦例1: SDV保護によるチェックビハインド

**状況**: 6-max、100BB、BTN（IP）vs BB（OOP）。BTNオープン、BBコール

**ボード**: K♥ 9♠ 3♦ — 4♣ — 8♠
（フロップCBet、ターンチェックバックを経てリバー到達）

**IPのハンド**: Q♣ 9♦

**役の確認**:
全カード = Q♣, 9♦, K♥, 9♠, 3♦, 4♣, 8♠

- 9が2枚（9♦と9♠）→ セカンドペア（9's）
- best 5 = K-9-9-Q-8
- ストレートチェック: K(13),9,8,4,3 → 5連続なし
- フラッシュチェック: ♠=9♠,8♠ = 2枚のみ

**役: セカンドペア（9's）、K-9-9-Q-8**

**判断プロセス**:

```
IPのQ9（セカンドペア）でのバリューベット検討:
  BBのコールレンジ（リバーベットに対して）:
    Kx（トップペア）, 89（2ペア）, 98（2ペア）, 9x（セカンドペア強いキッカー）など

  Q9はKxに全て負ける。Kxは典型的なBBのコールレンジに多く存在する。
  コールされたとき、相手のコールレンジに対する勝率は50%を大幅に下回る。

  → チェックビハインド（SDV保護）が正解
```

**学習ポイント**: セカンドペアは「ベットするには弱く、フォールドするには強い」中間ハンドです。チェックビハインドでショーダウンに持ち込み、BBの弱いハンド（バストドローなど）に対してもポットを獲得できます。

---

### 実戦例2: OOPのバリューCR

**状況**: 6-max、100BB、BTN（IP）vs BB（OOP）

**ボード**: J♠ 9♦ 4♣ — 2♠ — 5♥（リバー5♥）

**アクション**: フロップCBet → BBコール。ターン・リバーはBBチェック。IPがリバーで50%ポット（10BB）ベット（ポット20BB）。

**BBのハンド**: J♥ 9♥

**役の確認**:
全カード = J♥, 9♥, J♠, 9♦, 4♣, 2♠, 5♥

- Jが2枚（J♥とJ♠）、9が2枚（9♥と9♦）→ 2ペア
- best 5 = J-J-9-9-5
- ストレートチェック: J(11),9,5,4,2 → 2-3-4-5-6(3,6なし)、連続5なし ✓
- フラッシュチェック: ♥=J♥,9♥,5♥ = 3枚のみ ✓

**役: 2ペア（J's and 9's）、best 5 = J-J-9-9-5**

**後手スコアの計算**:
```
HandScore（2ペア）= 30点（役スコア）+ ドロー加点0（リバー）+ ブロッカー加点0
HandScore = 30

後手スコア = 30 + A − 3 − C − M
  A（セミウェット）= 2、C（50%ポット）= 5、M（HU）= 0

後手スコア = 30 + 2 − 3 − 5 − 0 = 24

24 ≥ 8 → CR検討
```

**判断プロセス**:
```
BBの2ペア（J's and 9's）はIPのコールレンジに対して高い確率で勝てる。
IPが50%ポットベットするレンジには、バリュー（Jx、9x、Ax）と
ブラフ（バストドロー）が混在している。

IPの10BBベットを30BB（3倍）にCR:
  コールコスト = 20BB
  コール後のポット = 20 + 10 + 30 = 60BB
  IPのコールオッズ = 20 ÷ 60 ≒ 33%

BBの2ペアはIPのコールレンジ（Jx = 1ペア、Ax = 1ペア等）に勝つ。
→ バリューCR（30BB）が正解
```

**学習ポイント**: 2ペアはリバーCRのバリュー下限です。IPがリバーでベットするレンジには1ペアが多く含まれます。2ペアでCRしてIPの1ペアのコールを引き出すことで利益を最大化できます。

---

### 実戦例3: BCR（ブラフチェックレイズ）

**状況**: 6-max、100BB、BTN（IP）vs BB（OOP）

**ボード**: K♠ 8♠ 4♥ — 2♣ — J♦（リバーJ♦）

**アクション**: フロップCBet → BBコール（フラッシュドローとして）。ターンBBチェック、IPチェックバック。リバーJ♦でBBチェック、IPが75%ポット（15BB）ベット（ポット20BB）。

**BBのハンド**: A♠ 6♠

**役の確認**:
全カード = A♠, 6♠, K♠, 8♠, 4♥, 2♣, J♦

- スペード: A♠, 6♠, K♠, 8♠ = **4枚**（フラッシュドロー、5枚目が落ちなかった = バスト）
- ストレートチェック: A(14),J,K,8,6,4,2 → 連続5なし（A-2-3-4-5は3,5なし）✓
- ランクカウント: 全て1枚ずつ → ハイカード
- best 5 = A-K-J-8-6

**役: 役なし（Aハイ）**

**BCRの成立要素確認**:
```
要素1: フォールドエクイティ
  IPがリバーで75%ポットベット。IPのレンジにはバリュー（Kx、Jx等）と
  ブラフが混在している。IPが1ペア（Kx）でCRに対してフォールドしやすい。

要素2: ブロッカー
  A♠を保有 → ナッツフラッシュ（A♠+ スペード4枚でフラッシュ成立）のうち
  A♠を使うコンボをブロック。IPがナッツフラッシュコールしにくくなる。
  ただしリバーでフラッシュは完成していない（4枚のみ）ため、直接的なフラッシュブロッカーではなく、
  Kx系（IP強バリュー）に対するブロッカー効果は限定的。

要素3: ストーリーの一貫性
  フロップでスペードフラッシュドローとしてコールしたことが自然。
  リバーでCRしても「フラッシュが完成したかも？」とIPに誤解させられる。
  ただし実際には4枚のみでバストしている。
```

**BCRのサイズ計算**:
```
IPの15BBベットを45BB（3倍）にCR:
  IPのコールコスト = 30BB
  コール後のポット = 20 + 15 + 45 = 80BB
  IPのコールオッズ = 30 ÷ 80 = 37.5%

BBはIPが37.5%以上の頻度でフォールドすることを期待する。
IPが1ペア以下でベットしているコンボの一部がフォールドしてくれれば成立。
```

**判断**: A♠のブロッカーとストーリーの一貫性（スペードドロー保有の見せ方）を活用したBCRが機能しやすい局面です。ただしIPが強いバリュー（Kx、Jx）を多く含む場合は機能率が下がります。BCRはバリューCRのバランス補完として限定的に使います。

**学習ポイント**: BCRは「バストドロー + ブロッカー + ストーリー」が揃ったときに初めて成立します。3要素のひとつでも欠けると期待値が大幅に低下します。

### 実戦例4: IPがリバーCRを受けたときの判断

**状況**: 6-max、100BB、BTN（IP）vs BB（OOP）

**ボード**: Q♥ J♦ 7♣ — 2♠ — 5♦（リバー5♦）

**アクション**: フロップCBet → BBコール。ターン・リバーBBチェック。IPが33%ポット（6BB）ベット（ポット18BB）。BBが20BBにCR。

**IPのハンド**: K♠ Q♦

**役の確認**:
全カード = K♠, Q♦, Q♥, J♦, 7♣, 2♠, 5♦

- Qが2枚（Q♦とQ♥）→ トップペア（Qペア）
- best 5 = K-Q-Q-J-7
- ストレートチェック: K,Q,J,7,5,2 → J-Q-K-A（4枚連続、Aがボードになく不成立）、7-8-9-T-J（8,9,Tなし）→ なし ✓
- フラッシュチェック: ♦Q♦,J♦,5♦ = 3枚のみ ✓

**役: ワンペア（Qペア）、TPTK（Kキッカー）**

**コール基準の計算**:
```
IPのコールコスト: 20 − 6 = 14BB（差額）
コール後のポット: 18 + 6 + 20 = 44BB
IPのコールオッズ: 14 ÷ 44 ≒ 32%

→ BBのCRレンジのブラフ率が32%を上回るならIPはコール有利
  BBのCRレンジのブラフ率が32%を下回るならフォールド有利
```

**BBのCRレンジを推測する**:
```
BBのバリューCR候補:
  - セット（77、22、55）→ フルハウス/セット
  - 2ペア（Q7、J7、Q2等）
  - J5s（2ペア: J's and 5's）→ J♦5♦が2ペアになる？
    ： J♦と5♦でフラッシュ要素あり、J+5でリバー2ペアが疑われる

BBのBCR候補:
  - バストドロー（スペードフラッシュドロー外れなど）
  - ブロッカーを持つ役なし系

実戦上の判断:
  BBがリバーでCRするとき、そのほとんどがバリューCRである。
  BCRは条件が揃ったときのみ機能するため、実際のBCR率は低い。
  コールオッズ32%に対してBBのBCR率がそれを上回る根拠が薄い。
  → フォールドが無難
```

**学習ポイント**: TPTKはフロップやターンでは強いハンドですが、リバーのCRに対してはそのまま「コールハンド」とはなりません。CRはバリューレンジが中心であり、TPTKは典型的にそのバリューレンジに負けます。「強いハンドだからコールする」という感情的判断が失点を招きます。

### 実戦例5: インダクトベット（罠張り）

**状況**: 6-max、100BB、BTN（IP）vs BB（OOP）

**ボード**: 9♠ 8♦ 3♣ — 3♥ — K♠（リバーK♠）

**アクション**: フロップCBet → BBコール。ターンBBチェック、IPチェックバック。リバーK♠でBBチェック。IPの番。

**IPのハンド**: 9♦ 9♣

**役の確認**:
全カード = 9♦, 9♣, 9♠, 8♦, 3♣, 3♥, K♠

- 9が3枚（9♦, 9♣, 9♠）→ セット
- 3が2枚（3♣, 3♥）
- best 5 = 9-9-9-3-3 → **フルハウス（9's full of 3's）**
- ストレートチェック: K,9,8,3,3 → 6-7-8-9-T(6,7,Tなし)→ なし ✓
- フラッシュ: ♠=9♠,K♠ = 2枚のみ ✓

**役: フルハウス（9's full of 3's）**

**インダクトの判断プロセス**:
```
IPの9♦9♣ = フルハウス（ナッツに近い）

通常のバリューベット（75%ポット）を選んだ場合:
  → BBはフルハウスより弱いハンドをほぼフォールドまたは小さくコール

インダクト（チェック）を選んだ場合:
  → リバーK♠は「BTNがターンでチェックバック → 弱い？」のシグナル
  → BBが攻撃的なプレイヤーであれば、ここでブラフベットを打ってくる
  → K♠がヒットした（BBのKxが強くなった）と感じてバリューベットしてくる可能性もある

インダクトが有利になる条件（本例での確認）:
  条件1: BBが攻撃的 → 「よく当てはまる場合」を想定
  条件2: K♠はBBのブラフ・バリューベットを誘発しやすい（Kがヒットした可能性）
  条件3: 自分はフルハウス（ほぼナッツ）→ 何に対してもコール/CRで対応可能
  条件4: ターンチェックバックで「IPは弱い」イメージを植え付けている

→ インダクト（チェック）を選び、BBのベットを待つ
  BBがベットしてきたらコール、またはCR（ポット設計次第）
```

**学習ポイント**: インダクトはナッツ近辺のハンドで機能します。フルハウスでリバーチェックをして、相手のブラフまたはバリューベットを誘い出すことで期待値を最大化します。ターンのチェックバックが「IPの弱さのイメージ」を作った流れが活きます。

## ミニクイズ

### 問1

BTN（IP）がリバーでチェックビハインドすべきハンドはどれですか。ボードはA♠T♦5♥8♣2♠（リバー2♠）。スタック深い（SPR≒4）、ポット20BB。

1. J♠9♠（バストフラッシュドロー ─ 役なし、Aハイ）
2. A♥Q♦（トップペア ─ Aペア+Qキッカー）
3. 5♣5♦（セット ─ ボードの5♥と合わせて5が3枚）

### 問2

OOP（BB）がリバーでCRした場合、IPが1ペア（TPTK）でコールすることが正当化されるのはどの状況ですか。

1. BBのCRレンジのブラフ率が、IPのコールオッズを大幅に上回ると判断できる
2. 自分の1ペアのキッカーが強い（Aキッカー）
3. ポットが大きいため降りたくない

### 問3

インダクトベットが最も機能しやすい状況はどれですか。

1. 自分が役なし（バストドロー）で、相手が慎重なタイト系のプレイヤー
2. 自分がフルハウスで、相手が攻撃的でブラフを打ちやすい状況
3. 自分がTPTKで、相手が守備的でほとんどベットしてこない

---

### 解答

- **問1**: 1（J♠9♠は役なし。バリューベットにもブラフにもなりにくいため、諦めチェックが正解。AQはTPTKで33%ポット程度のバリューベット候補。5♣5♦はセットでバリューベットまたはトラップ候補）

- **問2**: 1（コールオッズを上回るブラフ率が根拠。キッカーの強さやポットの大きさは直接の根拠にならない。リバーCRは強いシグナルであり、1ペアでのコールは通常マイナスEV。ブラフ率の定量的評価が唯一の判断基準）

- **問3**: 2（インダクトは「ナッツ近辺 + 相手が攻撃的」の組み合わせで機能する。役なしでのインダクトはブラフが通らない。相手が慎重なら誘い出せない。TPTKではコールされたときのリスクが大きすぎる）

> **本章まとめ**
>
> - IPのチェックビハインドには「SDV保護」「トラップ」「諦めチェック」の3用途がある。「なんとなくチェック」は最悪の選択。
> - OOPのリバーCRは「バリューCR」と「BCR（ブラフCR）」の2種類で、セミブラフは存在しない。BCRは3要素（フォールドエクイティ・ブロッカー・ストーリー）が揃ったときに限定する。
> - リバーCRのサイズは2〜3倍が標準。α式でIPのコールオッズを計算し、BCRの必要フォールドエクイティを確認する。
> - IPがCRを受けたとき、1ペア以下ではフォールドが基本。コールはOOPのCRブラフ率がコールオッズを上回ると判断できる場合のみ。
> - インダクトベットはナッツ近辺のハンドで相手のブラフを誘う積極的な戦略。相手が攻撃的なプレイヤーのとき最大限に機能する。
> - 本章の判断はすべて第8章（α式）・第9章（後手スコア）・第10章（ブロッカー論）を実戦に適用したもの。

**【GTOとのズレ】**

GTOでは、IPはリバーでバリューベットとチェックビハインドを混在させてレンジバランスを保ちます。たとえばTPTKでも一定頻度でチェックバックしてトラップを混入することで、OOPが「IPチェック = 弱い」と単純に読めないようにします。

実戦の多くのプレイヤーは強いハンドをほぼ全てベットし、弱いハンドをほぼ全てチェックする傾向があります。この偏りによって「IPがチェックしたら積極的に攻める」という搾取が成立します。本章で示したトラップとインダクトはその搾取を逆利用する戦術ですが、GTO的には頻度管理が必要です。強いハンドでのチェックを混入しすぎると、今度はチェックバックが弱いハンドに見えなくなります。

OOPのCRについても同様です。GTOではバリューCRとBCRのバランスが厳密に管理されますが、実戦プレイヤーはリバーCRをほぼバリューのみで行う傾向があります。この現実を踏まえると、「相手のリバーCRにはほとんどブラフが入っていない」という前提でフォールドを多めに選ぶことが実戦エクスプロイトになります。GTOと実戦のズレを意識しながら、相手プロファイルに合わせた調整が重要です。
