# 第12章　リバー チェックビハインドとチェックレイズ

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: リバーでの IP のチェックビハインドと OOP のチェックレイズを正確に理解し、搾取されない対応を習得する。

---

## 12-1 「チェックビハインド」の価値

IP (BTN) がリバーでチェックビハインドすることは、しばしば最善の選択です。

### なぜリバーのチェックビハインドが有効か

```
「ベットよりチェックビハインドが優れる」状況:

1. 薄いバリュー (勝率 55-65%):
   ベットすると、コールしてくる相手は自分に勝っている確率が高い
   → チェックビハインドで「無料でショーダウン」が最善

2. ブラフキャッチャー:
   相手のバリューに負けるが、コールされる価値がない
   → ベットの価値ゼロ → チェックビハインドでポット確保

3. 相手のチェックレイズが多い:
   ベットすると頻繁にチェックレイズされる状況では、
   チェックビハインドでショーダウンが安全
```

### 実戦例

**ボード**: A♣9♦4♠ 8♣ Q♠ で IP が Q♣J♠ を持つ。

- フロップ: Ax が多い状況でチェックバック
- ターン: 8 が落ちて 8x に注意
- リバー: Q が落ちてトップペア

Q♣J♠ (トップペア 2nd キッカー) でベットするか？

```
BB のリバーコールレンジ: AQ, A8, AA, 99, 44 (ツーペア以上), Q-high がブラフ程度
QJ は BB の Ax 系 (A9, A8, A4) や Ax ツーペアには負ける
→ コールレンジの半数以上に負ける → チェックビハインド推奨
```

---

## 12-2 チェックビハインドのレンジ

GTO 的に見ると、IP のリバーチェックビハインドは以下のハンドで構成されます。

### チェックビハインドレンジの構成

```
強いチェックビハインド (トラップ狙い):
  モンスター (ナッツ近辺): BB のリードを誘う
  例: ストレートフラッシュ、クワッズ

通常のチェックビハインド (ショーダウンバリュー):
  薄いバリュー (勝率 50-65%): ベット → コールで損
  例: トップペア弱キッカー、オーバーペア (ボード有り)

ブロッカーチェックビハインド:
  バリューもブラフも出しにくいが、ブロッカーを持つ
  例: Ax on Ax-heavy board (相手のバリューをブロック)
```

---

## 12-3 OOP のチェックレイズ

OOP (BB) がリバーでチェックしてから IP のベットにレイズすることを **リバー チェックレイズ** と呼びます。

### チェックレイズの 2 種類

| 種類 | 例 | 目的 |
|---|---|---|
| **バリューチェックレイズ** | セット、ストレート、フラッシュ | IP からより多くを取る |
| **ブラフチェックレイズ** | バストドロー、ポラライズドブラフ | IP をフォールドさせる |

### チェックレイズが有効な条件

```
バリューチェックレイズが有効:
  IP がほぼ確実にベットする場面 (IP のレンジが広い)
  自分がナッツ付近
  相手のコールレンジにある程度の厚みがある

ブラフチェックレイズが有効:
  バストドローを持つ (ドローミス = チェックレイズブラフのタイミング)
  ブロッカーを持つ (相手のコールハンドをブロック)
  適切な確率でのバランス調整
```

---

## 12-4 チェックレイズに対する IP の対応

IP がリバーでベットし、BB がチェックレイズしてきた。

### 対応基準

```
IP のベットがバリューだった場合:
  コールハンドの基準: BB のチェックレイズレンジのブラフ率 > ポットオッズ

例: ポット 20BB, IP が 10BB ベット, BB が 30BB にレイズ
  → コールコスト: 20BB (30-10の追加)
  → コールするポット: 20 + 10 + 30 = 60BB
  → コールオッズ: 20/60 = 33%
  → BB のチェックレイズの 33% 以上がブラフなら、IP のコールが有利
```

### IP のコール/フォールド基準 (実戦的)

| IP のハンド | BB チェックレイズへの対応 |
|---|---|
| ナッツ〜ナッツ近辺 | コール or 4bet |
| 強いバリュー (2ペア以上) | コール |
| 1ペア | 基本フォールド (弱ブラフキャッチ) |
| ブラフキャッチャー | BB の頻度を読んでコール |

> **実用ルール**: リバーの BB チェックレイズに対して、1ペアでコールするのは通常 -EV です。BB がリバーのチェックレイズを打つとき、そのレンジは強いバリューが中心です。

---

## 12-5 「ドンクベット」への対応

OOP (BB) がリバーで先にベットしてくる「ドンクベット」への対応です。

### ドンクベットとは

チェックではなく、BB が先手でリバーベットすること。

```
フロップ: IP → CBet, OOP → コール
ターン: OOP → チェック, IP → チェックバック or ベット
リバー: OOP → ベット (ドンクベット)
```

### なぜ BB はドンクベットするか

1. **ドローが完成した**: フラッシュ・ストレートで IP のベットを待たずに動く
2. **IP のレンジが弱いと読んだ**: IP のチェックバックで「IP は弱い」と判断
3. **ブラフ**: IP を降ろしにいく

### IP の対応

```
IP の基本方針:
  ドンクベット = ある程度の強さのシグナル (または偽装)
  
  コール基準: IP のハンドがコールオッズを満たす場合
  レイズ: IP がナッツ付近でバリューを最大化したい場合
  フォールド: IP のハンドが BB のバリューレンジに対して弱い場合
```

実戦ではドンクベットに対して「なぜこのタイミングで?」を考えることが重要です。ドローが完成するカードでドンクベットを受けた場合は、そのドロー完成を強く疑います。

---

## 12-6 OOP のバランス: ベット or チェックレイズ

GTO では OOP はリバーで「ベット (ドンクベット) / チェック」を使い分けています。

強いハンドで常にチェックレイズするのは偏りがあり、搾取されます。

```
OOP のバランス例:
  ナッツ (ストレートフラッシュ等): 
    一部 → ドンクベット (IP のレンジが広い状況)
    一部 → チェックレイズ (IP がベットすると確信がある状況)
  
  強いバリュー (フラッシュ, 2ペア等):
    一部 → チェックコール (ポットを大きくしたくない)
    一部 → ドンクベット
```

---

## 12-7 インダクトベット（罠張り）の概念

「インダクトベット」とは、強いハンドであえて「弱く見せるベット」をして相手のレイズを誘う技術です。

```
通常のバリューベット: 強いハンドで普通にベット → 相手がコール or フォールド
インダクトベット:    強いハンドで「弱いサイズ」でベット → 相手がレイズしてくる → コール or 4bet
```

**インダクトベットが有効な条件:**
1. 相手が積極的なプレイヤー（チェックレイズをよくする）
2. 自分がナッツ〜準ナッツ（レイズに対してコールできる）
3. 相手がコールするよりレイズしてくれた方がポットが大きくなる

```
例: ボード A♠K♦Q♥ J♠ T♣（ロイヤルに近い）
  自分: Q♠J♦（2ペア、フラッシュドロー外れ→なし）
  相手がベット → 自分はチェックレイズ

  逆に:
  自分: A♠Q♦（AQ 2ペア = ナッツ近辺）
  相手がチェック → 33% ポットの「誘いベット」で相手のブラフチェックレイズを誘う
```

## 12-8 スロープレイとの使い分け

チェックビハインドには「ショーダウンバリュー確保」「スロープレイ」「インダクト」の 3 つの意味があります。

| チェックビハインドの理由 | 状況 | 例 |
|---|---|---|
| ショーダウンバリュー確保 | 勝率 50〜65%、ベットで逆選択が起きる | トップペア弱キッカー |
| スロープレイ（罠） | ナッツ持ち、相手がリバーブラフしてくれる期待 | セット、ストレート |
| インダクトベット後の待ち | 小さいベットで相手のレイズを待つ | ナッツ、小さいバリュー |

実戦では「なぜチェックビハインドするか」を明確にすることが判断精度を上げます。「なんとなく」のチェックビハインドが最も EV を失います。

## ミニクイズ

### 問1

IP（BTN）がリバーでチェックビハインドすべきハンドはどれですか。ボードは A♥T♠5♦ 8♣ 3♦。

1. A♠K♦（トップペア TPGK）
2. T♣9♣（セカンドペア）
3. 5♣5♦（セット）

### 問2

OOP（BB）がリバーでチェックレイズした場合、IP が 1ペアでコールすることが正当化されるのはどの状況ですか。

1. BB のチェックレイズレンジにブラフが多い（ブラフ率がポットオッズを上回る）
2. 自分の 1ペアが比較的強い
3. ポットが大きいので乗り続ける

---

### 解答

- **問1**: 2（セカンドペア T9 は「コールされると負けるが、フォールドされると一応ポット取れる」中程度ハンド → チェックビハインドでショーダウン。AK はバリューベット、55 はスロープレイ or バリューベット）
- **問2**: 1（ポットオッズを上回るブラフ率 → コール有利。1ペアの強さやポットサイズは直接的な判断基準ではない）

---

> **本章まとめ**
>
> - IP のチェックビハインドは「薄いバリューを守る」重要な技術
> - BB のチェックレイズは強いシグナル (1ペアでのコールは通常 -EV)
> - ドンクベットを受けた場合は「なぜこのカードで?」を分析する
> - OOP もドンクベット/チェックレイズのバランスを保ちながら動く

---

**【GTO とのズレ】**

GTO ではチェックビハインドとバリューベットの境界は「ベット額」によって変わります。

例えば「50% ポットベット → トップペア OK」「100% ポットベット → 2ペア以上」のように、ベットサイズに応じてバリューラインを調整します。本章の「1ペアはフォールド」は100% ポットベットやオーバーベットを仮定した場合の基準です。

実戦では「相手は今、どれくらいのサイズでどれくらいの頻度でブラフをするか」の読みがチェックビハインドの決断に大きく影響します。GTO の純粋な計算に対し、実戦ではこの「相手モデル」がズレの主要因です。
