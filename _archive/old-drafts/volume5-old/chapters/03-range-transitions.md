# 第3章　ストリート横断のレンジ遷移

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: フロップ・ターン・リバーの各ストリートでアクションがレンジをどう変化させるかを追跡し、リバーに到達したときに相手のレンジを推定できるようにする。

---

## 3-1 アクションはレンジへの情報刻印である

第2章では Capped と Uncapped というレンジの状態を学びました。本章ではその状態が「どのアクションによって決まるか」を、フロップからリバーまでの3ストリートにわたって体系化します。

ポーカーの各アクションは単なる意思決定ではありません。アクションを選ぶたびに、自分のレンジの情報が相手に開示されます。逆に、相手のアクション履歴から相手のレンジを絞り込むことができます。

この「アクション = レンジへの情報刻印」という視点を持つことが、リバー判断の出発点です。

```
プリフロップ前: 両者のレンジ = 全ハンド（1326 コンボ）

BTN オープン    → BTN レンジが約 45% に絞られる
BB コール       → BB レンジが約 45% に絞られる

フロップ CBet   → BTN: Uncapped（強い + ブラフ）
フロップ コール → BB: Capped（中強度の集合）

ターン CBet     → BTN レンジがさらにバリューヘビー化
ターン コール   → BB の弱ハンドが除外され、より強い中強度に収束

リバー前: 両者のレンジが最も絞り込まれた状態に達する
```

ストリートが進むほどレンジが収束し、相手の「最もあり得るハンド群」が浮かび上がってきます。この収束プロセスを「レンジ遷移」と呼びます。

---

## 3-2 5つのアクションとレンジへの影響

### アクション1: ベット（攻撃開始）

ベットを打つと、ベット側のレンジは「バリューハンド + ブラフ」にポラライズ（二極化）します。同時に、相手の弱いハンドがフォールドしてレンジから除外されます。

```
BTN がフロップ CBet:
  BTN のレンジ: バリュー（セット・トップペア等）+ ブラフ → Uncapped 状態
  BB のコールしなかったハンド: レンジから除外
```

GTO の観点では、ベットレンジはバリューとブラフのバランスが必要です。バリューだけでベットすると相手はフォールドしやすくなり、ブラフが増えすぎると相手はコールで搾取できます。この均衡点が GTO ベットレンジの構造を決めます。

### アクション2: チェック（パスまたは罠）

チェックは必ずしも弱さを意味しません。チェックを選んだプレイヤーのレンジには「中強度」と「トラップ（スロープレイ）」が混在します。

```
IP がフロップ チェックバック:
  IP のレンジ: 中強度（1ペア等でショーダウン志向）+ 一部スロープレイ
  OOP の解釈: IP はやや弱い → 次のストリートで先手を取りやすくなる

OOP がフロップ チェック → IP が CBet:
  OOP がコールした場合: フォールドするほど弱くない（最低強度を超えている）
  ただしレイズしなかった: ナッツが少ない → Capped 寄り
```

両者がチェックした場合、双方のレンジに強いハンドが少ない（両者 Capped）状態になります。このとき次のストリートの主導権は「ターンカードで改善した側」が得ます。

### アクション3: コール（ついていく）

コールはレンジを「中強度」に収束させます。強いハンド（ナッツ → レイズが推奨）と弱いハンド（フォールドが推奨）の双方がレンジから除外されるためです。

```
BB がフロップ CBet にコール:
  BB のレンジ: トップペア〜セカンドペア、強いドロー、弱いドロー
  除外: ナッツ（セット等、通常はチェックレイズが推奨）
  除外: 完全な空振り（フォールドが推奨）
```

コールが続くと中強度がさらに絞り込まれます。フロップコール → ターンコールと重なると、「ターンまでコールし続けられる強度を持つハンド」のみが残ります。コールは Capped 状態を維持するアクションです。

### アクション4: レイズ（強さの主張）

レイズはレンジを「ナッツ + 一部ブラフ」にポラライズし、Uncapped 状態を生み出します。

```
BB がフロップ チェックレイズ（CR）:
  BB のレンジ: セット・強い2ペア・強ドロー（ナッツ級）+ ブラフ CR
  除外: 中強度1ペア（CR しないでコールまたはフォールドが推奨）

→ BB の CR = Uncapped なポラライズレンジ
```

チェックレイズを受けた IP がコールで返した場合、IP のレンジは「3-bet するほど強くない中強度以上」に絞られます。CR 後は BB が Uncapped、IP が Capped 気味という非対称状態になります。

### アクション5: フォールド（降りる）

フォールドはそのプレイヤーのレンジ遷移を終了させます。しかし残ったプレイヤーの観点では「相手がフォールドしなかった = 最低強度を超えている」という情報が各ストリートで蓄積されています。複数ストリートのコール継続は、それだけ相手のレンジが絞り込まれていることを意味します。

## 3-3 Capped / Uncapped 状態遷移の整理

第2章で学んだ Capped / Uncapped の概念を、アクションのシーケンスとして整理します。

| フロップのアクションシーケンス | BTN の状態 | BB の状態 |
|---|---|---|
| CBet → コール | Uncapped | Capped |
| チェックバック → チェック | Capped | Capped |
| CBet → チェックレイズ → コール | Capped 気味 | Uncapped |
| CBet → チェックレイズ → 3-bet → コール | Uncapped | Uncapped |

最も頻繁に起きるのは「CBet → コール」のパターンです。このとき BTN が Uncapped、BB が Capped という非対称状態でターンに入ります。

ターンでも同様の更新が起きます。BTN がターンでもベットすれば Uncapped を維持し、チェックバックすれば Capped に傾きます。BB がターンでコールを続ければ Capped のままで、さらに弱ハンドが除外されます。

## 3-4 主要な4シーケンス

フロップからリバーへの代表的な流れを4パターンで整理します。これらがリバー判断の「前提の読み方」の骨格になります。

### シーケンス A: 全ストリートで IP がアグレッサー（3バレル）

```
フロップ: BTN CBet → BB コール
  BTN: Uncapped   / BB: Capped

ターン:   BTN バレル → BB コール
  BTN: Uncapped 維持（バリューヘビー化）
  BB: 弱ハンド除外 → 強い中強度に収束

リバー前の状態:
  BTN: Uncapped を2ストリートにわたり主張した → バリュー主体のレンジ
  BB:  2ストリートコール = 強い中強度（2ペア・強ドロー完成・TPTK等）
       弱ハンドはフロップかターンでフォールドしている
```

BBが2ストリートコールし続けたということは、コール判断を繰り返せる強度があったということです。リバーでのBBの主力レンジは「TPTK 以上、2ペアやドロー完成を含む」クラスになります。

### シーケンス B: ターンで OOP が チェックレイズ

```
フロップ: BTN CBet → BB コール
  BTN: Uncapped   / BB: Capped

ターン:   BB チェック → BTN ベット → BB チェックレイズ → BTN コール
  BTN: Capped 気味（CR に 3-bet しなかった）
  BB:  Uncapped（ターン CR = ナッツ + ブラフのポラライズ）

リバー前の状態:
  BTN: 強いハンドを持っているが、ナッツの主張は弱い
  BB:  Uncapped → 主導権を持つ側に逆転
```

このシーケンスではリバーの主導権が BB にある場合が多くなります。BB のリバードンクベットや大きなベットに BTN は受け身で対応することになります。

### シーケンス C: フロップ・ターン両者チェック

```
フロップ: BTN チェックバック → BB チェック
  BTN: Capped   / BB: Capped（両者 Capped）

ターン:   BB チェック → BTN チェックバック（または BTN 遅延 CBet）
  両者チェック → BTN: さらに Capped 強化
  BTN 遅延 CBet → BTN の Uncapped 意志表示

リバー前の状態（両者チェックの場合）:
  BTN: Capped 強化（2ストリートチェックバック）
  BB:  中強度だが Capped
  主導権: 中立またはリバーで改善した側
```

両者チェック展開では、リバーのドンクベットが BB から出やすくなります。「チェックしてきた IP は弱い」という読みが成立しやすいためです。

### シーケンス D: リバーで OOP がリード（ドンクベット）

```
前提: いずれかのシーケンスで両者がリバーに到達

リバー: BB がドンクベット
  → BB の主張: 「ターンからの改善がある、またはストーリーを持つ」
  → BTN から見ると: BB の Capped は解除の可能性がある
  → BTN の対応: コール、フォールド、またはレイズ

リバー ドンクベットの分類:
  ナッツ系: 完成ドロー・ボード改善によるバリュー
  ブラフ系: 外れたドロー・弱いハンドでフォールドを狙う
  中間系: ミスプレイ（GTO 的には推奨されない頻度が高い）
```

リバーで OOP がリードする場合、そのレンジは「自信がある強いハンド」か「外れたドローのブラフ」に偏ります。中程度のハンドのドンクベットは GTO 的には頻度が低く、対応するリバーの範囲が絞られます。

## 3-5 リバー直前のレンジ最終形

### 2ストリートコールしたプレイヤーのレンジ構造

3ストリートすべてコールしたプレイヤー（シーケンス A の BB）のレンジは、以下の構造を持ちます。

```
3ストリート全コールのレンジ:

最も多いカテゴリ: 強い中強度
  TPTK・2ペア・完成ドロー（フラッシュ・ストレート）
  → 3回コールし続けられる強度を持つハンド

次のカテゴリ: スロープレイのナッツ
  セット・ナッツストレートをスロープレイした場合
  → 頻度は低いが存在する（罠の可能性）

少ないカテゴリ: 弱い中強度
  「ポット規模から降りにくい」感覚で続けたハンド
  → 数学的には誤りだが、実戦では存在する
```

このレンジに対するリバーブラフは GTO 的にはほぼ機能しません。2ストリートコールしてきた相手はショーダウン価値を求めているため、ブラフに反応してフォールドする可能性が低いためです。

### ターンでコールを止めたプレイヤーのレンジ

ターンでフォールドしたプレイヤーのレンジは分析対象ではありません。重要なのは「リバーまで残ったプレイヤーのレンジ」です。ターンコールのあとリバーに到達したOOP（BB）は、フロップでコールした全レンジから「ターンでフォールドした弱ハンド群」を除いた構造になっています。

ターン後にリバーに入るBBの主力は次のとおりです。

| カテゴリ | 具体例 | 状態 |
|---|---|---|
| TPTK またはそれ以上 | Kx on K72 でターンブランク | 維持 |
| 2ペア | K7 on K72 + ブランク | 維持 |
| 完成ドロー | OESD やフラッシュドローがターンで完成 | 強化 |
| 未完成ドロー | フラッシュドローが外れた場合はターンでフォールドが多い | 除外 |
| セカンドペア〜ボトムペア | 7x や 2x on K72 | ポット次第で残ることも |

「ターンで降りなかった = ある程度の強度がある」という読みを常に持つことが、リバー判断の精度を上げます。

## 3-6 リバー前の4ステップ推定フロー

ここまでの内容を実戦で使うための4ステップフローです。

```
ステップ1: プリフロップのアクションからベースレンジを確認
  「BTN オープン ≈ 45%」「BB コール ≈ 45%」
  「3-bet ポット = BTN の 3-bet レンジ vs BB のコールレンジ」

ステップ2: フロップのアクションで Capped / Uncapped を更新
  CBet:             BTN → Uncapped
  BB コール後:      BB → Capped
  BB チェックレイズ後: BB → Uncapped、BTN コール後 → Capped 気味
  チェックバック:   BTN → Capped

ステップ3: ターンのアクションでさらに更新
  BTN バレル:       BTN のブラフが減少（バリューヘビー化）
  BB コール:        BB の弱ハンドが減少（中強度に収束）
  BTN チェックバック: BTN の Capped 化が進行
  BB ドンクベット:  BB の Uncapped 化が進行（ターン CR 後の BB は特に強力）

ステップ4: リバーで「残ったレンジ」で判断
  相手の残レンジ: 何が最もあり得るか
  自分のレンジ:   今のアクションは相手にどう見えるか
  EV 比較:        コール / フォールド / ベットのどれが最大か
```

このフローを実戦で回す習慣が、リバー判断の精度を大幅に高めます。自分のハンドの強さだけで判断せず、「今ここにある両者のレンジ」を出発点にすることが核心です。

## 3-7 レンジ推定の実例

### 実例: K♠7♦2♣ フロップ + 9♥ ターン + A♠ リバー

シーケンス A（BTN CBet → BB コール → ターン BTN バレル → BB コール）の場合。

**フロップ CBet → コール後の BB のレンジ（Capped）**:
- トップペア: Kx（強キッカー以外）
- セカンドペア: 7x
- ボトムペア: 2x
- バックドアドロー: 9-8s、6-5s 等（3枚連続の弱いセミブラフ）
- オーバーカード: Ax（まだ役なし）

**ターン 9♥ → バレル → コール後の BB のレンジ（Capped 継続・さらに絞込み）**:
- Kx（トップペア維持）
- 7x（セカンドペア維持）
- 98s（9-8でターンがトップペアに昇格、または9ペアが2ペア相当の強度に）
- フロップで Ax を持っていたハンドはターンコールを続けるものと降りるものに分岐

**リバー A♠ 後の BB のレンジ推定**:
- Ax（A がリバーで落ちたためトップペアに昇格）
- Kx（2番手に降格、ただし依然として強い）
- 2ペア系（A-K の2ペアなど）
- ターンまで持ち込んだ 7x・9x はリバーA 落ちで相対的に弱化

リバー A♠ は BB の「オーバーカード組」を強化し、「元々のトップペア組（Kx）」を弱化させます。BTN がこのリバーでバリューベットをするには、自分がAx かそれ以上を持っているかが重要になります。

## 3-8 第4章への橋渡し

本章では「アクション → レンジ遷移」を3ストリートにわたって追跡する方法を整理しました。

レンジ遷移を追跡することで、リバーに到達したときの「相手が持ちうるハンドの集合」が見えてきます。しかし実際の判断では、相手のレンジを把握した上で「自分のハンドがその相手のレンジに対してどの役割を担うか」を決める必要があります。

リバーでは第5章で確認したとおり、ハンドのロールは3つに集約されます。

- **バリュー**: コールされても高い確率で勝てる
- **ブラフ候補**: コールされると負けるが、フォールドさせれば利益になる
- **チェック**: バリューを出せるほど強くなく、ブラフにするには強すぎる中間

次章（第4章）では、自分のハンドをこの3層に分類するための判断軸を体系化します。レンジ遷移の追跡で「相手の持ちうるハンド」が見えたとき、その相手に対して自分のハンドがどの層に属するかを素早く決めるための枠組みです。

## ミニクイズ

### 問1

BTN がフロップ CBet → BB コール → ターン BTN チェックバック という展開です。ターン後の各レンジの状態として正しいものはどれですか。

1. BTN: Uncapped のまま / BB: Capped のまま
2. BTN: Capped に変化 / BB: Capped のまま（両者 Capped）
3. BTN: Capped に変化 / BB: Uncapped に逆転

### 問2

BTN CBet → BB チェックレイズ → BTN コール という展開後、リバーの主導権はどちらにありますか。

1. BTN（CBet のアグレッサーだから）
2. BB（チェックレイズで Uncapped 化したため）
3. 両者同等（アクションが相殺されるから）

### 問3

「2ストリート全コールしたプレイヤーのリバーレンジ」の説明として最も正確なものはどれですか。

1. 弱いハンドが多く、ブラフを打てば多くがフォールドする
2. ナッツが主体であり、相手はほぼ勝ちを確信している
3. 強い中強度（TPTK・2ペア・完成ドロー等）が主体であり、ブラフへの耐性が高い

---

### 解答

- **問1**: 2（BTN のターンチェックバックは「ナッツなら打っていた」というシグナルです。フロップ CBet は Uncapped でしたが、ターンチェックバックで Capped に変化します。BB はコールのまま Capped が継続します。両者 Capped になると、次のストリートの主導権はリバーカードで改善した側が持ちます）
- **問2**: 2（BB のチェックレイズはナッツ + ブラフのポラライズ = Uncapped 化です。BTN はコールで返した時点で「3-bet するほど強くない」と開示されるため、Capped 気味になります。リバーでは Uncapped レンジを持つ BB が先手攻撃やドンクベットを有効に使える立場です）
- **問3**: 3（2ストリートコールし続けたプレイヤーは、ナッツならレイズしていた可能性が高く、弱ハンドなら早い段階でフォールドしていたはずです。残ったレンジは「強い中強度」が主体となり、ショーダウン価値を求めてリバーまで持ち込んでいます。このレンジへのブラフは GTO 的に有効性が低くなります）

---

> **本章まとめ**
>
> - 各アクションはレンジに情報を刻印する: ベット→ポラライズ、コール→中強度化、チェック→中強度またはトラップ、レイズ→Uncapped 化
> - Capped / Uncapped の状態はアクションの積み重ねで決まり、各ストリートで更新される
> - 最頻パターン「CBet → コール」では BTN: Uncapped、BB: Capped でターンに入る
> - 4シーケンス（全 IP アグレッサー / ターン BB CR / 両者チェック / リバー BB ドンク）でリバー前の状態は大きく異なる
> - 2ストリート全コールした相手のレンジは「強い中強度主体」であり、ブラフへの耐性が高い
> - 4ステップの実戦フローでレンジ遷移を追跡し、リバーで「残ったレンジ」を判断の出発点にする

---

**【GTOとのズレ】**

GTO はすべてのアクションシーケンスで精密なレンジ遷移を計算しています。実戦での最大の「GTOとのズレ」は、**レンジ遷移を追跡せずに自分のハンドの強さだけで判断すること**です。

典型例を挙げます。BTN がフロップでチェックバックし、ターンでも BBがチェックした状況を想像してください。「自分は KT で1ペア = 中程度だからベットしない」と判断してしまうプレイヤーがいます。しかし GTO 的には、この状況では両者が Capped 化しているため、チェック継続が適切な場面と遅延 CBet が有効な場面が混在します。レンジ遷移を無視した判断は、どちらの選択にも「なぜ」がなくなります。

もう一つの典型的なズレは、「コールレンジには強いハンドがない」という思い込みです。実際には、コールレンジにはスロープレイのセットや完成ストレートが一定数含まれています。特にウェット板では、BB のコールレンジにナッツ級のハンドが潜んでいます。この点を過小評価すると、リバーでのブラフや大きなバリューベットが不適切に多くなります。

「相手が今どのレンジを持っているか」を4ステップで継続的に更新する習慣が、GTOとの差を縮める最も重要なスキルです。次章では、追跡した相手のレンジを前提に「自分のハンドをどの役割に振り分けるか」を体系化します。
