# ICM 理論と Malmuth-Harville アルゴリズム

## ICM とは

ICM（Independent Chip Model、独立チップモデル）は、トーナメントでチップを賞金額（$EV）に変換するための数学モデルです。

キャッシュゲームでは「チップ = 現金」なので、1 BB の利益は常に同じ価値を持ちます。トーナメントは違います。チップは賞金構造を通じて間接的にしか現金化できず、しかもその換算レートは**スタック分布**と**残り賞金**に依存して刻一刻と変わります。

ICM はこの換算レートを与える唯一の標準モデルです。本書では ICM が出力する値を **ICM equity（chip→$EV 変換の結果）** と呼びます。

---

## 基本仮定

ICM は以下を仮定します。

1. **どのプレイヤーがいつ勝つかはチップ量に比例する**。例: 残りスタックが 4500 / 3000 / 2500 のとき、それぞれが 1 位になる確率は 45% / 30% / 25%。
2. **同様に 2 位、3 位…も「残りチップ」に比例する**。1 位が確定した後、残りスタックの中で同じ比例則が再帰的に適用される。
3. **スキル差は考慮しない**。全員同じ実力と仮定する（実戦補正は別途必要）。

仮定 3 は ICM の限界として知られていますが、本書ではまずこの「素の ICM」を学び、第6章で**スキル補正**と**ポジション補正**を追加します。

---

## Malmuth-Harville アルゴリズム

ICM の計算式は Malmuth (1987) と Harville (1973) に由来します。

### 1位の確率

\[
P(i \text{ が 1 位}) = \frac{s_i}{S}
\]

ここで $s_i$ はプレイヤー $i$ のスタック、$S = \sum_j s_j$ は全チップ。

### 2位の確率（条件付き）

プレイヤー $j$ が 1 位という条件下で、

\[
P(i \text{ が 2 位} \mid j \text{ が 1 位}) = \frac{s_i}{S - s_j}
\]

### 一般の k 位

完了順 $(j_1, j_2, \ldots, j_k)$ となる確率は、

\[
P(j_1, j_2, \ldots, j_k) = \prod_{m=1}^{k} \frac{s_{j_m}}{S - \sum_{l < m} s_{j_l}}
\]

### $EV の計算

プレイヤー $i$ の $EV は、すべての完了順 $\sigma$ について確率と賞金額をかけて足し合わせる。

\[
\$EV(i) = \sum_{\sigma} P(\sigma) \cdot \text{payout}(\text{rank of } i \text{ in } \sigma)
\]

n 人なら $n!$ 通りの順列を全列挙する。n = 9 で 362,880 通り。最終卓（n ≤ 9）なら数秒で計算できる。

## 数値例：3-handed の ICM

3 人プレイヤー、賞金 $50 / $30 / $20、スタックが 5000 / 2500 / 2500 のとき。

### 各プレイヤーが 1 位になる確率

- P1: 5000 / 10000 = 50%
- P2: 2500 / 10000 = 25%
- P3: 2500 / 10000 = 25%

### P1 の $EV

P1 が 1 位の場合: 50% × $50 = $25.0

P2 が 1 位 (25%) で、P1 が 2 位の確率は 5000 / (10000 − 2500) = 5000/7500 = 66.67%
→ 25% × 66.67% × $30 = $5.00

P2 が 1 位 (25%) で、P3 が 2 位の場合 (1 − 66.67% = 33.33%) → P1 は 3 位
→ 25% × 33.33% × $20 = $1.67

P3 が 1 位 (25%) で、P1 が 2 位 → 25% × (5000/7500) × $30 = $5.00
P3 が 1 位 (25%) で、P2 が 2 位 → 25% × (2500/7500) × $20 = $1.67

合計 P1 $EV: $25.00 + $5.00 + $1.67 + $5.00 + $1.67 = **$38.33**

### 計算結果

| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 5000 | 50.00% | 38.33 | 38.33% |
| P2 | 2500 | 25.00% | 30.83 | 30.83% |
| P3 | 2500 | 25.00% | 30.83 | 30.83% |

**重要な観察**: P1 は **チップの 50% を持っているが、$EV は 38.3% しか得ていない**。トーナメントの最大の特徴である「ICM 圧縮」がここに現れる。チップを増やせば増やすほど、その追加チップ 1 枚あたりの $価値は減衰する。

---

## ICM 圧縮の意味

トーナメントのチップは「逓減的価値（diminishing returns）」を持つ。1 枚目のチップは賞金圏入りに直結するため非常に価値が高いが、リードしているプレイヤーが追加 1 枚を得ても得られる $価値は小さい。

この非線形性こそが、トーナメントとキャッシュの根本的な違いです。

```
キャッシュ: チップ価値 ∝ チップ数（線形）
トーナメント: チップ価値 ∝ ICM equity（凸関数、逓減）
```

リバースサイドの帰結:

- **大きなスタック**: 1 チップ追加の $価値は小さい → リスクを取る価値も小さい（守備的に）
- **小さなスタック**: 1 チップ追加の $価値は大きい → リスクを取る価値が大きい（積極的に）

これが本書 第3部 で扱う「スタック深度別戦略」の数学的根拠です。

---

## ICM の限界

1. **スキル差を無視**: 弱い相手に勝ちやすいプレイヤーは、ICM 値より高い実 $EV を持つ。この補正は **ICM 補正** として後述する。
2. **ポジションを無視**: ボタン側に座る/座らない、ブラインド構造の影響は別途。
3. **将来のブラインドを無視**: 残りプレイ時間が短いほど ICM 値が事実上低下する。

実戦では ICM をベースラインとし、これらの要因で「修正」する形で使う。

## 計算ツール

本シリーズでは Python スクリプト `scripts/icm_calc.py` を提供し、任意のスタック分布から ICM equity を即座に計算できる。

```bash
python scripts/icm_calc.py --stacks "4500,3000,1500,1000" --payouts "50,30,20"
```

主要コマンド:

- `--stacks`: チップスタック（カンマ区切り）
- `--payouts`: 賞金額（1位、2位、…）
- `--bubble-factor N`: プレイヤー N の bubble factor を計算
- `--preset KEY`: 標準シナリオ（hu / 3-handed-equal / bubble-9max-stt / ft-9max など）
- `--all-presets`: 全シナリオを表示
- `--json`: JSON 出力
