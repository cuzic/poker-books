# 第 4 章　Cash ディフェンス

ディフェンス判断はすべて同じスコア式を使います。変わるのは閾値 T だけです。

## 4.1 BB ディフェンス（vs オープン）

BB は 1BB 投資済みでポットオッズが最も良く、最も広いレンジが正当化されます。

### 判定フロー（HU）

```
Score ≥ T_3bet          → 3-bet
T_call ≤ Score < T_3bet → コール
Score < T_call          → フォールド
```

### オープナー別 閾値（Cash GTO データ）

| オープナー | T_3bet | T_call | 備考 |
|---|---|---|---|
| UTG | 36 | 23 |  |
| HJ | 34 | 22 |  |
| CO | 30 | 20 |  |
| BTN | 28 | 18 |  |
| SB | 30 | 18 | BvB |

スラッシュなし行は T_3bet = T_call です。つまりコールレンジがなく、3-bet か fold かの二者択一になります。

### 計算例

**BB vs UTG open — ATo**
```
H=14, L=10, gap=3, offsuit
Score = 14 + 10 - min(3,4) + 4 = 25
T_call (vs UTG) = 23
25 ≥ 23 → コール ✓
```

**BB vs UTG open — J8s**
```
H=11, L=8, gap=2, suited
Score = 11 + 8 + 7 - min(2,4) = 24
T_call (vs UTG) = 23
24 ≥ 23 → コール ✓
```

## 4.2 IP ディフェンス（vs オープン）

IP ポジション（BTN / CO / HJ）がオープンに 3-bet またはコールで参加します。

スラッシュ表記 = **T_3bet / T_call** です。スラッシュなしの場合は 3-bet or fold（コールレンジなし）になります。

| 自分 / オープナー→ | UTG | HJ | CO |
|---|---|---|---|
| **BTN** | 36 / 29 | 36 / 28 | 26 |
| **CO** | 32 / 30 | 28 | — |
| **HJ** | 30 | — | — |

---

## 4.3 OOP（SB）ディフェンス

SB はポジション不利です。BB より tight で、suited 補正は適用しません。

| オープナー | T_3bet | T_call |
|---|---|---|
| UTG | 34 | 30 |
| HJ | 32 | 29 |
| CO | 30 | 27 |
| BTN | 25 | 25 |

---

## 4.4 オープナー vs 3-bet（4-bet or call or fold）

3-bet を受けてオープナーが判断する局面です。GTO データから導き出した閾値を使用します。

| 判断 | 閾値 | ハンド例（Cash） |
|---|---|---|
| 4-bet | **37** | AA, KK, AKs, QQ |
| コール | ≥ 約31 | AQs, JJ, AJs, TT, ATs, KQs |
| フォールド | < 31 | — |

`Score ≥ 37 → 4-bet` / `31〜36 → コール` / `< 31 → フォールド` という流れになります。

---

## 4.5 4-bet ディフェンス（3-bettor が 4-bet を受けた場合）

※ 理論値です。GTO 検証は行なっていません。100BB・標準サイジング想定です。

```
open 2.5BB → 3-bet 9BB → 4-bet 22BB
コール追加コスト: 22 − 9 = 13BB
ポットオッズ: 13 / 46 ≈ 28%（スタック残 ≈ 78BB、SPR ≈ 2.4）
```

| 判断 | 閾値目安 | ハンド例 |
|---|---|---|
| 5-bet shove | ≥ **37** | AA, KK, AKs, QQ |
| コール（4-bet） | ≥ 約31 | AQs, JJ, AJs, TT, ATs, KQs |
| フォールド | < 31 | A5s 等ブラフ 3-bet を含む |

ポイントは、4-bet レンジ（Score ≥ 37）と 5-bet shove レンジが対称になることです。
コール判断では、ポットオッズ 28% に加えて残スタック SPR≈2.4 の implied odds も加味しましょう。

---

## 4.6 5-bet ディフェンス（5-bet オールインを受けた場合）

※ 理論値です。GTO 検証は行なっていません。100BB 全イン想定です。

```
コスト: 78BB（4-bet 22BB 投資済み → 残 78BB を追加）
ポットオッズ: 78 / 200 = 39%
```

コール可否は**相手の 5-bet レンジ**に依存します。以下の表を参考にしてください。

| 相手の 5-bet レンジ | KK | QQ | AKs | 実戦判断 |
|---|---|---|---|---|
| AA のみ | 18% ✗ | 18% ✗ | 12% ✗ | AA 以外はフォールド |
| AA / KK / AKs | 32% ✗ | 27% ✗ | 32% ✗ | AA のみコール |
| AA / KK / AKs / QQ（標準） | 57% ✓ | 40% ✓ | 42% ✓ | KK / QQ / AKs コール可 |

**実戦推奨**: 相手の 5-bet レンジに KK や QQ が含まれると読めるなら KK・QQ・AKs はコールしてもよいでしょう。
AA のみと読めるなら KK もフォールドするのが理論的に正しい判断です。

小ペア・スーテッドコネクターは全イン後に implied odds がゼロになるため、
ポットオッズ 39% を超えられず常にフォールドになります。

## 【GTO とのズレ】

### シナリオ別の実測整合率

GTO Wizard hand-level の主アクション（50%+ frequency）と本式の予測を照合した結果をまとめました。

| シナリオ | 整合率 | 備考 |
|---|---|---|
| BB defense（補正なし） | **74.1%** | 22〜44 / 32s〜53s を取りこぼし |
| BB defense（補正後） | 約 87% | 第 2 章 §2.5 の suited −2 補正適用 |
| IP defense（BTN/CO/HJ） | **91.5%** | 本式が最も機能するシナリオ |
| SB OOP defense | **89.8%** | BTN vs SB のみ T_3bet=T_call=25 |
| vs 3-bet（4-bet or call or fold） | **90.3%** | 12 シナリオ平均 |

### 各シナリオの主なズレ

**BB defense**: 22 / 33 / 44 / 32s / 42s / 43s / 52s / 53s（Score 12〜21）が
本式では fold ですが GTO は 90〜100% call を示唆しています。原因は set mining と BB ポットオッズです。
**第 2 章 §2.5 の suited −2 補正 + 低ペアコール推奨** を活用すれば、74% → 87% に改善できます。

**IP defense**: BTN vs CO は GTO が実際にはコールレンジを持つのですが、
本式では T_3bet ≈ T_call となり事実上 3-bet or fold に単純化されます。
それでも整合率 91.5% で本式が最もよく機能するシナリオなので、実戦には充分です。

**SB OOP defense**: BTN open に対しては T_3bet = T_call = 25（コールレンジなし）が GTO の標準です。
他オープナーに対しては 3-bet と call を分けるようになります。

**vs 3-bet**: 12 シナリオすべてで 85〜93% の安定した精度が得られています。
T_4bet = 37 / T_call = 31 という 2 段階閾値が機能している証です。

### 検証対象外

4.5（4-bet defense）/ 4.6（5-bet defense）は GTO ソルバー検証を行なっていません。
ポットオッズ理論とモンテカルロ法（n=40,000）による近似値として参考にしてください。
