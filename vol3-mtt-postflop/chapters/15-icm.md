# 第15章 ICM 補正——バブル/FT での UCBS-v2 調整

MTT のバブルやファイナルテーブル（FT）では、チップ EV とドル EV が乖離します。
本章では ICM（Independent Chip Model）がポストフロップ戦略に与える影響を定性的に解説し、
UCBS-v2 への補正方法を一般ルールとして示します。
なお、ICM に特化した定量データは現時点では未取得であり、本章の数値は定性的な推定値です。
将来的な MTTGeneral_ICM6m200PTT2 データ取得後に定量化する予定です。

## ICM とは——チップ EV と $EV の乖離

ICM（Independent Chip Model）は、チップスタックを賞金ドルに換算するモデルです。
プリフロップ（Vol1 参照）では ICM がオープンレンジやコールレンジを引き締める効果を学びました。
ポストフロップでも同じ圧力が働きます。

**チップ EV と $EV の違い**を具体例で確認します。

- チップ EV: ポットの 50% を勝つ期待値（チップ量）
- $EV: ポットを勝ったときと負けたときの**賞金差**の期待値

バブル直前（たとえば 11 人残り 10 人賞金圏）では、
脱落すると賞金 $0 で確定します。一方、サバイブすれば $XX の最小賞金が保証されます。
この「脱落コスト」が大きいほど、コインフリップ的な勝負を避けるインセンティブが高まります。

**ICM 圧力の大きさ**はおおむね以下のステージに比例します。

| ステージ | ICM 圧力 | 説明 |
|---|---|---|
| 序盤（SBR≥25、賞金圏に遠い） | 無視可 | チップ EV ≈ $EV |
| 中盤 | 小〜中程度 | 微調整が必要 |
| バブル直前（入賞ライン付近） | 大きい | 大幅な守り志向 |
| FT（最終卓残留中） | ステージ・賞金差次第 | 強い守りからアグレッションまで幅広い |

## バブルでの cbet 調整——全体 -5〜-15pt

バブル直前では UCBS-v2 の計算結果に**マイナス補正**を加えることで ICM プレッシャーを反映できます。

一般的な推定補正値（定量データ未取得、定性推定）:

| プレイヤー状況 | 推定補正 | 理由 |
|---|---|---|
| **平均スタック以上（ビッグスタック）** | -5〜-8pt | 脱落リスク低、適度に引き締め |
| **ショートスタック（存亡の瀬戸際）** | -10〜-15pt | 脱落 = 収入ゼロ、大幅に守り志向 |
| **コール側（BB defense）** | -5〜-10pt | DCBS 値からさらに折り曲げ |

バブルでの調整ルール（簡易版）:

1. UCBS-v2 の計算結果 freq を求める
2. バブル補正 B を差し引く（ビッグスタック: B=5、ショート: B=10〜15）
3. 結果が 30% 未満なら check を優先、65% 以上なら bet（補正なしと同じ）

**注意**: この補正値は GTO Wizard の ICM ポストフロップデータから**直接算出したものではありません**。
MTT ポストフロップ ICM データ（MTTGeneral_ICM6m200PTT2 など）は現時点で未取得です。
これらの数値は経験則と既存の ICM プリフロップ補正値からの類推であり、将来の実測で更新予定です。

## FT（ファイナルテーブル）での cbet 調整

FT では賞金差が最大となり、ICM プレッシャーが最も複雑になります。

**賞金差の概念**: FT 9 人残りでは 9 位と 1 位の賞金差が大きく、
スタックを失うコストは中盤より遥かに高い場合があります。
一方、残り 2-3 人（HU〜3人）になると賞金差が確定的になり、
ここではチップ EV の最大化が再び重要になります。

| FT 状況 | 推定補正 | コメント |
|---|---|---|
| 9 人残り（初期 FT） | -8〜-12pt | 早期脱落のコストが大きい |
| 5-6 人残り | -5〜-10pt | 序列確定に向けて引き締め |
| 3 人残り | -3〜-5pt | 賞金差が縮小してくる |
| HU（1 対 1） | 0〜-3pt | ほぼチップ EV で判断可 |

**ビッグスタック vs ショートスタック**:

FT ではスタックの相対的な大きさも重要です。
ビッグスタックはショートスタックをプレッシャーに掛けられるため、
ICM 上は**より攻撃的**に動ける場面があります（ショートスタックの脱落を促す）。
逆にミドルスタックは「じっと待つ」戦略が ICM 的に有利になることがあります。

これらは UCBS-v2 の context 補正としては現行フレームワークで表現できていません。
FT の戦略は Vol1（プリフロップ ICM）で学んだコンセプトをポストフロップに応用する形で補完してください。

## UCBS-v2 との統合——context 選択後に ICM 補正を加える

ICM 補正を UCBS-v2 に組み込む実戦フローを示します。

**UCBS-v2 + ICM 補正フロー（2 ステップ）**:

```
Step 1: UCBS-v2 で freq を計算
        （通常の context 選択 → CBS → Confidence → freq）

Step 2: ICM 補正を加算
        freq_icm = freq - ICM_adjustment
        clamp(freq_icm, 0.02, 0.98)
```

概算式（定性モデル）:

```
freq_icm ≈ freq × (1 - icm_factor)
```

ここで `icm_factor` は以下の目安です:

| 状況 | icm_factor |
|---|---|
| バブル + ビッグスタック | 0.08〜0.12（8〜12% 減） |
| バブル + ショートスタック | 0.15〜0.25（15〜25% 減） |
| FT 9 人残り | 0.10〜0.18（10〜18% 減） |
| FT 3 人残り | 0.05〜0.08（5〜8% 減） |
| HU | 0〜0.03（ほぼ補正なし） |

**計算例（定性）**:
mtt_50bb context（WRMSE 12.96%）で top_pair が BTN から bet する場合、
UCBS-v2 計算結果が 65% だったとします。
バブル + ミドルスタックの場合: 65% × (1 - 0.10) ≈ **59%**。
この場合でも 59% は bet 方向のままなので、bet 判断は変わりません。

**重要な注記**:
本章の ICM 補正値は GTO Wizard の ICM ポストフロップデータから直接算出したものではありません。
MTTGeneral_ICM6m200PTT2 や類似のデータセットの取得と解析が完了した段階で、
この章は定量的な補正値に更新される予定です。

## MTTGeneral_ICM データと将来拡張

GTO Wizard には ICM 対応のゲームツリー（MTTGeneral_ICM6m200PTT2 等）が存在します。
このデータを取得・解析することで、以下の定量化が可能になります。

- バブル係数の context 別 WRMSE
- ショートスタック vs ビッグスタック別の ICM 係数
- FT 各段階での補正値

**Vol1（プリフロップ ICM）との関係**:
Vol1 では ICM 補正として「バブル +10〜15% 要求エクイティ増加」「FT さらに増加」を学びました。
ポストフロップでも概念は同じですが、プリフロップの「全イン判断」と異なり、
ポストフロップは bet 頻度の調整（all-in でないレンジ的な判断）なので、
プリフロップ ICM より補正値の絶対量は小さくなります。

目安: プリフロップ ICM 補正（≒ 10〜25% エクイティ）の **40〜60% 程度**がポストフロップの ICM 圧力と考えると実用的です。

この将来拡張に向けて、本書では context 構造を ICM 対応可能な形に設計しています。
ICM context（MTTGeneral_ICM6m200PTT2）が追加されれば、
既存の 13 context と同じフレームワークで ICM 状況を定量的に扱えます。

## まとめ：ICM 補正の 4 原則

本章の要点を 4 点にまとめます。

1. **ICM 補正は「マイナス方向」**: バブル/FT では UCBS-v2 の計算 freq から 5〜25pt 引いて守り志向に補正する。
2. **ショートスタックほど大きい補正**: 脱落コストが高いほど bet 頻度を絞る。ビッグスタックは補正小さめ。
3. **現時点は定性データのみ**: MTTGeneral_ICM データ未取得のため、本章の補正値は推定値。定量化は将来課題。
4. **Vol1 プリフロップ ICM の連携**: プリフロップで習得した ICM コンセプトをポストフロップに縮小適用（係数は 40〜60% 程度）。
