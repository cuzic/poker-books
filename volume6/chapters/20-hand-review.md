# 第20章　トーナメントハンドレビュー法

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: 5ステップのレビュー手順と6種のミスパターンを習得し、ICMミスを自力で発見できるようになる。

---

## 20-1 なぜトーナメントのレビューは難しいか

キャッシュゲームのレビューは「chip EVを最大化できたか」という一軸で評価できます。トーナメントはそうではありません。スタック分布・賞金構造・ステージという3変数がすべて絡み、同じコール判断でも$EVが正にも負にもなります。エクイティ52%でオールインに乗った判断が、バブル直前では$EVマイナスになる場合があります。

レビューに必要な固有観点は3つです。第一に、テーブル全体のスタック分布を考慮したICM計算。第二に、ステージ判定（バブル・ITM・FT・HU）。ICM補正の大きさはステージで大きく変わります。第三に、結果ではなく判断の質を評価すること。正しい判断が負けになることはあり、間違った判断が勝つこともあります。両者を混同すると学習が歪みます。

---

## 20-2 5ステップレビュー手順

レビューは以下の5項目を順番に確認します。

- ステップ1（状況再現）: 残プレイヤー数・全スタック・賞金構造・自分のM値・ステージを復元する
- ステップ2（ICM計算）: `scripts/icm_calc.py` でバブルファクターとICM補正（平均）を取得する
- ステップ3（必要equity確認）: 必要equity = BF ÷ (BF + 1) を計算し、自分のハンドのエクイティと比較する
- ステップ4（判断の評価）: 実戦のアクションが必要equity条件を満たしていたか確認する
- ステップ5（一般化・記録）: 「次回同じ状況でどう判断するか」を1文で書き、ミスならパターンを特定する

ICM計算をツールで数値化することが、このレビューをキャッシュレビューと区別する核心です。

---

## 20-3 ICM計算ツールの基本操作

```bash
python scripts/icm_calc.py --stacks "4500,3000,1500,1000" --payouts "50,30,20" --bubble-factor 2
```

`--bubble-factor` の引数はプレイヤーのインデックス（0始まり）です。出力の「ICM補正（平均）」を読み、必要equity = BF ÷ (BF + 1) で判断基準を算出します。

主要なBFと必要equityの対応は以下のとおりです。

| 状況 | BF | 必要equity |
|:---|:---|:---|
| バブルSTT 中スタック vs リーダー | 2.245 | ≈ 69% |
| バブルSTT 中スタック vs 中スタック | 2.036 | ≈ 67% |
| FT 3-handed 中スタック vs リーダー | 1.698 | ≈ 63% |
| MTT中盤（BF ≈ 1.5） | 1.500 | = 60% |
| HU（ICM補正ゼロ） | 1.000 | = 50% |

よく使うシナリオはプリセットで呼び出せます。

```bash
python scripts/icm_calc.py --preset bubble-9max-stt --bubble-factor 2
python scripts/icm_calc.py --preset ft-3way-uneven --bubble-factor 1
```

## 20-4 バブル前後のICM補正の変化

ハンドレビューで見落としやすいのが「ステージが変わったときのICM補正の急変」です。バブル直前（STT 4名残り、スタック配分 4500/3000/1500/1000 の非等スタックシナリオ）でP3（スタック1500）の平均ICM補正は0.825です（等スタックシナリオでは0.875）。P4が脱落してバブルを突破すると、P2（中スタック3000、3名残り）の平均ICM補正は0.349に半減します。

この変化を「感覚で把握する」のは難しいため、レビュー時にはツールで実測することを推奨します。必要equityで言えば約64%から約57%に下がります。この差は「AT級ではコールできないか、できるか」という判断に直結します。

FTでも脱落ごとにICM補正は変動し、HUになった瞬間にゼロになります。ステージが変わるたびに再計算する習慣を持つことが、レビュー精度を上げる最短経路です。

## 20-5 典型的なICMミスパターン6種

実戦で繰り返されやすいICMミスには共通のパターンがあります。自分のレビューでどのパターンに当たるかを特定することで、修正が速くなります。

- **パターン1（バブル直前の過剰コール）**: BF ≈ 2.2 → 必要equity ≈ 69%。エクイティ50〜60%のハンドでは大幅不足です。「エクイティ50%+なら参加できる」という誤認が根底にあります
- **パターン2（ITM直後の過剰タイト）**: バブル突破後はICM補正が0.825→0.349に急落します。バブル中の感覚をリセットしないと、ITMでは十分な勝算があるオールインもフォールドしてしまいます
- **パターン3（HUでのICM守備モード）**: HUはBF = 1.000、ICM補正ゼロです。BTN/SBの最適オープンレンジは約70〜80%で、「負けたくない」気持ちから絞りすぎると大量のEVを失います
- **パターン4（サテライトの通常ICM思考）**: 「上位N名一律賞金」構造はICMの非線形性が通常のフリーズアウトと全く異なります。チケット圏内なら通常より大幅に保守的に判断します（第16章参照）
- **パターン5（ペイジャンプ意識の過剰タイト）**: 必要equityを満たすハンドはペイジャンプ前でも参加すべきです。良いハンドを待ちすぎるとスタックが目減りし、ペイジャンプ後に弱い立場から戦う羽目になります
- **パターン6（ティルト後のコール）**: バッドビート直後は「取り戻し」動機でコールしやすくなります。直前ハンドの結果は次のハンドの必要equityを変えません。ティルト疑いがある場合は必要equityを数値で確認してから判断します

## 20-6 レビューの記録形式

レビュー結果は以下の8項目でシンプルに記録します。

```
日付・トーナメント名:
状況:    スタック分布、賞金構造、ステージ
アクション: コール / フォールド / 3betシャブ 等
ICM補正（avg）: [計算値]
必要equity: [%]
ハンドのエクイティ: [%]
判定:    正解 / ミス
ミスパターン: [1〜6のどれか]
次回の判断基準: [一文]
```

この記録を月次で見返すことで、「自分はどのパターンのミスを繰り返しているか」が明確になります。6種のうち1〜2個に集中している場合は、そのパターンへの対処を優先的に訓練します。

セッション直後のレビューが最も効果的です。スタック分布・賞金構造・自分のハンドの詳細は30分後には忘れ始めます。実戦中にメモを取る習慣（スマートフォンのメモアプリなど）を持つことで、後のレビューの質が上がります。

## 20-7 ハンドレビュー実例

**状況**: STTバブル直前（4名残り）。スタック: 自分（BB）= 1500、大スタック（SB）= 4500、ほか2名。賞金 50/30/20。SBのオールインプッシュに対してBB（自分）がA♠T♦で3betシャブを検討中。

**ICM計算結果**: BF（自分 vs SB）= 2.245、必要equity ≈ 69%。A♠T♦の対コールレンジ（AJ+、KQ+、TT+）のエクイティは約40〜50%で大幅不足。フォールドが正解。

**教訓**: バブル直前は大スタック相手のBFを必ず確認する。AT程度のハンドでは69%の必要equityに届かない。パターン1（過剰コール）の典型例。

## ミニクイズ

### 問1

STTバブル直前（4名残り、Top 3賞金圏）で、中スタック（3000）がリーダー（4500）のオールインを受けました。BF = 2.036のとき、コールに必要な最低equityはいくらですか。

1. 約50%
2. 約60%
3. 約67%

### 問2

FT残り3名（リーダー/中スタック/ショートスタック）で、中スタック（P2）のリーダー（P1）に対するBF = 1.698でした。正しい対応はどれですか。

1. BFが1.6以上あるためバブル直前と同程度に守備的に判断する
2. 必要equity ≈ 63%を確認し、それ以上のエクイティがあるハンドでコールする
3. FT以降はICM補正なしでエクイティ50%で判断する

### 問3

バッドビート直後に「取り戻そう」という気持ちでオールインコールを検討しています。最も正しい対処法はどれですか。

1. 気持ちを切り替えてすぐ次のハンドへ進む
2. ICM計算で必要equityを数値確認し、超えていればコール・超えていなければフォールドを貫く
3. ティルト状態の判断も長期的に均等化するため許容してよい

---

### 解答

- **問1**: 3が正解。必要equity = BF ÷ (BF + 1) = 2.036 ÷ 3.036 ≈ 67%。中スタックがバブル直前にリーダーとオールインする場合、エクイティ67%以上のハンドでのみコールが$EV上プラスになります。
- **問2**: 2が正解。BF = 1.698 → 必要equity = 1.698 ÷ 2.698 ≈ 63%。バブル直前の67%より低いですが50%ではありません。HUになって初めてBF = 1.0（ICM補正ゼロ）になります。
- **問3**: 2が正解。ミスパターン6（ティルト後のコール）に当たります。直前ハンドの結果は次のハンドの必要equityを変えません。数値で「エクイティが足りない」と確認することで感情的な判断を防ぎやすくなります。

---

> **本章まとめ**
>
> - トーナメントのレビューには「ICM計算」「ステージ判定」「結果vs判断の質の区別」という3つの固有観点が必要。
> - 5ステップ: 状況再現 → ICM計算 → 必要equity確認 → 判断の評価 → 一般化・記録。
> - 必要equity = BF ÷ (BF + 1) が判断の数値基準。BFはツールで取得する。
> - ミスパターン6種を把握し、自分のレビューで該当パターンを特定することで修正が速くなる。
> - バブル前後でICM補正は大きく変わる（例: STT中スタックで0.825 → 0.349）。ステージが変わるたびに再計算する。

---

**【GTOとのズレ】**

ICMIZER等の商用ソルバーは本章の5ステップのうちステップ2〜4をより精密に計算します。最もズレが出やすいのはプリフロップの境界ハンドです。BFが0.1変わるだけでコール/フォールドの判断が逆転することがあります。また「フォールドエクイティ」の扱いもずれの原因です。3betシャブの判断には「コールされたときのEV」だけでなく「フォールドされたときに得るEV」も加味した計算が必要で、正確な評価にはソルバーが必要です。本章のフローは大きなミスを防ぐ近似であり、境界線上の判断はソルバーに委ねることを推奨します。
