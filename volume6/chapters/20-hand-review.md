# 第20章　トーナメントハンドレビュー法

<!-- markdownlint-disable MD026 MD033 MD036 MD040 MD060 -->

> **本章のゴール**: キャッシュゲームとは異なるトーナメント固有のレビュー観点を習得し、ICM 計算ツール（scripts/icm_calc.py）を使った 5 ステップのレビュー手順と、典型的な 6 つの ICM ミスパターンを自力で発見・修正できるようになる。

---

## 20-1 トーナメントのハンドレビューはなぜ難しいか

キャッシュゲームのハンドレビューは、大半の判断を「chip EV（チップ期待値）で最大化できたか」という一軸で評価できます。実戦後に暗算式の計算を再確認し、ソルバーと比較すれば、判断のズレが明確になります。

トーナメントのレビューはこれよりも複雑です。同じ「コール」という判断でも、その行為が $EV（賞金期待値）を上げたかどうかはスタック分布・賞金構造・ステージによって全く異なります。「エクイティ 52% でオールインに乗った」判断が、バブル直前では $EV ではマイナスになる場合があります。逆に、「エクイティ 45% のコール」がバブル突破後の ITM 直後では正解になる局面もあります。

つまり、トーナメントのレビューには 3 つの固有観点が必要です。

**観点1: スタック分布全体の考慮（ICM 計算）**

自分のスタックの変化だけでなく、テーブル全体のスタック分布がどう変わるかが $EV に影響します。大スタックに負けることと、ショートスタックに負けることでは、ICM ペナルティが大きく違います。

**観点2: ステージ判定（バブル / ITM / FT / HU）**

ICM 補正の大きさはステージによって変わります（第19章参照）。同じハンドに対するコール判断も、ステージが違えば正解が変わります。「いつ・どのステージの判断か」を再現しなければ、レビューが機能しません。

**観点3: 結果ではなく判断の質を評価する**

トーナメントではバッドビートが頻繁に起きます。ICM 上正解のコールでも結果が負けになることはあります。「結果が悪かった」という事実と「判断が誤っていた」という事実は別です。正しい判断を間違いと評価し、修正してしまうことが最大の学習リスクです。

本章ではこの 3 観点を組み込んだ、トーナメント固有のレビュー手順を示します。

## 20-2 トーナメントハンドレビューの 5 ステップ

レビューは次の 5 ステップで完結します。各ステップに要する時間の目安も示します。

```
ステップ 1: 状況再現（1〜2分）
  記録または記憶から以下を復元する
    - 残プレイヤー数、自分のポジション
    - 全プレイヤーのスタック（チップ数）
    - 賞金構造（上位何位まで支払われるか、金額）
    - 自分の M 値 = スタック ÷ (SB + BB + アンテ合計)
    - ステージ判定（バブル直前 / ITM 直後 / FT 等）
    - 相手の傾向（攻撃的 / 守備的）があれば記録

ステップ 2: ICM 計算（2〜3分）
  scripts/icm_calc.py で現状の ICM equity を計算する
    python scripts/icm_calc.py --stacks "..." --payouts "..."
  必要に応じてバブルファクターを取得する
    python scripts/icm_calc.py --stacks "..." --payouts "..." --bubble-factor [自分のインデックス]
  ICM 補正値（ICM 補正（平均）の行）を読む

ステップ 3: 必要 equity の確認（30秒）
  必要 equity = (1 + ICM 補正) ÷ (2 + ICM 補正)
  自分のハンドの実際のエクイティと比較する
  (エクイティは暗算、またはポーカー計算ツールで確認)

ステップ 4: 自分の判断を評価する（3〜5分）
  自分が実戦でとったアクションを再現する
  「そのアクションは必要 equity 条件を満たしていたか」を確認する
  第19章の ICM 補正済み暗算式も使って判断の質を評価する
    - Score（プリフロップ開戦）
    - 後手スコア（ポストフロップ守備）
    - α 式（リバー配分）

ステップ 5: 一般化と記録（1〜2分）
  「同じ状況に次回遭遇したときどう判断すべきか」を 1 文で書く
  ミスがあれば 6 つのミスパターン（20-4 節）のどれに当たるかを確認する
  心理的な要因（ティルト、ペイジャンプ誘惑）がなかったかも確認する
```

この 5 ステップは「状況再現 → 数値化 → 検証 → 評価 → 一般化」という学習の基本形です。特にステップ 2（ICM 計算）をツールで正確に行うことが、トーナメントレビューをキャッシュレビューと区別する核心です。

## 20-3 ICM 計算ツールの実践的な使い方

### scripts/icm_calc.py の基本操作

`scripts/icm_calc.py` は Malmuth-Harville アルゴリズムによる正確な ICM 計算ツールです。チップスタックと賞金構造を入力すると、各プレイヤーの $EV（ICM 換算の賞金期待値）を出力します。

**基本的な呼び出し方**

```bash
python scripts/icm_calc.py --stacks "4500,3000,1500,1000" --payouts "50,30,20"
```

スタックはカンマ区切りで全プレイヤー分を入力します。ペイアウトは上位から順に、支払われる割合または金額（同じ単位なら比率でも可）を入力します。

出力例（STT バブル直前、4 名残り、上位 3 位に支払い）:

```
| Player | Stack | Chip% | $EV  | ICM% |
| P1     | 4500  | 45.00%| 35.64| 35.64%|
| P2     | 3000  | 30.00%| 30.02| 30.02%|
| P3     | 1500  | 15.00%| 20.13| 20.13%|
| P4     | 1000  | 10.00%| 14.21| 14.21%|
```

Chip%（チップ比率）と ICM%（ICM エクイティ比率）のズレが「ICM の歪み」です。P1 はチップ比率 45% に対して ICM% も 35.64% にとどまります。チップが多いほど ICM 価値の上昇が鈍化する構造が数値で確認できます。

**バブルファクター（bubble factor）の取得**

```bash
python scripts/icm_calc.py --stacks "4500,3000,1500,1000" --payouts "50,30,20" \
  --bubble-factor 2
```

`--bubble-factor` の引数はプレイヤーのインデックス（0 始まり）です。P3（インデックス 2）を自分と設定した場合の出力:

```
## Bubble factor for P3
| Villain | V Stack | Bubble Factor |
| P1      | 4500    | 2.245         |
| P2      | 3000    | 2.036         |
| P4      | 1000    | 1.194         |

ICM 補正（平均）: 0.825
```

P3 が P1 と対戦した場合のバブルファクターは 2.245 です。これは「P3 がチップを失うことのコスト」が「同量のチップを得る利益」の 2.245 倍であることを意味します。必要 equity はおよそ BF ÷ (BF + 1) = 2.245 ÷ 3.245 ≈ 69% です。

「ICM 補正（平均）: 0.825」は、全相手を平均したときの ICM 補正値です。第19章の式に代入すると「必要 equity ≈ (1 + 0.825) ÷ (2 + 0.825) ≈ 64.5%」という全体的な判断基準が得られます。

### プリセットシナリオの活用

一般的なシナリオはプリセットとして用意されています。

```bash
python scripts/icm_calc.py --preset bubble-9max-stt --bubble-factor 2
python scripts/icm_calc.py --preset ft-3way-uneven --bubble-factor 1
```

以下のプリセットが利用できます。

| プリセット名 | 内容 |
| :--- | :--- |
| `bubble-9max-stt` | STT 4 名残り、上位 3 位支払い |
| `ft-3way-uneven` | FT 3 名残り、リーダー vs 2 ショートスタック |
| `ft-9max` | FT 9 名残り、等スタック |
| `3-handed-equal` | 3 名等スタック |
| `hu` | HU、等スタック |

### 商用ツールとの組み合わせ

scripts/icm_calc.py は簡易確認に最適ですが、レンジ vs レンジの GTO 解析が必要な場面では商用ツールを使います。

**ICMIZER**: ICM 解析の業界標準ツール。プッシュ/フォールドチャートを ICM 補正込みで生成でき、「A♥T♦ on BTN、スタック 18BB、バブル直前」のような具体的な局面で最適プッシュ/フォールドを出力します。

**HRC（Holdem Resources Calculator）**: ナッシュ均衡解の計算と ICM 補正の組み合わせに強いツール。短スタック時の push/fold を精密に計算します。

**PioSolver**: ポストフロップの GTO 解析ツール。ICM モジュールを追加すると、フロップ・ターン・リバーの判断に ICM 補正を組み込めます。

本章の暗算式（第19章の ICM 補正済み式）はこれらの商用ツールの近似として機能します。実戦後のレビューには scripts/icm_calc.py で数値を取り、深いポストフロップ分析には PioSolver や ICMIZER を使うという組み合わせが効率的です。

## 20-4 典型的な ICM ミスパターン 6 種

実戦で繰り返されやすい ICM ミスには共通のパターンがあります。6 つを以下に示します。自分のレビューでどのパターンに当たるかを確認することで、修正が速くなります。

### ミスパターン 1: バブル直前の過剰コール

**状況**: バブル直前の中スタック、大スタック相手のオールインに「エクイティ 50%+ だからコール」と判断した。

**なぜミスか**: バブル直前の中スタックが大スタックと対戦するバブルファクターは 2.0 前後です（icm_calc.py の実測: STT バブル直前で P2 vs P1 の BF = 2.036、P3 vs P1 の BF = 2.245）。この場合の必要 equity は BF ÷ (BF + 1) = 2.245 ÷ 3.245 ≈ 69% です。エクイティ 50〜60% のハンドでは大幅に不足します。

**典型例**: AT オフスートで BF = 2.245 の大スタックのオールインにコール。AT の対 40% オープンレンジのエクイティ（実力差込み）はおよそ 50〜55% 程度であり、必要 equity 69% を大きく下回ります。

**教訓**: バブル直前は大スタック相手の BF を必ず確認する。scripts/icm_calc.py で BF を取得し、必要 equity を計算してからコールを判断する。

### ミスパターン 2: ITM 直後の過剰タイト

**状況**: バブルを突破して ITM になった直後、相手のオールインに対して「まだ守備的に行くべきだ」とフォールドを繰り返した。

**なぜミスか**: バブル突破後、ICM 補正は劇的に下がります。scripts/icm_calc.py の実測では、STT バブル突破後 3 名残りの P2（チップ 3000）の ICM 補正（平均）は 0.349 です。バブル直前の 0.825 から大幅に低下します。バブル中の「高 ICM 補正」感覚をそのまま持ち込むことで、ITM では十分な勝算のあるオールインもフォールドしてしまいます。

**典型例**: ITM 直後の FT 3 名残りで、中スタックが BF = 1.615 のリーダーに対して「まだバブル感覚で fold」。必要 equity = 1.615 ÷ 2.615 ≈ 62% であり、KJ のようなハンドでも状況次第では参戦できます。

**教訓**: ステージが変わったらすぐに ICM 補正を再計算する。「バブル中の感覚」はリセットする。

### ミスパターン 3: HU での「ICM 守備モード」

**状況**: ヘッズアップになった後も「相手に消されたら終わり」という意識でフォールドを繰り返した。

**なぜミスか**: HU（ヘッズアップ）は ICM 補正 = 0.000 です（scripts/icm_calc.py のプリセット `hu` で確認可）。HU ではチップ獲得の利益とチップ喪失のコストが等しく、キャッシュゲームと同じ判断基準が成立します。必要 equity は 50% であり、第15章で確認した広いプッシュレンジが正解です。

**典型例**: HU で BTN から 90% のハンドをプッシュすべきところ、「負けたくない」気持ちからプッシュレンジを 50% 程度に絞った。ICM 補正が 0 なのに ICM 圧力下の判断をすることで、大量の EV を失います。

**教訓**: HU になった瞬間に「ICM 補正はゼロ」を確認する。巻①〜5 のキャッシュ用戦術（第15章も参照）をそのまま適用する。

### ミスパターン 4: サテライトでの「通常 ICM 思考」

**状況**: サテライト（上位 N 名に同額チケット）で、「エクイティ 54% でコールできる」と判断してオールインに応じた。

**なぜミスか**: サテライトの賞金構造は「上位 N 名一律」というステップ関数です。N+1 位と N 位の差が大きく、N+2 位と N+1 位の差は 0 です。この構造では ICM 補正が通常のフリーズアウトと全く異なります。チケット獲得圏に入っていれば大スタック相手のコールは不利になりやすく、必要 equity は 80%+ になる局面も多くあります。

**典型例**: サテライト残り 4 名、チケット圏 3 名。自分は 3 番手スタック。大スタックのオールインに AJ でコール。通常 ICM では参戦できる場面でも、サテライトでは 3 番手の「チケット確定に近い立場」を守る価値が大きく、フォールドが正解です。

**教訓**: サテライトの賞金構造を事前に確認する。「自分はチケット圏内か」を最初に判断し、圏内であれば通常より大幅に保守的に判断する（第16章参照）。

### ミスパターン 5: ペイジャンプ意識による過剰タイト

**状況**: FT で次の脱落者が出ると賞金が跳ね上がる局面で、「次のペイジャンプを待とう」と良いハンドでもフォールドし続けた。

**なぜミスか**: ペイジャンプによる ICM 上昇は、脱落者が出たときにのみ実現します。良いハンドをフォールドし続けることで、スタックが目減りし、むしろペイジャンプ後に弱い立場から戦う羽目になります。ICM 計算に基づく必要 equity（通常 55〜65% 程度）を満たすハンドでのオールインは、ペイジャンプ前であっても参加すべきです。

**典型例**: FT 5 名残り、4 位に賞金追加。自分はミディアムスタック。BTN のスティールに AK で「ペイジャンプを待って fold」。AK の 3bet シャブはほぼあらゆる ICM 条件下で正解です。

**教訓**: ペイジャンプは「一つの変数」にすぎない。ICM 計算で必要 equity を確認し、それを超えるハンドでは参加する。

### ミスパターン 6: ティルト後のコール（感情的コール）

**状況**: バッドビートを受けた直後、「取り戻そう」という意識でエクイティが明らかに不足するオールインにコールした。

**なぜミスか**: 直前ハンドの結果は、次のハンドの $EV 計算に影響しません。前のハンドでチップを失ったという事実は、次の判断の必要 equity を変えません。感情的な「取り戻し」動機でコールすることは、ICM 上も chip EV 上も損失です。バッドビート後の判断は特に慎重に確認する必要があります。

**典型例**: QQ が AA に負けた直後の次のハンドで、KJ のオールインコールを「エクイティ 40%、バブル直前、必要 equity 65%」という状況で実行した。

**教訓**: バッドビートの直後は「自分はティルト状態か」と自問する（第18章参照）。ティルト疑いがある場合は、ICM 計算を一度行い、必要 equity と自分のハンドのエクイティを数値で比較してから判断する。

## 20-5 ハンドレビュー実例

5 ステップのレビューを実際のハンドに適用する例を示します。

### 実例: STT バブル直前の ATs 3bet シャブ判断

**状況の記録**

- STT（9 名参加）、バブル直前、残り 4 名
- 賞金構造: 1 位 50、2 位 30、3 位 20（単位: ポイントまたは同比率の金額）
- スタック: P1（自分）= 1500 / P2 = 3000 / P3 = 4500（SB）/ P4 = 1000
  - 上の P3 が P1（自分）の BB に対して open 2BB（SB から）
- 自分のハンド: A♠T♦（ATs）
- 自分は 3bet シャブ（全スタック約 15BB のオールイン）を検討

**ステップ 1: 状況再現**

```bash
python scripts/icm_calc.py --stacks "1500,3000,4500,1000" --payouts "50,30,20"
```

出力（自分 = P1、インデックス 0）:

```
| Player | Stack | Chip% | $EV  | ICM% |
| P1     | 1500  | 15.00%| 20.13| 20.13%|
| P2     | 3000  | 30.00%| 30.02| 30.02%|
| P3     | 4500  | 45.00%| 35.64| 35.64%|
| P4     | 1000  | 10.00%| 14.21| 14.21%|
```

**ステップ 2: ICM 計算**

```bash
python scripts/icm_calc.py --stacks "1500,3000,4500,1000" --payouts "50,30,20" \
  --bubble-factor 0
```

出力（P1 = 自分のバブルファクター）:

```
## Bubble factor for P1
| Villain | V Stack | Bubble Factor |
| P2      | 3000    | 2.036         |
| P3      | 4500    | 2.245         |
| P4      | 1000    | 1.194         |

ICM 補正（平均）: 0.825
```

自分が SB（P3 = 4500）とオールインで対戦する場合の BF = 2.245 です。

**ステップ 3: 必要 equity の確認**

```
BF = 2.245 の場合:
必要 equity = BF ÷ (BF + 1) = 2.245 ÷ 3.245 ≈ 69.2%
```

A♠T♦ が P3 の SB オープンレンジ（約 40〜50%）に対して 3bet シャブを打った場合、コールされるのは絞ったレンジ（AJ+、KQ+、TT+ 等）です。A♠T♦ の対コールレンジのエクイティは概ね 40〜50% 程度です（Aを共有するコンボが多いため不利）。

**ステップ 4: 判断の評価**

```
必要 equity: 約 69%
自分のエクイティ(対コールレンジ): 約 40〜50%

判定: エクイティ不足。3bet シャブは $EV マイナス。
```

この局面での A♠T♦ の 3bet シャブは、バブル直前 STT の ICM 圧力下では過剰なリスクです。相手がフォールドする確率が高い場合（フォールドエクイティが大きい場合）はフォールドEVがプラスになりますが、P3 のスタックが 4500（全チップの 45%）と大きく、コール可能なレンジも広いため、コールされた場合の損失が大きすぎます。

フォールドが正解です。

**ステップ 5: 一般化と記録**

「バブル直前 STT で大スタック相手への 3bet シャブは、BF ≈ 2.2 → 必要 equity ≈ 69% が必要。ATs はコールレンジに対してエクイティが不足するためフォールド。バリューでの 3bet は QQ+、AK 相当のみ。」

ミスパターン 1（バブル直前の過剰コール）に近い判断ミスでした。今回はコールではなく 3bet シャブという形でしたが、根底にある「エクイティ 50%+ なら参加できる」という誤認が原因です。

## 20-6 バブル前後での ICM 補正の変化 ── レビューで見るべき「数値の動き」

ハンドレビューで最も重要な確認事項の一つは「このハンドが起きたときの ICM 補正は本当にその値だったか」という確認です。ステージが変わると ICM 補正が大きく変化するため、バブル前後のハンドを連続してレビューするときは特に注意が必要です。

以下に「バブル前後の ICM 補正の変化」を scripts/icm_calc.py の実測値で示します。スタック分布が同じ場合でも、残プレイヤー数が変わると ICM 補正が変化します。

**バブル直前（STT 4 名残り）の ICM 補正**

```bash
python scripts/icm_calc.py --stacks "4500,3000,1500,1000" --payouts "50,30,20" \
  --bubble-factor 2
# ICM 補正（平均）: 0.825（P3 の場合）
```

**バブル突破直後（3 名残り）の ICM 補正**

```bash
python scripts/icm_calc.py --stacks "4500,3000,1500" --payouts "50,30,20" \
  --bubble-factor 1
# ICM 補正（平均）: 0.349（P2 の場合）
```

P4 が脱落してバブル突破すると、P2（中スタック）の ICM 補正は 0.825 から 0.349 へと約半分以下に下がります。必要 equity で言えば、約 64% から約 57% に下がります。

この変化を「感覚で把握する」のは難しいため、レビュー時には必ずツールで実測することを推奨します。「バブル突破後は守備的にしなくていい」という感覚を持っていても、具体的に何%の必要 equity になるかは計算しなければわかりません。

同様に、FT での脱落ごとに ICM 補正が変動します。FT 3 名残りの中スタック（P2: 2500）の ICM 補正（平均）は 0.385 です（scripts/icm_calc.py プリセット `ft-3way-uneven` 実測値）。「FT だからまだ ICM 圧力が高い」という感覚は正しいですが、HU になった瞬間に補正はゼロになります。

## 20-7 レビューの頻度と記録方法

### レビュー頻度の目安

| タイミング | 対象ハンド | 目的 |
| :--- | :--- | :--- |
| セッション直後 | 重要ハンド 3〜5 件 | 直後の記憶が鮮明なうちに状況を復元する |
| 週次 | 直近の ICM 判断ハンド全体をスキャン | ミスパターンの頻度を確認する |
| 月次 | 系統的なミスパターンの洗い出し | 繰り返しミスがどのパターンに集中しているかを確認する |

セッション直後のレビューが最も効果的です。スタック分布・賞金構造・自分のハンドの詳細を 30 分後には忘れ始めます。実戦中にメモを取る習慣（スマートフォンのメモアプリなど）を持つことで、後のレビューの質が上がります。

### 記録の形式

レビュー結果はシンプルな形式で記録します。

```
ハンド番号: [日付・トーナメント名]
状況: スタック分布、賞金構造、ステージ
自分のアクション: [コール / フォールド / 3bet シャブ 等]
ICM 補正（avg）: [計算値]
必要 equity: [%]
自分のハンドのエクイティ: [%]
判定: [正解 / ミス]
ミスパターン: [1〜6 のどれか]
次回の判断基準: [一文で]
```

この記録を月次で見返すことで、「自分はどのパターンのミスを繰り返しているか」が明確になります。6 つのパターンのうち 1〜2 個に集中している場合は、そのパターンへの対処を優先的に訓練します。

### ソルバーとの組み合わせ

ポストフロップのハンドレビューには、scripts/icm_calc.py に加えて PioSolver（ICM モジュール）や ICMIZER を使うことで精度が上がります。scripts/icm_calc.py が「ICM 補正値という数値の基準」を提供し、PioSolver が「その補正値を前提にした GTO レンジ」を提供するという分業です。

ただし、商用ツールがない場合でも本章の 5 ステップと scripts/icm_calc.py だけで、プリフロップ判断の大半はカバーできます。ポストフロップ ICM 解析は「より深い改善」であり、まずはプリフロップとオールイン判断のレビューを優先します。

## ミニクイズ

### 問1

STT バブル直前（4 名残り、上位 3 位支払い）で、自分は中スタック（チップ 3000）です。リーダー（チップ 4500）がオールインを仕掛けてきました。scripts/icm_calc.py で自分（P2）のバブルファクターを取得した結果、P1 に対する BF = 2.036 と出ました。このとき、コールに必要な最低エクイティはおよそいくらですか。

1. 約 50%（キャッシュゲームと同じ）
2. 約 57%（ICM 補正 0.32 程度の必要 equity）
3. 約 67%（BF ÷ (BF + 1) = 2.036 ÷ 3.036 ≈ 67%）

### 問2

FT で残り 3 名（リーダー / 中スタック / ショートスタック）の状況です。バブルはすでに突破しています。あなたは中スタック（P2）で、scripts/icm_calc.py でバブルファクターを計算したところ、リーダー（P1）に対する BF = 1.698 でした。以下のどれが正しい対応ですか。

1. ITM 後でも BF が 1.6 以上あるため、バブル直前と同程度に守備的に判断する
2. BF = 1.698 → 必要 equity ≈ 63% 程度。バブル直前ほどではないが ICM 補正は依然として存在するため、リーダーへのコールはエクイティ 63% 以上を確認してから判断する
3. FT に来たら ICM 補正はなくなるため、エクイティ 50% で判断する

### 問3

バッドビートを受けた直後、「取り戻そう」という気持ちでオールインコールを検討しています。ハンドレビューの観点から最も正しい対処法はどれですか。

1. バッドビートはポーカーの運。気持ちを切り替えてすぐ次のハンドへ進む（特にレビュー不要）
2. scripts/icm_calc.py でバブルファクターを確認し、自分のハンドのエクイティが必要 equity を超えているかを数値で確認してから判断する。超えていればコール、超えていなければフォールドを貫く
3. ティルト状態のコールも長期的に均等化するため、一時的な感情判断は許容してよい

---

### 解答

- **問1**: 3が正解。必要 equity = BF ÷ (BF + 1) = 2.036 ÷ 3.036 ≈ 67% です。中スタックがバブル直前にリーダーとオールインで対戦する場合、エクイティ 67% 以上のハンドでのみコールが $EV 上プラスになります。AK でも 66% 程度のエクイティがあることが多く、「AK でもギリギリの局面」というのがバブル直前の中スタック vs リーダーの特徴です。

- **問2**: 2が正解。BF = 1.698 は「FT ITM 後」のリーダー相手でも依然として意味のある ICM 補正があることを示します。必要 equity = 1.698 ÷ 2.698 ≈ 63% です。バブル直前の 67% より低いですが、50% ではありません。ICM 補正はゼロではなく、コール判断にはエクイティ確認が必要です。HU になって初めて BF = 1.0（ICM 補正 = 0）になります（選択肢3 は誤り）。

- **問3**: 2が正解。バッドビート後の「ティルト判断」はミスパターン 6 に当たります。直前ハンドの結果は次のハンドの必要 equity を変えません。感情的な判断を防ぐ最善の方法は、必要 equity を数値で確認するという機械的なプロセスを踏むことです。数値で「エクイティが足りない」と分かれば、感情が止まりやすくなります。

> **本章まとめ**
>
> - トーナメントのハンドレビューには「ICM 計算」「ステージ判定」「結果 vs 判断の質の区別」という 3 つの固有観点が必要。キャッシュのレビューとは根本的に異なる。
> - 5 ステップ: 状況再現 → ICM 計算（scripts/icm_calc.py）→ 必要 equity の確認 → 判断の評価 → 一般化。ICM 計算を数値で行うことが核心。
> - scripts/icm_calc.py の `--bubble-factor` オプションでバブルファクターと ICM 補正（平均）を取得し、必要 equity = BF ÷ (BF + 1) で計算する。
> - 典型的な ICM ミスパターン 6 種: バブル直前の過剰コール / ITM 直後の過剰タイト / HU での ICM 守備モード / サテライトの通常 ICM 思考 / ペイジャンプ意識の過剰タイト / ティルト後のコール。
> - バブル前後の ICM 補正変化は large（例: STT P3 の補正が 0.825 → 0.349 に半減）。ステージが変わるたびに再計算することが必須。
> - レビュー記録はシンプルに「状況・アクション・ICM 補正・必要 equity・エクイティ・判定・パターン・教訓」の 8 項目。月次でパターンを集計する。

**【GTO とのズレ】**

ICMIZER や HRC などの商用 ICM ソルバーは、本章で示した 5 ステップのうちステップ 2〜4 をより精密に計算します。特にポストフロップ ICM 解析（PioSolver の ICM モジュール等）では、「フロップ CBet のサイズ選択まで ICM 補正を加味した最適解」を出力できます。本章の暗算式と scripts/icm_calc.py は、その近似として機能します。

最もズレが出やすいのは「プリフロップのレンジ境界ハンド」です。AT（ミスパターン 1 の典型例）や KJs などのハンドがコール / フォールドのどちらかという局面では、BF が 0.1 変わるだけで判断が逆転することがあります。本章の必要 equity 計算（BF ÷ (BF + 1)）は正確な数式ですが、「自分のハンドのエクイティをどのレンジを想定して計算するか」によって実際の判断は変わります。

もう一つのズレは「フォールドエクイティ」の扱いです。3bet シャブなどの判断では「コールされたときのエクイティ」だけでなく「フォールドされたときに得るEV」も加味した計算が必要です。本章の実例（AT の 3bet シャブ）では「コールされた場合の必要 equity」を中心に評価しましたが、実際には「シャブに対するコール確率 × コールされたときの EV + フォールド確率 × フォールドされたときの EV」という計算が必要です。正確な評価には ICMIZER のようなツールが必要になります。本章のフローは「大きなミスを防ぐ」ための近似であり、境界線上の判断はソルバーに委ねることを推奨します。
