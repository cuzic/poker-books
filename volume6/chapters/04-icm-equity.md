## 4-2 ICM の正式定義 ─ Malmuth-Harville 式

ICM の計算アルゴリズムは、Harville（1973）の競馬着順確率モデルをポーカートーナメントに適用した Malmuth（1987）の論文に由来します。

### 基本的な仮定

アルゴリズムは1つの仮定の上に成り立っています。

> **「あるプレイヤーが特定の順位に到達する確率は、そのプレイヤーのチップ量と残りチップ合計の比率に比例する」**

これだけです。1位になる確率はチップ比率に等しく、2位になる確率は「1位が確定した後の残りチップ分布のなかでのチップ比率」に等しく、3位以降も同じルールが再帰的に続きます。

スキル差なし、ポジションなし、ブラインド進行なし、という単純化は ICM の限界でもありますが、同時にどんな状況でも適用できる汎用性の根拠でもあります。

### 計算式の形

プレイヤーを 1, 2, …, n と呼び、各プレイヤーのスタックを s₁, s₂, …, sₙ、全チップの合計を S とします。

**1位の確率**:

```
P(プレイヤー i が 1 位) = sᵢ ÷ S
```

**2位の確率（条件付き）**:

プレイヤー j が1位になったとき、その後の「残りチップ」は S から sⱼ を引いた量になります。プレイヤー i（j 以外）が2位になる確率は、

```
P(i が 2 位 | j が 1 位) = sᵢ ÷ (S − sⱼ)
```

**完了順全体の確率**:

「j₁ が 1 位、j₂ が 2 位、j₃ が 3 位、……」という特定の完了順の確率は、各段階の条件付き確率を掛け合わせます。

```
P(完了順 j₁, j₂, j₃, …) = (sⱼ₁ ÷ S)
                          × (sⱼ₂ ÷ (S − sⱼ₁))
                          × (sⱼ₃ ÷ (S − sⱼ₁ − sⱼ₂))
                          × …
```

**ICM equity（$EV）**:

プレイヤー i の ICM equity は、すべての完了順についてその確率と i の賞金を掛けて合計した値です。

```
ICM equity(i) = Σ [全完了順 σ] P(σ) × 賞金(σ における i の順位)
```

n 人なら n! 通りの完了順が存在します。3人なら6通り、9人なら 362,880 通りです。手計算は現実的ではありませんが、構造を理解するには3人の例が最適です。

## 4-3 3-handed 完全計算 ─ 6通りの完了順を追う

第2章でも使った数値例（P1 = 5,000 chip、P2 = P3 = 2,500 chip、合計 10,000 chip、賞金 $50 / $30 / $20）を、今度は6通りの完了順すべてを書き出して計算します。

### 6通りの完了順と P1 の取り分

| 完了順 | 確率の計算 | 確率 | P1 の賞金 | P1 への貢献 |
| :--- | :--- | ---: | ---: | ---: |
| P1 → P2 → P3 | (5000/10000)×(2500/5000)×1 | 25.0% | $50 | $12.50 |
| P1 → P3 → P2 | (5000/10000)×(2500/5000)×1 | 25.0% | $50 | $12.50 |
| P2 → P1 → P3 | (2500/10000)×(5000/7500)×1 | 16.67% | $30 | $5.00 |
| P2 → P3 → P1 | (2500/10000)×(2500/7500)×1 | 8.33% | $20 | $1.67 |
| P3 → P1 → P2 | (2500/10000)×(5000/7500)×1 | 16.67% | $30 | $5.00 |
| P3 → P2 → P1 | (2500/10000)×(2500/7500)×1 | 8.33% | $20 | $1.67 |
| **合計** | | 100% | | **$38.33** |

P2 の計算を1行だけ追ってみましょう。「P2 → P1 → P3」の行で P2 が1位を取る確率は 2,500 ÷ 10,000 = 25%、次に P1 が2位になる確率は「P2 を除いた 7,500 チップの中で」5,000 ÷ 7,500 ≈ 66.7%、最後の P3 は自動的に3位なので確率は1です。

掛け合わせると 25% × 66.7% × 1 ≈ 16.67%。この完了順で P1 は2位なので $30 の賞金を受け取ります。貢献額は 16.67% × $30 ≈ $5.00 です。

### 3名の ICM equity 一覧

| プレイヤー | スタック | Chip% | ICM equity | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 5,000 | 50.0% | $38.33 | 38.33% |
| P2 | 2,500 | 25.0% | $30.83 | 30.83% |
| P3 | 2,500 | 25.0% | $30.83 | 30.83% |
| 合計 | 10,000 | 100% | $100.00 | 100% |

（v7b 蒸留モデルではなく、`scripts/icm_calc.py` で実測した値です）

### 本章で最も重要な数値

> P1 は **チップ 50%** を保有しているのに、ICM equity は **38.3%** しかない

この約 **11.7 ポイントの乖離**が「ICM 圧縮」の実体です。第2章では「ICM 圧縮」という言葉で現象を捉えました。本章の目的はこれが計算アルゴリズムの必然的な帰結であることを確認することです。

P2 と P3 はチップ比率（各25%）より高い ICM%（各 30.83%）を持っています。大スタックから圧縮された価値が、ショートスタック側に移転しています。これはアルゴリズムの構造から来るものであり、賞金に「天井（1位の $50）」が存在する以上、避けられない数学的帰結です。

## 4-4 なぜ大スタックほど1チップが軽いのか ─ 凸関数として見る

ICM equity をチップ量の関数として描くと、**上に凸の曲線（凸関数）**になります。

凸関数の直感的な意味は「増えるほど増え方が遅くなる」です。たとえば、ヒット数が増えるほど次のヒットを打つのが難しくなるスポーツの打率曲線や、収入が増えるほど1万円の増加が感じにくくなる限界効用のグラフと同じ形です。

### 3-handed での凸関数（実測値）

3人残り（50/30/20 賞金）、全体チップ 10,000 の状況で、P1 のチップ量を変えながら ICM equity を計算した実測値（`scripts/icm_calc.py` による）を示します。

| P1 のチップ | Chip% | ICM equity | ICM% | 1,000 チップ当たりの $価値 |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 10% | $24.64 | 24.6% | — |
| 3,000 | 30% | $32.23 | 32.2% | $3.80 |
| 5,000 | 50% | $38.33 | 38.3% | $3.05 |
| 7,000 | 70% | $43.47 | 43.5% | $2.57 |
| 9,000 | 90% | $47.95 | 48.0% | $2.24 |

（各ケースで P2 と P3 は残りチップを均等に保有しています）

チップが 3,000 → 5,000 に増えると、ICM equity は $32.23 → $38.33 で約 $6.10 増えます。  
チップが 7,000 → 9,000 に増えると、ICM equity は $43.47 → $47.95 で約 $4.48 増えます。

同じ 2,000 チップを得ても、少ないとき（低いチップ水準から）の方が、多いとき（高いチップ水準から）より大きな $EV を得ます。これが **限界価値逓減** です。

### 凸関数のグラフ

```
ICM equity ($)
    50 |                              ........ (天井 $50)
    45 |                    ·········
    40 |           ·········
    38 |        ·
    35 |     ·
    30 |   ·
    25 | ·
       +--+-------+-------+-------+-------+---
       0  1k     3k      5k      7k      9k    Chip
```

縦軸が ICM equity、横軸がチップ量です。左側（チップ少）では傾きが急で、チップを少し増やすだけで $EV が大きく動きます。右側（チップ多）では傾きが緩く、多くのチップを増やしても $EV の増加は小さくなります。そして $50 という天井に漸近していき、超えることはありません。

### 戦術への示唆

この凸関数の形状が、スタック別の戦略の非対称性を数学的に説明します。

**大スタック（チップ曲線の右側）**: チップを増やしても $EV の増加が小さい。チップを失うと $EV の損失が相対的に大きい（曲線の傾きが逆方向では急になるから）。「得るより失う方が痛い」状態です。

**小スタック（チップ曲線の左側）**: チップを増やすと $EV の増加が大きい。チップを失っても元々少なかったため、損失する $EV は相対的に小さい。「得る方が有利」な状態です。

スタック深度別の具体的な戦略は第III部（第7〜10章）で扱います。ここでは「なぜ大スタックが守備的に振る舞い、小スタックが積極的に動くのか」の数学的根拠が凸関数にあることを押さえてください。

## 4-5 ICM equity の早見表 ─ チップ% から ICM% を読む

実戦でスタックを数えるたびに計算ツールを開くのは非現実的です。第6章では暗算フローを提供しますが、その前に「典型的なステージごとのチップ% → ICM% の対応」を早見表として確認します。

すべての値は `scripts/icm_calc.py` で計算したものです。

### バブル直前（n=4、Top 3 払い 50/30/20）

4人残りで次の脱落者がバブルブレイク、という典型的な9人 SnG のバブル局面です。自分以外の3人が均等にチップを持つケースを基準としています。

| Chip% | ICM% | ボーナス / ペナルティ |
| ---: | ---: | ---: |
| 5% | 7.0% | +40% |
| 10% | 12.7% | +27% |
| 20% | 21.5% | +8% |
| 30% | 28.0% | −7% |
| 50% | 37.0% | −26% |
| 60% | 40.3% | −33% |

「ボーナス / ペナルティ」の列は「ICM% が Chip% から何% 乖離しているか」を示しています。Chip 5% でも ICM% が 7.0%になるのは40% のボーナス（生存価値プレミアム）があるからです。Chip 60% でも ICM% が 40.3%にとどまるのは 33% のペナルティがあるからです。

重要な境界線は **Chip 20〜30% あたり**です。この水準でボーナスからペナルティへと符号が反転します。Chip 20% では +8% のボーナスがある一方、Chip 30% では −7% のペナルティに変わります。等スタックは全員 25% なのでちょうど中立に近い水準です。

### 中盤（n=6、Top 3 払い 50/30/20）

6人残りの中盤戦。バブルより ICM 圧力は低く、ペナルティも小さくなります。

| Chip% | ICM% | ボーナス / ペナルティ |
| ---: | ---: | ---: |
| 5% | 5.7% | +14% |
| 10% | 10.8% | +8% |
| 20% | 19.3% | −3% |
| 33% | 27.9% | −15% |
| 50% | 36.1% | −28% |

バブル直前と比べて、ボーナスもペナルティも小さくなっています。この「圧力の弱さ」が中盤での積極性を正当化します。

### FT（n=9、9-place 全員払い、30/20/13/10/8/6/5/4/4）

9人残りのファイナルテーブル開始時点。全員が ITM 済みですが、上位の賞金が大きいため ICM 圧縮は強く続きます。

| Chip% | ICM% | ボーナス / ペナルティ |
| ---: | ---: | ---: |
| 5% | 7.7% | +53% |
| 10% | 10.5% | +5% |
| 20% | 14.9% | −25% |
| 33% | 19.1% | −42% |
| 50% | 23.0% | −54% |

FT では上位の賞金（1位 $300 vs 9位 $40）が大きく傾斜しているため、ICM 圧縮が極めて強くなります。リーダー（Chip 50%）でも ICM% は 23% にとどまります。これはバブル直前（37%）よりも低い値です。「FT は脱落直前より楽になる」という直感は誤りで、賞金構造によっては FT の方が ICM 圧縮が強いことを示しています。

## 4-6 ICM が効く場面と効かない場面

ICM は万能ではありません。「ICM の効き目が強い状況」と「ほぼ効かない状況」を区別することが、ICM を道具として正しく使うための前提になります。

### ICM が強く効く場面

**バブル直前（賞金圏まで1〜2名）**  
賞金構造の「段差」が最も急な局面です。1人脱落すれば全員が入賞し、あなたが脱落すれば収入ゼロです。この非対称性が ICM 圧縮を最大化します。等スタックでオールインコールするためには、約65% 以上の勝率が必要です（第5章で計算します）。

**ファイナルテーブル（FT）のペイジャンプ前後**  
FT では2位と3位の賞金差、3位と4位の差が大きくなります。特に5→4人、4→3人になる「ペイジャンプ直前」では ICM 圧縮が局所的に最大化します。

**スタック非対称が大きい局面**  
大スタックと小スタックが対戦するとき、ICM 補正の非対称性が最も大きくなります。大スタックにとってコールのコストは高く（負けると $EV が大きく落ちる）、小スタックにとってはプッシュのリターンが高い（勝てば $EV が大きく増える）。

### ICM が弱くなる場面

**ヘッズアップ（HU）**  
2人対戦では計算が完全に線形化します。チップ 70% のプレイヤーが1位になる確率は 70% であり、$EV は「70% × 1位賞金 + 30% × 2位賞金」で計算できます。ICM 圧縮は存在しますが、3人以上の場面と比べて格段に小さくなります。特に cEV と $EV を「プレイスタイルが変わるほどの差」は生まれません。

**序盤（フィールドの50%以上が残存）**  
ITM まで遠すぎるため、賞金構造の傾斜が実質的に判断に影響しません。cEV と $EV はほぼ一致します。序盤から ICM を意識しすぎると、攻撃機会を逃す過剰守備のミスになります。

**サテライト（特殊な賞金構造）**  
上位 N 名が一律で同じ賞金（例: メインイベントへの招待権）を得るサテライトでは、通常の ICM が適用できません。この場合は「入賞圏に入れば同じ」という性質から、非常に特殊な戦略（生存が最優先、チップを増やすインセンティブが非常に低い）が求められます。第16章でサテライト専用の補正を扱います。

### ICM の位置づけ

ICM はすべての実戦要因を取り込んだ「完全解」ではなく、「純粋なチップ分布から来る $EV のベースライン」です。

スキルの差・ポジション優位・ブラインド進行・相手のスタック量という実戦要因を ICM に上乗せすることで、実戦的な $EV に近づきます。

```
実戦的な $EV ≈ ICM equity
              + スキル補正
              + ポジション補正
              − ブラインド圧力
```

本書の暗算式はこの「ICM equity をベースに補正を加える」フローを実装します。第5章でリスクプレミアム（ICM 補正）を、第19章で巻①〜5 の暗算式への ICM 補正統合を扱います。

## 4-7 計算ツールの使い方

ICM の計算は手作業では困難です。本書では `scripts/icm_calc.py` を提供しています。このスクリプトを使えば、任意のスタック分布での ICM equity を即座に確認できます。

### 基本コマンド

```bash
python scripts/icm_calc.py --stacks "5000,2500,2500" --payouts "50,30,20"
```

出力例:

```
| Player | Stack | Chip% | $EV | ICM% |
| ---: | ---: | ---: | ---: | ---: |
| P1 | 5000 | 50.00% | 38.33 | 38.33% |
| P2 | 2500 | 25.00% | 30.83 | 30.83% |
| P3 | 2500 | 25.00% | 30.83 | 30.83% |
```

### 主要オプション

| オプション | 説明 | 例 |
| :--- | :--- | :--- |
| `--stacks` | チップスタック（カンマ区切り） | `"5000,3000,2000"` |
| `--payouts` | 賞金（1位、2位、…）| `"50,30,20"` |
| `--bubble-factor N` | プレイヤー N の bubble factor を計算 | `--bubble-factor 0` |
| `--preset KEY` | 事前定義シナリオを使用 | `--preset bubble-9max-stt` |
| `--all-presets` | 全シナリオを一括表示 | — |
| `--json` | JSON 形式で出力 | — |

### プリセットシナリオ

```bash
python scripts/icm_calc.py --preset bubble-9max-stt
# 9-max STT、4-handed バブル（Top 3 払い 50/30/20）
```

```bash
python scripts/icm_calc.py --preset ft-9max
# 9-max FT 開始時、等スタック、標準 9-place 払い
```

実戦ハンドをレビューするとき、またはスタック分布に対する ICM equity の感覚を養いたいときに活用してください。

### bubble factor の計算

第5章で詳述しますが、`--bubble-factor` オプションを使うと「あなたが特定の相手とオールインを争うとき、負けたコスト vs 勝ったリターンの比率」が計算できます。

```bash
python scripts/icm_calc.py --stacks "4500,3000,1500,1000" --payouts "50,30,20" --bubble-factor 0
```

これがリスクプレミアムの計算の土台になります。

## ミニクイズ

### 問1

4人残りで全員が均等スタック（各 2,500 chip、合計 10,000 chip）、賞金が $50 / $30 / $20 の状況です。各プレイヤーの ICM equity は？

1. 全員 $25（賞金プール $100 を4等分）
2. P1 が $35、残り3人で $65 を分割（1位を取りやすい人が有利）
3. P1 が $20 のみ（最小賞金の3位相当）、残りはほかプレイヤーへ

### 問2

5人残り、P1 が 5,000 chip（50%）、ほか4人が各 1,250 chip（各 12.5%）を保有しています。賞金は $50 / $30 / $15 / $5 / $0 です。P1 の ICM equity はいくらに最も近いか。

1. $50（全チップの50%なので1位賞金をほぼ確保）
2. $36（チップ50%でも ICM 圧縮により賞金の36%相当）
3. $25（等スタックの基準値と変わらない）

### 問3

バブル直前（n=4、Top 3 払い 50/30/20）で自分のチップ比率が30%のとき、ICM% はいくらに最も近いか。また、このことが戦術的に意味するのはどれか。

1. ICM% ≈ 30%。チップ比率と等しいので ICM 圧縮がない
2. ICM% ≈ 28%。ICM ペナルティがあり、チップを失うリスクの方が大きい
3. ICM% ≈ 35%。ICM ボーナスがあり、積極的に動くべき状況

---

### 解答

- **問1**: 1が正解（全員 $25）。全員のスタックが均等なら、ICM の対称性から全員の $EV も均等です。$100 ÷ 4人 = $25 が各人の ICM equity になります。各人の1位確率も2位確率も3位確率も同じため、計算上も均等配分となります。「チップ均等 = $EV 均等」は ICM の基本的な対称性から導かれる結果です。

- **問2**: 2が正解（約 $36）。`scripts/icm_calc.py --stacks "5000,1250,1250,1250,1250" --payouts "50,30,15,5,0"` で実測すると P1 の $EV は **$36.00** です。チップ50%を持っていても、$EV は賞金の36%にとどまります。1位賞金の $50 には届かず、ICM 圧縮が明確に現れています。

- **問3**: 2が正解（ICM% ≈ 28%、ペナルティあり）。早見表（4-5節）より、Chip 30% のときの ICM% は 28.0%（ペナルティ −7%）です。チップ比率（30%）よりも $EV が低いため、チップを失うコストの方が得るリターンより大きい状態にあります。コールは慎重に行うべきで、「こちらが有利に見えるコールでも ICM では不利」が起きやすい水準です。

> **本章まとめ**
>
> - ICM（Malmuth-Harville 式）の核心は「各プレイヤーが順位を獲得する確率はチップ比率に比例し、その計算が再帰的に続く」という1つの仮定。
> - 3-handed（50% / 25% / 25% スタック、賞金 50/30/20）の完全計算では、P1 の ICM% は 38.3% となり、Chip 50% から約 11.7 ポイント圧縮される。この乖離が「ICM 圧縮」の正体。
> - ICM equity をチップ量の関数として描くと「上に凸の曲線（凸関数）」になる。チップが多いほど追加1チップが生む $EV が小さく（限界価値逓減）、これが大スタックの守備的インセンティブと小スタックの積極的インセンティブの数学的根拠。
> - 早見表では、バブル直前（n=4）で Chip 5% の ICM ボーナスは +40%、Chip 60% のペナルティは −33%。FT では ICM 圧縮がバブル直前より強くなることがある。
> - ICM が最も効くのはバブル直前・FT のペイジャンプ前後・スタック非対称局面。ヘッズアップ・序盤・サテライトでは効き目が弱くなるか、別の計算が必要。
> - `scripts/icm_calc.py` で任意のスタック分布の ICM equity を実測できる。

**【GTOとのズレ】**

ICM は「スキル差ゼロ」を仮定します。この仮定は現実と乖離します。たとえばあなたが残り全員より明らかに実力が上だとすれば、ICM が示す値より高い実 $EV があるはずです。逆に、強いプレイヤーが多い卓では ICM 値より低い実 $EV になります。GTO ソルバー（例: ICMIZER、HRC）はスキル補正を追加入力として受け付けるものもありますが、設定が難しく、不確かな仮定に頼ることになります。

本書では ICM を「スキル補正なしのベースライン」として使い、スキル差は局所的な補正（第19章）で加えます。これは「ICM 値を正確に計算できる方が、大まかなスキル補正を加えた不正確な値より実用的」という判断に基づいています。

もう1つのズレはポジションです。ICM はポジションを無視しますが、ブラインドが自分に迫っているかどうか、次のハンドでどの席になるかは $EV に影響します。特にバブル直前の FT では、ブラインドが大きく、席次が「あと何ハンドプッシュできるか」を決定的に左右します。M 値の概念（第6章）はこの「残り時間」を補正するための道具です。

ICM の値を精度の目安として使い、上記の要因で「実際にはもっと有利/不利」という方向で調整する習慣が、本書の暗算アプローチの核心です。
