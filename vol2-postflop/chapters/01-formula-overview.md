# 第 1 章　公式の全体像

## 1.1 公式そのもの

本書の中核となるのが次の 1 行です。

```
Score = Grid[カテゴリ][board]
      + DV × mult[street]
      + 2 × overcards
      + 4 × pot
      − 2 × bs

if Score ≥ 43: レイズ
elif Score ≥ 14: コール
else:                 フォールド
```

すべての変数は整数値なので、暗算することができます。

## 1.2 各項目の役割

| 項 | 範囲 | 由来 |
|---|---|---|
| `Grid[カテゴリ][board]` | 1〜40 | hand と board の interaction (本書の魔法核心) |
| `DV × mult` | 0〜12 | draw value × Rule of 4/2 整数化 |
| `2 × overcards` | 0〜4 | hero のカードがボード最高 rank より上の枚数 |
| `4 × pot` | 0〜16 | pot 種別 (SRP/vs CR/3BP/4BP) |
| `−2 × bs` | 0〜−10 | 相手の bet サイズが大きいほど不利になることを示します |

スコア理論上の最大は約 40+12+4+16 = 72、最小は約 1−10 = −9 ですが、実戦の大半は **0〜50** に収まります。

## 1.3 判定の閾値

| Score | 行動 |
|------:|------|
| ≥ 43 | **レイズ** (バリュー / ブラフレイズ) |
| 14〜42 | **コール** (ショーダウン / ブラフキャッチ) |
| < 14 | **フォールド** |

閾値 14 と 43 は data から決まった整数値です。少し中途半端に見えるかもしれませんが、暗算では「15 弱・40 強」と覚えれば十分です。詳細は第 5 章を参照してください。

## 1.4 公式が解いている問題

本公式は、ポストフロップの **「相手の bet 受けで call / raise / fold を出す」** 状況を一括で扱います。具体的には:

- ベット側 (hero がベット / レイズする場面)
- コール側 (hero が受ける場面)
- SRP / 3BP / 4BP / vs CR

これら全部が **1 つの式** で解けてしまいます。

## 1.5 5 つの判定軸との関係

MATCHA Framework では、ポストフロップ判断は次の 5 軸で記述されます (詳細は第 3 部)。

1. レンジ分布 (board の形状)
2. ハンドストレングス
3. ベットサイジング
4. SPR
5. エクイティバケット

MATCHA Score 公式は、この 5 軸を **整数の重み付け和** に圧縮したものです。「エクイティバケット」は本公式に数値として吸収されており、独立の暗記対象ではありません。

## 1.6 性能まとめ

GTO データ全 154,216 spots での検証結果です：

- **avg loss = 0.3587 BB**
- **huge loss% (>5 BB) = 1.49%**

### 街別 huge%

| street | huge% |
|---|---:|
| flop | 1.10% |
| turn | 1.69% |
| river | 2.55% |

river が最も高くなっています。例外 11 ルールの #2 (2P+ × wet × river × SRP) で大幅救済します。

### pot 別 huge%

| pot | huge% |
|---|---:|
| SRP | 2.62% |
| vs CR | 1.45% |
| 3BP | 1.45% |
| **4BP** | **0.53%** ★ |

**4BP huge% 0.53%** は本公式の最大の成果です。「2P+」(2P〜SF) を 1 階層に統合したことで、4BP の高 EV spots が的確に捕らえられています。

## Cash/MTT note

公式そのものは Cash/MTT 共通です。ただし bs (bet size) は ante 込み pot で実 bb 単位が ±10% ずれ、SPR は MTT で若干低くなります。Cash で rake 重時は t_call +1〜+2 推奨です。詳細は第 21 章を参照してください。
